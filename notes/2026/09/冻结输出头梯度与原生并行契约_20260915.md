# 冻结输出头：为什么仍要算 Hidden 梯度

> 学习日期：2026-09-15；整理日期：2026-09-17（北京时间）
> 来源：本周 MTP 输出端优化与代码审查对话；这里只记录通用机制，不记录内部实现。
> 状态：已整理

## 0. 先抓住一个问题

MTP 的共享输出头权重被冻结后，能不能跳过整个输出头的反向传播？**不能。**冻结只表示不更新这份权重；MTP 模块仍要从 loss 接收传回来的 hidden-state 梯度。

## 1. 用最小例子理解

设 MTP hidden state 为 `H[N,d]`，输出头权重为 `W[d,V]`，`logits = H @ W`。交叉熵给出 `dLogits[N,V]`：

```text
dH = dLogits @ Wᵀ      ← MTP 前面层继续训练需要它
dW = Hᵀ @ dLogits      ← W 冻结时可不计算/不累积
```

所以“冻结 W”与“不要反向”是两件事。若整个 head backward 被跳过，前面的 MTP 参数可能失去这条梯度路径。

`detach_encoder` 又是另一层边界：它决定 MTP 辅助 loss 是否继续影响主干输入侧；不应把“隔离主干梯度”误解成“切断 MTP 内部所有深度之间的梯度”。具体还要看模型实现把哪些 tensor detach 了。

## 2. 为什么二维 `mm` 与三维 `bmm` 会成为问题

当梯度为 `[N,1,V]`、权重为 `[V,d]` 时，数学上可以先把前者重排为 `[N,V]`，做二维矩阵乘法，再把结果恢复为 `[N,1,d]`。恢复 shape 是为了满足上游 autograd 对原输入形状的契约，不是额外生成新语义。

但是源码写 `matmul` 并不保证实际走 `mm`。长度为 1 的维度可以拥有多种合法 stride；编译后输出布局、`requires_grad` 和具体框架版本都会影响分派。显式二维化能控制局部计算路径，但仍需核对数值、梯度、并行通信和真实 GPU trace；不能仅凭 CPU 对照宣布端到端加速。

## 3. “复用原生层”到底保留什么

在 TP/SP 训练里，Linear 不只是矩阵乘法，还承担参数分片、输入/输出映射、梯度归约、AMP/重算等协议。局部优化反向乘法时，应尽量保留原生 forward 与其并行协议，只替换被明确证明冗余或低效的局部路径。否则即使单卡数值相同，也可能破坏多卡梯度语义。

浅拷贝模块对象也不等于复制整份 GPU 权重。判断是否增加显存，要查参数对象和底层 storage 是否共享；减少 Python 对象构造次数不自动等于减少权重显存或 GPU 时间。

## 5. 一分钟复习与自测

1. 冻结 W：省掉 `dW`，不省 `dH`。
2. `reshape → mm → reshape`：控制局部执行路径，同时遵守输入梯度 shape 契约。
3. TP/SP 的通信与映射属于原生层契约，不能只验单卡结果。

自测：若权重不更新，但前面的 MTP 模块要更新，输出头反向至少必须提供什么？答案：传回 MTP hidden state 的 `dH`。

## 6. 未证边界

CPU/mock 数值对照可以证明局部代数；真实 GPU、多卡通信、混合精度与端到端性能需要独立验证。一次 trace 中的 `mm`/`bmm` 次数也不能直接等同于整次 PPO 更新的加速比。
