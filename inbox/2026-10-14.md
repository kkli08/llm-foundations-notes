>
> 来源：Claude Code 会话 `c6b45672`、`60e4e2ab`

### 今天的问题

- 以前从 ckpt 恢复时，实验曲线接不上，生成长度等很多“权重之外的东西”也变了——断点续训在后训练里是不是意义不大？
- 一般做这种一两天的 RL 实验，会开断点恢复吗？

### 对话或资料摘录

- 被纠正：完整断点恢复保存权重、Optimizer、LR Scheduler、RNG、全局步、数据读取位置和各计数器；丢掉的只是短期状态（在途 Rollout、离策略缓冲、推理引擎随机状态与前缀缓存），只扰动恢复后头一两步；
- 生成长度是 Policy 学出来的行为，由权重决定；恢复后长度跳回初期，说明“其实是新起了一个 run（Warm Start）”或推理端还在用旧权重；
- 曲线断开常是实验追踪工具没有用固定 run id + resume，写进了新实验；
- 续训意义确实有限的两种情况：Online RL 的数据流不可重放；要求逐 bit 复现；
- 一般会开：只存权重的 checkpoint 用于评测或当新起点，恢复快照才能无缝接着跑；代价约“每参数 14 字节”的磁盘（bf16 权重 + fp32 主权重 + Adam 两个动量）和每次几分钟。

>
> 来源：Claude Code 会话 `4dfc7f28`

### 今天的问题

- 冒烟结论是不是每步降了十几秒、内存降了但显存没降，再往下优化意义不大？
- 长跑跑完却被标成失败，这个问题和路由回放有关吗？是之前的流程包本身有 bug、还是别人加的？

### 对话或资料摘录

- 被纠正：子阶段省下的时间包含在父阶段省下的时间里，嵌套计时不能相加；
- 显存不降是预期：显存问题由驻留方式解决，后两项只针对 CPU 侧；
- 训练侧开销在 Rollout 主导的异步训练里被等待盖住；训练成为瓶颈或上下文继续变大时才值得重新捡起；
- 被纠正：误判失败与功能无关，也不是原流程包有 bug——派生流程包时只在主进程安装了存盘守护钩子，没带上“每个 Python 进程启动时都会自动加载”的 `sitecustomize.py`，真正执行存盘的 Ray worker 进程里没有钩子；
- 打补丁的进程边界：在 driver 进程 monkeypatch 不会影响 Ray worker 进程。

>
> 来源：Claude Code 会话 `4777f0df`

### 今天的问题

- 推理栈里 PagedAttention 和 KV Cache 显存管理具体是怎么做的？

### 对话或资料摘录

- KV 池大小在启动时 profile 决定：预算 = 总显存 × 利用率 − 权重 − 峰值激活 − 非 torch 显存；
- CPU 侧簿记（block、引用计数、链式哈希、LRU 空闲队列），GPU 侧只认 block id 与 slot 编号；
- 链式块哈希只收录写满的块，哈希里没有权重版本 → 换权重必须清前缀缓存；
- “空闲但仍挂着哈希”的中间态是前缀复用的关键；释放时逆序放回队尾；
- 显存不足时抢占：释放块、进度清零、回 waiting 队列重算。

>
> 来源：Claude Code 会话 `2e0044da`

### 今天的问题

- 推理栈里 Continuous Batching 是怎么做的？

### 对话或资料摘录

- 每一步 forward 重新决定算哪些 token；依赖“每步调度”与“KV 按块随时分配释放”两件事同时成立；
- V1 不再区分 prefill/decode 阶段，只问“还差多少 token 没进 KV”；token 预算 + 最大并发两个上限，chunked prefill；
- 所有请求的 token 拼成一维、不 padding；attention 按请求分段、MLP 逐 token 独立，所以混合 batch 正确；
- batch 永远不“跑完”，换权重时要人为造边界：暂停准入、abort 在途请求、清缓存，客户端续写。

>
> 来源：Claude Code 会话 `933963c1`

### 今天的问题

- CUDA Graph 是什么？

### 对话或资料摘录

- decode 时 kernel 很短、数量很多，CPU 发射跟不上；录制一串 kernel 后一次 replay；
- 录下的是固定地址、固定 shape、固定路径：static buffer + copy_、按 batch size 分档 padding、图内无数据相关控制流与 CPU 同步；
- piecewise 图：attention 留在图外；RL 权重更新必须原地写入，否则图静默读旧地址；
- 出问题先切 eager 对比。

## 15:39｜GSPO 是什么，和 PPO/GRPO 的异同

> 记录时间：2026-10-14 15:39
>
> 内容归属日期：2026-10-14
>
> 整理状态：已整理
>
> 正式笔记：[GSPO 序列级比率与 PPO 论文精读](../notes/2026/10/GSPO序列级比率与PPO论文精读_20261014.md)
>
> 来源：Claude Code 会话 `9be5c822`、`cdba1a2c`、`4b55adff`

### 今天的问题

- GSPO 是啥？“online 模式”是指 RL 理论里的 online 吗？PPO 和 GSPO 之前就不支持吗？
- 要不要趁机把 GRPO 代码的问题一起修了？
- 带我读一下 PPO 和 GSPO 的论文。

### 对话或资料摘录

- GSPO = GRPO 只改 ratio 与 clip 的单位：整条序列的几何平均 ratio，整条一起 clip，clip 范围约 1e-4 量级；
- 动机：重要性采样要靠多样本平均，token 级 ratio 每个位置只有一个样本，只引入噪声；MoE 路由变化让 token ratio 剧烈跳动；
- 被纠正：这里的 online 不是 RL 理论的 online，而是“外部环境平台驱动会话、框架只提供推理接口并收集数据”的 rollout 接入方式；算法框架本身支持 PPO/GSPO，只是这条链路围绕 GRPO 搭建；
- 异步框架里论文的 π_old 拆成 π_behave 与 π_prox，序列级 ratio 只作用在 π_θ/π_prox 一侧；代码按 token 数聚合而非每条序列等权；只改粒度不改 ε 等于没 clip；
- 推理引擎默认返回的 logprob 可能是温度与 top-p/top-k 之前的原始分布；
- 先只读审查、分类（确认 bug / 设计问题 / 配置有误导性），归因实验期间不改训练行为。

>
> 来源：Claude Code 会话 `4b55adff`

### 今天的问题

- top-p、top-k 是什么？为什么 RL 要关心？
- 训练和推理脚本都设了 T/k/p，online 模式下是不是三个都没传到网关、平台全按默认值走？
- 外部平台进程是不是跑在 rank 0（Ray head）的 CPU 上？
- “raw logprob 与温度”这一项指的是什么？

### 对话或资料摘录

- 截断后真实采样概率 `q = p/Z`；重要性修正少一个 `1/Z`；被截掉的词采不到、拿不到负 Advantage（长尾/EOS 抬高只是推测）；
- 被纠正：不是三个都没生效——训练配置经启动脚本转发并覆盖平台配置，温度、top-p 到达，只有 top-k 被网关按函数签名白名单丢弃；助手也更正了自己“训练配置不参与”的说法；同时改 top-p 与 top-k 的对照实际只测了 top-p；
- 推理端默认返回 raw logprob（T=1、不截断）：T=1 时比值自洽但都不是真实分布；T≠1 时无 off-policy 也系统偏离 1（玩具例：高概率词 1.20、低概率词 0.71）；验证看近似 KL 均值，修法做成“返回处理后 logprob”的开关；
- 单次更新时只有 `π_prox/π_behave` 生效，序列级处理前先把分母算对；
- 外部平台进程在 rank 0 上，但由启动脚本 fork，不在 Ray 资源调度内，与 driver/GCS 抢资源。
