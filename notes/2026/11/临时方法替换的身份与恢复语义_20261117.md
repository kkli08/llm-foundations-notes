## 0. 今天最终要解决的问题

用户带来一个测试反馈：恢复前后取得的是同一实例上的同一方法，为什么 `is` 仍会失败？核对时进一步发现，“恢复原方法”是否需要把实例属性也恢复原状？

## 1. 先给结论

- 普通 Python 实例方法经属性访问得到绑定方法对象；同一函数与实例的两次绑定，不要求是同一个包装对象。
- 测试要区分包装对象身份、底层函数身份和绑定实例身份。
- 临时替换结束时，需恢复原先的属性来源：原来有实例属性就恢复其原对象；原来从类取得方法，就移除临时实例覆盖。
- “仍能调用且结果一样”不足以证明查找结构恢复；异常退出也必须检查。

## 2. 前置概念

普通定义在类上的函数是非数据描述符；实例访问时可以产生绑定方法，里面保存 `__func__` 与 `__self__`。同名实例属性优先于这类描述符，因此写入实例会遮蔽类上的方法。[Python 描述符文档](https://docs.python.org/3/howto/descriptor.html#functions-and-methods)

这里的“定义在类上”指普通实例方法，不是专指 `@classmethod`；自定义描述符、属性和特殊 `__getattribute__` 需要另外分析。

## 3. 完整原理

### 3.1 `is` 比较了哪一层

下面是独立教学例子：

```python
class Model:
    def score(self):
        return 1

m = Model()
a, b = m.score, m.score
assert a is not b
assert a.__self__ is b.__self__
assert a.__func__ is b.__func__
```

本批本地 Python 实测中 `a == b` 也成立。若要准确表达“同一函数绑定同一实例”，显式检查 `__func__` 和 `__self__` 最直观；不能把这个结论推广到所有可调用对象的 `==` 语义。

### 3.2 把旧绑定方法赋回去为什么不完全等价

若保存 `old = m.score`，临时替换后执行 `m.score = old`，调用可能仍返回 1，但 `m.__dict__` 多出了 `score`。之后类上的方法发生变化，m 仍可能使用保存的旧方法。这说明调用结果相同和恢复原始查找结构是两个不同断言。

绑定方法还持有 m，赋回实例会形成一条引用环；有环本身不证明永久内存泄漏，Python 的循环垃圾回收可能回收它。这里可直接验证的问题是无意留下的实例覆盖，而非猜测内存一定泄漏。

### 3.3 恢复要记“原来是否存在”

对具有普通实例字典的对象，一种 scoped 替换规则是：

1. 进入时检查属性名是否在实例字典内；若存在，保存字典里的原对象。
2. 写入临时实例属性。
3. 在 finally 中：原来存在则赋回原对象；原来不存在则删除临时覆盖，让查找重新落到类上。

不能只用 `getattr()` 保存结果，因为它可能已经执行描述符绑定，丢失“值来自类还是实例”的信息。对已有实例覆盖，原对象的身份通常才是应该用 `is` 检查的对象。

此规则假定替换作用域控制该属性，没有别的并发写者。若作用域期间其他代码也会改它，必须另定义所有权或同步规则，不能在退出时盲目覆盖他人的写入。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 同一个方法就必须 `is` 相同 | 要先定义比较的是绑定包装还是函数和实例 |
| 赋回 getattr 的结果就完成恢复 | 还需恢复原始属性来源与覆盖关系 |
| 存在引用环就是永久泄漏 | 要考虑可达性和垃圾回收，不能只凭环下结论 |

## 8. 自测问题

### 问题 1

为什么 `m.score = old_bound_method` 可能是一个不完整的恢复？

期望回答：它在实例字典新增覆盖，原本从类动态绑定的方法不再走相同查找路径；原来没有实例属性时应移除临时覆盖。

### 问题 2

什么时候恢复断言应使用 `is`？

期望回答：原先实例字典里就存着一个明确对象、要求恢复原对象时；不是无条件用于两次描述符访问产生的绑定包装。
