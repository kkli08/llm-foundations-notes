## 1. 先给结论

- **模型结构和训练算法是两件事**：结构是“前文 → 下一 Token 分布”的函数；SFT/PPO/GRPO 是训练循环。RL 算法对 Actor 只用两个接口：采样生成，以及对已有文本算逐 Token Logprob。唯一碰结构的是 Critic——换了输出头。
- **Critic = 同主干 + `hidden → 1` 的输出头**，每个位置输出“预计最后能拿多少分”；用 MSE 回归实际 Return，和 Actor 一起训练。
- **Ref 只为 KL 服务**，指本次 RL 起跑的 Checkpoint，不一定是原始预训练模型；不用 KL 就能连 Ref 的前向和显存一起省掉。
- **Clip 只在“同一批数据更新多次”时才起作用**：整批只做一次梯度更新、prox 又是用同一份权重刚算的，则 ratio ≡ 1，Clip 永不触发——clip-higher、序列级 ratio 这类开关在这种设置下基本不生效。
- **重算 Logprob 是为了把“这一步改了多少”和“数据有多陈旧 + 训推有多不一致”拆成两个比值**。
- **PPO + GAE 理论上能做轨迹内的功劳分配**，但长程稀疏 Reward 下 Critic 难训准、Token 级 λ 衰减太快，实际常退回接近 GRPO。
- **PPO 没有组内等待**：一条跑完就能算一条；批屏障和陈旧度是两者共有的。

## 2. 前置概念

### 2.1 PPO 的四个角色

| 角色 | 结构 | 输入 → 输出 | 是否训练 |
|---|---|---|---|
| Actor | 原版 LLM | 前文 → 下一 Token 分布；推理引擎和训练引擎各有一份 | 训练 |
| Critic | 同样的 Transformer 主干，输出头换成 `hidden → 1` | 一条轨迹 → **每个 Token 位置一个标量 V** | 训练 |
| Reference | Actor 的起跑权重，冻结 | 一条轨迹 → 每个 Token 的 Logprob，用来算 KL | 不训练 |
| Reward | 规则、测试或打分模型 | 一条轨迹 → 一个分数 | 不训练 |

GRPO 不需要 Critic；不用 KL 时也可以不配 Reference。

### 2.2 Critic 是什么

- **结构上**：普通 LLM 最后一层是 `hidden → vocab_size`；Critic 换成 `hidden → 1`，每个位置只输出一个数。通常从同一预训练模型初始化，所以和 Actor 一样大。
- **含义上**：V(s_t) 回答“走到这个位置时，预计最后能拿多少分”。在多轮终端任务里，找到关键配置那一轮之后 V 应明显上升，改错文件那一轮之后 V 应下降。
- **用途**：每一步的 TD 误差就是“这一步之后的预期”减“这一步之前的预期”：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

  有了它，PPO 能**在同一条轨迹内部区分好坏**：即使整条轨迹成功，“改错文件”那一步也会被压低。GAE 把这些 δ 往后做加权累加（见 §3.5）。
- **怎么训练**：普通回归。每个位置“实际最后拿到的分”（Return）是标签，用 MSE 让 V 拟合，同样带 Clip 防止单步改太多。Actor 变强后“预期得分”随之变化，Critic 必须一直跟着更新。

### 2.3 PPO 一步的九段流程

| # | 做什么 | GRPO 有没有 |
|---|---|---|
| 1 | Rollout：推理引擎里的 Actor 采样轨迹，记下每个 Token 的采样 Logprob | 有 |
| 2 | Reward：每条轨迹得到一个分数 | 有 |
| 3 | Critic 前向：每个位置算出 V | **无** |
| 4 | Ref 前向：算 Ref Logprob，用于 KL | 用 KL 时有 |
| 5 | Actor 前向：训练引擎用当前权重重算 Logprob（不带梯度） | 有 |
| 6 | 算 Advantage：KL 并入 Reward，用 V 做 GAE | 改为组内归一化 |
| 7 | 更新 Actor：PPO Clip Loss | 有 |
| 8 | 更新 Critic：让 V 拟合 Return | **无** |
| 9 | 同步权重给推理引擎 | 有 |

**GRPO = 去掉第 3、8 步，第 6 步改为组内归一化**。实现上常见做法是不配 Critic、令 V 全为 0，再加组级 Reward 归一化（[GRPO = V ≡ 0 的 GAE 特例](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#22-grpo-就是配置出来的-ppo)）。

## 3. 完整原理

### 3.1 Ref 与 KL 的两种放法

Ref 只有算 KL 这一个用途；作用像一根橡皮筋，防止为刷 Reward 走到语言退化、Reward Hacking 之类的奇怪区域。KL 有两种放法，二选一：

| 放法 | 形式 | 典型来源 |
|---|---|---|
| 进逐 Token Reward | 每个 Token 加小 Reward `−β·(logp_old − logp_ref)`（k1 估计），经 Advantage 间接影响梯度 | PPO 风格 |
| 作为 Loss 项 | Loss 里直接减 `β·KL(π_θ‖π_ref)`（k3 估计） | 原版 GRPO |

前者经 Return-to-go 累加，有长度效应（[10 月 9 日 §3.3](AgentRL的Reward崩溃与归因实验_20261009.md#33-可疑诱因kl-进-reward--γλ1-的隐式长度惩罚假设)）。成本上，每步都要对整批长轨迹做一次 Ref 前向并占显存；KL 系数很小、作用很弱时，干脆关掉 KL、不建 Ref 是常见做法。

### 3.2 Actor 怎么用 Advantage 更新：三层

**第一层：朴素策略梯度**

```text
loss = − A · log π_θ(y_t)      对每个模型 Token 求，再对所有 Token 取平均
```

反向只经过“被采到的那个 Token”的 log 概率，但梯度传遍整个网络。A > 0 推高、A < 0 压低；再经梯度裁剪和优化器走一步。这就是“用 Advantage 更新”的全部机制（logit 层面的形式见 [10 月 12 日 §3](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#3-advantage-在梯度里到底做什么)）。

**第二层：同一批数据更新多次时，引入 ratio 与 Clip**

经典 PPO 把一批数据切成几个 Minibatch 或跑几个 Epoch。从第二次更新起，模型已经不是采样时那个模型了：

```text
ratio = π_θ(y_t) / π_old(y_t)
loss  = − min( ratio·A,  clip(ratio, 1−ε, 1+ε)·A )        常见 ε = 0.2
```

ratio = 1 时梯度与第一层完全相同。Clip 的意思是“同一个 Token 改够了就停手”：

| A 的符号 | ratio 位置 | 结果 |
|---|---|---|
| A > 0（想推高） | ratio > 1+ε（已推高超过 ε） | **梯度为 0，停止推** |
| A > 0 | ratio ≤ 1+ε | 正常推 |
| A < 0（想压低） | ratio < 1−ε（已压低超过 ε） | **梯度为 0，停止压** |
| A < 0 | ratio ≥ 1−ε | 正常压 |

clip-higher 就是把第一行的上界单独放宽（例如 1.2 → 1.28）。

**第三层：异步训练的解耦版本**

数据可能由落后若干版本的权重采样，于是用三个 Logprob：

```text
ratio    = π_θ / π_prox        ← 做 Clip，含义同上
behave_w = π_prox / π_behave   ← 修正“数据是旧模型采的”，过大则 mask 或过滤
loss     = − behave_w · min(ratio·A, clip(ratio)·A)
```

四类 Logprob 的定义见 [7 月 24 日 §5.9](../07/训练与RL后训练基础_20260724.md#59-相同-token-的四类-logprob到底指什么)。

### 3.3 关键推论：单次更新时 Clip 退化

若**整批只做一次梯度更新**（一个 Minibatch、一个 Epoch），而 π_prox 又是更新前用同一份权重刚算出来的，那么在计算梯度的那一刻：

```text
π_θ ≡ π_prox  →  ratio ≡ 1  →  Clip 永远不触发
```

Loss 退化成“朴素策略梯度 × behave_w”。由此：

- **clip-higher、收紧 Clip 下界**这类开关在这种设置下基本不起作用；
- **序列级重要性采样**在 ratio 一侧也不起作用（一串 1 的几何平均还是 1），真正生效的只剩 behave_w 一侧，例如拒绝采样改成按整条序列、调整上限；
- 验证方法：看 Clip 比例类指标，应几乎为 0，只剩数值噪声。

这会改变对“移植配方”类实验的解读：声明的改动里有几项实际没有生效，真正生效的改动集合更小（与 [声明的参数不一定生效](训练崩溃归因的工作流与实验解读_20261012.md#35-解读时要提前想好的四个陷阱) 是同一类陷阱，这次是算法层面）。

### 3.4 为什么要重算 Logprob

推理引擎采样时已经返回了每个 Token 的 Logprob（π_behave），但不能直接当 PPO 的锚点：

1. **版本不同**：异步训练下，采样权重可能比训练端落后若干版本（[Staleness 窗口](权重同步版本语义与Staleness窗口_20261008.md)）；
2. **同版本数值也不同**：推理与训练是两套计算栈，Kernel、并行切分、BF16 累加顺序、CUDA Graph、Prefix Cache、投机解码都不一样，同一 Token 的 Logprob 会有偏差（训推不一致）。直接用它做 ratio，这些噪声会混进 Clip 判断和梯度。

所以用训练引擎、当前权重对整批再做一次**不带梯度的前向**得到 π_prox，把两件事分开：

- `π_θ / π_prox`：干净的“这一步改了多少”，两边都来自训练引擎；
- `π_prox / π_behave`：单独度量“数据有多陈旧 + 训推有多不一致”，用于加权和拒绝采样；对应的监控是行为侧近似 KL、重要性权重与被过滤比例。路由回放、MTP 等训推一致性问题没修好时，会体现在这一项上。

代价是每步多一次全批前向；有的框架提供用插值近似 π_prox 跳过这次前向的选项，用一点精度换吞吐。

### 3.5 PPO + GAE 能否比 GRPO 更好地分配功劳

$$
A_t = \delta_t + (\gamma\lambda)\,\delta_{t+1} + (\gamma\lambda)^2\,\delta_{t+2} + \cdots
$$

- **λ = 1**：A 等于“实际最终得分 − V(s_t)”，完全依赖真实结果，无偏但方差大（后面所有步骤的运气都算进来）；
- **λ 较小**：主要依赖 V 自己的判断，方差小，但 V 不准时有偏差。

GRPO 相当于“λ = 1，且整条轨迹只用一个 V（组均值）”，所以无法区分轨迹内部哪一步好坏。实现上 GAE 还可以跳过环境输出的 Token，只在模型 Token 之间传递功劳，所以按轮次分配功劳在机制上可行。

**但在长程 LLM 任务里有两个现实问题**：

1. **Critic 很难训准**：从语言模型初始化，起初对“这道任务最终能不能过”毫无判断；Reward 是几十轮后才给一次的稀疏 0/1。V 不准时 λ < 1 等于让不准的裁判分配功劳，偏差可能比 GRPO 更大。
2. **Token 级 λ 衰减太快**：一条轨迹几万 Token，λ = 0.95 时功劳往前传约 100 个 Token 就衰减到 e⁻⁵ 以下（0.95¹⁰⁰ ≈ e⁻⁵·¹），最终 Reward 几乎传不回前面的轮次。所以长序列里 λ 只能取得非常接近 1，又退回接近 GRPO，还多付一个 Critic 的成本。

已有工作的方向（按讲解时记忆，具体结论未核实）：先单独预训练 Critic、Actor 与 Critic 用不同 λ、按序列长度自适应 λ。多轮 Agent 还有折中：只在**轮次边界**估 V，或给每一轮单独打过程分（Process Reward），做到轮次级功劳分配。

这是“上限能不能更高”的问题，和“为什么会崩”关系不大；归因阶段继续用 GRPO 即可。

### 3.6 PPO 有没有组内长尾

**组内等待这一层，PPO 没有**：它的 Advantage 只依赖这条轨迹自己的 Reward 和 V，跑完一条就能算一条。GRPO 必须等同题 G 条全部跑完才能算组均值和标准差，一条卡住的会话带来三个代价：

- 其余已跑完的轨迹被拖住，不能进入训练；
- 等待期间它们越来越陈旧，可能被拒绝采样过滤掉；
- 若有组级超时且超时整组作废，G 条全部浪费。

PPO 只会损失卡住的那一条。**两者共有的长尾**：每个训练步仍要凑满一批（批屏障）；跑得越久的轨迹采样版本越旧，受最大离策略版本差约束——这与算法无关。PPO 自己的额外开销是每步多一次 Critic 前向与反向，以及一份同等大小模型的显存。

总结：**GRPO 用“按组等待 + G 倍采样”换掉了 Critic**。单轮短回答里组内等待几乎无代价；多轮、时长差异大的 Agent 任务里代价明显变大（[Cohort 并发与会话容量](../08/OnlineRL的Cohort并发与会话容量_20260818.md#3-global-concurrency-与-physical-session-capacity)）。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| PPO/GRPO 是一种模型结构 | 是训练循环；模型结构不变，只有 Critic 换了输出头 |
| Critic 是一个小的打分网络 | 通常与 Actor 同主干、同大小，只是输出 `hidden → 1` |
| Ref 就是原始预训练模型 | 是本次 RL 起跑的 Checkpoint |
| 配了 clip-higher 就一定在防熵塌缩 | 整批只更新一次时 ratio ≡ 1，Clip 不触发 |
| 推理引擎已经给了 Logprob，重算是浪费 | 重算把“更新幅度”与“陈旧 + 训推不一致”分开度量 |
| PPO + GAE 一定比 GRPO 分配功劳更准 | 长程稀疏 Reward 下 Critic 难训，λ 只能接近 1，常退回接近 GRPO |
| 组内长尾是所有 RL 的通病 | 组内等待是 GRPO 特有；批屏障与陈旧度才是共有的 |

## 7. 一分钟复习

1. 结构是函数，算法是循环；Critic = 同主干 + `hidden → 1`，V(s_t) = 预计最终得分，MSE 拟合 Return。
2. PPO 九段；GRPO 删 Critic 前向与更新，Advantage 改组内归一化。
3. Ref 只为 KL；KL 进 Reward（k1）或进 Loss（k3）。
4. 策略梯度 → ratio + Clip（改够就停）→ 解耦（ratio 对 prox，behave_w 管陈旧与训推差）。
5. 整批只更新一次：ratio ≡ 1，Clip 与序列级 ratio 失效。
6. λ 小方差小但依赖 V；λ = 0.95 约 100 Token 衰减到 e⁻⁵，长序列只能 λ ≈ 1。
7. PPO 无组内等待；批屏障与陈旧度共有。

## 8. 自测问题

### 问题 1

Critic 与 Actor 在结构上有什么区别？它的训练标签是什么？

期望回答：同一 Transformer 主干，Critic 把 `hidden → vocab` 的输出头换成 `hidden → 1`，每个位置一个标量 V；标签是每个位置实际得到的 Return，用 MSE（带 Clip）回归。

### 问题 2

为什么整批只做一次梯度更新时，PPO Clip 不起作用？

期望回答：π_prox 是更新前用同一份权重刚算的，梯度计算时 π_θ = π_prox，ratio ≡ 1，永远落在 Clip 区间内；Loss 退化为朴素策略梯度乘以行为侧权重。

### 问题 3

推理引擎已经返回了采样 Logprob，为什么还要用训练引擎重算一次？

期望回答：一是采样权重可能落后若干版本；二是即使同版本，两套计算栈数值不同。重算得到 π_prox 后，`π_θ/π_prox` 只度量本步改动，`π_prox/π_behave` 单独度量陈旧与训推不一致。

### 问题 4

为什么长序列 LLM 任务里 PPO + GAE 的优势常常发挥不出来？

期望回答：稀疏 0/1 Reward 下 Critic 难训准，λ < 1 会引入偏差；Token 级 λ 衰减太快，λ = 0.95 时约 100 Token 就衰减到 e⁻⁵，只能取 λ ≈ 1，又接近 GRPO，还多付 Critic 成本。

### 问题 5

一条会话卡住，在 PPO 和 GRPO 下分别损失什么？

期望回答：PPO 只损失这一条；GRPO 会拖住同组其他轨迹、让它们变旧被过滤，组级超时后整组作废。
