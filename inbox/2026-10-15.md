### 今天的问题

- 昨天说“验证方法很便宜：对比不同运行的 `log π_prox − log π_behave` 均值”，帮我实际验证一下。

### 对话或资料摘录

- 先写判断标准再看数字：这个均值本来就混着正常 off-policy 漂移和两套引擎的数值误差，T=1 也不会正好是 0；支持“温度口径问题”的证据是：差距稳定存在、陈旧度接近 0 时仍在、方向为正；
- 最干净的对照是同一模型只改温度：T=1 稳定在极小的负值，T<1 明显为正，且与陈旧度几乎不相关 → 偏差来自温度，不来自模型或陈旧度；
- 偏差随熵下降而收缩：分布越尖，温度对被采样 token 概率的影响越小；
- 序列级几何平均把逐 token 的正负偏差平均掉，序列权重贴近 1，拒绝采样上限从未触发 → 真实但很小的系统偏差，解释不了崩溃；
- 截断那部分概率质量这个指标看不到：分子分母都是“不截断”的值；
- 顺带：整批只更新一次时，近似 KL 与 clip 比例每一步都是精确 0，实测坐实了 ratio ≡ 1；一个物理上不可能为负的指标出现负值，直接指向定义差了一个版本；
- 在崩溃的运行里，训推不一致比熵上升晚出现 → 它是崩溃的结果，不是诱因。

>
> 来源：Claude Code 会话 `e5a8f9d2`

### 今天的问题

- （11:24）审查清单里“批级 Advantage 归一化”这一项具体是什么问题？
- 我的理解：对 GRPO 而言，minibatch 里按 token 做的 adv norm 真正影响的是零方差组？
- 到底归一化的是什么？是每个 token 的 reward 吗？
- 为什么会出现零方差组？就是这组要么全对、要么全错？

### 对话或资料摘录

- 被纠正（范围）：减 m、除 s 作用在每一个 token 上，有信号的组同样被平移和缩放；零方差组只是“性质变化”最显眼（0 → 非 0）；m<0 时答错的长回答受罚变轻；
- 被纠正（位置）：不是在 minibatch 里做，而是对整个训练 batch 只算一次，再切 minibatch；
- 归一化两次、对象不同：组内归一化的是每条回答的 reward（按条数）；批级归一化的是每个 token 的 advantage（按 token）；同一条回答里 advantage 几乎都一样，等于那条回答的分数被复制 |y| 份；
- 手算：+0.7（3 token）与 −0.7（5 token），按条数均值 0，按 token 均值 −0.175；
- 零方差组 = 同题 G 条拿到完全相同的 reward；细分为“全零”（全错、超时或出错）与“同分非零”（多半全对）；原因是题目相对当前模型太难或太简单；
- 健康期零方差组就不少（以全对为主）；崩溃过程中构成翻转为几乎全是全错，有信号的组消失，1/s 放大最剧烈；
- 1/s 像自动增益（AGC）：信号变弱时自动调大音量，噪声一起放大 → 等价于有效学习率随信号变少而变大。

> 内容归属日期：2026-10-15

> 整理状态：已整理
>
> 正式笔记：[温度口径偏差的实测判读与 KL 放置位置](../notes/2026/10/温度偏差实测与KL放置位置_20261015.md#38-grpo-还要什么-gaegae-在这里退化成了广播)
>
> 来源：Claude Code 会话 `e5a8f9d2`

### 今天的问题

- 同事说这个 GRPO 写法里 KL 的位置不对：KL 写进 reward 里一起走了 GAE，GRPO 还要什么 GAE，那不是 PPO 才用的吗？

### 对话或资料摘录

- 同事说对了一半：GAE 在 V≡0、γ=λ=1 下退化成 reward-to-go，对任务 reward 只是“广播到每个 token”，与 GRPO 论文的 Â 一样；它唯一多做的事是把 KL reward 也累加进去；
- KL 进 reward（PPO-RLHF / InstructGPT 写法）：k1 估计、detach、只通过策略梯度起作用；token t 受到从 t 到结尾所有 KL 之和的约束 → 约束整条序列的 KL 总量，长回答罚得多；参与批级归一化，会被 1/s 放大；多轮拼接成一行时第一轮 token 累积后面所有轮的 KL；
- KL 进 loss（GRPO 论文）：k3 估计、对 π_θ 求导、只管自己这个 token；
- 两个实现缺口：两种开关同时打开会把 KL 加两次且不报错；loss 形式里 ref 的温度不随 actor 同步，T≠1 时模型没变 KL 也不为 0；
- 诊断：样本若真来自记录的分布，k1 的均值（即 KL）不可能为负；崩溃后变负 = 训推失配的又一证据；
- 健康期累积 KL 只占 advantage 的百分之几，且不加 KL 的运行同样崩了 → KL 位置不是根因；
- 建议：GRPO/GSPO 显式二选一——不要 KL（关 KL、不建 ref），或只用 loss 形式；带 critic 的 PPO 保留 KL 进 reward 是标准做法。

> 正式笔记：[KL 估计器与放置位置的设计动机](../notes/2026/10/KL估计器与放置位置的设计动机_20261015.md)
>
> 来源：Claude Code 会话 `e5a8f9d2`（次日补漏写入）

### 今天的问题

- k1 和 k3 是什么意思？
- 论文把 KL 加在 loss 里，现有写法在算 advantage 时就加进去了，两者异同和各自的目的是什么？
- 这种写法是不是为了异步流式训练设计的？
- 不开批级 adv norm，是不是就没法放 KL、训练里就没有 KL 了？
- 审查清单第 3 项（批级归一化）是配置问题还是实现问题？

### 对话或资料摘录

- 记 r = π_ref/π：k1 = −log r（无偏、可为负、方差大），k2 = ½(log r)²（有偏、非负），k3 = (r − 1) − log r（无偏、非负、方差小）；k3 无偏是因为 E_π[r] = 1；
- 手算：π=0.5、π_ref=0.4 → k1=+0.223、k3=+0.023；π=0.1、π_ref=0.2 → k1=−0.693、k3=+0.307；
- 4 token 例子：KL 进 reward 时没偏离的 token 也替后面的偏离买单；KL 进 loss 时只有偏离的位置被拉回；
- k1 直接进 loss 求导，期望梯度为 0（E_π[∇log π]=0）；k3 进 loss 的梯度 (1−r)∇log π，期望是反向 KL(π_ref‖π_θ) 的梯度；
- KL 进 reward 源自带 KL 约束的目标 E[R] − β·KL，前提是有 critic；GRPO 把 KL 放进 loss 是为了让 Â 保持“每条一个数”；
- 不是为异步设计（同步 PPO-RLHF 继承下来）；资源上两种放法代价相同（同一次 ref 前向）；异步下 k1 进 reward 恰好更自洽，k3 进 loss 未乘重要性权重，属于巧合的好处；
- KL 与批级归一化是独立开关；开批级归一化时等效 β = β/s，信号少时被放大；
- 被纠正：批级归一化“本身没问题”不完全对——按 token 加权减均值对序列级 advantage 是实现缺陷，除以 s 是设计取舍；PPO 下按 token 统计是对的；全 batch 与按 minibatch 归一化语义不同；某 rank 全空提前返回、跳过集合通信会卡死。

>
> 来源：Claude Code 会话 `e5a8f9d2`（次日补漏写入）

### 今天的问题

- minibatch 为 1 时重要性 ratio 就不起作用，它不会被加到相对优势里，对吧？
- “+ recompute”是什么意思？是开了重算才恒等吗？
- 这个重算和反向时开的重算是一回事吗？
- 所以 minibatch=1 时本质上没有 clip，一步跨得再大也没法裁剪？
- minibatch=1 唯一的隐患就是不能 clip，和算优势无关，优先级可以降低？
- 不是说都开了重算吗，为什么第 2 项还用推理引擎的 logprob？

### 对话或资料摘录

- r ≡ 1 时 loss 退化为 REINFORCE × 行为侧权重；GSPO 序列比值在 r=1 时梯度与 token 级相同（每 token 导数 1/|y|，求和抵消）；
- 被纠正：失效的只是 π_θ/π_prox；π_prox/π_behave 照常起作用；r ≡ 1 仍是梯度来源（∇r = r∇log π），换成常数 1 梯度为 0；比值在 loss 里乘 A，不加进 A；
- “+recompute”是成立条件：分母来自同权重重算才 ≡ 1；四种组合（解耦+重算 / 解耦+插值 / 非解耦+重算 / 非解耦+不重算）中只有分母重算的两种 ≡ 1；分母 ≠ 重算时 clip 拦的是训推差 + 陈旧度，不是原意；
- logprob 重算（算法，产出 π_prox）≠ 激活重算（系统，用计算换显存，不改结果）；一步约三遍前向；
- 被纠正：clip 本来就限制不了“单独一步”，标准 PPO 的第一个 minibatch 也是 r=1；它限制的是同一批数据多次更新累积的偏移；单步大小由学习率、梯度裁剪、Adam 决定；跨步只有旧样本会被行为侧权重/拒绝采样纠正；多 minibatch 同时意味着更激进地用数据；
- minibatch 数只影响更新方式，不影响 advantage（切分前已算好）→ 低优先级 + 启动期提示；
- 重算产出 π_prox，不替换 π_behave；三个分布各有来源；行为侧近似 KL 非 0 即证明 π_behave 仍在用；只有非解耦 + 重算才会覆盖；
- 读数陷阱：被过滤 token 的权重置 0 但分母按过滤前计数，平均重要性权重会 < 1，看起来像 ratio 在变。
