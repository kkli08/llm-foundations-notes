## 0. 今天最终要解决的问题

1. OPD 和 MOPD 分别是什么？和熟悉的 PPO、GRPO、GSPO 比，差在哪里？
2. 要把它们接进训练与测试体系，需要额外关心什么？

## 1. 先给结论

- **OPD（On-Policy Distillation，在线策略蒸馏）**：学生自己采样回答（和 GRPO 一样是 on-policy）；一个更强、**不训练**的教师对学生写出的回答做一次前向，得到每个 token 的 log π_T；每个 token 的奖励是 **R_t = log π_T(o_t) − log π_θ(o_t)**。优化它等价于最小化**反向 KL**：KL(π_θ ‖ π_T)。
- **和 ref KL 形式相同、方向不同**：KL 进 reward 时每个 token 加的是 β(log π_ref − log π_θ)；OPD 把 π_ref 换成 π_T。ref KL 把学生**拉回原来的自己**（锚定），OPD 把学生**拉向更强的教师**。
- **信号更密**：verifier 一条回答给一个 0/1，再广播到所有 token；PPO 的 critic 虽然给出逐 token 的价值，来源仍是同一个最终奖励；OPD 每个 token 各有一个独立分数。
- **不需要 verifier**：规则判分难写的任务也能用。
- **和 SFT 蒸馏的区别**：SFT 在教师写的文本上训练，训练时看到的前缀与推理时自己生成的前缀不一致（exposure bias）；OPD 在学生自己写的文本上训练，没有这个错位。
- **MOPD（Multi-teacher OPD，多教师在线蒸馏）**：先用 RL 分别训出几个领域专家（数学、代码、视觉……），再按每条样本的领域字段路由给对应教师打分，之后同 OPD；可以再叠加任务本身的 RL advantage，同时学教师和最终奖励。
- **工程上要关心**：教师与学生共用 tokenizer、逐位置对齐（错一位全错）、路由与配额、教师分数全部有限；教师前向成本随回答长度线性增长、教师通常比学生大，共卡 / 卸载 / 分卡是资源编排问题（[附加模型的显存编排](附加模型的显存编排与判分服务设计_20261026.md#21-一次-rl-训练里有哪些附加模型)）。

## 2. 前置概念

### 2.1 正向 KL 与反向 KL

```text
正向 KL(π_T ‖ π_θ) = E_{o~π_T}[log π_T(o) − log π_θ(o)]    在教师的样本上算（SFT / logit 蒸馏）
反向 KL(π_θ ‖ π_T) = E_{o~π_θ}[log π_θ(o) − log π_T(o)]    在学生自己的样本上算（OPD）
```

- 正向 KL 惩罚“教师会写、学生不会写”的地方 → 学生倾向**覆盖**教师的所有模式（mean-covering），能力不够时会把概率摊薄到教师的各种写法上；
- 反向 KL 惩罚“学生写了、教师认为不合理”的地方 → 学生倾向**集中**到教师的主要模式（mode-seeking），宁可少写几种，不写教师不认可的。生成任务里后者通常更合适（MiniLLM 的论点）。

### 2.2 为什么 R_t 的期望就是负的反向 KL

在第 t 步，学生按 π_θ 采样 o_t：

```text
E_{o_t~π_θ}[R_t] = Σ_o π_θ(o)·(log π_T(o) − log π_θ(o)) = −KL(π_θ ‖ π_T)  （该位置）
```

整条回答的奖励和在 on-policy 采样下的期望，按链式法则就是序列级的 −KL(π_θ ‖ π_T)。所以“最大化每个 token 奖励之和”= “最小化反向 KL”。每个位置只用采到的那个 token 估计，是 [k1 式](KL估计器与放置位置的设计动机_20261015.md) 的单样本估计：无偏、单个 token 可正可负。

## 3. 完整原理

### 3.1 OPD 一步做什么

```text
学生 π_θ 采样回答（on-policy，与 GRPO 相同）
→ 教师 π_T 对 [prompt + 学生回答] 做一次前向，取每个位置上学生所写 token 的 log π_T
→ 学生（训练侧重算）得到每个位置的 log π_θ
→ R_t = log π_T(o_t) − log π_θ(o_t)
→ 当作逐 token 的奖励 / 优势，走同一套策略梯度 loss
```

和 PPO / GRPO / GSPO 比：

| | 信号来源 | 信号粒度 | 需要什么 |
|---|---|---|---|
| GRPO / GSPO | verifier 的最终奖励，组内归一化 | 一条回答一个数，广播到所有 token | verifier |
| PPO | verifier 的最终奖励 + critic 的价值 | 逐 token 的优势，但都源自同一个最终奖励 | verifier + critic |
| OPD | 教师对每个 token 的 logprob | 每个 token 一个独立分数 | 教师（不训练） |

实现上常见的组合是 `RL 权重 × RL loss + 蒸馏权重 × 反向 KL`：RL 权重为 0 时就是纯蒸馏；两者都非 0 时同时学最终奖励和教师。教师建成一个**不带优化器**的引擎，可以卸载。

> 10 月 27 日补充：这是设计意图。若混合分支把 `log π_θ − log π_T`（教师 detach）直接当 loss，求导后教师项消失、期望梯度为 0，教师不起作用；要用 `½(log π_θ − log π_T)²` 或把 R_t 当优势，见 [OPD 损失的梯度陷阱与两种蒸馏分支](OPD损失的梯度陷阱与两种蒸馏分支_20261027.md#31-joint-分支detach-的教师项求导后消失)。

### 3.2 与 ref KL 的关系

| | 每个 token 加到奖励里的项 | 作用 |
|---|---|---|
| KL 进 reward（[两种放法](KL估计器与放置位置的设计动机_20261015.md)） | β·(log π_ref − log π_θ) | 学生偏离起点就扣分 → 锚定，防漂移 |
| OPD | log π_T − log π_θ | 学生偏离教师就扣分 → 拉向更强的模型 |

两者形式完全一样，只是“锚”换了：ref 是学生自己的起点，teacher 是另一个更强的模型。所以对 KL 估计器、放在 reward 还是 loss 的理解可以直接迁移过来。

### 3.3 为什么叫 on-policy：与 SFT 蒸馏的区别

| | SFT 蒸馏 | OPD |
|---|---|---|
| 训练用的文本 | 教师写的 | 学生自己写的 |
| 优化的散度 | 正向 KL（在教师样本上） | 反向 KL（在学生样本上） |
| 训练 / 推理的前缀 | 不一致：训练只见过教师的“好前缀”，推理时自己写错一步就进入没见过的状态（exposure bias） | 一致：恰好在学生自己会犯的错误上得到纠正 |
| 每步成本 | 低（离线数据） | 高（学生采样 + 教师前向） |

### 3.4 MOPD：按领域路由的多教师

要解决的问题：先用 RL 分别训出几个领域专家，再把它们的能力合到一个学生里。

1. 每条样本带一个领域字段，按这个字段**路由**给对应领域的教师打分；
2. 打分之后与 OPD 相同；
3. 可以再叠加任务本身的 RL advantage（一个系数控制：0 为纯蒸馏，> 0 时混入任务奖励），并对优势做截断防止个别 token 的极端分数主导更新。

### 3.5 接入训练与测试体系时的检查点

| 检查点 | 为什么 |
|---|---|
| 教师与学生共用 tokenizer | 逐 token 的 logprob 要比较的是同一个 token；词表不同就没法直接相减 |
| 位置对齐 | 第 t 个位置的输出分布给第 t + 1 个 token 打分；教师与学生都要按同样的方式移一位，错一位整条信号就错了 |
| 路由与配额 | MOPD 要确认每条样本进了对的教师，各教师的负载与配额符合预期 |
| 教师分数全部有限 | 学生写出教师认为概率极低的 token 时 log π_T 可能极负甚至溢出 |
| 教师前向成本 | 随回答长度线性增长，长回答下不小；教师通常比学生大，MOPD 还有 N 个 |
| 资源编排 | 教师共卡、卸载还是独占卡，与 PPO 的 critic 是同一类问题（[共卡卸载与每步搬运](附加模型的显存编排与判分服务设计_20261026.md#33-每步搬运的成本与优化阶梯)） |

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 蒸馏奖励整体异常、学生不收敛 | 位置错一位：拿第 t 个位置的分布给第 t 个 token 打分 | 用学生自己当教师，R_t 应全为 0 |
| 个别 token 奖励极负 | 学生写出教师认为几乎不可能的 token | 统计 R_t 的最小值与非有限值个数 |
| MOPD 某领域进步明显慢 | 路由错误或该教师配额不足 | 按领域统计样本数与教师调用数 |
| 长回答任务步时大幅增加 | 教师前向成本随长度线性增长 | 拆分每步耗时中的教师前向部分 |

“用学生自己当教师”是一个好用的数值检查：两边模型相同、位置对齐时，每个 token 的 R_t 都应为 0（与 [单次更新下 ratio ≡ 1](单次更新下两个比值的分工与Clip的真实作用_20261015.md) 同一类“代入理想情况应得恒等值”的检查）。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| OPD 就是在教师生成的数据上做 SFT | 那是离线蒸馏（正向 KL）；OPD 在学生自己的样本上用教师逐 token 打分（反向 KL） |
| OPD 的 KL 和 GRPO 的 ref KL 是两回事 | 形式完全相同，只是锚从 ref 换成了教师，方向从“拉回自己”变成“拉向教师” |
| PPO 的 critic 已经给了逐 token 信号，和 OPD 一样密 | critic 的逐 token 价值都源自同一个最终奖励；OPD 每个 token 的分数是独立的 |
| 多教师就是把几个教师的 logprob 平均 | MOPD 按样本领域路由到一个对应教师 |
| 教师不训练，所以不占资源 | 每个 token 都要做教师前向，教师又通常更大，显存与时间都要编排 |

## 7. 一分钟复习

1. OPD：学生采样 → 教师前向 → R_t = log π_T − log π_θ → 最大化 = 最小化反向 KL(π_θ ‖ π_T)。
2. 与 ref KL 同形：β(log π_ref − log π_θ)；ref 锚定自己，teacher 拉向更强。
3. 信号密度：GRPO 一条一个数；PPO critic 逐 token 但源自同一个奖励；OPD 每个 token 独立；不需要 verifier。
4. 与 SFT 蒸馏：教师文本 + 正向 KL + exposure bias vs 学生文本 + 反向 KL；反向 KL 集中于教师主模式。
5. MOPD：领域专家 → 按领域字段路由教师 → 同 OPD，可混入任务优势。
6. 检查：共用 tokenizer、移一位对齐（学生当教师 → R_t ≡ 0）、路由配额、分数有限、教师成本与资源编排。

## 8. 自测问题

### 问题 1

写出 OPD 每个 token 的奖励，并说明为什么最大化它等价于最小化反向 KL。

期望回答：R_t = log π_T(o_t) − log π_θ(o_t)。o_t 按学生 π_θ 采样，E[R_t] = Σ π_θ(o)(log π_T(o) − log π_θ(o)) = −KL(π_θ ‖ π_T)；整条回答求和后按链式法则是序列级的负反向 KL，所以最大化期望奖励和就是最小化 KL(π_θ ‖ π_T)。

### 问题 2

OPD 的逐 token 奖励和 GRPO 里“KL 进 reward”的项有什么关系？作用有什么不同？

期望回答：KL 进 reward 时每个 token 加 β(log π_ref − log π_θ)，OPD 加 log π_T − log π_θ，形式相同，只是锚从 π_ref 换成 π_T。ref KL 让学生不要偏离起点（防漂移），OPD 让学生靠近更强的教师（学能力）。

### 问题 3

为什么说 OPD 比 SFT 蒸馏更不受 exposure bias 影响？代价是什么？

期望回答：SFT 蒸馏只在教师写的文本上训练，学生推理时一旦写出教师不会写的前缀，就进入训练中没见过的状态；OPD 在学生自己写的文本上训练，教师恰好对学生会犯的错误逐 token 打分纠正。代价是每步都要学生采样和教师前向，成本远高于离线数据，且教师前向随长度线性增长。

### 问题 4

接入 OPD 时，怎样用一个简单检查排除“位置对齐错一位”？

期望回答：让教师与学生是同一个模型（同一份权重）。位置对齐正确时，每个 token 的 log π_T 与 log π_θ 相同，R_t 应全为 0；出现非 0 就说明有一边的移位方式不同，或 tokenizer / 上下文不一致。

## 9. 尚未解决与后续路线

- 逐 token 单样本估计与完整（或 top-k）分布上算逐位置 KL 的方差与成本对比；
- OPD 与 RL loss 混合时两个权重怎么定，纯蒸馏与混合的效果差异；
- MOPD 多个教师的共卡 / 卸载 / 分卡策略与每步耗时；
- 教师与学生 tokenizer 不同时的对齐方法。
