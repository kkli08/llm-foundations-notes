## 1. 先给结论

- **现象大多是真的，但 7 条里没有一条完全对**：有几条药方会削弱"不编造"这条底线。
- **核实一条审计意见要回答五件事**：在当前代码上是不是这样；当初为什么加这个限制；这个理由现在还成不成立；用已有数据估收益；风险（更容易编造、泄露、变慢变吵）。
- **"不够聪明"先看轨迹**：金标样例的步数主要花在超长引用被退回重发、输出被截断、撞上时限。根因 3 次都找对了，缺的是因果链。只放开预算治不好。
- **流式必须和截断处理一起改**：只改流式、再放大输出上限，工具调用会在中途被截断，直接报错，整轮调查失败。
- **截断在温度 0 下是确定性的**：原样重试只会在同一处再截断一次。丢掉这一步、提示少写，连续两次就收尾。
- **每一步的时限 = min(剩余预算, 单步上限)**，重试时重新算；收尾那一步要预留时间。
- **思考 token 和预算互相挤占**：它计入每步的输出上限和累计上限，按估算每步多十几到六十几秒，和现有预算不相容，要先测。
- **问答读调查结论时，只给卡片上真发过的内容**：同一个判断函数、同一个文本函数、同一个脱敏出口；没发出结论的报告要明说"不能当结论"。
- **离线测不出的要写明**：模型会不会主动调用新工具、调用后的回答会不会被门禁误杀，要真实模型问几题才知道。
- **（晚间补录）报错信息就是模型下一步的提示词**：只说"最多 300 字符"，模型就原样重发；要写出实际长度和怎么改，并把上限提前写进工具说明。
- **（晚间补录）真机实测时凭证留在用户的终端**：agent 不读凭证文件；用会回显假值的金丝雀查所有输出通道；题目要逼出被测路径；20 次请求的上限没有重试余量。

## 2. 前置概念

### 2.1 审计意见分三层

（整理时的理解）

| 层 | 问题 | 怎么核 |
|---|---|---|
| 现象 | 代码里是不是这样 | 在当前主干上读那几行 |
| 诊断 | 这是不是"不聪明"的原因 | 看轨迹：步数和时间实际花在哪 |
| 药方 | 改了会不会更好、会不会更糟 | 查当初为什么这样设计，估收益和风险 |

外部审计常把三层写得一样确定。核实时要分层打分：现象对，不代表诊断对；诊断对，也不代表药方能用。

### 2.2 截断在流式下长什么样

（整理时的理解）

| | 非流式 | 流式 |
|---|---|---|
| 返回 | 一次返回完整结果 | 分片到达 |
| 截断的样子 | 看结束原因和用量 | 工具参数只到一半，JSON 解析失败 |
| 常见的错处理 | 把截断当成功 | 把半截调用当普通错误重试 |

温度 0 时，同一个请求会在同一个位置再截断一次，所以"重试"等于把截断重复几遍。

## 3. 完整原理

### 3.1 审计说了什么，总控先怎么判断

审计的几条主要论断：思考模式被写死关掉；告警分析没开流式，所以单次输出被网关时限锁死；深挖的预算档位被一个硬封顶变成了死代码；上下文折叠时丢了历史推理；问答和后台调查"脑裂"，问答读不到调查已经查出的结论。

总控派评估之前先给了初步判断，并写明以评估结果为准：

- **最值得先做**：告警分析改流式。这一条已经确认属实，也本来就在单卡计划里；
- **最接近用户说的"交互不聪明"**：问答读不到调查报告、能用的日志工具也弱；回答发出前的检查太严，正常回答也会被拦成"证据不足"；
- **最要谨慎**：让模型看配置目录。之前把它藏起来，就是因为里面有明文 Key，脱敏也一直有漏洞（[11 月 5 日 §3.8](调查Agent的质量归因与Harness设计_20261105.md#38-模型要看配置配置里有密钥)）。

### 3.2 逐条核实的结果

评估 agent 对每一条都在当前代码上核对（审计读的那份代码，行号可能对不上），并查清当初为什么加这个限制。总控又抽查了评估引用的关键代码行，都一致。

| 审计的说法 | 核实 | 处理 |
|---|---|---|
| 告警端没开流式，思考被关 | 流式这条成立；思考要先测 | **先做**流式和截断修复；思考等小探针测完再定 |
| 硬封顶把预算锁死，档位和升档失效 | 现象成立；封顶是设计上的保险，升档目前是空操作 | **后做**：等断点续跑做完，按档位逐步放开，不是直接去掉封顶 |
| 问答和调查"脑裂" | 成立 | **先做**：问答能读调查报告；问答看全量日志的能力后做 |
| 一个必选的复核步骤吃掉了步数 | 部分成立 | **不做**豁免：豁免恰好会放过金标样例里那个真实失败的关键簇，老问题会回来 |
| 成文时用早期笔记覆盖了终稿 | 是有意的：优先用调查中记下、带日志原文的根因笔记 | **不做**：改用终稿的自由文本，就绕开了"引用必须有原文"这层约束 |
| 预处理结果和配置对模型不可见 | 预处理已在计划里 | 按计划在脱敏修复后开；配置只考虑白名单摘要，有条件再做 |
| 问答的门禁过敏 | 部分成立 | **后做**：引用不够时重试一次，不去掉引用门禁 |

（整理时的理解）外部审计读到的是代码，读不到每个限制背后的那次事故。核实的价值主要在"当初为什么"这一列，这正是 [11 月 2 日"否掉的方案 + 理由"表](Agent系统的权限分层与事务性副作用队列_20261102.md#313-否掉的方案表) 和 [10 月 10 日"先追溯意图再删"](../10/HF导出索引一致性与旧MTP头_20261010.md#31-一个多余开关的来历先追溯再删除) 的用处。**限制看起来一刀切，往往是因为写的人知道它防的是什么，而读的人不知道。**

### 3.3 "不够聪明"先看轨迹

金标样例 3 次运行的轨迹：

| 观察 | 说明 |
|---|---|
| 3 次都停在时间预算上 | 不是步数不够，是时间被别的东西吃掉了 |
| 超过长度上限的引用被退回 | 模型只能重发 |
| 有的步输出被截断 | 这一步作废 |
| 撞上单步时限 | 这一步作废 |
| 根因 3 次都找对了 | 缺的是因果链 |

所以**只放开预算治不好"不够聪明"**：钱花在重发和作废的步上，加了预算也会这样花掉。这些是同一组样例上的数据，要单独标明。（[11 月 5 日：加预算前先量余量，再问缺什么](调查Agent的质量归因与Harness设计_20261105.md#34-多给预算之前先量余量再问缺什么)）

### 3.4 流式和截断必须一起改

评估指出一个坑：如果只把告警端改成流式，再把工具步的输出上限从 1024 提到 2048，输出在工具调用中途被截断时，代码会直接报"半截工具调用"的错，整轮调查失败。旧的截断分支只认非流式的形状，流式下的半截调用根本走不到那里。温度 0 下截断是确定性的，按普通错误退避重试，一次截断会变成三次生成，外加约 40 秒等待。

改动：

| 改动 | 说明 |
|---|---|
| 告警两条路径改流式 | 绕开网关的等待型超时 |
| 半截工具调用 | 丢掉这一步，提示模型少写；连续 2 次就收尾；不再用同样的请求等一会儿再试 |
| 旧路径同样处理 | 共用的循环里加一个默认关闭的开关，只在告警路径打开。问答也用这个循环，问答的请求一个字节都不能变，所以问答遇到截断仍报错，这是故意的，在 PR 里写明 |
| 工具步输出上限 1024 → 2048 | 网关切断后的降级值 512 不动 |
| 单步时限 | 每次尝试前算 min(max(剩余预算, 1 秒), 90 秒)，重试时重新算，保证重试不超出总预算 |
| 服务在线时收到 502 | 当作排队，立刻重发一次，不降低输出上限；第二次再失败才判模型不可用 |

总控特别核对了收尾那一步会不会因为剩下的时间太少而失败：调查在第 180 秒停止调工具，总预算 300 秒，收尾还剩约 120 秒，按 90 秒封顶，够用。

测试用真实的流式分片，在工具参数中途截断，并确认关掉新分支后测试会失败。

为什么判断可以直接合入：

- 线上现在只跑旧路径，它的输出上限一直是 1024，一步约 22 秒，本来就在 30 秒以内，所以合入后对线上主要是多了截断处理，延迟基本不变；
- 问答已经在同一个网关上用了一阵流式，这条路是通的；
- 真正受益、也真正需要实测的是新调查路径，所以小探针和金标重跑放在打开它之前，本来就在启用清单里。

还剩的：超过 90 秒仍走通用重试；剩余时间的估算没算进解码时间。

（整理时的理解）这三条都接着 11 月 6 日：[流式要分开验证](推理网关的时限与流式调用_20261106.md#34-流式绕过了但要分开验证)、[确定性失败不要原样重试](推理网关的时限与流式调用_20261106.md#33-确定性失败不要原样重试)、[响应字段不能全信](推理网关的时限与流式调用_20261106.md#35-响应字段不能全信)。新的一点是：**换一种传输方式，失败的形状也会换，原来的错误分支可能根本走不到。**

### 3.5 思考开关和预算互相挤占

| 要点 | 内容 |
|---|---|
| 思考 token 算在哪 | 计入每步的输出上限和整张票的累计生成上限 |
| 估算的代价 | 每步多十几到六十几秒 |
| 和现有预算的关系 | "20 步 / 300 秒"放不下，每步都开思考不可行 |
| 服务端 | 推理解析器能不能正确拆出思考内容，要用探针确认 |
| 证据等级 | 只有估算表，没有源码和实测 |

计划：在可缩到 0 的服务上跑约 20 次请求的小探针，不超过 1 卡时；它会先触发约 10 分钟的冷启动，结束后还要约 30 分钟才缩回去（见同日 [缩到零的实测](推理服务缩到零的实测与按需唤醒_20261109.md)）。

（整理时的理解）"开思考会更聪明"是一个要测的假设，它花的是同一份时间和 token 预算。和 §3.3 一样：先看预算现在花在哪，再决定往哪里加。

### 3.6 问答读调查结论：只给卡片上真发过的

| 做法 | 为什么 |
|---|---|
| 判断报告发不发，用和发卡片同一个函数；文字也用同一个函数生成 | 问答说的和卡片上的一致 |
| 只留已验证的引用；复核失败的报告不给根因；保留"模型生成、未执行"的标签；不返回原始对话 | 不放大没过复核的内容 |
| 没发出结论的报告，返回"没有结论，不能当结论"；没有报告时不记为来源 | 防止模型把"空"当依据 |
| 票号的算法抽成一个共用函数 | 生产方和消费方不会算出两种号 |
| 输出走和其他问答工具同一个脱敏出口 | 不比主干弱 |
| 提示词只加一句：问某条告警的原因、怎么处理时，先调用这个工具 | 改动面最小 |

金标回答里存的是哈希，没法逐字比对。总控改为读代码确认：会影响请求内容的只有新工具的定义和这一句提示。另一种做法是在临时副本里撤掉预期的改动重新生成，结果和主干逐字节一致，就证明差异只来自这几处。

离线测不出、要真实模型问 6～8 题才知道的风险：

- 只用了这个工具的回答不走日志引用校验，卡片照常标"未读日志"，对用户可能有点误导，因为报告本身是校验过的；
- 私聊的门禁可能把说原因的回答拦掉；
- 提示词里"不给操作建议"和"问怎么处理先调工具"互相冲突；
- 报告里的引用是调查文件名，不是证据路径，模型照抄会验证失败、被丢掉。

（整理时的理解）一个模块的输出喂给另一个模块时，**接口应当是"对方已经对用户说过的话"**，不是内部状态。这样复核只做一次，两边不会说出两套结论。引用校验的局限见 [11 月 6 日：问 A 答 B](问答前台的路由与对象绑定_20261106.md#35-问-a-答-b猜到的身份不算证据)：它查"这行存在"，查不出"这行属于被问的对象"。

### 3.7 给模型的报错要说怎么改（晚间补录）

§3.3 的轨迹里，超长引用被退回之后，模型会原样重发：引用的日志行超过 300 字符就被拒，可报错只说"最多 300 字符"。金标里有一次连发 9 次，白花约 60 秒，因果链只剩 2 环。晚上总控汇报慢轨现状时，把它列为第一个短板，上线清单里本来就写着"打开后第一个修"，是风险最低的一项。用户（19:59）：**现在修。**

改动只有一句报错和半句说明：

| 改动 | 内容 |
|---|---|
| 报错 | 写出这次是多少字符；告诉模型从那一行里只截一段能支撑结论的连续文字，比如异常类名加消息开头，不要把整行再发一遍 |
| 工具说明 | 原来只写"要从读过的行里原样摘取"，没写上限；补上"最多 300 字符，只截行内关键的一段" |
| 数字从哪来 | 说明里的上限取自校验用的同一个常量，两边不会漂移 |
| 不碰问答 | 先查谁导入了这份工具定义：只有调查流程用，问答不用；金标测试通过，问答的请求一个字节没变 |

其他校验和数值都不动，没加测试。没有用真实模型验证，重发次数是不是真的下降还不知道，PR 里写明了。

（整理时的理解）对模型来说，**报错信息就是下一步的提示词**。只说"违反了什么"，它最可能的修正就是原样再试一遍，温度低时尤其如此（§2.2，[11 月 6 日：确定性失败不要原样重试](推理网关的时限与流式调用_20261106.md#33-确定性失败不要原样重试)）。好的报错要回答三件事：实际是多少、限制是多少、怎样改才能通过。能提前写进工具说明的限制，就别等模型撞上了再告诉它。

### 3.8 问答读报告的真机实测：凭证留在用户的终端（晚间补录）

用户同意给 §3.6 做真实模型实测（问 6～8 题）。实现 agent 卡在凭证上：本地没有推理服务的地址和 Key，唯一的来源是部署机上的一个凭证文件，它问能不能在进程里读这个文件、不打印也不写出。总控没同意：**凭证由用户决定怎么给，agent 不去读。**

改成一条由用户在自己终端里跑的命令：地址和 Key 从用户自己 export 的两个环境变量里读，agent 只读结果文件。另一个选项是用户直接在消息平台的告警话题里追问，走线上的真实模型，不经手任何凭证，只是"有报告但不显示"这类情况不容易碰到。

脚本的设计：

| 设计 | 做法 |
|---|---|
| 背景数据 | 假的三个实验、三条告警，覆盖三种报告状态：有可发的报告（而且和规则摘要说法不一致）、没有报告、有报告但策略是不显示 |
| 题目 | 有报告、要日志细节、没有报告、报告不显示、无关问题；私聊题在有余量时才跑 |
| 改题 | "要日志细节"那题原来问的信息报告里已经有，模型不读日志也能答，就测不到读日志那条路；改成问报告里没有的退出码 |
| 副作用 | 一次一题；不发消息，不写任何真实的状态文件；只连接给定的地址 |
| 上限写死在代码里 | 模型请求最多 20 次；等服务起来最多 25 分钟，超时就在发出任何模型请求之前退出；健康探测不算模型请求，单独计数 |
| 缺参数 | 缺变量只打印变量名并退出；地址不是 https 也退出，只报变量名 |
| 泄漏自检 | 用一组好认的假地址和假 Key 跑真实代码路径，打了补丁的假模型**故意在回答和抛出的异常里回显这两个值**；然后在标准输出、标准错误、结果文件和异常回溯里搜，都找不到 |

预算的账：每个工具步就是一次模型请求。直接读报告的题约 3 次，要先列告警再读日志的题约 5～6 次，五类必做题合起来就要约 20 次，**没有任何重试余量**。到了上限，后面的题跳过，报告里写明。从 0 冷启动要等十几分钟，整轮约 0.5～1 卡时。

一个小插曲：实现 agent 先给总控发了"脚本已经备好"，随后才意识到脚本其实还不存在，于是当场补齐，只用离线模式和假值验证。

（整理时的理解）

- **凭证能不经手就不经手**：让持有人在自己的环境里执行、agent 只读结果，比"在进程里读、保证不打印"强。后者靠的是代码写对，前者根本不给代码接触的机会。和同日 [风险在凭证，不在程序](守护服务从一人扩到一组的设计_20261109.md#32-风险在凭证不在程序) 是一条线。
- **泄漏测试要用金丝雀，而且要让它真的被回显**：只确认"代码里没有打印 Key 的语句"不够，要让假模型把值吐回来、让异常带上它，再查每一个输出通道，包括回溯。[11 月 5 日也用过金丝雀](调查Agent的质量归因与Harness设计_20261105.md#38-模型要看配置配置里有密钥)，那次确认的是读不到，这次确认的是写不出。
- **题目要逼出被测路径**：模型能绕开的题，答对了也什么都没测到。这是 [smoke 没跑到被测代码不算验证](../10/附加模型的显存编排与判分服务设计_20261026.md) 在评测题上的版本。
- **"已备好"也是自报**：[四种状态](多Agent并行开发的编排与核实_20261104.md#22-一件事的四种状态)里，自报完成不等于已核实，发出去的话要回头兑现。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 审计写得很确定就是对的 | 现象、诊断、药方要分开核 |
| 限制看起来一刀切就该去掉 | 先查它防的是哪次事故 |
| 加预算就更聪明 | 先看预算花在哪 |
| 改流式只是加个参数 | 失败形状变了，截断要一起改 |
| 截断了就重试 | 温度 0 下会在同一处再截断 |
| 开思考一定更好 | 它和步数、时间共用一份预算 |
| 问答读调查报告就该给全部内容 | 只给卡片上真发过、复核过的 |
| 离线测试过了就能用 | 模型会不会调、会不会被门禁拦，要真机问 |

## 7. 一分钟复习

1. 审计意见分三层：现象、诊断、药方；7 条里没有一条完全对。
2. 核实五件事：当前代码、当初为什么、理由还成不成立、收益、风险。
3. 不聪明先看轨迹：时间花在重发超长引用、截断和撞时限；根因找对了，缺因果链。
4. 流式下截断是半截 JSON，旧截断分支走不到；流式和截断要一起改。
5. 截断：丢这一步、提示少写、连续 2 次收尾；不原样重试。
6. 单步时限 = min(max(剩余, 1), 90)，重试重算；收尾留时间。
7. 在线时 502：立刻重发一次、不降上限；第二次再判不可用。
8. 思考 token 计入每步和累计上限，先用小探针测。
9. 问答读结论：同一判断函数、同一文本函数、同一脱敏出口；没结论要明说。
10. 金标存哈希时，撤掉预期改动重生成，逐字节一致才算归因清楚。
11. （晚间）给模型的报错：实际多少、限制多少、怎么改；限制提前写进工具说明，数字取自同一个常量。
12. （晚间）真机实测：凭证不经手、金丝雀要被回显、题目逼出被测路径、请求上限要算重试余量。

## 8. 自测问题

### 问题 1

外部审计说"不聪明是因为限制太多"。核实一条意见要回答哪几件事？举一个现象对、药方不能用的例子。

期望回答：在当前代码上核对现象；查当初为什么加这个限制；看这个理由现在还成不成立；用已有数据估收益；评估会不会更容易编造、泄露、变慢变吵。例子：审计说一个必选的复核步骤吃掉了步数，现象部分成立，但豁免它恰好会放过金标样例里那个真实失败的关键簇；又如成文时优先用带日志原文的根因笔记，是为了防编造，换成终稿自由文本就绕开了约束。

### 问题 2

为什么说只放开预算治不好"不够聪明"？

期望回答：金标样例 3 次都停在时间预算上，时间花在超长引用被退回重发、输出被截断作废、撞上单步时限；根因 3 次都找对了，缺的是因果链。加预算只会被同样的重发和作废吃掉，先要减少浪费的步。

### 问题 3

只把告警端改成流式、再把输出上限提到 2048，会出什么问题？正确的改法是什么？

期望回答：输出在工具调用中途被截断时，流式下拿到的是半截参数，旧的截断分支走不到，代码直接报错，整轮调查失败；温度 0 下截断确定性重现，按普通错误重试只会把截断重复几遍。改法：半截调用当截断处理，丢掉这一步、提示少写，连续 2 次就收尾；共用循环里用默认关闭的开关，只在告警路径打开，问答请求不变；单步时限按 min(剩余, 90 秒) 每次重算；在线时 502 立刻重发一次、不降上限。

### 问题 4

思考模式为什么不能直接打开？

期望回答：思考 token 计入每步的输出上限和整张票的累计上限，估算每步多十几到六十几秒，"20 步 / 300 秒"的预算放不下；服务端解析器能不能正确拆出思考也要确认。所以先用约 20 次请求的小探针测，再决定。

### 问题 5

问答读调查结论时，为什么要"只给卡片上真发过的"？还有哪些风险离线测不出？

期望回答：问答和卡片用同一个判断函数和文本函数，说出来的就和用户在卡片上看到的一致；只留验证过的引用，复核失败的不给根因，没发出结论的明说不能当结论；票号共用一个函数，输出走同一脱敏出口。这样复核只做一次，两边不会说两套。离线测不出：模型会不会主动调用这个工具；只用它的回答会被标"未读日志"；门禁可能拦掉说原因的回答；提示词里两句互相冲突；报告里的引用是文件名，照抄会验证失败。

### 问题 6（晚间补录）

模型引用超长被拒后反复原样重发，怎么改报错？给问答做真实模型实测时，agent 没有 Key，为什么不让它读部署机上的凭证文件？泄漏自检怎么做才算数？

期望回答：报错要写出实际长度、上限，以及怎么改（只截一段能支撑结论的连续文字，比如异常类名加消息开头，不要整行重发）；上限提前写进工具说明，数字取自校验用的同一个常量。只说违反了什么，模型的修正就是原样重试。凭证由用户决定怎么给：改成用户在自己终端 export 两个变量、跑一条命令，agent 只读结果，代码根本接触不到凭证，比"读了但保证不打印"强。泄漏自检用好认的假地址和假 Key，让假模型在回答和异常里故意回显，再在标准输出、标准错误、结果文件和回溯里都搜一遍。另外题目要逼出被测路径：报告里已有的信息，模型不读日志也能答，要改成问报告里没有的；每个工具步是一次请求，20 次上限只够五类题，没有重试余量。
