## 1. 先给结论

- **失效的只是两个比值中的一个**：`π_θ/π_prox` 恒为 1、clip 不触发；`π_prox/π_behave` 照常变化、照常起修正作用。
- **恒为 1 的比值仍是梯度来源**：loss 写的是 `−A·r`，`∇r = r·∇log π_θ`。把 r 换成常数 1，梯度就没了。它失去的是“约束”作用，保留的是“把梯度传进来”的作用。
- **比值不加进 advantage**：advantage 先算好、固定、不求导；比值在 loss 里和它**相乘**。
- **“+ recompute”是成立条件**：只有分母是用同一份权重重算出来的，单次更新时比值才精确等于 1。分母取自推理引擎或插值近似时比值 ≠ 1，但 clip 拦的就成了“训推差 + 陈旧度”，不是它原本的用途。
- **logprob 重算 ≠ 激活重算**：前者是算法层面，产出 π_prox；后者是系统层面，用计算换显存，不改结果。
- **clip 本来就限制不了“单独一步”**（被纠正的误解）：标准多 minibatch PPO 的第一个 minibatch 也是 r = 1。clip 限制的是**同一批数据多次更新累积的偏移**。单步大小由学习率、梯度裁剪和 Adam 决定。
- **minibatch 数与 advantage 无关**：advantage 在切分前已算好。所以这一项是“配置有误导性”，低优先级，加启动期提示即可。
- **重算不替换 π_behave**：它产出的是另一个量 π_prox。三个分布来源不同、各有用途。

## 2. 前置概念

### 2.1 解耦 PPO 里的三个分布

| 角色 | 从哪来 | 用在哪 |
|---|---|---|
| π_behave | rollout 时推理引擎顺带返回的 logprob | 行为侧权重 `π_prox/π_behave` 的分母、拒绝采样的过滤指标、KL 进 reward 时 k1 里的“当前策略”项 |
| π_prox | 重算：训练开始前，训练引擎用当前权重做一次不求梯度的前向 | PPO ratio 的分母，同时是行为侧权重的分子 |
| π_θ | 训练时带梯度的前向 | PPO ratio 的分子，梯度从这里走 |

对应两个比值（定义见 [10 月 13 日 §3.4](PPO的Critic与Clip在单次更新下的退化_20261013.md#34-为什么要重算-logprob)）：

```text
π_θ / π_prox      这一步更新走了多远        两边都来自训练引擎
π_prox / π_behave 数据有多旧 + 训推差多少    分子训练引擎，分母推理引擎
```

### 2.2 每个 token 的 loss

```text
loss_t = −A_t × r_t × w_t        r_t = π_θ/π_prox（被 clip），w_t = π_prox/π_behave（被拒绝采样过滤）
单次更新时 = −A_t × 1 × w_t      梯度 = −A_t × w_t × ∇log π_θ
```

这就是带 off-policy 权重的朴素策略梯度（REINFORCE）。

## 3. 完整原理

### 3.1 “ratio 不起作用、也不加进优势”：两处要说准（被纠正的误解）

**第一处：不起作用的只是一个比值，而且它也不是“完全没用”。**

| 比值 | 作用 | 单次更新时 |
|---|---|---|
| π_θ/π_prox（PPO ratio） | clip、GSPO 序列比值都作用在它上面 | 数值恒为 1，clip 永不触发 |
| π_prox/π_behave（行为侧权重） | 修正“数据来自旧策略或推理引擎”，配合拒绝采样 | 照常变化，不等于 1 |

行为侧权重确实在变：逐 token 版本可以从零点几到一点几，序列级版本因几何平均只在 1 附近很窄的范围内。

PPO ratio 虽然恒为 1，**仍然是梯度的来源**：`∇(−A·r) = −A·r·∇log π_θ`，r = 1 时得到标准策略梯度。若把 r 替换成常数 1，loss 变成常数，梯度为 0，模型什么也学不到。

**第二处：两个比值都不加进优势。** advantage 在算 advantage 的阶段一次算好（组内归一化、KL、批级归一化），之后固定、不参与求导；到更新阶段，比值才在 loss 里和它相乘。比值是 advantage 之外的放大、缩小或截断权重，不改 advantage 本身的值。

一句话：单次更新时 PPO 的 clip 这层保护失效，训练退化为“带 off-policy 权重的策略梯度”；还在起作用的修正只剩行为侧权重和拒绝采样。所以行为侧权重的分母口径（[推理端 raw logprob 与温度](采样截断与Logprob口径的训推偏差_20261014.md#32-推理端-raw-logprob-与温度不一致)）对在线 PPO/GSPO 很重要。

### 3.2 GSPO 在 r = 1 时为什么和 token 级梯度一样

序列比值 `s = exp( (1/|y|) Σ_t log r_t )`。r_t 全为 1 时 s = 1，且

```text
∂s/∂log π_θ(y_t) = s · 1/|y| = 1/|y|                         （r_t 全为 1）
GSPO：  −A·s 广播到 |y| 个 token 再求和 → 梯度 = −|y|·A·(1/|y|)·Σ_t ∇log π_θ(y_t) = −A·Σ_t ∇log π_θ(y_t)
token 级：Σ_t (−A·r_t)                 → 梯度 = −A·Σ_t ∇log π_θ(y_t)
```

每个 token 的导数是 1/|y|，再按 token 广播求和刚好抵消，与 token 级 GRPO 的梯度一模一样（这里假设实现把序列项广播到每个 token 后按 token 聚合，见 [实现与论文的聚合差别](GSPO序列级比率与PPO论文精读_20261014.md#37-实现与论文的三处差别)）。所以单次更新时写着“GSPO”，梯度上仍是 GRPO。

### 3.3 “+ recompute”：分母从哪来决定比值是否恒为 1

用户问：“是开启重算才会恒等吗？”是。ratio 的分母取决于两件事：是否用解耦 loss、π_prox 是重算还是近似。单次更新时四种组合：

| 模式 | ratio 的分母 | 单次更新时 ratio | clip 约束的是什么 |
|---|---|---|---|
| 解耦 + 重算 π_prox | 重算的 π_prox | **≡ 1** | 什么都不约束；off-policy 修正靠行为侧权重和拒绝采样 |
| 解耦 + 插值近似 π_prox | 按版本差在 π_behave 与 π_θ 间插值，不做前向 | ≠ 1 | 主要是训推差和陈旧度（新鲜样本的插值系数为 0，分母就是 π_behave） |
| 非解耦 + 重算 π_old | 重算的 π_old | **≡ 1** | 什么都不约束，而且没有 off-policy 修正 |
| 非解耦 + 不重算 | 推理引擎的 π_behave | ≠ 1 | 训推差和陈旧度混在一起 |

准确的说法：**只要分母是重算出来的，并且只有一次更新，ratio 就恒为 1**。

后两种“ratio ≠ 1”并不是让 clip 恢复了本来的作用。PPO 设计里 clip 防的是“同一批数据上更新太多次、走得太远”；这两种组合里 clip 拦的是“两个引擎算出的概率不一样，再加上样本旧了”，语义完全不同。想让 clip 发挥原本的作用，正路是**每批更新多次**（多个 minibatch 或多个 epoch）。

### 3.4 两种“重算”不是一回事（用户的判断正确）

| | logprob 重算 | 激活重算 |
|---|---|---|
| 层面 | 算法：决定 PPO ratio 的分母 | 系统：省显存，又叫 gradient checkpointing |
| 做什么 | 训练前用当前权重把整批序列多跑一次纯前向，得到 log π_prox | 训练前向时不保存部分中间激活，反向时从检查点重新算出来 |
| 产出 | 一份数据 π_prox，后面要进 loss | 不产出新数据，只是用计算换显存 |
| 改不改数学结果 | 改：没有它就没有 π_prox，ratio 语义随之改变 | 不改（只差浮点非确定性） |

更早的区分见 [两种 Recompute 必须严格区分](../08/OnlineMTP训练成本与性能归因_20260826.md#5-两种-recompute-必须严格区分)。这里补两点：

- **“ratio ≡ 1”只与第一种有关**。激活重算开不开都不影响：它只是反向时把同样的前向再算一遍，logits 来自训练那次前向，数值不变。
- **一步大约三遍前向**：logprob 重算一遍、训练前向一遍、反向时激活重算（full 粒度下接近完整前向）又一遍，再加一遍反向。用插值近似 π_prox 能省掉第一遍，代价是 §3.3 表里的语义变化。

### 3.5 Clip 到底限制什么（被纠正的误解）

用户的理解：“minibatch 为 1 时本质上没有 clip，一步跨得再大也裁不住。”现象对，但结论要补两点。

**第一，clip 本来就限制不了“单独一步”。** 即使是标准的多 minibatch PPO，第一个 minibatch 那一步也是 r = 1、不受 clip 约束。clip 的真正作用是：同一批数据要更新好几次时，已经被推出 [1−ε, 1+ε] 的 token，后续就不再给它梯度（[clip 只在“更好看”的方向生效](GSPO序列级比率与PPO论文精读_20261014.md#31-ppo-论文2017怎么读)）。它限制的是**多次更新累积下来的偏移**，不是某一步迈出去的大小。

所以单次更新时损失的准确说法是“多次更新之间的信任域”。可本来每批数据就只更新一次，也就不存在需要它来防止的过度更新。代码行为符合 PPO 的数学，所以**不算 bug**；问题在于配置里写着 clip 上下界、clip-higher、dual clip、序列级重要性采样这些参数，读的人以为在起作用，系统没有任何提示。

**第二，一步能迈多大由别的机制决定：**

- **单步之内**：学习率、梯度裁剪阈值、Adam 自身的归一化。归因时要注意：同时改了 clip 范围和梯度裁剪阈值的实验，真正生效的只有后者。
- **跨步之间（只对旧样本有效）**：上一步迈得太大，下一批里用旧权重生成的样本会出现 π_prox（新权重）与 π_behave（旧权重）差得很远，拒绝采样把它们过滤掉，行为侧权重重新加权。所以过大的一步会在下一步通过旧样本被部分纠正；**用新权重新生成的样本不受这层约束**。

**多更新几次不是白捡一层保护**：每批多更新几次，同时意味着更激进地利用同一批数据、数据也更“旧”。clip 是给“多次更新”兜底的，而多次更新本身就是风险来源。已经出现训练崩溃的背景下，增加更新次数不一定更稳定，需要实验确认。

让 PPO/GSPO 与 GRPO 在梯度上真正不同，有两条路：

1. **每批更新多次**：同一批切成几份、每份一次 optimizer step。数据仍只过一遍，总计算量基本不变，只是 step 变多、每步 batch 变小。从第二份起 ratio 偏离 1，clip 与序列级 ratio 才生效。
2. **不重算，直接拿推理端 logprob 当 π_old**：即使只更新一次 ratio 也 ≠ 1，但 clip 约束的是训推差 + 陈旧度，异步训练下要谨慎评估。

### 3.6 优先级：和 advantage 无关，只做提醒（用户的判断正确）

minibatch 数只影响 loss 这一步怎样更新，和相对优势的计算完全无关：advantage 在切分前已经一次算好，切几份都不改变它的值；批级归一化也在切分前对整个 batch 做。

所以这一项定为低优先级，修法只是加一条启动期提示：**解耦 + 重算 + 每批只更新一次同时出现时，提示 clip 与序列级重要性采样不会生效**。降级后仍要保留两句“使用时要知道”的话：

- **解读实验时**：声明改了 clip 范围的实验，clip 改动没有生效，差异只能归因于其他同时改动的设置（与 [打包实验的隐含混杂](训练崩溃归因的工作流与实验解读_20261012.md#35-解读时要提前想好的四个陷阱) 同类）；
- **支持在线 PPO/GSPO 时**：如果仍然每批只更新一次，“支持了 GSPO”只是名义上的；每批更新几次、序列级处理放在 `π_θ/π_prox` 一侧还是 `π_prox/π_behave` 一侧，要在设计阶段定下来。

### 3.7 “都开了重算，为什么还在用推理端 logprob”（被纠正的误解）

用户以为重算会把推理引擎的 logprob 替换掉。**不会**：重算产出的是 π_prox，π_behave 仍然保留（§2.1）。两者都要保留：

- π_behave 是这批样本**真正被采样时**的概率。要修正“数据来自旧策略或推理引擎”的偏差，分母必须用采样时的概率；
- π_prox 是“当前训练权重眼里的概率”。

所以“单次更新 ratio ≡ 1”（讲 π_θ/π_prox）和“推理端 raw logprob 口径”（讲 π_prox/π_behave 的分母）是两个不同比值上的两件事，不冲突。

**读数可以证明 π_behave 仍在用**：行为侧近似 KL 就是 `log π_prox − log π_behave` 的均值。如果重算覆盖了推理端的值，它应该恒为 0；实测在 T < 1 时为正、T = 1 时为极小负数，都不是 0（[读法见当天 §2.1](温度偏差实测与KL放置位置_20261015.md#21-近似-kl-均值的符号本身就是证据)）。

**只有一种情况会覆盖**：非解耦模式 + 重算时，重算结果直接写回原来的 logprob 字段，推理端的值不再使用；但那种模式也没有任何 off-policy 修正。

### 3.8 一个读数陷阱：平均重要性权重 < 1 不代表 ratio 在变

不要用“平均重要性权重”判断 ratio 是否恒为 1。被拒绝采样过滤掉的 token，权重被置成 0，但平均的分母用的是过滤**之前**的 token 数，所以这个均值会小于 1，看起来像 ratio 在变。判断 ratio 应该看 `π_θ` 与 `π_prox` 之间的近似 KL 和 clip 比例：单次更新时两者都是精确的 0。

这和 [“不可能的读数先查定义”](温度偏差实测与KL放置位置_20261015.md#33-顺带得到的两条读数) 是同一类问题：先弄清指标的分子分母各数了什么，再解读数值。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| minibatch = 1 时重要性 ratio 都不起作用 | 只有 π_θ/π_prox 恒为 1；π_prox/π_behave 照常修正 |
| ratio 恒为 1，删掉也一样 | 它仍是梯度来源；换成常数 1 梯度为 0 |
| 比值会被加进相对优势 | advantage 先算好、固定；比值在 loss 里与它相乘 |
| 只要每批更新一次 ratio 就是 1 | 还要求分母是同一份权重重算的；插值或推理端分母时 ≠ 1 |
| 分母不重算让 clip 恢复了作用 | 那时 clip 拦的是训推差 + 陈旧度，不是原本的多次更新偏移 |
| logprob 重算就是反向时的激活重算 | 前者产出 π_prox、改变 ratio 语义；后者只用计算换显存 |
| 有 clip 时一步迈太大会被裁住 | 第一次更新 r = 1，clip 从不限制单独一步；只限制多次更新的累积 |
| 多 minibatch = 多一层保护 | 也意味着更激进地用数据，不一定更稳 |
| minibatch 数会影响 advantage | advantage 在切分前已算好 |
| 开了重算，推理端 logprob 就不用了 | 解耦模式下它仍是行为侧权重的分母 |

## 7. 一分钟复习

1. 三个分布：π_behave（推理端）、π_prox（重算）、π_θ（训练）；两个比值：π_θ/π_prox 管本步走多远，π_prox/π_behave 管陈旧 + 训推差。
2. 单次更新：r ≡ 1，loss = −A·w·∇log π，是带 off-policy 权重的 REINFORCE；r 仍传梯度，比值乘在 loss 里，不加进 A。
3. r ≡ 1 的条件：分母重算 + 只更新一次；分母不重算时 r ≠ 1，但 clip 拦的是训推差。
4. GSPO 在 r = 1 时每 token 导数 1/|y|，广播求和后与 GRPO 相同。
5. logprob 重算（算法，产 π_prox）≠ 激活重算（系统，换显存）；一步约三遍前向。
6. clip 只限制同一批多次更新的累积偏移，从不限制单独一步；单步靠学习率、梯度裁剪、Adam，跨步靠旧样本的行为侧权重。
7. 重算不覆盖 π_behave；平均重要性权重 < 1 可能只是过滤后的分母口径。

## 8. 自测问题

### 问题 1

单次更新时 ratio 恒为 1，能不能干脆把 ratio 从 loss 里删掉、换成常数 1？

期望回答：不能。loss 是 −A·r，梯度来自 ∇r = r·∇log π_θ；换成常数后 loss 与参数无关，梯度为 0。ratio 失去的是约束作用，不是梯度作用。

### 问题 2

同样每批只更新一次，为什么“解耦 + 插值近似 π_prox”时 clip 会触发？它约束的是什么？

期望回答：分母不是同一份权重重算的，而是在 π_behave 与 π_θ 之间按版本差插值（新鲜样本时就是 π_behave），所以 ratio ≠ 1。此时 clip 拦的是训推数值差和陈旧度，不是 PPO 原本要防的“同一批数据更新多次走太远”。

### 问题 3

“标准 PPO 有 clip，所以一步迈太大会被裁住。”错在哪？

期望回答：每批的第一次更新时 π_θ = π_old，r = 1，clip 不起作用。clip 只在同一批数据后续的更新中，对已经超出 [1−ε, 1+ε] 的 token 停止给梯度，限制的是累积偏移。单步大小由学习率、梯度裁剪和优化器决定。

### 问题 4

一个实验同时把 clip 范围收紧、把梯度裁剪阈值调小，每批只更新一次。它与基线的差异能归因于哪个改动？

期望回答：只能归因于梯度裁剪（以及其他同时改动的设置）；clip 范围在 ratio ≡ 1 时不生效。

### 问题 5

都已经开了 logprob 重算，为什么还要关心推理端 logprob 的温度口径？

期望回答：解耦模式下重算产出的是 π_prox，π_behave 仍来自推理端，作为行为侧权重 π_prox/π_behave 的分母。单次更新时这是唯一生效的 off-policy 修正，分母口径错了修正就错了。行为侧近似 KL 不为 0 也证明推理端值仍在使用。
