## 1. 先给结论

- **三个开关互相独立**：比值粒度（token / 序列）决定 GRPO 还是 GSPO；clip 范围决定这个比值能偏离 1 多远；拒绝采样作用在另一个比值 π_prox/π_behave 上。**GRPO 与 GSPO 唯一的区别是 π_θ/π_prox 按 token 算还是按序列几何平均算**。
- **clip 不参与算 advantage，也不扔样本**：advantage 在 loss 之前就一次算好；clip 只在 loss 里让“已经朝有利方向走够了”的样本不再给梯度。
- **GSPO 的 clip 要小约三个数量级，是因为几何平均把逐 token 波动平均掉了**：长度 L 的序列，波动大约缩小 √L 倍（独立假设下的估算）。
- **r ≡ 1 是“数值相同、梯度不同”**：π_prox 是不求梯度的常数，π_θ 是 θ 的函数，r 只传梯度、不限步长（[10 月 15 日 §3.1～3.2](单次更新下两个比值的分工与Clip的真实作用_20261015.md#31-ratio-不起作用也不加进优势两处要说准被纠正的误解)）。验证 GSPO 必须让每批更新多次，否则两者梯度相同、什么实验都区分不出来。
- **四格 = 想要的粒度 × 一行装什么**：粒度只有两种（用户对）；另一个轴是导出布局。两者一致的对角线两格不用写代码。
- **按轮比值只改“哪些 token 共用一个比值”**：advantage 不变；GSPO-token 的 stop-gradient 形式只在“序列单位比 advantage 粒度粗”时才需要。
- **“按轮”是一个数据标记，可供三处独立使用**：按轮 reward/advantage（信用分配）、按轮比值（只对序列级比值有意义）、按轮 loss 聚合（权重）。一个开关只改一件事。
- **更新次数 = minibatch 数 = 每个训练步的 optimizer step 数**；micro-batch 只是梯度累积，不算更新；“多久更新一次”由 batch 大小、权重同步与陈旧上限决定，是另外三件事。
- **命名陷阱**：名字带 “importance sampling” 的开关和名字带 “importance weight” 的指标，可能都在说 PPO 比值，而不是行为侧权重。

## 2. 前置概念

### 2.1 三个开关各管哪个比值

| 开关 | 作用在哪个比值 | 管什么 | 是 GRPO/GSPO 的区别吗 |
|---|---|---|---|
| 比值粒度（token / sequence） | π_θ / π_prox | 按 token 算，还是按序列几何平均 | **是，唯一区别** |
| clip 下界 / 上界 | 同一个 π_θ / π_prox | 允许偏离 1 多远 | 不是，但 GSPO 要配小得多的值 |
| 拒绝采样（及其 token / sequence 级别） | π_prox / π_behave | 数据旧、训推不一致时的 IS 加权与过滤 | 不是，两者都能开 |

被纠正的混淆来源：配置里可能**两处都写着 sequence**——一处是 PPO 比值的粒度（这才是 GSPO），一处是拒绝采样的判定级别（序列级 RS）。名字一样，作用在两个不同的比值上（两个比值的分工见 [同日 IS/RS 笔记 §2.1](异步离策略的三个来源与IS和RS_20261019.md#21-三个分布两个比值)）。

### 2.2 clip 的作用位置

```text
advantage：组内归一化，loss 之前一次算好，没有 clip
loss_t   = −min( r_t·A , clip(r_t, 1−ε_low, 1+ε_high)·A )     （GSPO 时 r_t 换成序列比值 s_i）
```

- A > 0 且 r 已超过 1+ε_high：已经推够了，这一项不再给梯度；
- A < 0 且 r 已低于 1−ε_low：已经压够了，不再给梯度；
- 其余情况照常给梯度（包括朝“不利方向”偏离的情况，见 [clip 只挡“更好看”的方向](GSPO序列级比率与PPO论文精读_20261014.md#31-ppo-论文2017怎么读)）。

## 3. 完整原理

### 3.1 clip 不碰 advantage、也不是拒绝（被纠正的误解）

用户的三个猜测都要改：

| 用户的理解 | 更准确的说法 |
|---|---|
| clip 量级和算 advantage 有关 | advantage 在 loss 之前算好；clip 只在 loss 里限制比值 |
| GRPO 与 GSPO 的区别在 RS | 区别只在 π_θ/π_prox 的粒度；RS 在另一个比值上，两者都能开 |
| clip 开太小，样本就都被拒掉了 | clip 不删样本，只让“朝有利方向越界”的那一项梯度为 0；RS 的阈值只看 π_prox/π_behave，和 ε 设多小无关 |

GSPO 下有一点要说准：被 clip 的是**整条序列**的那一项，所以这条序列在这一次更新里整体不给梯度；但它并没有从 batch 或分母里被拿走，下一次更新（如果有）仍会重新判断。这和 RS 的“按权重排除出梯度”是两件事。

clip 设得很小也不会报错：

- 每批只更新一次：r ≡ 1，ε 多小都不触发——问题不是“被拒光”，而是 clip 根本没作用；
- 每批更新多次：从第 2 个 minibatch 起 s_i 略偏离 1，部分序列被 clip，比例有限。若某框架报告的 GSPO clip 比例异常高，先查它是不是跳过重算、把推理端概率直接当成了 π_old，把训推差也塞进了这个比值（[同日 §3.8](异步离策略的三个来源与IS和RS_20261019.md#38-对-gspo-的含义异步本身不会让序列比值生效)）。

### 3.2 为什么 GSPO 的 clip 要小约三个数量级

[10 月 14 日](GSPO序列级比率与PPO论文精读_20261014.md#37-实现与论文的三处差别) 记下了结论（论文约 3e-4 / 4e-4，GRPO 约 0.2），这里补一个量级估算：

```text
假设一次更新后，每个 token 的 log 比值有 ±0.05 的随机波动，且各 token 近似独立

token 级：每个 token 偏离 1 约 5%            → ε = 0.2 是合理量级
序列级：  s_i = exp(mean_t log r_t)
          L = 1000 时波动 ≈ 0.05 / √1000 ≈ 0.0016 → 偏离 1 只有千分之一几
          ε = 0.2 永远不会触发；要 1e-4～1e-3 才起到同样的约束
```

独立是简化假设：同一次参数更新带来的偏移在 token 之间往往相关、还可能有共同的均值，实际缩小倍数会小于 √L。但结论的方向不变——序列越长，s_i 越贴近 1。

反过来也成立：**很短的序列（或很短的一轮）只平均几个 token，比值噪声大**，同样的 ε 对它更容易触发。这是 §3.6 按轮比值要注意的风险。

### 3.3 r ≡ 1：同一个值，不同的东西（用户的判断正确）

用户问“π_θ 和 π_prox 本质上是一个值吗”——数值上是：每批只更新一次时，π_prox 在更新开始前用当前权重 θ₀ 对整批做一次不求梯度的前向；唯一那次训练前向发生在唯一那次 optimizer step 之前，用的也是 θ₀。同一份权重、同一份数据，logprob 逐位相同；`log π_θ − log π_prox` 的近似 KL 每一步**精确为 0、连浮点噪声都没有**，就是这个状态的读数签名。

区别在梯度：π_prox 是常数，π_θ 是 θ 的函数，∇r = r·∇log π_θ = ∇log π_θ，所以 −A·r 的梯度就是标准策略梯度（推导与 GSPO 版本见 [10 月 15 日 §3.2](单次更新下两个比值的分工与Clip的真实作用_20261015.md#32-gspo-在-r--1-时为什么和-token-级梯度一样)）。

用户的第 3 点“每批只更新一次时不产生 clip 很正常，不需要关心”在语义上对，但对**验证**有直接后果：此时 GSPO 与 GRPO 梯度完全相同，任何对照实验都区分不出两者。所以单测要构造 π_θ ≠ π_prox 的输入，端到端对照要让两组都每批更新多次，并在启动时提示“当前配置下 clip 与序列比值不会生效”。

### 3.4 四格：想要的粒度 × 一行装什么

用户说得对：GSPO 的计算粒度只有两种——整条轨迹共用一个序列比值，或者每次 LLM 调用一个。图上的另一个轴不是第三种粒度，而是数据进训练侧时“一行装的是什么”（两种导出布局的定义见 [同日拆行笔记 §2.1](多轮轨迹拆行对GRPO与GSPO的影响_20261019.md#21-两种导出粒度)）。

两种布局在实现上的差别：

- **每轮一行**：每次调用导出一行 = 这次调用的完整输入（mask 为 0）+ 这次的输出（mask 为 1）。前几轮的助手输出也在输入里但被 mask，所以每个助手 token 只训练一次；代价是 K 轮就要 K 行、一行比一行长，前缀被反复前向（[成本示例](多轮轨迹拆行对GRPO与GSPO的影响_20261019.md#36-差别四系统成本与历史只追加假设)）。
- **整条一行**：多轮调用在 token 层面一轮接一轮往下拼，每次调用记一个指向上一轮的“父”指针；导出时只保留最后一次调用，沿父指针把 loss mask、logprob、版本标记逐轮继承下来，再接上新的工具返回（mask 为 0）和本轮输出（mask 为 1）。结果一行就是整条轨迹，所有助手轮都参与训练。单轮任务里两种布局结果相同。

序列比值在实现里通常按“行”（打包边界）分组，所以工作量只取决于“想要的粒度”与“一行装什么”是否一致：

| 布局 | 整条轨迹一个比值 | 每次调用一个比值 |
|---|---|---|
| 整条一行 | 正好等于一行，现成 | 要在行内按轮切段（§3.5），工作量小到中 |
| 每轮一行 | 要跨行汇总；同一轨迹的行可能落在不同 micro-batch 甚至不同 DP rank，工作量大 | 正好等于一行，现成 |

对角线两格免费；这张表只回答“选哪种布局，想要的粒度就不用写代码”。推论：在“每轮一行 + advantage 按整条轨迹广播”的组合下直接打开序列级比值，得到的就是按轮 GSPO，不用改代码；代价是每轮一行的前缀重算，长轨迹下不小，所以“整条一行 + 行内切段”仍值得做。

另一个容易混的点：**“按什么单位算 advantage”和“一行的布局”是两个独立开关**。按整条轨迹算 advantage、再广播到它的所有行上，是可以和“每轮一行”组合的。

### 3.5 按轮比值：只改比值的分组，advantage 不变（用户的判断正确，一处用词校正）

用户的理解对，只有一个用词：随行传入的元信息切开的不是“轨迹”，而是**同一条轨迹里的每一轮**——整条一行时，一行本来就是一整条轨迹。

数据链路：

- 布局、micro-batch 切分、CP 都不变；
- 在 loss mask 旁边多带一个与它同形状的“轮次编号”字段，训练侧对它做和 loss mask **完全相同的对齐移位**（与 [版本标记要跟着 logprob 一起移位](训练口径的隐性错误与读数签名_20261019.md#34-版本标记必须跟着-logprob-一起移位) 同一原则）。

比值：

- 分组键从“行号”换成“行号 + 轮次”；每一段助手输出各自求平均 log 比值、取 exp 得到 s_k，各自做 clip；
- 工具返回的 mask 为 0，不计入任何一段；
- 一轮里出现大的偏离时，不再被整条长轨迹平均掉（与 [序列级 RS 被稀释](多轮轨迹拆行对GRPO与GSPO的影响_20261019.md#35-差别三序列级操作不只-gspo) 同一机制，这里发生在 π_θ/π_prox 一侧）。

advantage：不变，仍是同一 prompt 的 G 条轨迹组内归一化，这一行的所有轮共用同一个 Â_i。真正变的只有比值与 clip 的粒度。

**什么时候需要 GSPO-token 的 stop-gradient 形式**（被修正的设计结论）：原先写的是“以后改成按轮 advantage，就必须换成 GSPO-token”。更准确的条件是：常见实现会在每个 GSPO 序列内部对 advantage 取平均，所以

| 序列单位 vs advantage 粒度 | 序列内 advantage | 现有序列级实现能否直接用 |
|---|---|---|
| 一样细（按轮比值 + 按轮 advantage；或整条比值 + 整条 advantage） | 常数 | 能 |
| 序列单位更粗（整条一个比值，但每轮 advantage 不同） | 不同的值被平均抹平 | 不能，需 GSPO-token：`s_{i,t} = sg[s_i]·π_θ(y_t)/sg[π_θ(y_t)]`，数值仍是 s_i，但每个 token 能带自己的 advantage（[论文 §4.4](GSPO序列级比率与PPO论文精读_20261014.md#32-gspo-论文2025qwen-团队怎么读)） |

这一选项只对多轮有用：单轮时一行就是一次回答，每轮一行时一行就是一次调用，按轮与按行完全等价；只有整条一行的多轮轨迹，按轮才和按整条不同。

### 3.6 “按轮”的三种用途要解耦（用户的判断正确）

用户问“按轮是不是在 reward 计算里改的”。不是：上面的按轮 GSPO 只改了 loss 里算序列比值的那一步，在 advantage 之后，不影响上游——reward 仍是每条轨迹一个，advantage 仍按整条轨迹归一化。

“按轮”本身只是数据层的一个标记，可以给链路上三个互相独立的环节用：

| 用途 | 改的是哪一段 | 适用算法 | 前提 |
|---|---|---|---|
| 1. 按轮 reward / advantage | 信用分配（reward → advantage） | GRPO 也能用 | 环境能给出每轮的 reward |
| 2. 按轮计算比值 | loss 里的序列比值分组 | 只对序列级比值有意义；token 级本来每个 token 一个比值，没东西可分组 | 无 |
| 3. 按轮聚合 loss | 每一轮在 loss 里的权重 | GRPO 也能用 | 无 |

设计教训：最初让“按轮”开关**同时**改了比值分组和聚合权重（每轮等权，权重 1/(T_k·K)），等于把第 2、3 项绑在一起；“只有几个 token 的短轮比值噪声大，却和长轮拿到一样的权重”这条风险，正是绑定带来的（噪声来源见 §3.2 末尾）。拆开后：

- 序列单位开关只管比值分组，聚合仍按行（每个 token 1/T_row），各轮按自己的 token 数自然占比；每行权重之和仍为 1，全局分母不用改；
- 按轮聚合以后需要时，作为 loss 聚合方式的一个新取值单独加，对 GRPO 同样适用；
- 轮次编号作为通用数据字段导出，不挂在任何算法名下。

这与 [拆行笔记](多轮轨迹拆行对GRPO与GSPO的影响_20261019.md#37-小结表) “四点拆开讨论，不整套切换”是同一原则：一个开关只改一件事，否则对照实验分不清是哪一项起的作用。

### 3.7 “ratio 不是重算 logp ÷ 推理 logp 吗”：两个比值（被纠正的混淆）

用户说的“重算 logp 与推理端 logp 之比”是 **π_prox/π_behave**；“每批只更新一次时恒为 1”说的是 **π_θ/π_prox**。两者都逐 token 计算：

| | PPO 比值 π_θ/π_prox | 行为侧 IS 权重 π_prox/π_behave |
|---|---|---|
| 衡量什么 | 这次更新里参数已经走了多远 | 训推差 + 异步造成的版本落后 |
| 每批只更新一次时 | 恒为 1 | 不为 1 |
| 谁来约束 | clip | 拒绝采样（mask / clamp），不经过 clip |
| 何时进入 loss | 一直在 | 有的实现只在配置了拒绝采样时才乘进去（[2×2 表](异步离策略的三个来源与IS和RS_20261019.md#31-minibatch--1-时重要性采样还在不在被纠正的误解)） |

一个典型实现的逐 token loss：

```text
r_t = exp(log π_θ − log π_prox)           # 第一层：PPO 比值，带梯度；粒度开关控制 token / 序列
w_t = exp(log π_prox − log π_behave)      # 第二层：行为侧权重，detach；只在配了 RS 时乘入
L_t = w_t · max(−Â_t·r_t, −Â_t·clip(r_t, 1−ε, 1+ε_high))
loss = Σ_t L_t / N                        # N：RS 之前的有效 token 数
```

没有第二层时，π_prox 只作为 clip 的锚点，不对行为策略的偏差做任何修正——每批只更新一次时，PPO 式的信赖域约束实际不生效，限制步长只能靠学习率与梯度裁剪（[clip 只限累积偏移](单次更新下两个比值的分工与Clip的真实作用_20261015.md#35-clip-到底限制什么被纠正的误解)）。比值分母从哪来（重算 / 插值近似 / 直接用推理端）决定单次更新时是否恒为 1，四种组合见 [10 月 15 日 §3.3](单次更新下两个比值的分工与Clip的真实作用_20261015.md#33--recompute分母从哪来决定比值是否恒为-1)。

**两个命名陷阱**（与 [四个“KL”指标](GRPO训练步的参数时序与四个KL指标_20261016.md#35-名字带-kl-的四个指标被纠正的混淆) 同类）：

- 名为“重要性采样级别”的开关，控制的可能是**第一层** PPO 比值的粒度，与拒绝采样的级别正交；
- 日志里名为“importance weight”的指标，记录的可能也是第一层的 r_t：每批只更新一次时它的均值恒为 1、近似 KL 恒为 0。第二层要看行为侧近似 KL 和被过滤比例。读指标先查它的分子分母是哪两个分布。

### 3.8 更新次数、minibatch 与 micro-batch（被纠正的说法）

先校正用词：设成 1 的是“**minibatch 个数**”，不是“minibatch size”。它说的是**更新次数**——一个训练步里用同一批数据做几次参数更新——而不是“多久更新一次”。

一个训练步的流程（不带 epoch 循环、每条数据只用一遍的实现）：

```text
rollout 收齐一批 → 算 advantage、只算一次 π_prox
→ 按 minibatch 个数 k 切成 k 份
→ 每份：清梯度 → 切若干 micro-batch，逐个前向 + 反向、累加梯度 → 一次 optimizer.step
→ 一个训练步里参数更新 k 次
```

用户的追问依次是：

1. **“和 ratio 有关的是更新次数吗？”** 是。前提是分母是重算出来的（§3.7）；ε 只决定允许偏离多大，不会让比值偏离 1。
2. **“只要 logp 重新算了，是不是也算一次更新？”** 不算。π_θ 在每个 minibatch 的前向里都会重算，但只要参数还是重算 π_prox 时那一份，值就和 π_prox 一模一样。真正让两者拉开的是**两次前向之间发生过 `optimizer.step()`**。
3. **“影响 ratio 的是更新次数，还是 minibatch 数量，还是都会？”** 是同一个东西：一个 minibatch 正好对应一次 step，所以 **参数更新次数 = minibatch 个数 = 这一个参数**。

由此得到：

- 第 j 个 minibatch 前向时，参数已被 step 过 j−1 次，比值偏离 1 的程度大致随 j 增大；
- **第 1 个 minibatch 永远是 r = 1**，所以 k = 4 时只有后 3 个 minibatch 的 clip 起作用；
- **micro-batch 不算更新**：它只是为了省显存把一个 minibatch 拆开累加梯度，中间不 step，对比值没有影响（按 token 上限切分时其个数还会随数据长度浮动）；
- batch 总量固定时，“minibatch 个数”和“每个 minibatch 多大”是同一件事的两种说法：个数越多、每份越小、step 越多，比值越容易偏离 1。

“多久更新一次”由另外三件事决定，都和 minibatch 个数无关：

| 问题 | 由什么决定 |
|---|---|
| 每个训练步消费多少数据 | batch 大小 |
| 推理侧多久拿到新权重 | 每个训练步结束后的权重同步 |
| 允许用多旧的数据 | 最大离策略版本差（[准入门槛](异步离策略的三个来源与IS和RS_20261019.md#33-最大离策略版本差准入门槛不是比值)） |

另一个读配置时的提醒：框架里这个参数的默认值不一定是 1，“大部分配置都是 1”往往是配置文件显式改的；判断某次实验 clip 有没有生效，要看实际生效的配置和 §3.3 的读数签名，不看默认值。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 写着 GSPO、clip 比例与近似 KL 恒为精确 0 | 每批只更新一次，π_θ ≡ π_prox | 查实际生效的 minibatch 个数 |
| GSPO 用 ε = 0.2，多次更新下 clip 比例仍为 0 | 几何平均让 s_i 贴近 1 | 看 s_i 的分布宽度；ε 改到 1e-4 量级 |
| GSPO 的 clip 比例异常高 | 分母没重算，训推差进入序列比值 | 改回重算 π_prox 对比 |
| GSPO 与 GRPO 对照“没有差别” | 两组都每批只更新一次，梯度本来相同 | 两组都改为多次更新再比 |
| 按轮比值后短轮频繁被 clip | 短轮只平均几个 token，噪声大 | 按轮长分桶统计 clip 比例 |
| 按轮开关打开后长轮的梯度份量明显下降 | 开关同时改了聚合权重（每轮等权） | 拆开比值分组与聚合权重，单变量对照 |
| “importance weight”均值恒为 1，却以为行为侧没在修正 | 该指标记录的是 PPO 比值 | 看行为侧近似 KL 与过滤比例 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| clip 量级和算 advantage 有关 | advantage 在 loss 前算好；clip 只限比值 |
| GRPO 与 GSPO 的区别在拒绝采样 | 只在 π_θ/π_prox 的粒度；RS 在另一个比值上 |
| clip 设太小会把样本拒光 | clip 不删样本，单次更新时根本不触发 |
| r ≡ 1 就没有梯度 | 值是 1，导数是 ∇log π_θ |
| 四格 = 四种粒度 | 两种粒度 × 两种行布局 |
| 按轮比值要改 reward 或 advantage | 只改 loss 里比值的分组键 |
| 按轮 advantage 一定要 GSPO-token | 只有序列单位比 advantage 粗时才需要 |
| 按轮比值顺带每轮等权更合理 | 那是另一个开关（聚合方式），绑在一起会放大短轮噪声 |
| minibatch size = 1 | 是 minibatch 个数 = 1，即每批只更新一次 |
| 只要 logp 重算了就算更新 | 拉开 π_θ 与 π_prox 的是 optimizer.step |
| micro-batch 越多，比值越容易偏离 1 | micro-batch 只累加梯度，不 step |

## 7. 一分钟复习

1. 三开关：粒度（GRPO/GSPO 唯一区别）、clip 范围（同一比值能偏多远）、RS（另一个比值）。
2. advantage 在 loss 前算好；clip 不删样本，只让有利方向越界那项梯度为 0。
3. 序列比值波动 ≈ 逐 token 波动 / √L → ε 小约三个数量级；短轮反而噪声大。
4. r ≡ 1：值同、梯度不同；验证 GSPO 必须每批多次更新。
5. 四格 = 粒度 × 一行装什么，对角线免费；整条一行 + 行内按轮切段是按轮 GSPO 的低成本做法。
6. 按轮比值：分组键 = 行号 + 轮次，轮次编号随 mask 一起移位，advantage 不变；GSPO-token 只在序列单位比 advantage 粗时需要。
7. “按轮”三用途：信用分配 / 比值分组 / 聚合权重，各自独立开关。
8. 更新次数 = minibatch 个数 = step 次数；第 1 个 minibatch 永远 r = 1；micro-batch 不算；“多久更新”看 batch、权重同步、陈旧上限。

## 8. 自测问题

### 问题 1

有人说“GSPO 的 clip 要设 3e-4，可我们的框架 clip 一小就把样本全拒掉了，所以只能用 0.2”。这句话错在哪里？

期望回答：clip 不删样本，只在比值朝 advantage 有利方向越界时让那一项梯度为 0；RS 的阈值只看 π_prox/π_behave，与 ε 无关。每批只更新一次时 r ≡ 1，ε 多小都不触发；多次更新时序列比值只偏离千分之一量级，ε = 0.2 才是永远不触发。

### 问题 2

用 √L 估算：逐 token log 比值波动约 0.05，序列长 1000 和长 8 时，序列比值大约偏离 1 多少？各说明什么？

期望回答：约 0.05/√1000 ≈ 0.0016 和 0.05/√8 ≈ 0.018（独立假设，实际缩小更少）。前者说明长序列需要 1e-4～1e-3 的 ε；后者说明很短的轮次噪声大一个数量级，按轮比值时短轮更容易被 clip。

### 问题 3

想要“每次调用一个序列比值”，数据分别是“整条一行”和“每轮一行”时，各要做什么？

期望回答：每轮一行时一行就是一次调用，直接打开序列级比值即可，代价是前缀反复前向；整条一行时要带一个与 loss mask 同形状、同样移位的轮次编号，把分组键从行号改成“行号 + 轮次”。advantage 两种情况都不变。

### 问题 4

什么情况下必须用 GSPO-token 的 stop-gradient 形式？

期望回答：序列单位比 advantage 粒度粗时，例如整条轨迹共用一个比值、但每轮 advantage 不同。常见实现会在序列内平均 advantage，把不同值抹平；GSPO-token 让数值仍是 s_i，但每个 token 带自己的 advantage。两者一样细时现有实现可直接用。

### 问题 5

一批数据切成 4 个 minibatch，每个又切成 6 个 micro-batch。一个训练步里参数更新几次？哪几份的 clip 可能生效？

期望回答：4 次（每个 minibatch 一次 step，micro-batch 只累加梯度）。第 1 个 minibatch 的 r ≡ 1，只有第 2～4 个 minibatch 的 clip 可能生效。

### 问题 6

日志里 “importance weight” 均值恒为 1、近似 KL 恒为 0，能否说明异步陈旧没有被修正？

期望回答：不能。这两个读数可能都记录的是 π_θ/π_prox，只说明每批只更新一次。行为侧修正要看 π_prox/π_behave 的近似 KL、被过滤比例，以及行为侧权重是否真的乘进了 loss。

## 9. 尚未解决与后续路线

- 每批多次更新后，GSPO 与 GRPO 在线对照的稳定性与效果尚未实验；
- 按轮比值在短轮上的噪声是否需要最短轮长或合并短轮，待数据统计；
- 按轮 reward / advantage 依赖环境给出每轮奖励，目前不在范围内；
- loss 按 token 还是按序列平均（论文按序列）仍需与按轮选项分开决定（沿用 [10 月 19 日拆行笔记 §9](多轮轨迹拆行对GRPO与GSPO的影响_20261019.md#9-尚未解决与后续路线)）。
