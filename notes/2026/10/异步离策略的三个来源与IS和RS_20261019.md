## 0. 今天最终要解决的问题

按提问顺序：

1. 推理端传来的 raw logprob 本来就不含温度和 top-p/k；本来就有 π_prox/π_behave 这个比值吸收两边差异，这应该不算 bug？
2. 仓库里很多配置 minibatch 设为 1，GRPO 其实根本没开重要性采样的 ratio，对吗？
3. 框架是异步的，所以也不算严格的 on-policy？
4. “最大离策略版本差”这个比值是干嘛的？开了拒绝采样会怎样？
5. RS 和 IS 出现频率很高，但一直没太理解是干什么用的。

## 1. 先给结论

- **异步训练严格说不是 on-policy**，离策略来自三处：异步造成的样本陈旧、训推数值差异、同一批数据多次更新。前两处由 `π_prox/π_behave` 处理，第三处由 `π_θ/π_prox`（含 clip、GSPO 序列比值）处理。
- **minibatch = 1 只消掉了第三处**：`π_θ/π_prox ≡ 1`。前两处一直存在，是否被修正取决于行为侧权重有没有真的乘进 loss（有的实现只在配置了拒绝采样时才乘）。
- **最大离策略版本差不是比值**，是“样本最多落后几个权重版本”的整数上限，是**准入门槛**；IS/RS 管的是“进来之后在 loss 里怎么加权”。
- **IS（重要性采样）修偏差**：用 A 分布的样本估计 B 分布下的期望，每个样本乘 B/A。
- **RS（这里指按权重拒绝）控方差**：权重太极端的样本不再贡献梯度，但仍计入分母。clamp 变体就是截断重要性采样（TIS）。
- **RS 在 LLM 圈有两种意思**：按重要性权重过滤（这里）vs 按 Reward 筛回答拿去微调（拒绝采样微调）。看到 RS 先问它过滤的依据是概率比还是回答好坏。
- **比值吸收不了分母口径错误**（被纠正的误解）：比值能修正的前提是分母是真实采样概率；代入“不陈旧、数值完全一致”的理想情况，比值应恒为 1，T ≠ 1 时 raw logprob 分母却让它报告一个不存在的偏移。

## 2. 前置概念

### 2.1 三个分布、两个比值

沿用 [10 月 15 日 §2.1](单次更新下两个比值的分工与Clip的真实作用_20261015.md#21-解耦-ppo-里的三个分布) 与 [10 月 16 日五个分布](GRPO训练步的参数时序与四个KL指标_20261016.md#21-一个训练步里的五个分布)：

```text
π_behave：推理引擎采样时记录的概率（可能是旧版本权重、另一套数值实现）
π_prox  ：训练引擎用当前权重重算、不求梯度
π_θ     ：训练引擎带梯度的前向

π_θ / π_prox      → 同批多次更新走了多远（clip、GSPO 序列比值在这一侧）
π_prox / π_behave → 数据有多旧 + 训推差多少（IS 权重、RS 在这一侧）
```

### 2.2 重要性采样恒等式

$$
\mathbb{E}_{x\sim B}[f(x)] = \mathbb{E}_{x\sim A}\Big[\tfrac{B(x)}{A(x)}\, f(x)\Big]
$$

用来自 A 的样本，乘上权重 w = B/A，就得到 B 下期望的无偏估计。RL 里 A = π_behave（样本真正来自谁），B = π_prox（想估计谁的梯度）。

## 3. 完整原理

### 3.1 minibatch = 1 时重要性采样还在不在（被纠正的误解）

用户以为 minibatch = 1 时 GRPO 根本没有重要性 ratio。实际要看两个维度：

| minibatch 数 | 行为侧权重是否乘进 loss | π_θ/π_prox（PPO ratio + clip） | π_prox/π_behave（IS + RS） | 实际效果 |
|---|---|---|---|---|
| 1 | 是 | 恒为 1，clip 不触发 | **生效** | 只有离策略修正这一侧 |
| 1 | 否 | 恒为 1 | 不生效 | **退化成没有任何修正的朴素策略梯度** |
| > 1 | 是 | 从第 2 个 minibatch 起 ≠ 1，clip 生效 | 生效 | 两侧都在 |
| > 1 | 否 | clip 生效 | 不生效 | 只有 PPO 信任域 |

所以 minibatch = 1 缺的是 **PPO 的信任域**（只在同批多次更新时才有意义，[clip 只限累积偏移](单次更新下两个比值的分工与Clip的真实作用_20261015.md#35-clip-到底限制什么被纠正的误解)），不一定缺离策略修正。“开了解耦 loss 却没配拒绝采样，行为侧权重就不乘进 loss”这类实现细节要逐个配置核对（[10 月 16 日 §3.4](GRPO训练步的参数时序与四个KL指标_20261016.md#34-π_prox--π_behave-有什么用)）。

### 3.2 异步为什么不是严格 on-policy：三个来源

| 来源 | 怎么产生 | 由哪个比值处理 | minibatch = 1 时 |
|---|---|---|---|
| ① 异步陈旧 | 训练第 k 步时 rollout 仍在用旧权重生成；online 模式下换权重只暂停接纳新会话，在途会话继续跑，**同一条多轮轨迹的前后轮可能来自不同版本** | π_prox/π_behave | 存在，靠 IS/RS 修正 |
| ② 训推差异 | 权重相同，两套引擎的数值实现也不同；还可能叠加 raw logprob 口径（温度前、截断前） | π_prox/π_behave | 存在，靠 IS/RS 修正 |
| ③ 同批多次更新 | 第 2 个 minibatch 起，权重已被前面的 minibatch 改过 | π_θ/π_prox | 不存在，比值恒为 1 |

这正是解耦 PPO 把 π_old 拆成 π_behave 与 π_prox 的原因：把“数据从哪来”与“这一轮更新走多远”分开处理。所以“minibatch = 1 时 ratio 恒为 1”只说明 ③ 不存在，① ② 一直在。

每个 token 都带一个“由哪个版本的权重生成”的标记，所以可以从版本标记统计样本平均落后多少个版本（统计前先确认这个指标的定义没有差一，见 [同日口径笔记 §3.4](训练口径的隐性错误与读数签名_20261019.md#34-版本标记必须跟着-logprob-一起移位)）。

### 3.3 最大离策略版本差：准入门槛，不是比值

它是一个整数上限 N，单位是版本号：

- 接收一组样本时，检查其中**所有**生成 token 的版本是否都落在 `[当前版本 − N, 当前版本]`；只要有一个 token 超窗，**整组丢弃**，不会只丢一部分（与 [整组拒收是放大器](AgenticRollout吞吐分解与整组拒收_20261009.md) 同一类机制）；
- N = 0 是严格同步：换权重前要排空所有在途 rollout，每个样本都由当前权重生成，代价是吞吐下降；
- N 越大，允许的陈旧越多、吞吐越高（容量公式见 [Staleness 窗口](权重同步版本语义与Staleness窗口_20261008.md)）。

分工：

```text
最大离策略版本差：决定哪些样本能进来（粗粒度门槛）
IS / RS          ：决定进来的样本在 loss 里怎么加权（细粒度修正）
```

**N = 0 也不能去掉 IS/RS**：② 训推差异与版本无关，仍然存在。

### 3.4 IS：给每个样本乘一个修正权重

策略梯度要求样本来自正在求梯度的策略。现在样本来自 π_behave，想要的是 π_prox，于是每个 token 的 loss 乘 $w = \pi_\text{prox}/\pi_\text{behave}$：

| w | 含义 | 修正方向 |
|---|---|---|
| > 1 | 采样时概率低、被采到的偏少，但当前策略认为它更可能出现 | 放大，把“该有的份额”补回来 |
| < 1 | 采样时概率高、被采得太多，当前策略没那么偏好 | 缩小，把多出来的份额压下去 |
| = 1 | 两个分布看法一致 | 不修正 |

类比：对有偏的监控采样按采样率反向加权（采样率 10% 的事件乘 10）。

### 3.5 RS：把权重太极端的样本排除出梯度

IS 的致命问题是 w 偶尔会极大。例：某 token 推理端概率 0.01、训练端 0.5，w = 50，这一个样本就主导整个梯度，方差暴涨。RS 的做法：

1. **过滤**：w 超出 [下限, 上限] 的 token（序列级时按整条序列的几何平均判断）不再贡献梯度；
2. **仍计入分母**：被过滤的 token 仍算在 loss 的 token 计数里，所以过滤一部分之后，剩下的梯度不会被放大（反例见 [同日 §3.3 先 mask 再算 loss](训练口径的隐性错误与读数签名_20261019.md#33-两层-loss-归一化必须用同一个-token-计数)）；
3. **通常只设上限**：w 很大意味着某 token 被严重高估，乘上去会让方差暴涨，是危险方向；w 很小只是把它的权重调低，影响有限；
4. **clamp 变体**：不扔样本，而是把 w 截到上限再乘进去，即截断重要性采样（TIS）。

IS 修偏差，RS 控方差，所以通常一起用；不扔离群点时一个点就能把平均值带偏。

**token 级 vs 序列级**：序列级用几何平均，正负偏差互相抵消，权重贴近 1、很少触发；token 级范围大得多。定性规律：健康期 w 均值≈1、RS 几乎不触发，主要是 IS 在轻微重新加权；训推差异突然变大的崩溃期，RS 开始成批过滤，起安全阀作用（与 [10 月 16 日 §3.4](GRPO训练步的参数时序与四个KL指标_20261016.md#34-π_prox--π_behave-有什么用) 一致）。

相关诊断量：w 本身的分布、`log w` 的均值（行为侧近似 KL）、被过滤比例。

### 3.6 比值能不能吸收分母口径错误（被纠正的误解）

用户的理解有两点是对的：推理引擎默认返回温度前、截断前的 raw logprob，是有文档说明的默认行为，不是引擎 bug；流水线里也确实有 π_prox/π_behave 专门吸收两边差异。

但比值能修正的前提是**分母就是采样时真正用的概率**。分母错了，比值没法自己纠正自己。检验方法——代入理想情况（数据不旧、两套引擎数值完全一致），此时比值应恒为 1：

| 采样设置 | 样本实际来自 | 分子 π_prox | 记录的分母 | 理想比值 | 实际比值 |
|---|---|---|---|---|---|
| T = 1，top-p < 1 | 截断后的 q = p/Z | p | p | 1（相对真实 q 应为 Z） | 1，但漏掉 1/Z |
| T < 1 | 温度后（再截断）的分布 | p_T | p_1（T = 1） | ≈ 1 | p_T/p_1：高概率 token 偏大、低概率 token 偏小 |

第二行里采样和重算其实都用了同一个温度，两边本来一致；只因分母取了 T = 1 的值，比值就报告了一个并不存在的离策略偏移，IS/RS 会把它当成“数据旧了”处理——比值不是在吸收差异，而是在制造差异。佐证：这个偏移只随温度变、与陈旧度几乎无关（实测读法见 [10 月 15 日](温度偏差实测与KL放置位置_20261015.md)）。

定性（沿用 [10 月 15 日的分类](KL估计器与放置位置的设计动机_20261015.md#36-批级归一化哪部分是缺陷哪部分是取舍被纠正的误解)）：不是引擎 bug，也不是某行代码算错，是**集成时取错了量**（推理端 logprob 模式没有配置入口）。当前影响可能很小，但一旦在线 PPO/GSPO 依赖这一侧做序列级决策，或有配置用更低温度，分母必须先对。

### 3.7 RS 的两种意思

| | 本文（rollout 修正里的 RS） | 别处常见的 RS |
|---|---|---|
| 过滤依据 | 重要性权重 w = π_prox/π_behave 是否太极端 | 回答的 Reward 高不高 |
| 过滤对象 | token 或序列，不参与本次梯度 | 候选回答，只保留好的拿去训练 |
| 典型名字 | rejection sampling / TIS / MIS | 拒绝采样微调（RFT、RAFT 一类） |

两者名字相同、做的事完全不同。

### 3.8 对 GSPO 的含义：异步本身不会让序列比值生效

GSPO 的序列比值在 π_θ/π_prox 一侧，异步只影响 π_prox/π_behave 一侧，所以“异步”不会让单次更新时的 GSPO 生效。

反过来，若实现**跳过重算、直接把 π_old 设为推理端概率**（有开源框架提供这种 bypass 模式），陈旧与训推差（①②）就进入了 GSPO 的序列比值；再配上 GSPO 1e-4 量级的极紧 clip，会出现大量裁剪。保留重算 π_prox 的结构，正好把“数据从哪来”与“这一轮走多远”分开。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| minibatch = 1 时 GRPO 没有重要性采样 | 只是 π_θ/π_prox ≡ 1；π_prox/π_behave 是否生效看实现与配置 |
| 有了 π_prox/π_behave，raw logprob 口径无所谓 | 比值修正的前提是分母正确；理想情况下它应恒为 1 |
| 最大离策略版本差是一个比值 | 是版本差上限，准入门槛 |
| 版本差设为 0 就是严格 on-policy，可以去掉 IS/RS | 训推差异仍在 |
| 被 RS 过滤的 token 从分母里去掉 | 仍计入分母，否则剩下的梯度被放大 |
| RS 就是挑高分回答 | 这里是按重要性权重过滤；挑高分是拒绝采样微调 |
| 异步会让 GSPO 序列比值生效 | 序列比值在 π_θ/π_prox 一侧，异步只影响另一侧 |

## 7. 一分钟复习

1. 离策略三来源：异步陈旧、训推差异 → π_prox/π_behave；同批多次更新 → π_θ/π_prox。
2. minibatch = 1 只消掉第三个；行为侧权重没乘进 loss 时就是朴素策略梯度。
3. 版本差上限 = 准入门槛，超窗整组丢；N = 0 也去不掉训推差。
4. IS：E_B[f] = E_A[(B/A)·f]，修偏差；RS：w 极端就排除出梯度但留在分母，控方差；clamp = TIS；通常只设上限。
5. RS 两义：按权重过滤 vs 按 Reward 挑回答。
6. 检验比值口径：代入理想情况看是否恒为 1；比值修不了自己的分母。

## 8. 自测问题

### 问题 1

minibatch = 1、开了解耦 loss，但没配拒绝采样，而所用实现只在配置拒绝采样时才乘行为侧权重。此时训练等价于什么？

期望回答：π_θ/π_prox ≡ 1、clip 不触发，π_behave 不进入策略 loss，等价于没有任何离策略修正的朴素策略梯度。

### 问题 2

为什么把最大离策略版本差设成 0 之后，π_prox/π_behave 这层修正仍不能去掉？

期望回答：版本差为 0 只消掉异步陈旧；推理引擎与训练引擎的数值差异（以及 logprob 口径差）与版本无关，仍然存在。

### 问题 3

被拒绝采样过滤掉的 token，为什么还要计入 loss 的分母？

期望回答：若从分母里去掉，剩下 token 的平均梯度会被放大 N_前/N_后 倍，等于过滤反而加大了步长。计入分母时，过滤只是让这些 token 的贡献为 0。

### 问题 4

T < 1 采样、推理端返回 T = 1 的 raw logprob。用“理想情况”说明为什么行为侧权重在制造偏差。

期望回答：理想情况下数据不旧、数值一致，采样与重算都用同一温度，比值应为 1；分母却是 T = 1 的概率，比值变成 p_T/p_1，高概率 token 被放大、低概率被缩小，IS/RS 把这个假偏移当作陈旧来修正。

### 问题 5

看到“RS”两个字母，第一件要分清的事是什么？

期望回答：过滤依据是重要性权重（概率比）还是回答好坏（Reward）。前者是 rollout 修正里的拒绝采样，后者是拒绝采样微调。
