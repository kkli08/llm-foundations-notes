> 记录时间：2026-10-13 10:00

>
> 来源：Claude Code 会话 `9be5c822`

### 今天的问题

- Critic / Value Model 到底是什么？
- PPO 是 RL 的训练流程，和模型结构是两件事，对吗？

### 对话或资料摘录

- 对：模型结构是“前文 → 下一 Token 分布”的函数；SFT/PPO/GRPO 是训练循环，决定喂什么数据、用什么 Loss、按什么顺序调用哪些模型。RL 对 Actor 只需要“采样生成”和“给已有文本算逐 Token Logprob”两个接口；
- Critic 与 Actor 同主干，只把输出头从 `hidden → vocab` 换成 `hidden → 1`，每个位置输出一个标量 V(s_t)：“走到这里，预计最后能拿多少分”；通常从同一预训练模型初始化，和 Actor 一样大；
- Critic 用 MSE 回归每个位置的实际 Return（同样带 Clip），与 Actor 一起训练、互相依赖；
- PPO 一步九段：Rollout → Reward → Critic 前向 → Ref 前向 → Actor 前向（重算 Logprob）→ KL 并入 Reward + GAE → 更新 Actor → 更新 Critic → 同步权重；GRPO = 去掉 Critic 前向与更新，Advantage 改为组内归一化。

## 11:08｜Ref 只为 KL？Clip Loss 是什么？为什么要重算 Logprob

>
> 来源：Claude Code 会话 `9be5c822`

### 今天的问题

- Ref 做前向只是为了算 KL 吗？Ref 是冻结的初始权重吧？
- Actor 怎么用 Advantage 更新？PPO Clip Loss 是什么？
- 为什么 Actor 还要再做一次前向算 Logprob？

### 对话或资料摘录

- Ref 只服务于 KL；“初始”指本次 RL 起跑的 Checkpoint；KL 有两种放法：进逐 Token Reward（k1），或像原版 GRPO 那样作为 Loss 项（k3）；不用 KL 时可以连 Ref 前向和显存一起省掉；
- 三层：朴素策略梯度 `−A·log π` → 多次更新时引入 ratio 与 Clip（改够了就停手）→ 异步训练的解耦版本（ratio 对 prox 做 Clip，prox/behave 单独加权或过滤）；
- 关键结论：整批只做一次梯度更新、prox 又是同一份权重刚算的，则 ratio ≡ 1、Clip 永不触发，clip-higher 与序列级 ratio 都不起作用；
- 重算的两个理由：采样权重可能落后若干版本；即使同版本，推理与训练两套计算栈数值也不同。

>
> 来源：Claude Code 会话 `9be5c822`

### 今天的问题

- 下一步给我介绍一下 GRPO。

### 对话或资料摘录

- GRPO = PPO 去掉 Critic，用同题 G 次采样的平均分充当“预期得分”；代价是推理侧 G 倍采样、Credit Assignment 退化到轨迹粒度；
- 原版 GRPO：组内减均值除 std，每条回答内部按长度平均再组内平均，KL 作为 Loss 项；
- 已知问题与变体：长度偏差（Dr.GRPO/DAPO 改 Token 等权）、难度偏差（Dr.GRPO 不除 std）、零方差组（DAPO 动态采样）、熵塌缩（clip-higher）、截断回答（超长惩罚）、Token 级 ratio 噪声（GSPO 序列级）、均值含自身（RLOO 留一）；
- 多轮 Agent 下：一个“回答”是整个会话，所有模型 Token 共用一个 A；Token 等权让长轨迹主导梯度；“组”在 infra 上是必须整组跑完的约束。

>
> 来源：Claude Code 会话 `9be5c822`

### 今天的问题

- 轨迹内“哪一步做错了”GRPO 分不出来，PPO+GAE 是不是能更好平衡偏差和方差？
- 之前最先想验证的，就是“按 Token 归一化会不会导致 Reward 归 0”吗？
- PPO 会有 GRPO 那种组内长尾问题吗？

### 对话或资料摘录

- 理论上可以：λ 调偏差与方差；但 Critic 在稀疏 0/1 Reward 下难训准，且 Token 级 λ 衰减太快（λ=0.95 约 100 Token 衰减到 e⁻⁵），长序列只能取 λ≈1，退回接近 GRPO；折中是轮次边界估值或过程奖励；
- 被纠正：有两个不同的“按 Token”——批级 Advantage 归一化的统计口径（改 A 的值）与 Loss 的 Token 等权聚合（改每条轨迹的权重）；那个实验只测前者，Reward 归 0 是终态而非直接测量对象；
- PPO 没有组内等待：每条轨迹跑完即可算；GRPO 一条卡住会拖住同组、使其变旧、超时则整组作废；批屏障与陈旧度两者共有。

> 来源：Claude Code 会话 `9be5c822`

### 今天的问题

- 批级 Advantage 归一化具体有哪些操作？按 Token 是其中一步吗？能按轨迹做吗？

### 对话或资料摘录

- 被纠正：“按 Token”不是单独一步，而是求均值和标准差时的计数口径；
- Reward → Advantage 五步：Reward 预处理 → 组内归一化 → 展开到 Token（加 KL 小 Reward）→ GAE → 批级归一化；前两步一条轨迹一个数，之后每个模型 Token 一个数；
- 手算例子：按 Token 统计时成功被放大、失败被缩小、零方差组变非 0；按轨迹统计时均值恰为 0，只剩统一缩放；
- 平移只来自按 Token 计数；缩放两种口径都有；
- 拆分方法：只留缩放（不减均值）、在 Reward 层除以按轨迹统计的全批 std，可把“平移”和“缩放”分开测试。

### 今天的问题

- Advantage 归一化是 GRPO 专有的吗？是在算每组 Advantage 吗？均值层级、标准差层级分别是什么？

### 对话或资料摘录

- 被纠正：Advantage 归一化不是 GRPO 专有，最早为 PPO + Critic 设计；组内比较由另一处 Reward 归一化完成，两处共用同一配置结构，容易混；
- 统一运算 `(x − M) / (S + eps)`：均值层级决定 M（batch / group / 不减），标准差层级决定 S（batch / group / 不除）；另有组大小（按连续样本切组）、留一均值（RLOO）、无偏 std、eps；
- 不减均值时 std 实际是围绕 0 的均方根；未写出的字段取默认值，改配置时两个层级都要显式写；
- 原版 GRPO、Dr.GRPO、RLOO、LitePPO、PPO 的差别大多就是两处归一化的组合不同。
