## 1. 先给结论

- **两个分支是同一个教师配置段、靠一个权重切换**：RL loss 权重为 0 → 纯蒸馏（只有教师信号，verifier 奖励照算但不进 loss）；大于 0 → joint（RL loss + 一个小权重的蒸馏正则，形式上就是把 ref KL 的“锚”换成教师）。
- **joint 分支的 bug：把 `log π_θ − log π_T` 直接当 loss**。教师项 detach 后是常数，求导时消失，只剩 `∇log π_θ`；样本来自学生自己时它的期望恰好为 0。所以教师对梯度**完全不起作用**，每步白付一次教师前向，效果约等于普通 GRPO。这正是 [10 月 15 日 §3.3 “k1 直接进 loss 期望梯度为 0”](KL估计器与放置位置的设计动机_20261015.md#33-为什么-reward-用-k1loss-用-k3) 的同一个陷阱，只是 π_ref 换成了 π_T。
- **正确写法有两种**：`½ (log π_θ − log π_T)²`（k2）直接进 loss；或把 `R_t = log π_T − log π_θ` detach 后当逐 token 优势走策略梯度。两者在学生自己的样本上，期望梯度都**恰好**是反向 KL(π_θ ‖ π_T) 的梯度。
- **“估计值无偏”≠“梯度无偏”**：k1 作为 KL 的数值估计是无偏的，但直接求导得到的梯度期望为 0；k2 作为数值估计有偏，求导却给出精确的反向 KL 梯度。说“最小化 logp − teacher_logp 等价于最小化反向 KL”只对**值**成立，对梯度不成立——它漏掉了“采样分布本身依赖 θ”的那一项。
- **验证方法：换一个教师，梯度变不变**。小词表上按精确期望算，两个完全不同的教师得到同样的（全 0）梯度 → 教师没进梯度。
- **纯蒸馏分支方向对，但整段替换掉了 PPO loss**：比值不裁剪、拒绝采样失效、ref KL 被丢、轨迹加权被忽略。更好的写法是把 R_t 当逐 token 优势交给已有的 PPO loss，保护全部复用。
- **兼容性没校验**：教师与学生词表不一致时（例如新一代模型新增的特殊 token 超出旧一代教师的词表），教师对这些 token 的 logp 来自未训练的 embedding 行（推断，未实测）；教师温度不随学生采样温度同步。
- **继承的配置字段“写了不报错 ≠ 生效”**：教师配置继承了整个 actor 配置，clip、KL、优势归一化、minibatch 个数等字段语法合法，但教师从不进入训练，全都不生效。

## 2. 前置概念

### 2.1 score function 恒等式

```text
E_{x~π_θ}[∇log π_θ(x)] = Σ_x π_θ(x) · ∇π_θ(x)/π_θ(x) = ∇ Σ_x π_θ(x) = ∇1 = 0
```

在**自己的**样本上，“把采到的 token 的 logp 往上推（或往下压）”的期望梯度为 0：被采到的 token 被推，同时没被采到的 token 在别的样本里也被推，平均下来抵消。所以任何形如“常数 − log π_θ”或“log π_θ − 常数”的 loss，对 on-policy 样本只贡献噪声。

### 2.2 两个分支是什么

| | 纯蒸馏 | joint（RL + 蒸馏，文献中也称 KDRL） |
|---|---|---|
| 切换方式 | RL loss 权重 = 0 | RL loss 权重 > 0（框架默认） |
| 学习信号 | 只有教师 | verifier 奖励（GRPO / PPO）+ 教师 |
| loss | 蒸馏权重 × 策略梯度形式的蒸馏项 | RL 权重 × RL loss + 蒸馏权重 × 蒸馏项 |
| verifier 奖励 | 照常计算，但不进 loss | 正常使用 |
| 蒸馏权重的含义 | 只是整体缩放（相当于学习率倍数） | 教师项相对 RL 的比重，通常远小于 RL |
| 适用场景 | 没有 verifier，或先把小模型往教师方向拉 | 有奖励，想借教师加速、稳定训练 |

纯蒸馏就是 [10 月 26 日](在线蒸馏OPD与多教师MOPD_20261026.md#31-opd-一步做什么) 讲的 OPD 本体。joint 则是在正常 RL 上加一个正则项，与 [ref KL 同形异向](在线蒸馏OPD与多教师MOPD_20261026.md#32-与-ref-kl-的关系)：ref KL 把学生拉回原来的自己，这一项把学生拉向教师。

## 3. 完整原理

### 3.1 joint 分支：detach 的教师项求导后消失

某位置上（前缀固定），反向 KL 及其梯度：

```text
KL(π_θ ‖ π_T) = Σ_x π_θ(x) · (log π_θ(x) − log π_T(x))
∇KL = Σ_x ∇π_θ(x) · (log π_θ − log π_T) + Σ_x π_θ(x) · ∇log π_θ(x)
    = E_{x~π_θ}[(log π_θ(x) − log π_T(x)) · ∇log π_θ(x)]  +  0
```

joint 分支写的是：

```text
loss = mean_t( log π_θ(o_t) − log π_T(o_t) )      log π_T 已 detach
∇loss = mean_t( ∇log π_θ(o_t) )                   ← 与教师无关；期望为 0（§2.1）
```

少的正是系数 `(log π_θ − log π_T)`。后果：

- 教师对梯度不起作用：换任何教师，梯度都一样；
- 剩下的项把每个采到的 token 的 logp 一律往下压，期望为 0、只增加噪声；
- 默认配置（RL 权重 > 0）和自带示例走的都是这条分支 → 用这条分支得到的“KD + RL”曲线，不能算作蒸馏的效果。

**为什么“值等价”会骗人**：`E_{o~π_θ}[log π_θ(o) − log π_T(o)]` 的值确实等于反向 KL。但对样本均值求导时，样本 o 被当成固定的，没有对“采样分布 π_θ 随 θ 变化”求导；那一项（score function 项）恰好是携带教师信息的那一项。对 on-policy 样本写 loss，要问的是**梯度**的期望对不对，而不是 loss 值的期望对不对。

### 3.2 正确的两种写法：k2 进 loss，或把 R_t 当优势

| 写法 | 单样本梯度 | 在 π_θ 下的期望 |
|---|---|---|
| k1 直接进 loss：`log π_θ − log π_T` | `∇log π_θ` | **0** |
| k2 进 loss：`½ (log π_θ − log π_T)²` | `(log π_θ − log π_T) · ∇log π_θ` | **∇KL(π_θ ‖ π_T)** |
| R_t detach 当优势：`−sg(log π_T − log π_θ) · log π_θ`（或乘比值） | `(log π_θ − log π_T) · ∇log π_θ` | **∇KL(π_θ ‖ π_T)** |
| k3 进 loss（r = π_T/π_θ）：`(r − 1) − log r` | `(1 − r) · ∇log π_θ` | ∇KL(π_T ‖ π_θ)（**正向**） |

- 修 joint 分支最小的改法是第二行：只把 loss 换成平方的一半；日志里仍可以记原来的差值，便于阅读。
- 第三行就是纯蒸馏分支的做法（比值在 θ = θ_old 处的梯度等于 `∇log π_θ`），所以它方向是对的。
- 第四行是整理时按 [10 月 15 日 §3.3 的 k3 推导](KL估计器与放置位置的设计动机_20261015.md#33-为什么-reward-用-k1loss-用-k3) 补的：k3 进 loss 优化的是**正向** KL。对 ref 来说 π_θ 与 π_ref 很接近，方向差别不大；教师与学生往往差得远，两个方向的行为不同（[正向覆盖、反向集中](在线蒸馏OPD与多教师MOPD_20261026.md#21-正向-kl-与反向-kl)），**不能把 ref KL 的 k3 写法直接搬给教师**。

记忆方式：k1 是“值无偏、梯度为 0”，k2 是“值有偏、梯度精确”，k3 是“值无偏、梯度对应反方向”。

### 3.3 手算：换一个教师，梯度变不变

两个 token a、b，学生 π_θ = (0.5, 0.5)（logits 参数化），对 z_a 求梯度：∇log π(a) = 1 − π(a) = +0.5，∇log π(b) = −π(a) = −0.5。

**教师 A：π_T = (0.8, 0.2)**。系数 c = log π_θ − log π_T：c_a = ln 0.5 − ln 0.8 ≈ −0.470，c_b = ln 0.5 − ln 0.2 ≈ +0.916。

```text
k1 进 loss：E[∇] = 0.5·(+0.5) + 0.5·(−0.5) = 0
k2 进 loss：E[∇] = 0.5·(−0.470)(+0.5) + 0.5·(+0.916)(−0.5) ≈ −0.347
真实 ∇KL：π(a)·(c_a − E[c]) = 0.5·(−0.470 − 0.223) ≈ −0.347   ✓
```

梯度下降让 z_a 变大 → 学生往教师偏好的 a 移动。

**教师 B：π_T = (0.2, 0.8)**：k2 的期望梯度变成 ≈ +0.347（往 b 移动）；k1 仍然是 0。

**换教师、梯度不变 → 教师没进梯度**。当天的审查在一个 6 词表的小策略上按精确期望做了同样的检查：两个完全不同的教师下，joint 分支的梯度都是全 0，纯蒸馏分支与真实反向 KL 梯度一致。没有 GPU、甚至没有深度学习框架时，用纯 Python 精确求和就能做，这比跑一次训练看曲线更直接。

### 3.4 纯蒸馏分支：方向对，但整段替换掉了 PPO loss

纯蒸馏分支先算好了 PPO loss，然后用蒸馏 loss **整段覆盖**它。梯度方向是对的，但 PPO loss 里的保护一起被丢掉：

| 被绕过的东西 | 后果 |
|---|---|
| 比值裁剪 | 比值分母取推理端的行为 logprob 时，权重是 `exp(log π_θ − log π_behave)`；允许样本落后几个版本、再叠加训推数值差，罕见 token 上比值可能很极端（[离策略三来源](异步离策略的三个来源与IS和RS_20261019.md#32-异步为什么不是严格-on-policy三个来源)） |
| 拒绝采样（RS） | 配了上限也不生效 |
| ref KL 项 | 直接被丢 |
| 轨迹等权的 loss 权重 | 引擎按权重给 microbatch 加权，分支内部却按 token 平均，口径不一致 |

**更好的写法**：不另写一套 loss，把 `R_t = log π_T − log π_θ.detach()` 当作**逐 token 的优势**，交给已有的 PPO loss。比值、裁剪、拒绝采样、聚合权重全部复用；纯蒸馏与 joint 的差别也就只剩“优势里加不加 verifier 那部分”，与 [MOPD 混入任务优势](在线蒸馏OPD与多教师MOPD_20261026.md#34-mopd按领域路由的多教师) 的形式一致。

另一个小问题：joint 分支用 RL 权重乘整个 RL loss，**显式 ref KL loss 也被一起缩放**——改 RL 权重时，ref KL 的实际强度也悄悄变了。乘权重要乘在想缩放的那一项上。

### 3.5 只用当前 token 的奖励：一个常见近似

纯蒸馏分支每个位置只用 R_t，不把后面 token 的 R 累加进来。整条序列反向 KL 的完整梯度是（按因果性去掉过去项）：

```text
∇KL_seq = E[ Σ_t ∇log π_θ(o_t) · Σ_{t'≥t} (log π_θ(o_t') − log π_T(o_t')) ]
```

只用 R_t 相当于 reward-to-go 取 γ = 0：只让每个位置的分布向教师靠，不考虑“这个 token 会把后面带到教师更不认可的前缀上”。这是 KDRL 一类方法的常见近似（方差小、实现简单），不算 bug；但它和 [KL 进 reward 时“前面的 token 替后面的偏离买单”](KL估计器与放置位置的设计动机_20261015.md#31-用-4-个-token-看两种放法的差别) 是两种不同的信用分配（整理时补充的对照）。

### 3.6 教师与学生的兼容性：词表与温度

- **词表**：教师直接在学生的 token id 上取 logp。两边词表不一致时，结果不报错但没有意义。新一代模型常新增思考标记等特殊 token，id 可能超出旧一代教师训练过的词表范围，教师对它们的 logp 来自未训练的 embedding 行。这一条是根据两代词表的已知差异推断的，没有实际跑过；要在启动时校验，而不是靠“同一家族”的印象。
- **温度**：教师算 logp 默认用温度 1；学生的 logp 通常用采样温度。两者不同时，比较的是两个不同温度下的分布，R_t 带着系统偏差（与 [温度口径偏差](温度偏差实测与KL放置位置_20261015.md) 同类）。框架不自动同步也不告警，要显式写出教师温度。

### 3.7 可配置项的三类

**① OPD 专属：两个权重**

| 参数 | 作用 |
|---|---|
| RL loss 权重 | 既是分支开关（0 = 纯蒸馏），也是 RL loss 的权重 |
| 蒸馏权重 | joint 下是教师项相对 RL 的比重；纯蒸馏下只是整体缩放 |

**② 教师引擎：怎么加载、放在哪、怎么算**（教师只做一件事：对 rollout 结果算一次 logp）

| 类别 | 要点 |
|---|---|
| 权重路径 | 必须与学生共用 tokenizer，框架不校验 |
| 并行方式与精度 | 教师更大时通常要开 TP；精度一般跟 actor 一致 |
| 温度 | 不会自动和学生同步（§3.6） |
| 每个前向 microbatch 的 token 上限 | 教师更大时要调小防 OOM；长回答下会切出很多 microbatch |
| 卸载与共卡 | 默认独占卡；与 actor 共卡时通常要配合卸载，卸载还需要全局开关同时打开（[附加模型的显存编排](附加模型的显存编排与判分服务设计_20261026.md#31-共卡附加模型的初始化每个建完就卸)） |
| 优化器 | 保持为空：教师不训练，设了只会白占优化器状态显存 |
| dropout | 建议关闭，让教师 logp 确定 |
| 是否随机初始化 | 必须从权重加载，否则教师是随机模型 |

教师配置继承了整个 actor 配置：clip、KL 系数、奖励处理、优势归一化、拒绝采样、minibatch 个数、梯度检查点、LoRA 等字段写进去**语法合法，但都不生效**。配置继承带来的“看起来能配”要和“实际被读取”分开（与 [配置丢值看消费端](生成长度上限的意义与长跑对照的读数口径_20261023.md) 同一类问题）。

**③ actor 侧会影响蒸馏 loss 的参数**

| 参数类别 | 对 OPD 的影响 |
|---|---|
| 学生温度 | 要和教师温度一起考虑 |
| 比值分母取哪份 logprob（推理端行为 logprob / 训练端重算） | 纯蒸馏里重要性比值的分母 |
| 最大陈旧版本数 | 越大，纯蒸馏里比值偏离 1 越远，而这条分支不裁剪 |
| minibatch 个数 | 大于 1 时后面几个 minibatch 的比值偏离 1（[更新次数 = minibatch 个数](GSPO开关解耦与按轮序列比值_20261019.md#38-更新次数minibatch-与-micro-batch被纠正的说法)） |
| clip、RS | 只在 joint 分支经 PPO loss 生效 |
| ref KL 系数 | joint 下被 RL 权重一起缩放；纯蒸馏下被丢掉 |
| 轨迹等权的 loss 加权 | 纯蒸馏分支忽略 |
| 会修改 loss mask 的样本过滤 | 两个分支都受影响 |

在 joint 分支修好之前，想真正用上教师只能走纯蒸馏。

### 3.8 审查顺序与已核对的部分

当天的审查顺序可以复用：

1. 配置：有哪些字段、默认值是什么、默认走哪条分支；
2. 教师 logp 在哪里算、写进了哪个字段；
3. loss：每条分支对 θ 求导后**剩下什么**（detach 的项求导即消失）；
4. 位置对齐：教师 logp 与 ref / prox logp 是否同一种“位置 t 给 token t+1 打分”，有没有被重复移位；
5. 和其他配置组合：卸载、ref KL、拒绝采样、多次更新、轨迹加权；
6. 生命周期与观测：关闭时是否销毁教师、性能追踪是否覆盖教师阶段；
7. 有疑点时用小例子按精确期望做数值验证（§3.3）。

已核对、没有问题的部分：位置对齐正确（没有重复移位）；教师 logp 已 detach、没有优化器；卸载 / 加载顺序正确，打开卸载却没开全局开关会在启动时被拦下；两个权重经过拼接和 microbatch 切分后仍然保留；纯蒸馏的梯度方向正确。收尾遗漏：关闭时没有销毁教师、性能追踪漏了教师阶段。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 开了教师，曲线和普通 GRPO 几乎一样，步时却多了教师前向 | joint 分支的教师项 detach 后求导消失 | 换一个教师（或把教师换成学生自己）看梯度是否变化；小例子按精确期望算 |
| 纯蒸馏偶发梯度尖峰 | 整段替换 loss，比值不裁剪；陈旧样本 + 训推差让罕见 token 比值极端 | 统计纯蒸馏分支里比值的最大值、分位数 |
| 改 RL 权重后，ref KL 的读数也跟着变 | RL 权重乘在包含 ref KL 的整个 loss 上 | 看 ref KL 项实际进入 loss 时的系数 |
| 思考类特殊 token 上教师 R_t 异常 | 教师词表不含这些 token | 启动时比较两边词表大小与特殊 token 的 id |
| R_t 均值整体偏移 | 教师与学生温度不同 | 显式写出两边温度并对齐 |
| 教师配置里写了 clip / KL 等字段但没有任何效果 | 继承字段语法合法，教师从不进入训练 | 查这些字段是否被教师的代码路径读取 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| joint 和纯蒸馏是两套不同的配置（**当天的困惑**） | 同一个教师配置段，只靠“RL loss 权重是否为 0”切换 |
| loss 值的期望等于反向 KL，就等于在最小化反向 KL | 对 on-policy 样本要看梯度的期望；`log π_θ − log π_T` 直接进 loss 期望梯度为 0 |
| 教师项 detach 只是“不给教师传梯度” | 它在 loss 里变成常数，求导后整项消失；要靠 k2 或策略梯度形式把它变成系数 |
| k3 在 ref KL 里好用，教师也直接用 k3 | k3 进 loss 对应正向 KL；教师与学生差得远，方向差别不能忽略 |
| 纯蒸馏梯度方向对，就没问题 | 整段替换 loss 丢掉了裁剪、拒绝采样、ref KL 与轨迹加权 |
| 教师配置里能写的字段都会生效 | 继承来的训练字段语法合法但教师不训练，全都不生效 |
| 同一家族的教师和学生一定共用词表 | 新一代可能新增特殊 token，要在启动时校验 |

## 7. 一分钟复习

1. 两个分支 = 同一个教师配置段 + RL 权重是否为 0：0 → 纯蒸馏；> 0 → joint（RL + 拉向教师的正则）。
2. `log π_θ − log π_T`（教师 detach）直接进 loss → 梯度 `∇log π_θ` → on-policy 期望 0 → 教师不起作用（= k1 进 loss 的陷阱）。
3. 正确：`½(log π_θ − log π_T)²`（k2）或 `sg(R_t)` 当优势；期望梯度都是精确的 ∇KL(π_θ ‖ π_T)。k3 进 loss 是正向 KL。
4. k1 值无偏梯度 0；k2 值有偏梯度精确；k3 值无偏梯度反方向。
5. 检查：换教师梯度变不变；两个 token 手算 ±0.347 vs 0。
6. 纯蒸馏整段替换 loss → 绕过 clip / RS / ref KL / 轨迹加权 → 把 R_t 当逐 token 优势喂给已有 PPO loss。
7. 只用 R_t = γ = 0 的近似；词表与温度要显式校验；继承字段写了不生效。

## 8. 自测问题

### 问题 1

joint 分支把 `mean(log π_θ − log π_T)` 当 loss，log π_T 已 detach。为什么教师对梯度不起作用？

期望回答：log π_T 是常数，求导后消失，梯度只剩 mean(∇log π_θ)，与教师无关。样本由学生自己采样，E_{π_θ}[∇log π_θ] = Σ∇π_θ = ∇1 = 0，所以这项期望为 0，只是把采到的 token 的 logp 往下压的噪声。真正的反向 KL 梯度是 E[(log π_θ − log π_T)·∇log π_θ]，少了这个系数。

### 问题 2

给出两种能得到正确反向 KL 梯度的写法，并说明 k3 为什么不能直接搬过来。

期望回答：① loss = ½(log π_θ − log π_T)²，梯度 (log π_θ − log π_T)·∇log π_θ；② R_t = log π_T − log π_θ detach 后当优势，loss = −R_t·log π_θ（或乘比值），梯度相同。两者在 π_θ 下的期望都等于 ∇KL(π_θ‖π_T)。k3（r = π_T/π_θ）进 loss 的梯度 (1 − r)∇log π_θ，期望是 ∇KL(π_T‖π_θ)，是正向 KL；ref 与学生很接近时方向差别小，教师与学生差得远时差别不能忽略。

### 问题 3

学生 π_θ = (0.5, 0.5)，教师 π_T = (0.8, 0.2)。分别算 k1 进 loss 与 k2 进 loss 对 z_a 的期望梯度；把教师换成 (0.2, 0.8) 后又如何？这说明了什么检查方法？

期望回答：∇log π(a) = +0.5，∇log π(b) = −0.5。k1：0.5·0.5 + 0.5·(−0.5) = 0。k2：c_a ≈ −0.470、c_b ≈ +0.916，期望 ≈ 0.5·(−0.470)(0.5) + 0.5·(0.916)(−0.5) ≈ −0.347，与真实 ∇KL 一致。换教师后 k2 ≈ +0.347，k1 仍为 0。检查方法：换一个教师，梯度不变就说明教师没进梯度；小词表上可以按精确期望直接算。

### 问题 4

纯蒸馏分支梯度方向是对的，为什么仍然有问题？怎样改更好？

期望回答：它用蒸馏 loss 整段覆盖了 PPO loss，比值裁剪、拒绝采样、ref KL 项和轨迹等权的 loss 权重都被绕过。比值分母取推理端行为 logprob、又允许样本陈旧时，罕见 token 上比值可能很极端而不被裁剪。更好的写法是把 R_t = log π_T − log π_θ（detach）当逐 token 优势交给已有 PPO loss，复用全部保护。

### 问题 5

接一个新教师做 OPD 前，至少要显式确认哪三件事？

期望回答：① 教师与学生词表一致（含新增的特殊 token，id 不能超出教师词表）；② 教师温度与学生 logp 的温度对齐，框架不会自动同步；③ 教师只做前向：优化器为空、关 dropout、从权重加载而不是随机初始化。另外记住教师配置里继承来的训练字段不生效。

## 9. 尚未解决与后续路线

- joint 分支改成 k2 或优势形式后，RL 权重与蒸馏权重怎么定，与纯蒸馏的效果对比（接着 [10 月 26 日 §9](在线蒸馏OPD与多教师MOPD_20261026.md#9-尚未解决与后续路线)）；
- 只用 R_t（γ = 0）与 reward-to-go 形式的反向 KL 在长回答上的方差与效果差别；
- 词表不一致的教师能否对齐（截断到公共词表、映射 id），以及词表差异推断的实测确认；
- 教师温度该取 1 还是学生采样温度，取决于想蒸馏的是哪个分布。
