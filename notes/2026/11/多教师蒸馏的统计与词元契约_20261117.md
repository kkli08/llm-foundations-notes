## 0. 今天最终要解决的问题

用户先要求别逐项抛补丁，要按人的理解顺序解释全链路；随后问“分域归一化是每个领域按 token 吗”，最后问“考虑师生 Tokenizer 不同了吗”“除损失和 Tokenizer 之外还需要什么”。

## 1. 先给结论

- 从样本一路跟到参数更新，路由、token 身份、概率版本和统计权重都不能丢。
- 分域统计要明确总体；统计有效生成 token，不等于每个微批单独标准化，也不等于最终各域梯度相等。
- 对同一 token 直接相减 logprob，要求该 token 和上下文在师生两边语义一致。词表大小相同或模型同家族都不够。
- 异构 Tokenizer 需要重新定义比较事件与信用分配，不是只改一个 loss 开关。

## 2. 前置概念

一个“概率位置”至少包含：前缀、被预测 token、所属样本、教师、模型版本、温度等概率变换。数组长度相同只能证明形状兼容。

统计总体也要分清：当前优化批次、其中某个域的有效生成 token、实际 loss 使用的权重。统计采用 token 等权而 loss 采用序列等权可以是一种设计，但必须明确，不能误称二者一样。

## 3. 完整原理

### 3.1 先把全链路串起来

| 阶段 | 产物 | 进入下一阶段前要保持的语义 |
|---|---|---|
| 选样与标域 | 输入、域标识 | 提交配比与任务身份 |
| 学生生成 | token、行为概率、版本 | 哪些位置属于可训练回答 |
| 教师评分 | 教师身份、逐位置分数 | 同一上下文、token 与样本归属 |
| 组批与算损失 | 对齐后的张量、统计量 | 有效 mask、分母、求导路径 |
| 参数更新与发布 | 新学生参数及版本 | 数值检查成功后才发布 |
| 分域观测与固定评测 | 训练读数、独立效果 | 各域样本/token 占比与任务质量分别量 |

这是一张阅读地图，不是完整系统只有六个模块的断言。恢复训练还需还原或重新确认教师版本、路由和算法设置；教师没有优化器状态，不代表相关配置不必记录。异步汇合与入训配比详见[11 月 16 日笔记](异步教师打分的汇合与资源回收_20261116.md)，这里不重复其调度和清理机制。

### 3.2 分域归一化究竟统计什么

取本步一个固定参考概率版本，计算原始教师信号 a。对域 d 的有效生成位置集合 I_d，定义：

`N_d = |I_d|`，`μ_d = Σ a / N_d`，`σ_d² = Σ(a−μ_d)² / N_d`。

摘录讨论的一种设计是只缩放：`a′ = w_d a`，其中

`w_d = clip(σ_all / max(σ_d, ε), w_min, w_max)`，最后再对 a′ 做优势限幅。

这应当标为明确的算法选择：用哪个参考版本、统计是否包含全部域、ε 和上下界、空域及样本不足如何处理，均需约定。本批未找到足以确认摘录所称特定论文公式的原始依据，因此不保留论文归属或把其数字当通用默认值。

正数缩放保持 a 的符号；若再减经验域均值，一些 token 会翻号。但不能由此推出“任何 baseline 都错误”：在无裁剪的标准策略梯度中，与动作无关的 baseline 可以不改期望梯度；从本批样本估计基线、分域加权和裁剪组合的性质要另行分析。

### 3.3 相对缩放保留什么，又不能保证什么

若所有 a 同时乘一个正数 c，各标准差也同乘 c；在 ε 不主导时，`σ_all/σ_d` 不变。它保留了整体信号随训练缩小的趋势。各域标准差若本来不同，比值不必趋于 1，也不能仅凭此保证收敛。

先缩放再限幅，才把限幅施加在最终信号上；先限幅后乘 w，最终幅度可能再次超过原上限。两种顺序是不同算法。

“各域信号标准差相近”也不等于“各域贡献相同”：token 数、序列权重、`∇log p` 的大小与方向、裁剪激活比例仍会改变最终梯度。一个域整批没有样本时，不得用除零或任意统计量伪造该域贡献。

### 3.4 微批切分不应偷偷改变统计规则

若目标是整批域统计，不能每个 microbatch 各算一个 σ 后直接平均。各 rank 可汇总计数、和与平方和，或合并更稳定的均值/方差统计，再得到同一组固定缩放系数。平方和法存在相消误差，实际实现要关注累计精度。

只在持有互不重复样本的并行维度计数；不能把模型并行复制的同一 token 再算一次。集合通信的调用次数和顺序必须在参与 rank 间一致：各 rank 的轨迹数可能不同，把 all-reduce 放入逐轨迹循环会产生不匹配。整批统一汇合后调用，是一种清晰安排。

验证时固定同一批数据与权重，改变 microbatch 切分，检查统计量、损失分母和总梯度的容限一致性。这是验证口径，不声称本批已做多卡实测。

### 3.5 Tokenizer 不一致有两层错误

第一层是 ID 语义：相同整数可以指不同 token，甚至在教师词表内合法但含义错误。第二层是分段：相同文本可能一边一个 token、另一边多个 token，数组位置不再对应同一预测事件。

词表只是 Tokenizer 的一部分；归一化、预切分、分词模型和特殊 token 后处理也影响编码。[Hugging Face Tokenizer 流水线文档](https://huggingface.co/docs/tokenizers/python/latest/pipeline.html)列出了这些阶段。因此兼容检查应覆盖完整编码资产与特殊 token 语义，同时核对传给模型的实际上下文、对话模板与 mask；固定样本文本编码一致是回归样例，不是对所有输入等价的证明。

### 3.6 解码、重切词、概率相加之后还剩什么问题

设教师把一个文本片段切成 u₁、u₂，则链式法则给出：

`log q(u₁,u₂ | h) = log q(u₁ | h) + log q(u₂ | h,u₁)`。

这是**该指定 token 路径**的概率，不自动等于所有能解码成同一字符串的路径总概率，也不自动变成学生单个 token 的条件概率。若要做字符或字节片段对齐，还需明确：

1. 师生比较的公共文本事件与前缀边界；
2. Unicode、空白和特殊标记的处理；
3. 一对多或多对多的片段损失怎样分配回学生 token；
4. 不可逆解码、超长重切词和无法对齐样本如何处理。

教师生成文本、再由学生 Tokenizer 重编码做 SFT，可以避开直接逐 token 概率相减，但它改变了训练目标和数据来源。跨词表分布对齐则需要更多信息；不能把“支持混合 Tokenizer”包装成纯 loss 配置变更。

## 5. 工程中的具体表现

| 现象 | 可能原因 | 如何验证 |
|---|---|---|
| 只改微批大小，分域权重就变 | 统计范围随微批变化 | 固定整批重分片 |
| 换教师后无报错却打分异常 | ID 合法但编码语义不一致 | 比对完整编码资产与边界样例 |
| 各域 σ 相同，仍有一域主导 | token 数、权重或梯度方向不同 | 分别记录统计与梯度贡献 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 按域归一化就是每句各除自己的 σ | 先定义整批、域和有效位置的统计集合 |
| 同家族模型必然同 Tokenizer | 需核对具体版本和完整编码行为 |
| 多个 logprob 相加就完成异构蒸馏 | 只得到指定路径概率，目标与信用分配仍需设计 |

## 7. 一分钟复习

1. 沿样本流检查域、身份、位置、版本、mask 和权重。
2. 分域统计跨微批保持统一，通信按一致的集合调用执行。
3. 同词表大小不够；异构 Tokenizer 先定义相同文本事件。

## 8. 自测问题

### 问题 1

各 rank 轨迹条数不同，为什么不能在每条轨迹后做一次 all-reduce？

期望回答：集合通信要求参与者匹配调用，各自循环次数不同可能使一部分 rank 等不到对应调用；需要在共同批次边界汇总。

### 问题 2

相对标准差缩放能保证各域梯度等大吗？

期望回答：不能。它只调节信号尺度；token 数、loss 权重、策略梯度与裁剪仍不同。

### 问题 3

教师两个 token 的 logprob 之和代表什么？

期望回答：给定前缀下这条特定 token 路径的联合概率之对数；不是自动得到字符串所有分词路径的总概率。
