## 1. 先给结论

- **critic 算价值不生成任何东西**：把 rollout 回来的整行（prompt + 回答）原样送进 critic，不求梯度做一次前向，每个 token 位置输出一个数 V(s_t)，表示“写到这里，预计最后能拿多少分”。
- **GAE 就是逐 token 算相对优势**（用户对）；“相对”的对象是 critic 在这个位置的预期 V，不是同组其他回答的平均分。所以每个 token 的 A 不同，GRPO 里一整条回答共用一个 A。
- **critic 的拟合是回归**：目标是 returns G_t = A_t + V_t，用 MSE 让 V 逼近 G，带 value clip 限制同一批数据上一次改太多。
- **被纠正的两点**：目标是 G，不一定是 R（λ < 1 时 G 里混进了 critic 自己的估计，即 TD 学习）；更新的是整个 critic（主干 + 价值头），不只是价值头。
- **MSE 的最小点是均值**：同一前缀上 8 条回答、3 条答对，critic 在这个位置被拉向 3/8 = 通过率——恰好是 GRPO 的组内均值，但 critic 是跨题学出来的，还能在回答中间每个位置给值。
- **γ = 未来奖励每步打几折**：只有末端奖励时 γ < 1 等于惩罚长回答，LLM RL 通常取 1。**λ = 信结果还是信 critic**：λ = 1 只看最终结果（无偏、高方差），λ = 0 只看这一步让 V 变了多少（低方差、全靠 V）。critic 刚初始化时 V 不可信，先用 λ = 1。
- **给框架加 critic，算法链路通常现成，风险在工程闭环**：分布式模型换价值头必须在 DDP 包装之前、各 rank 初始化要一致；断点恢复要加载 critic、指标要导出、关键配置要校验；截断标记要逐行导出。

## 2. 前置概念

### 2.1 PPO 一步的七个环节

（完整九段与 GRPO 的差别见 [10 月 13 日 §2.3](PPO的Critic与Clip在单次更新下的退化_20261013.md#23-ppo-一步的九段流程)。）

| # | 环节 | 做什么 |
|---|---|---|
| 1 | Rollout | 推理引擎用当前版本权重生成；每个 token 记下采样 logprob（π_behave）、版本号、是否参与训练（loss mask）；每条轨迹一个标量分 R；版本落后太多的被拒 |
| 2 | critic 算价值 | 对每个 token 位置输出 V(s_t)，训练时现算，rollout 不带 |
| 3 | 重算 logp | ref 给出 π_ref（用于 KL）；actor 用当前参数重算 π_prox（clip 锚点） |
| 4 | GAE | 逐 token 奖励（每个位置 −β·KL_t，末 token 再加 R）→ 从后往前递推 A_t → returns G_t = A_t + V_t → A_t 再做批级白化交给 actor |
| 5 | actor 更新 | 切 k 个 minibatch，各一次 step；`max(−A·r, −A·clip(r))`，开了 RS 再乘 π_prox/π_behave |
| 6 | critic 更新 | 同样切 k 个 minibatch；value loss 带 value clip |
| 7 | 权重同步 | 只把 actor 同步给推理引擎，版本 +1；critic 只在训练侧用 |

GRPO 没有第 2、6 步（V ≡ 0），baseline 来自组内归一化；其余步骤两者一样（[GRPO = 配置出来的 PPO](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#22-grpo-就是配置出来的-ppo)）。

### 2.2 GAE 的两个公式

$$
\delta_t = r_t + \gamma V_{t+1} - V_t,\qquad A_t = \delta_t + \gamma\lambda\,A_{t+1}
$$

δ_t 的含义：“这一步之后的局面”比“这一步之前的局面”好了多少。展开即 $A_t = \delta_t + (\gamma\lambda)\delta_{t+1} + (\gamma\lambda)^2\delta_{t+2} + \cdots$。

## 3. 完整原理

### 3.1 critic 怎么算价值

- **结构**：和 actor 相同的 Transformer，通常从 actor 的权重初始化；唯一区别是输出头——actor 映射到词表大小（下一个 token 的分布），critic 换成只输出 1 个数的线性层 `Linear(hidden, 1)`（价值头）。HF 生态里常用“num_labels = 1 的 token 分类模型”实现同一件事。
- **算法**：在 rollout 结束、本轮更新之前，用 critic 当前参数对整行做一次 `no_grad` 前向；一行有多少 token 就有多少个 V。
- **含义**：因果注意力下，位置 t 的隐状态只看得到第 t 个 token 及之前的内容，所以 V(s_t) = “已经写到这里了，预计最后能拿多少分”。

### 3.2 用 4 个 token 走一遍 GAE（λ = γ = 1，不考虑 KL）

一道数学题，回答 4 个 token，答对，R = 1：

| | token 1 | token 2 | token 3 | token 4 |
|---|---|---|---|---|
| critic 给的 V | 0.4 | 0.7 | 0.8 | 0.9 |
| advantage A = R − V | 0.6 | 0.3 | 0.2 | 0.1 |
| returns G = A + V | 1 | 1 | 1 | 1 |

- V 从 0.4 起步：critic 认为这类题大约四成能做对；写得越接近正确答案，V 越高；
- 还没把握时走对了，A 大；已经很有把握的地方，A 小——这就是“相对于 critic 预期”的优势；
- λ < 1 时 A 会集中在 V 发生变化的那几个 token 上（§3.6），这就是信用分配。

两个边界规则：

- **跨工具段**：递推时跳过 loss mask = 0 的位置（工具输出），所以多轮轨迹里每一轮的结尾接上下一轮开头的 V；
- **末端**：正常结束时后面接 0；被截断时接这一行最后一个 token 的 V（要靠逐行的截断标记才判断得准，[截断 ≠ 结束](训练口径的隐性错误与读数签名_20261019.md#31-截断判定为什么会变成最长那一行)）。

returns 在批级白化**之前**算出：critic 拟合的是未白化的 G，actor 用的是白化后的 A。

### 3.3 critic 怎么拟合、为什么要拟合

**拟合什么**：目标是上表最后一行 G。γ = λ = 1 且没有 KL 时 G 就是这一行最后拿到的分 R，所以 critic 做的是回归——给定前缀，预测最终得分。

**怎么做**：

$$
L_V = \tfrac12\max\Big((V_\text{new}-G)^2,\ \big(V_\text{old}+\text{clip}(V_\text{new}-V_\text{old},-c,c)-G\big)^2\Big)
$$

- V_old 是 §3.1 在更新前算出的那份 V；对所有有效 token 求平均后反传；
- 和 actor 一样切成 k 个 minibatch，各做一次 optimizer step；
- **value clip**：V_new 相对 V_old 的变化超过 ±c 后，取 max 会选中被截断那一项，它对 V_new 没有梯度，于是停止继续移动。效果是同一批数据上 critic 一次不要改太多，和 actor 的 PPO clip 同一思路。例：c = 0.5 时，V_old = 0.4、G = 1 的位置这一轮最多被拉到 0.9 附近，不会一步跳到 1。

**一次更新的梯度**：只看一个位置，V_old = 0.4、G = 1，loss = ½(V − 1)²，dL/dV = V − 1 = −0.6，梯度下降把 V 往上推；每步推多少由学习率决定。几百步之后，V 逼近“从这个位置出发的平均得分”。

**为什么要拟合**：A = R − V 要有意义，V 必须接近从这一步出发的真实平均得分。V 准了，运气好碰巧答对的回答在 V 本来就高的位置只拿到很小的 A——advantage 的噪声变小，这就是 baseline 降方差的作用。

**用户的理解与校正**：“用 R 和 V 做 MSE、更新 value head 参数”基本对，补两点：

| 用户的说法 | 更准确的说法 |
|---|---|
| 目标是 R | 目标是 G_t；γ = λ = 1 时恰好等于 R；λ < 1 时 G_t 里混进了 critic 自己对后面的估计，相当于用自己的预测教自己（TD 学习） |
| 只更新 value head | 主干和价值头一起训练；主干也会学会抓取“这道题能不能做对”相关的特征 |

### 3.4 为什么 V 会学成“做对的概率”

一道题采了 8 条回答，3 条答对。看所有回答共享的那个位置——题目刚读完、还没开始作答。8 条回答在这里输入完全一样，critic 只能输出同一个 V，而 8 个目标是 1, 1, 1, 0, 0, 0, 0, 0：

$$
\min_V \tfrac12\sum_i (V-G_i)^2 \ \Rightarrow\ V = \bar G = 3/8 = 0.375
$$

critic 在这个位置被拉向这道题的通过率——恰好是 GRPO 的组内平均分。区别：

| | GRPO 组均值 | critic 的 V |
|---|---|---|
| 怎么得到 | 每次现场对同一题采一组回答 | 在所有题、所有回答上一起学出来，能泛化到没见过的题 |
| 在哪些位置有值 | 每条回答只有一个 | 回答中间每个位置都有，表示“写到这里还有多大把握” |
| 需要什么 | G 条同题回答 | 不需要分组 |

后一行正是 λ < 1 能把错误定位到具体 token 的前提。

### 3.5 γ：未来的奖励打几折

$$
G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots
$$

- γ = 1：不打折，最后拿到的 R 原样算到每个 token 头上；
- γ < 1：离结尾越远的 token 分到的越少。例：γ = 0.999、回答长 1000 个 token，第一个 token 的目标只剩 0.999¹⁰⁰⁰·R ≈ 0.37R。

奖励只在结尾给一次时，γ < 1 等于惩罚长回答，开头的 token 也因为离结尾远而被轻视，所以 LLM 的 RL 通常取 γ = 1（与 [KL 进 Reward 的长度效应](AgentRL的Reward崩溃与归因实验_20261009.md#33-可疑诱因kl-进-reward--γλ1-的隐式长度惩罚假设) 是两件事：那里是逐 token 的 KL 惩罚被累加）。

### 3.6 λ：信结果，还是信 critic

同一条**答错**的回答（R = 0），V 依次为 0.4、0.7、0.2、0.1（示例：token 1 让局面变好，token 2 写错了）：

| λ | 公式 | token 1 | token 2 | token 3 | token 4 | 优缺点 |
|---|---|---|---|---|---|---|
| 1 | A_t = R − V_t | −0.4 | −0.7 | −0.2 | −0.1 | 全是负数，把局面变好的 token 1 也被扣分；不依赖 V 准不准（无偏），但 R 本身噪声大（高方差） |
| 0 | A_t = r_t + V_{t+1} − V_t | +0.3 | −0.5 | −0.1 | −0.1 | 问题被定位到 token 2；方差低、信用分配准，但完全依赖 V，critic 不准时信号也是错的 |
| 0～1 | 两者加权，常用 0.95 左右 | 介于两者之间 | | | | 长序列下 λ = 0.95 衰减太快，见 [10 月 13 日 §3.5](PPO的Critic与Clip在单次更新下的退化_20261013.md#35-ppo--gae-能否比-grpo-更好地分配功劳) |

（λ = 0 时末 token 的 V_{t+1} 取 0，r_t = R = 0，所以 A_4 = −0.1。）

**起步取 λ = 1 的理由**：critic 刚初始化时价值头是随机的，V 不可信，λ < 1 会把这些噪声直接当成信号。等 critic 学得比较准再试 0.95。判断“比较准”的指标是 **explained variance**：

$$
\text{EV} = 1 - \frac{\mathrm{Var}(G - V)}{\mathrm{Var}(G)}
$$

EV ≈ 0 说明 V 不比一个常数好；明显大于 0 才说明 critic 学到了东西；为负说明比常数还差。

### 3.7 给 RL 框架加 Critic：算法几乎现成，工程闭环要补

用户的最后一问。按 §2.1 的七个环节逐个看，一个已有 GRPO 的框架通常是这样：

| 环节 | 通常已经有 | 通常要补 |
|---|---|---|
| 1. Rollout / 导出 | 一行一个 episode、末端标量 reward、工具段 mask 为 0、版本号 | 逐行的截断标记（GRPO 用不到，PPO 必需） |
| 2. critic 算价值 | 训练循环里自动调用 critic 前向；FSDP 侧的价值头 | **分布式后端的价值头能否真正建起来**（下文） |
| 3. ref / 重算 logp | 全部现成 | KL 系数 > 0 时必须配 ref 的校验 |
| 4. GAE | 带 value 的 GAE、returns、跨工具段跳过、批级白化 | explained variance 指标 |
| 5. actor 更新 | 和 GRPO 同一套 | 无 |
| 6. critic 更新 | value loss、value clip、minibatch、全局归一化 | 无 |
| 7. 权重同步 | 只同步 actor | 无（critic 不同步，所以与同步相关的检查对它不适用） |
| 循环之外 | critic 的创建、共卡、offload、保存 | 恢复时加载 critic、critic 指标导出、配置校验 |

**唯一的大改：在已包装好的分布式模型上换输出头**。读代码发现的三个问题都有通用性：

1. **找不到要换的层**：换头前要从包装里找到真正的语言模型。解包函数如果只认一种包装属性（例如只沿 `.module` 往下找），遇到多模态模型把语言模型挂在另一个属性下时就会报错；保存/加载价值头也复用这个函数，会一起出错。
2. **换的时机**：先用 DDP 包装、再把词表头换成价值头，新参数**不在 DDP 的梯度 buffer 和优化器的参数列表里**——要么直接报错，要么价值头根本不更新。修法：在模型创建的回调里换（发生在包装之前），并加一条启动断言“价值头参数在梯度 buffer 内”。
3. **各 rank 初始化不一致**：价值头随机初始化，各 rank 种子不同、事后又不广播，TP/DP 各 rank 上的价值头就不一样。修法：固定种子初始化，或初始化后广播。

另外两条加载细节：critic 从 actor 权重初始化时，加载要跳过词表头（`lm_head`）；价值头若有单独保存的权重再额外加载。输入落在 SP 区域的价值头，其梯度要在 TP 组内求和（[复制参数的梯度](PP_CP_SP的切分对象与通信代价_20261009.md#38-sp-补充传的是激活值不是参数)）。

**三处小补丁**：

- **断点恢复**：保存时存了 critic、加载时只加载 actor，恢复后 critic 回到初始权重（[恢复要存全部训练状态](RL断点恢复与训练故障的归因边界_20261014.md#21-两种checkpoint)）；
- **指标**：critic 跑在独立 worker 里，如果上报只汇总 actor 与 rollout 的统计，critic 的 loss、EV 在实验面板上就看不到；
- **配置校验**：“这是 critic”的开关默认关且不检查时，忘了写就会静默建出一个语言模型头；KL 系数 > 0 却没有 ref 时，读代码看 KL 惩罚会悄悄变成正向奖励（机制细节未核实）；critic 不支持的并行方式（如 PP > 1）或附加模块（如 MTP）应直接报错。

**配方取舍**（让对照只差 critic 一个变量）：γ = λ = 1 起步；去掉组内 reward 归一化（baseline 改由 critic 提供），保留批级 advantage 白化；KL、minibatch 个数、clip 与 GRPO 基线相同；critic 从 actor 权重初始化、与 actor 共卡并 offload，学习率取常见默认 1e-5。

**验证顺序**：上面三个问题都来自读代码，先跑一个只建 critic、单机、小模型、无外部打分依赖的 GPU 冒烟，确认价值头建得起来、会更新、指标能导出，再上大配方端到端。冒烟里第一次 offload 才暴露的错误（offload 选项走到一条已被关闭的实现路径）也说明：初始化成功不等于第一步能跑完，观察窗口要覆盖到第一个训练步结束。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| critic 建模型时报“找不到输出层” | 解包函数不认识多模态包装的属性 | 打印模型的包装层级 |
| critic 能跑但 loss 不降、价值头权重不变 | 价值头在 DDP 包装之后才换上，不在梯度 buffer / 优化器里 | 启动时断言价值头参数在梯度 buffer 内；比较两步间价值头权重 |
| 不同 rank 的 V 对同一输入不一致 | 价值头随机初始化种子不同、未广播 | 各 rank 打印价值头权重校验和 |
| 断点恢复后 EV 掉回 0 附近 | 恢复只加载了 actor | 查恢复时加载的模型列表 |
| 面板上看不到 critic loss | critic 统计没汇总到上报 | 查导出统计的来源 |
| EV 长期 ≈ 0 却把 λ 调到 0.95 | V 还是噪声，λ < 1 把噪声当信号 | 先看 EV 明显 > 0 再改 λ |
| 真截断的行价值目标异常 | 截断按最长行判断，bootstrap 用错 | 逐行比对截断标记与 bootstrap 位置 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| critic 算价值要生成文本 | 只对已有整行做一次 no_grad 前向，每个位置一个 V |
| GAE 的“相对优势”是相对同组其他回答 | 相对 critic 在该位置的预期 V |
| critic 拟合的目标就是 R | 是 G_t；γ = λ = 1 时才等于 R |
| 拟合只更新价值头 | 主干和价值头一起更新 |
| value clip 是裁剪 V 的取值范围 | 限制 V 相对更新前 V_old 的变化量 |
| γ 小一点更稳 | 只有末端奖励时 γ < 1 惩罚长回答、轻视开头 token |
| λ 越小信用分配越准，所以越小越好 | 前提是 V 准；critic 刚初始化时 λ < 1 是在放大噪声 |
| 有了 critic 就不需要关心截断 | 有了 critic 才必须逐行判截断 |
| 价值头随时换上去就行 | 必须在 DDP 包装之前换，且各 rank 初始化一致 |

## 7. 一分钟复习

1. critic = 同主干 + `Linear(hidden, 1)`；整行 no_grad 前向，每个位置一个 V = “写到这里预计得多少分”。
2. δ_t = r_t + γV_{t+1} − V_t，A_t = δ_t + γλA_{t+1}；returns G = A + V（白化前算）；跳过工具段，截断行接末位 V。
3. GAE = 相对 critic 预期的逐 token 优势；GRPO 一条回答共用一个 A。
4. critic 拟合：½(V − G)² 的 MSE + value clip（相对 V_old 最多变 ±c）；整个 critic 一起更新；λ < 1 时是 TD 学习。
5. 同一前缀多条回答 → MSE 最小点 = 均值 = 通过率 = GRPO 组均值；critic 能泛化、每个位置都有值。
6. γ：未来打折，只有末端奖励时 γ < 1 = 长度惩罚 → 取 1；λ：1 = 信结果（无偏高方差），0 = 信 critic（低方差有偏）；EV 明显 > 0 前先用 λ = 1。
7. 加 critic：算法现成；换头要在 DDP 包装前、各 rank 初始化一致、加载跳过词表头；恢复加载 critic、指标导出、配置校验；先单机冒烟。

## 8. 自测问题

### 问题 1

critic 的 V 在一行里有几个？为什么位置 t 的 V 能解释成“写到这里预计得多少分”？

期望回答：一行有多少 token 就有多少个 V（每个位置一个）。因果注意力下位置 t 的隐状态只看得到第 t 个 token 及之前的内容，价值头把这个隐状态映射成一个数，所以它只能是基于当前前缀的最终得分预测。

### 问题 2

手算：R = 1，V = [0.4, 0.7, 0.8, 0.9]，γ = λ = 1，不考虑 KL。写出 A 和 G，并说明 critic 这轮的目标是什么。

期望回答：A = [0.6, 0.3, 0.2, 0.1]，G = [1, 1, 1, 1]。critic 用 MSE 把每个位置的 V 往 1 推，value clip 限制每个位置相对 V_old 最多变 ±c。

### 问题 3

同一道题 8 条回答、3 条答对，critic 在“题目刚读完”的位置会学成多少？它和 GRPO 有什么关系、有什么不同？

期望回答：MSE 最小点是目标均值 3/8 = 0.375，即通过率，等于 GRPO 的组内均值。不同在于 critic 跨题学习、能泛化，不需要每次采一组；而且回答中间每个位置都有 V，可以做 token 级信用分配。

### 问题 4

R = 0，V = [0.4, 0.7, 0.2, 0.1]。分别用 λ = 1 和 λ = 0 算 A，说明两者各自的问题。

期望回答：λ = 1：A = [−0.4, −0.7, −0.2, −0.1]，把局面变好的 token 1 也扣分，方差高但无偏。λ = 0：A = [+0.3, −0.5, −0.1, −0.1]，把错误定位到 token 2，但完全依赖 V，V 不准时信号也错。

### 问题 5

γ = 0.999、回答长 1000 token、只有末端奖励，第一个 token 的目标约是多少？为什么 LLM RL 通常取 γ = 1？

期望回答：约 0.37R。γ < 1 等于惩罚长回答，开头 token 因为离结尾远而被轻视；奖励只在结尾时这不是想要的行为。

### 问题 6

在一个已经用 DDP 包装好的模型上把词表头换成价值头，会出什么问题？怎么改？

期望回答：新价值头不在 DDP 的梯度 buffer 和优化器参数列表里，可能报错，最好情况也是价值头不更新；各 rank 的随机初始化还可能不一致。改为在模型创建回调里、包装之前换头，固定种子或广播初始化，并加启动断言检查价值头在梯度 buffer 内。

## 9. 尚未解决与后续路线

- critic 在真实数学任务上的 EV 曲线、多久能明显大于 0，以及何时把 λ 从 1 调到 0.95；
- PPO 与 GRPO 只差 critic 的同条件对照尚未完成；
- 多轮任务每轮一行布局下的行末 bootstrap 与轮间奖励传播（见 [同日 §3.6](异步训练下的Minibatch个数与解耦PPO来源_20261020.md#36-按轮比值与-ppo按轮比值无关一行是什么关系最大)）；
- KL 系数 > 0 且无 ref 时 KL 项为何会变成正向奖励，需对照实现核实；
- value clip 的阈值 c 与奖励尺度的关系（奖励在 0/1 时 c = 0.5 已经很宽）。
