# 视频扩散训练与 Transformer 结构

> 知识归属：2026-09-18～20；2026-10-10 补录。适用范围：从 LLM 训练转向 FastVideo 与 Wan2.2 视频训练时需要的最小模型。公式中的尺寸与数值均为教学示例，不是实验配置。

## 一分钟复习

视频模型也能使用 Transformer，但 Token 往往是视频 latent 的小块，不是文字词元。DiT 在一次前向里处理一整段带噪 latent，预测去噪方向；训练时比较预测与目标并反向传播，生成时由采样器多次调用模型逐渐去噪。一次优化器更新、一次去噪迭代和训练配方的一个阶段，是三个不同的“步”。

## 1 从你熟悉的 LLM 接过来

你之前理解的 Transformer 可以继续用：输入先成为 hidden states，每一层 Attention 让不同位置交换信息，FFN 在各位置加工表示，残差把修正加回原表示。改变的是输入与输出的含义，而不是“用了 Transformer 就必须逐字生成”。

| 对象 | 自回归文字模型 | 这里讨论的视频扩散模型 |
|---|---|---|
| 输入 Token | tokenizer 产生的离散 ID | latent 被切成小块后投影出的向量 |
| 一次前向 | 为下一个文字 Token 提供分布 | 为许多视频位置同时预测去噪方向 |
| 最后输出 | LM Head 产生词表 logits | 输出投影还原 latent patch 的预测量 |
| 生成迭代 | 追加离散 Token | 更新同一段连续 latent |
| 训练目标 | 常见为下一个 Token 的交叉熵 | 这里以速度预测的平方误差说明 |

不是所有视频模型都采用完全相同的目标或 Attention mask；这个表服务于当前视频扩散路径，不是给所有生成模型分类。

## 2 视频怎样变成一串 Token

先把视频编码成低维 latent。VAE 可以理解为学出来的压缩和解压器：编码器把像素压成更小的张量，解码器把最终 latent 还原为像素。随后把 latent 在时间和空间维度切成小块，每块投影成一个 hidden 向量。

教学示例：latent 有 4 个时间位置，每个位置有 8×8 个空间格子；每 2×2 个格子组成一个 patch，时间方向暂不再切。这样产生 `4 × 4 × 4 = 64` 个 Token。每个 Token 描述一个时空小区域，不是一整帧，也不是一个词。

一般地，整除条件下 Token 数为：

$$
N = (T/p_t)(H/p_h)(W/p_w)
$$

这里的 T/H/W 是 latent 尺寸，p 是 patch 尺寸。原视频帧数不能直接当成 Transformer 序列长度，因为 VAE 与 patchify 都可能改变尺寸。Wan2.2 的公开实现包含视频 VAE 与 Transformer 路径；不同规格不要混用，尤其不能把 14B 家族的专家设计自动套到 5B 模型上。[Wan2.2 官方仓库](https://github.com/Wan-Video/Wan2.2)

## 3 带噪训练到底在学什么

用最容易理解的直线路径举例。设 x 是干净 latent，ε 是随机噪声，σ 是噪声混合比例：

$$
x_\sigma=(1-\sigma)x+\sigma\varepsilon,\qquad
v^*=\varepsilon-x
$$

模型接收带噪输入 xσ、噪声级别 σ 和条件，预测速度 vθ。一个简化的训练损失是：

$$
L=\operatorname{mean}\left[(v_\theta(x_\sigma,\sigma,c)-v^*)^2\right]
$$

例如只看一个标量：干净值 x=2，噪声 ε=10，σ=0.25，则带噪输入为 4，目标速度为 8。这里的减号是相减：模型学的是沿这条路径变化的方向和幅度，不是把数字 8 当成自然语言答案。

因为这条路径从干净数据走向噪声，生成时通常从噪声端向干净端积分。教学用 Euler 写法是 `x_next ≈ x_now + Δσ · vθ`，此时 Δσ 为负；实际采样器可能采用更高阶算法、不同时间参数化或预处理，不能把这条简式当作所有实现的精确更新代码。

训练通常随机取噪声位置来学这一方向，并不意味着每个训练样本都必须跑完生成时的全部去噪迭代。

## 4 两个时间别混在一起

视频时间回答“这块内容在第几帧附近”；扩散时间回答“这段 latent 现在有多少噪声”。一段带噪视频里，所有帧可能共享同一噪声级别，也可能按配方使用不同条件。它们不是同一个轴。

噪声级别经过条件网络后，可生成 scale、shift、gate 来调制 hidden。若某条件在同一帧内不变，可以先按帧算出条件，再广播到该帧的空间 Token；无需每个 Token 都重复运行同一条件网络。前提是条件真的相同，广播反向仍需累加所有消费者的梯度。详见[条件广播与训练峰值显存](条件广播与训练峰值显存_20260918.md)。

## 5 Self Attention 和 Cross Attention 各在问谁

Self Attention 的 Q/K/V 都来自视频 hidden：视频位置之间交换信息。Cross Attention 的 Q 来自视频，而 K/V 来自文字条件：视频位置查询文字描述。FFN 接着加工各位置的表示，最终输出仍是视频 hidden，不是某一层就“生成了一段视频”。

因此，Self Attention 与 Cross Attention 的耗时不能只按后端名字比较。前者可能面对很长的视频序列，后者的 Key 长度可能只是较短的文字序列。长度、head 数、mask、dtype 和前反向范围都要对齐，才能讨论哪个实现更快。

普通 Attention 的数学结构仍可参照[Q/K/V 基础](../07/基础理论_20260723.md)。FlashAttention 主要改变执行与访存方式，不会把视频 Token 自动变成文字 Token，也不会默认改变训练目标。

## 6 三种步及其工程后果

| 名称 | 实际做什么 | 不能推出什么 |
|---|---|---|
| 优化器更新步 | 前向、Loss、反向、更新参数，可能包含多个 microbatch | 不等于生成了一段完整视频 |
| 去噪采样步 | 用当前参数预测方向，更新 latent | 没有因此训练参数 |
| 训练阶段 Stage | 一套数据、mask、条件和训练配方 | 上一阶段跑通不证明下一阶段通过 |

同一主干进入新训练阶段后，因果 mask、数据形状、附加输出和保存时机都可能变化。还要分别检查 optimizer/scheduler 状态是否延续。视频预测训练本身也不自动等于在线 RL：是否有环境交互、Reward、策略更新，要看真实链路。

## 自测问题

1. 为什么视频模型用了 Transformer，却没有 LM Head 的词表采样？
2. 视频帧数、latent 时间长度、Transformer Token 数分别是什么？
3. 给定 x=3、ε=7、σ=0.5，带噪输入和速度目标各是多少？
4. 为什么某阶段长跑成功，不能据此证明另一个阶段保存恢复成功？

参考答案：1. 它预测连续 latent 的方向，输出空间不同。2. 原始时间、压缩后的时间、时空分块后的序列长度。3. 输入 5，目标 4。4. 执行契约与状态生命周期可能已变化。
