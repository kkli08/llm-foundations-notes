## 10:07｜GRPO 组内归一化与 Batch 级优势归一化的冲突

> 记录时间：2026-11-16 10:07–15:04  
> 内容归属日期：2026-11-16  
> 整理状态：已整理  
> 归档日期：2026-11-16  
> 正式笔记：[GRPO双重归一化偏差、Critic参数桶解耦与截断GAE自举](../notes/2026/11/2026-11-16.md)  
> 来源：Antigravity 会话 `60710e1e-4af7-4776-bdc1-9091bc363f76`

### 今天的问题

- GRPO 配置在组内奖励归一化（`reward_norm`）后，如果仍然开启 batch 级优势归一化（`adv_norm`），在数学和梯度上会发生什么冲突？
- 为什么在 PPO 时代默认开启的配置，搬到 GRPO 上会变成配置缺陷？

### 对话或资料摘录

- **执行链路**：`reward_norm` 与 `adv_norm` 是两道串行执行的归一化。第一道在 Prompt 组内对 $G$ 条轨迹的标量奖励做均值方差归一化 $\tilde{r}_i = \frac{r_i - \mu_{\text{group}}}{\sigma_{\text{group}}}$，保证 Response 粒度均值为 0。第二道把标量优势广播到生成 token 上，并在全 Batch 维度按有效 token 做批均值方差归一化 $\tilde{A}_{i,t} = \frac{A_{i,t} - \mu_{\text{batch}}}{\sigma_{\text{batch}}}$。
- **长度偏置（Length-biased baseline shift）**：不同 Prompt 的回答长度不等。长回答贡献更多 token，在计算批均值 $\mu_{\text{batch}}$ 时权重被放大。当正优势样本偏长时，批均值被拉高，原本组内均值为 0 的中性回答被减成负数，导致 Prompt 级别的相对优势排序被破坏。
- **零方差组被污染**：某 Prompt 组若所有采样全对或全错，组内标准差为 0，理论优势全为 0（不提供更新梯度）。但叠加批级归一化后，减去非零批均值 $\mu_{\text{batch}}$ 会使其获得非零优势，产生虚假更新。
- **奖励缩放抵消**：批级除以 $\sigma_{\text{batch}}$ 会抵消掉 `reward_scaling`，使得学习率调节失效。
- **结论**：GRPO 类算法开启组内归一化时，必须关闭批级优势归一化。

## 10:10｜GAE 截断轨迹与真实终态判分的自举值叠加

> 记录时间：2026-11-16 10:10–15:04  
> 内容归属日期：2026-11-16  
> 整理状态：已整理  
> 归档日期：2026-11-16  
> 正式笔记：[GRPO双重归一化偏差、Critic参数桶解耦与截断GAE自举](../notes/2026/11/2026-11-16.md)  
> 来源：Antigravity 会话 `ec9df569-f1ef-409b-a02e-f7083a5f4939`

### 今天的问题

- 当 LLM 生成被最大长度截断（`is_truncated=True`）时，若判分器对截断回答给出了真实判分（如 0 分），GAE 是否应该再加上 Critic 的自举价值 $V(s_T)$？

### 对话或资料摘录

- **终止与截断的区别**：终止（Termination）表示自然到达任务终态，后续价值为 0；截断（Truncation）表示时间步耗尽被迫截止，理论上后续状态应由价值函数补齐自举项 $G_t = R_t + \gamma V(s_{t+1})$。
- **LLM 判分场景的重叠**：在文本生成和数学判分中，判分器通常在截断时直接根据前缀生成质量给出一个全局评价（例如未完成答案判定为 0 分，或施加格式惩罚）。此时该标量奖励已经是全轨迹的综合评价。
- **自举双重叠加缺陷**：若代码在已保留判分奖励 $R_T$ 的同时，又因 `is_truncated=True` 盲目加上 $\gamma V(s_T)$，会导致同一时间步的价值被放大，尤其当 Critic 对长截断状态高估时，会诱导模型故意生成冗长截断的回答。
- **修正原则**：若截断结果已经被赋予了终态评估结果，必须屏蔽 Critic 自举项，将其视为终态处理。

## 14:38｜Megatron DistributedOptimizer 与 DDP 包装时序缺陷

> 记录时间：2026-11-16 10:10–14:52  
> 内容归属日期：2026-11-16  
> 整理状态：已整理  
> 归档日期：2026-11-16  
> 正式笔记：[GRPO双重归一化偏差、Critic参数桶解耦与截断GAE自举](../notes/2026/11/2026-11-16.md)  
> 来源：Antigravity 会话 `ec9df569-f1ef-409b-a02e-f7083a5f4939`

### 今天的问题

- 为什么在 Megatron-LM / DDP 分布式训练中，先调用 `get_model(wrap_with_ddp=True)` 之后再把模型的最后一层替换为 `ValueHead` 会导致 Critic 静默不训练？
- 这到底是一个 Megatron 的 Bug，还是用法时序错误？

### 对话或资料摘录

- **DDP 参数展平与优化器绑定机制**：PyTorch DDP 在初始化时，会遍历所有注册的参数并将其打平成连续内存桶（Bucket）。Megatron 的 `DistributedOptimizer` 紧随其后，按照初始参数列表划分张量分片并在各自 GPU 上绑定优化器状态。
- **替换引用导致通信与优化脱节**：如果在 DDP 包装完成后再执行 `model.output_layer = ValueHead(...)`：
  - 前向与反向计算走的是新 `ValueHead` 的张量，`.grad` 也写入新张量；
  - 但 DDP 的底层 Reducer 桶依然绑定的是旧层的内存地址，新层没有挂载任何通信钩子，梯度跨卡 AllReduce 被跳过；
  - `DistributedOptimizer` 的更新循环中遍历的依然是旧层的内存指针，优化器只对旧层执行空梯度更新，新层权重在整个训练过程中完全不更新。
- **静默失败的危害**：程序不会抛出任何异常，损失看似正常计算，但 Critic 头权重完全冻结在初始随机状态。
- **流水线并行（PP）规则**：Critic 价值头只能放置在流水线最后 Stage（`is_pipeline_last_stage()`），且必须解绑与首 Stage 的词表共享关系（`untie_embeddings_and_output_weights`）。

> 来源：Antigravity 会话 `4bf2b436-ef7d-41a1-9aa1-6d2b308f3216`

### 今天的问题

- 如何在同一套训推框架内统一 5 种强化学习与在线蒸馏算法（GRPO、GSPO、PPO、OPD、MOPD）的数学目标？
- 如何建立成本最低、防崩溃的工程验证门禁？

### 对话或资料摘录

- **多算法目标契约**：
  - GRPO：组内无 Critic 奖励归一化 + 标量优势广播 + PPO 策略裁剪；
  - GSPO：按轮序列级重要性采样比率，抑制长链乘积方差；
  - PPO：Actor + Critic + GAE + 价值头初始化与预热步；
  - OPD：学生模型结合任务奖励与单教师在线蒸馏（裁剪优势叠加或散度正则）；
  - MOPD：多专家教师按 domain 路由打分 + 离线混域配额 + 极端比值有限性保护（`log_ratio_clip=20`）。
- **三级验证门禁（L0/L1/L2）**：
  - L0 单元测试门（CPU/单卡，秒级）：验证极端数值防爆（`0 * Inf -> NaN` 兜底）、跨 microbatch 归一化梯度严格守恒、配置互斥；
  - L1 数值机制探针（小模型 5~10 步）：Same-Weight A0 探针（师生同权 step 0 蒸馏优势在有效 token 上位精确为 0）、双教师路由隔离探针；
  - L2 稳定性与效果基准矩阵（固定 Qwen3.5-9B、固定拓扑与步数）：监控梯度范数波动、clip 触发率与 Held-out 评测集基线收益。
