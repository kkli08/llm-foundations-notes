## 0. 今天最终要解决的问题

- MoE 路由回放（训练侧强制使用推理时的 Expert 选择）做了“驻留优化”之后，和不开回放的基线比，实际影响怎么样？

## 1. 先给结论

- **显存没有变成代价，时间变成了代价**：回放数据放在 CPU 侧时，各阶段结束时的显存读数与基线持平；多出来的是训练侧耗时，主要来自每次从对象存储整批取回路由数据，拷到 GPU 本身可以忽略。
- **先确认负载等价，再按有效 Token 归一化**：两边每步有效 Token 数与 Microbatch 数相近，训练侧的时间差才归因得到回放上。
- **跨周的两次运行不是 A/B**：Rollout 时间差来自环境负载不同，不能算到回放头上。
- **汇总指标没看出改善 ≠ 回放没用**：训推差异可能集中在少量 Token 的长尾，均值反映不出来；要用“同一批 Rollout、训练侧开关回放”的逐 Token 分布对比来证明。

## 2. 前置概念

### 2.1 路由回放在训练侧多做了什么

推理时记录每个 Token、每层选中的 Expert ID；训练侧重算 Logprob 和更新时，强制使用这些 ID，而不是重新路由（[MoE Router Replay 完整数据链](../08/MoERouterReplay与训推路由一致性_20260817.md#3-完整数据链)）。

训练侧因此多了一段数据流：

```text
路由数据（每步可达数 GB）存放在 CPU / 对象存储
→ 每次重算 Logprob、每次更新前取回
→ 拷到 GPU
→ 强制路由
```

### 2.2 两种回放驻留位置的权衡

| 驻留位置 | 显存 | 时间 |
|---|---|---|
| GPU 常驻 | 占用显存，可能放大峰值（[驻留范围 × 生命周期 × dtype](路由回放与动态形状的显存归因_20261008.md)） | 取用几乎免费 |
| CPU / 对象存储，用时取回 | 几乎不占显存 | 每次取回都有延迟 |

驻留优化就是从第一行搬到第二行：省显存，付时间。

## 3. 完整原理

### 3.1 先选对照

“和基线比”的第一步是选对基线：同模型、同序列长度、同卡数与并行布局，只差是否开回放。挑不到完全匹配的同期运行时，只能用已完成的历史运行，这时要把结论限定在“两次独立运行的对比”。

### 3.2 显存：看阶段读数，并说明它不是峰值

按训练步内各阶段（重算 Logprob 后、Policy 更新后）结束时记录 allocated / reserved / 整卡已用，逐步取均值和最大值，再看多步内有无上涨趋势。

这次的结论是持平甚至略低、两边都没有 OOM、也没有上涨趋势。但要写明限制：**阶段结束时的读数不是阶段内的峰值**，峰值要用 Allocator 快照或峰值统计单独看。

### 3.3 耗时：先核负载，再按有效 Token 归一化

1. 去掉前两步预热；
2. 确认两边每步有效 Token 数、Microbatch 数几乎一样——负载等价后，训练侧时间差才可归因；
3. 按阶段拆开比：重算 Logprob、训练更新、Advantage 计算、权重同步、Rollout；
4. 再算“每百万有效 Token 耗时”，消除步间样本量波动。

这次的分解：重算 Logprob 与训练更新两段明显变慢（重算段相对增幅更大），Advantage 计算持平、权重同步略增。用回放自身的计时细分后，主要来自**每次从对象存储整批取回路由**；H2D 拷贝只占毫秒级。

这与 [Ray Object Store 的数据流](../08/MoERouterReplay与训推路由一致性_20260817.md#81-ray-objectref-到消费端的数据流)一致：`get` 的耗时可能包含跨节点拉取、反序列化与拷贝，不是单纯的 PCIe 传输。

优化方向：预取（在上一阶段计算时提前取回），或按 Microbatch 按需取回，而不是每次整批取。

### 3.4 Rollout 差异为什么不能算进来

开回放那次的 Rollout 反而快了很多。但回放只让推理端多返回一份路由，不会让生成变快；两次运行隔了一周，环境（如沙箱平台）的负载和速度都不同。所以“这次每步总时间更短”不代表回放更快。

规则：**只比机制上可能受该改动影响的阶段**；不受影响的阶段出现大差异，说明两次运行的环境不等价，整段端到端时间都不可比（见 [Benchmark 对照的负载等价](Benchmark对照的负载等价与读数混杂_20261009.md)）。

### 3.5 训推一致性：均值看不见长尾

回放的设计初衷是缩小训推 Logprob 差异。但这次的汇总指标——行为重要性权重的均值、每步最大值的均值、训推 KL 均值、梯度范数、Reward、熵——两边几乎一样。

可能的解释（待验证）：在这个设置下路由本来就比较稳定，路由不一致只发生在少量 Token 上；一个 Batch 有上百万 Token，少数 Token 的大差异被均值稀释。

要证明算法收益，需要更直接的对照：

```text
固定同一批 Rollout 数据
→ 训练侧分别开、关回放，各重算一次 Logprob
→ 与推理端 Logprob 逐 Token 求差
→ 比较差异的分布（尤其是高分位与最大值），而不是均值
```

这个设计去掉了“采到的样本不同”和“环境不同”两个混杂因素，只剩回放这一个变量。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 开回放后显存持平，但训练段变慢 | 路由数据在 CPU 侧，每次整批取回 | 回放自身的取回耗时 vs H2D 拷贝耗时 |
| 开回放那次每步总时间反而更短 | Rollout 环境负载不同 | 只比受影响阶段；核对 Rollout 是否机制上会变 |
| 一致性均值与基线一样 | 差异集中在少数 Token | 固定 Rollout，比逐 Token 差异的高分位 |
| 两边训练段耗时差异波动大 | 每步样本量不同 | 先核有效 Token 与 Microbatch 数，再按 Token 归一化 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 显存没涨，说明驻留优化没有代价 | 代价从显存转到了取回耗时 |
| 回放那次总步时更短，说明回放更快 | 回放不改变生成速度；差异来自环境 |
| 取回慢是 PCIe 带宽不够 | 主要在对象存储的整批取回；GPU 拷贝只占毫秒 |
| 重要性权重均值没变，回放就没用 | 均值看不见少量 Token 的长尾差异 |
| 阶段结束时的显存读数就是峰值 | 峰值要用快照或峰值统计单独测 |

## 7. 一分钟复习

1. 选同配置、只差回放的基线；跨周运行只能算独立对比。
2. 驻留在 CPU：显存持平，代价是取回耗时；优化靠预取或按 Microbatch 取。
3. 比耗时：去预热 → 核有效 Token → 分阶段 → 按 Token 归一化。
4. 只比机制上会受影响的阶段。
5. 证明一致性收益：固定 Rollout，训练侧开关回放，比逐 Token 差异的分布。

## 8. 自测问题

### 问题 1

开了路由回放的运行 Rollout 快了很多，能说明回放提升了吞吐吗？

期望回答：不能。回放只让推理端多返回路由，不会让生成变快；两次运行环境负载不同，Rollout 差异不可归因，应只比机制上受影响的阶段。

### 问题 2

训推一致性的几个均值指标开不开回放都一样，怎样设计实验才能判断回放有没有算法收益？

期望回答：固定同一批 Rollout，在训练侧分别开、关回放重算 Logprob，与推理端逐 Token 求差，比较差异分布的高分位和最大值，而不是均值。
