## 1. 先给结论

- **学习率升满后 GSPO 的 clip 没有失控**：低侧在四分之一到三分之一之间波动。熵一度越过事先定的警戒线，随后停在比起步高约三成的水平；判对率没跌，“熵涨 + 判对率降”的报警组合没有出现 → 读作多样性停在更高水平，不是变散。
- **GRPO-k1 的失稳是一条有先后的链**：回答长度快速变短 → 熵塌到另外两组的一半以下 → 行为侧近似 KL、单 token 最大 logprob 差、RS 过滤比例一起放大 → 梯度范数升高 → 自行回落；之后同样的循环再来一次、幅度更大；第三次没停住，崩溃时**熵从极低反冲到很高**、长度塌到两百 token 以下、梯度范数高一个数量级、判对率明显下跌；最后恢复，但停在**另一个状态**（回答短约四成、熵完全不同），不是回到原模型。
- **修正 10 月 21 日的一个读法**：当时说“GRPO 学起来就熵降，与更新次数关系不大”。跑满后看，方向相同、深度不同——k4 降到起步的一半多一点后企稳，k1 降到起步的四分之一左右并反复失稳。“熵降是 GRPO 的共性”仍成立，“降多深与更新次数无关”不成立。
- **“只更新一次更稳”在这个配方、这个 seed 下不成立**：k1 学得最慢、最不稳。但 k1 与 k4 同时差了“有没有信任域”“每批几次 optimizer step”“每步梯度用多大的 batch”三件事，而且 k4 的 token clip 比例只有约千分之一——“k1 崩是因为没有 clip”只是推测，没有被这个对照证明。
- **行为侧近似 KL 放大不一定是训推数值差**：异步训练里 π_prox/π_behave 同时装着“陈旧一版”和“训推数值差”两个来源（[三个离策略来源](异步离策略的三个来源与IS和RS_20261019.md)）。每步更新幅度变大时陈旧部分也会变大，单看这个读数分不清是哪一个。
- **PPO**：critic 预热约 30 步 EV 走平、约 10 步 V 均值对上回报均值；actor 开始学之后 EV 回落约一半——判对率从一成多涨到七成多，critic 一直在追移动的目标。判对率与 GRPO-k4 接近，**熵降得最快、梯度范数持续上升**，是要盯的风险信号；0/1 奖励的单轮数学上 critic 的优势没体现出来。
- **口径**：PPO 组开了批级优势归一化、其余组没开，梯度范数不能直接比大小；GSPO 的 clip 比例是序列级、允许区间只有万分之几，和 token 级 clip 比例不是同一个量。
- **重复提问的答案没变**：PPO、GRPO、GSPO 共用同一个 actor loss；token 级比值 π_θ/π_prox 只有在同一批数据被更新多次（minibatch 个数 > 1）时才偏离 1、clip 才可能触发；异步修正 π_prox/π_behave 与 minibatch 个数无关，一直在起作用。

## 2. 前置概念

### 2.1 这次读失稳用到的六个读数

| 读数 | 它在量什么 | 失稳时的方向 |
|---|---|---|
| 回答长度 | 每条采样回答的平均 token 数 | 快速变短（写得越来越少）或暴涨 |
| 熵 | 采样位置上策略分布的平均熵 | 先塌到很低；崩溃时反冲到很高 |
| 行为侧近似 KL | π_prox 与 π_behave 在采样 token 上的 logprob 差的平均 | 绝对值放大 |
| 单 token 最大 logprob 差 | 同上，取整批最极端的一个 token | 从个位数放大到两位数 |
| RS 过滤比例 | 行为侧权重越界、被排除出梯度的 token 比例 | 从百万分之几涨到千分之几 |
| 梯度范数 | 裁剪前的全局梯度范数 | 持续升高，崩溃时出现一个数量级的尖峰 |

前三个是“策略形状”，中间两个是“训推/版本一致性”，最后一个是“更新有多猛”。判对率是滞后指标（[健康检查顺序](RL训练健康检查顺序与熵的两种失败方向_20261010.md)），这次它也是最后才掉。

### 2.2 三组 + 一组的定义

接着 [10 月 21 日 §2.1](GSPO对照实验的Clip比例读法与学习率预热口径_20261021.md#21-三组对照)：GSPO-k4、GRPO-k4、GRPO-k1 同模型、同数据、同 seed，各 150 步；PPO（k = 4）前 50 步只训 critic，比较时按 actor 实际更新步数对齐。k = 每批数据切成几个 minibatch、做几次 optimizer step。

## 3. 完整原理

### 3.1 学习率升满之后：GSPO 的 clip 与熵

10 月 21 日留下的担心是：学习率升满后每次更新走得更远，靠后 minibatch 的 clip 会明显上升，整步 clip 过半时 k = 4 退化成只有前一两个 minibatch 在学。跑满后的读数：

| 读数 | 学习率升满前 | 升满后到结束 |
|---|---|---|
| 序列 clip 低侧 | 约两成到四分之一 | 四分之一到三分之一之间波动，没有单调上升 |
| 熵 | 比起步略高 | 先继续上升、越过警戒线，随后停在比起步高约三成 |
| 梯度范数 | 三组最低 | 仍是三组最低、最平稳 |
| 判对率 | 与 GRPO-k4 持平 | 仍持平，最后一段略高但在单步波动内 |

两点读法：

- **熵上涨要看组合**。巡检时事先写下的报警条件是“熵继续涨到更高 + 判对率开始下降”。熵越过第一道线时判对率、长度、梯度范数都稳，于是继续观察而不是叫停；几步后熵停住。事先写下组合条件，就不会因为单个读数越线而误停（[停止规则的误停与迟停](AgentRL的Reward崩溃与归因实验_20261009.md#38-同期对照的逐步观察)）。
- **clip 的低侧比高侧多得多**，与 [10 月 21 日 §3.3](GSPO对照实验的Clip比例读法与学习率预热口径_20261021.md#33-序列-clip-比例约两成被剪的是梯度不是轨迹) 的解释一致（KL 让零方差组带一点负优势，一出界就计入低侧），学习率升满没有改变这个结构。

### 3.2 单次更新的 GRPO：从熵塌缩到崩溃的四个阶段

| 阶段 | 发生了什么 | 当时怎么判断 |
|---|---|---|
| ① 长度骤降 | 十几步内平均长度减半；答对、答错的回答都变短；最短回答没有变成空；截断比例很低 | 还不算退化：判对率稳定。警告是“比另外两组降得多得多”。对话中的推测：模型在学“少写推理、直接给答案”，在这类题上不掉分，在需要长推理的难题上可能吃亏 |
| ② 熵塌缩 + 一致性读数放大 | 学习率升满前后，熵降到另外两组的一半以下；行为侧近似 KL 几步内放大约一个数量级，单 token 最大差从个位数到两位数，RS 过滤比例涨约百倍；梯度范数稳步升高 | 典型的不稳定前兆，但判对率还没动 |
| ③ 自行回落 → 再来一轮 | 一致性读数见顶后回落到峰值的几分之一，长度反弹到和另外两组相近，熵停在低位不恢复；几十步后同样的“长度变短 → 读数放大”再来一次，峰值更高 | **振荡且一轮比一轮大 = 处在不稳定的边缘**，一次自行恢复不代表安全 |
| ④ 崩溃与恢复 | 第三轮没停住：长度塌到约 170 token，熵从极低反冲到很高，行为侧近似 KL 到正常水平的数百倍，梯度范数高一个数量级（裁剪一直在起作用），判对率跌掉约三分之一；十来步后各项回落，判对率回到与另外两组接近 | 恢复后回答短约四成、熵与崩溃前完全不同 → **恢复到的是另一个策略**，崩溃之后的数据不能当作原模型的延续去比较 |

可复用的三条：

1. **崩溃形态是“先塌缩、再反冲”**：熵先往下掉（[多样性丧失](RL训练健康检查顺序与熵的两种失败方向_20261010.md#33-熵持续往下掉多样性丧失)），崩溃那一刻反而往上冲（[不稳定的前兆](RL训练健康检查顺序与熵的两种失败方向_20261010.md#32-熵往上冲不稳定的前兆)）。只设“熵过高”或“熵过低”一种报警都会漏掉一半。
2. **长度在两个方向都会出问题**：这次 k1 先是变短，第一轮后又快速变长、一度超过另外两组，崩溃时塌到极短。看长度要同时看判对率和截断比例（[截断伪造的 Reward 涨幅](Benchmark对照的负载等价与读数混杂_20261009.md#32-截断伪造的-reward-涨幅)）。
3. **梯度裁剪限制了单步幅度**，可能是这次没有一路崩到底的原因（推测）。这与 [clip 只限多次更新的累积偏移、单步靠学习率与梯度裁剪](单次更新下两个比值的分工与Clip的真实作用_20261015.md#35-clip-到底限制什么被纠正的误解) 一致：k1 没有信任域，单步唯一的刹车就是裁剪和学习率。

### 3.3 行为侧近似 KL 放大，不一定只是训推数值差

对话里把阶段 ② 的读数放大解释为“熵很低时，推理引擎和训练引擎在少数 token 上的数值差被放大”。这有一个合理的局部机制：对采样到的 token y，log p(y) 对它自己 logit 的导数是 1 − p(y)——高概率 token 几乎不受 logit 误差影响，低概率 token 几乎一比一地传过去。策略越尖锐，偶尔采到的低概率 token 越“稀有”，同样的数值误差就越容易在单个 token 上表现成大的 logprob 差。

但整理时要补一个**另一种解释（未验证）**：异步训练里行为侧比值 π_prox/π_behave 装着两个来源——

| 来源 | 什么时候变大 |
|---|---|
| 训推数值差（同一权重、两个引擎） | 分布变尖、低概率 token 增多时（上面的机制） |
| 陈旧一版（rollout 用的是上一版权重） | **每步更新幅度变大时**：梯度范数升高、学习率刚升满，相邻两版策略差得更远 |

阶段 ② 恰好同时出现了“熵变低”和“梯度范数升高、学习率升满”，两种来源都会被放大，单看这一个读数分不清。区分办法：按样本的版本差分开统计（陈旧度为 0 的样本只剩数值差），或同一权重下单独比两个引擎的 logprob。这和 [比值修不了自己的分母](异步离策略的三个来源与IS和RS_20261019.md) 是同一类“先拆来源再归因”。

### 3.4 每步只更新一次更稳吗：这个对照证明了什么、没证明什么

起因是一个常见直觉：同一批数据更新次数越多，策略离采样策略越远，离策略问题越重，所以 k = 1 最稳。这次结果正好相反：k1 起步最慢（判对率过半晚了十几步）、全程最不稳、后期崩了一次；k4 全程没有这些现象。

能说的：

- **在这个配方、这个 seed 下，把 k 从 1 提到 4 没有伤害稳定性**，反例足以说明“k 越小越稳”不是普遍规律。

不能说的（整理时补充）：

| k1 与 k4 同时差的东西 | 对稳定性的可能影响 |
|---|---|
| 有没有信任域：k1 比值恒为 1、clip 永不触发；k4 从第 2 个 minibatch 起才可能 clip | 对话给出的推测原因 |
| 每批几次 optimizer step：k4 每批走 4 步 | 按理 k4 每批走得更远、应该更不稳；实际相反 → 不是“走得多就崩” |
| 每步梯度用多大的 batch：k1 一步用整批，k4 一步只用四分之一 | 梯度噪声不同，影响方向不明确 |

而且 **k4 的 token clip 比例只有约千分之一**。如果稳定确实来自 clip，它只能是通过剪掉极少数比值极端的 token 起作用（k4 每步的比值最大值可以到数倍）；这需要单独验证，比如只关掉 k4 的 clip、其余不变。再加上单 seed，“k1 崩是因为没有 clip”只能当假说；对话中说“k4 没问题，说明多个 minibatch 加裁剪确实起了稳定作用”是说过头了。

### 3.5 PPO 长跑：critic 预热够了吗、actor 开始学之后 EV 为什么回落

| 时期 | 读数 | 读法 |
|---|---|---|
| critic 预热（actor 冻结） | EV 从接近 0 升到约 0.3，约 30 步走平；V 均值约 10 步就和回报均值对上 | 用 [10 月 21 日的判据](PPO_Critic的价值头初始化两种预热与EV上限_20261021.md#35-ev-到多少算预热够了没有统一阈值)：EV > 0 且走平、V 均值对上 → 50 步够了，30 步可能就够 |
| actor 开始更新后 | EV 回落到约一半；判对率在一百个 actor 步内从一成多涨到七成多 | critic 的拟合目标是**当前策略**下的回报；策略变得快，目标一直在移，critic 跟得吃力。另外 EV 上限 ≈ 题间通过率方差 ÷ 奖励总方差，通过率分布在变，上限本身也在变 |
| 整体 | 判对率与 GRPO-k4 接近；熵降得四组最快（降到起步的四成左右）；actor 梯度范数持续上升到约两倍 | 0/1 奖励的单轮数学上，critic 的逐 token 信用分配没体现出优势；熵和梯度范数的趋势是风险信号，再跑长一些可能出问题 |

预热期 EV 走平不等于之后一直可靠：**预热只解决“起点不是噪声”，解决不了“目标在移动”**。actor 更新后的 EV 要单独看，它决定 GAE 里 V 有多大的可信度（[λ 的选择要以 EV 为前提](PPO的Critic价值估计GAE参数与工程适配_20261020.md)）。

### 3.6 PPO 也有 token 级比值吗（重复提问）

这是第三次问到同一组概念，答案与旧笔记一致，这里只串起来：

- PPO 的比值 r_t = π_θ(a_t)/π_old(a_t)，每个 token 一个，loss 是 min(r_t·A_t, clip(r_t, 1 − ε, 1 + ε)·A_t)。GRPO 只是把优势换成组内归一化奖励，比值和 clip 完全相同；GSPO 把 r_t 换成回答内的几何平均（[10 月 13 日 §3.3](PPO的Critic与Clip在单次更新下的退化_20261013.md#33-关键推论单次更新时-clip-退化)）。
- π_old 就是这批数据进来时 actor 的参数（重算得到的 π_prox）。k = 1 时更新那一刻 π_θ 与 π_prox 是同一组参数，r_t ≡ 1，clip 永不触发，loss 退化为普通策略梯度；k = 4 时第 1 个 minibatch 仍是 1，从第 2 个起才可能偏离。
- 异步时 loss 里还有 π_prox/π_behave：与 k 无关、一直乘在 loss 里，不参与 ε 裁剪，越界的 token 被 RS 排除。所以 **k = 1 缺的是信任域，不缺离策略修正**（[10 月 19 日的 2×2 表](异步离策略的三个来源与IS和RS_20261019.md)、[10 月 20 日：两段比值相乘](异步训练下的Minibatch个数与解耦PPO来源_20261020.md)）。

这次的新东西是实测印证：

| | GRPO-k1 | GRPO-k4 | GSPO-k4 | PPO-k4 |
|---|---|---|---|---|
| clip 比例 | 0 | 约千分之一（token 级） | 近三成（序列级） | 约千分之一（token 级） |
| 每步比值最大值 | 恒为 1 | 可到数倍 | 只比 1 大千分之几 | 可到数倍 |

读法：**clip 比例很小不等于比值都贴着 1**——平均值和比例看不到个别极端 token，最大值能看到。GSPO 的 clip 比例高，是因为序列比值平均后本来就贴近 1、允许区间只有万分之几（[√L 估算](GSPO开关解耦与按轮序列比值_20261019.md#32-为什么-gspo-的-clip-要小约三个数量级)），不能和 token 级比例直接比。

### 3.7 四组放在一起比时的口径

1. **对齐方式**：PPO 前 50 步只训 critic，横轴要用 actor 实际更新步数；否则 PPO 看起来晚 50 步。
2. **梯度范数**：批级优势归一化会把优势缩放到固定尺度（[PPO 为什么要批级归一化](截断采样与批级归一化的双条件崩溃机制_20261016.md#36-ppo-为什么要做批级归一化被纠正的误解)），开和不开的两组梯度范数量级不同，只能比各自的趋势，不能比大小。下一轮要加一个“关掉批级归一化的 PPO”对照。
3. **clip 比例**：token 级与序列级是两个量（§3.6）。
4. **结论分层**：判对率差距只有百分之二三，单 seed 下都在波动内；能说的是稳定性的定性差别（谁的熵塌、谁的梯度范数一路涨、谁崩过），不能说谁的收益更高。
5. **数据完整性**：汇总全程分段统计前，先确认手里是不是完整的 150 步——日志工具常只给尾部固定行数，早期步数会悄悄缺失；完整曲线应从指标平台取，或按时间窗分段拉。作业完成后在关闭进程时出现的 traceback，先看出现时刻，不影响训练结果。

### 3.8 换场景做稳定性对照时先想清楚什么

用户想把同样的对照搬到多模态、代码、多轮终端 agent 等场景。可复用的设计原则：

- **对照组跟着基线配方走**：基线本来就是 k = 4 的场景，不需要再单独比 k1/k4；基线是 k = 1 的场景才要四组。
- **critic 在哪最可能有价值**：单轮、0/1 奖励的任务里，逐 token 信用分配作用有限（这次数学就没体现）；长程、多轮、奖励稀疏的 agent 任务最可能体现 critic 的价值，应优先跑。
- **critic 的前置条件**：多模态任务要先确认 critic 能接收图像输入；回答很长的任务 critic 的前向和显存开销都大；多个模型共卡时显存和耗时是风险。
- **先功能、后长跑**：每个场景先跑两步功能验证（第 1 步数值正常、各指标存在），再上长跑；不稳定往往在后期才出现，长跑至少 300 步，并打开独立评测（[10 月 21 日 §3.7](GSPO长跑对照的同步数读法与系统对比设计_20261021.md#37-下一轮对比怎么设计问题-4)）。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 某组回答长度十几步内减半，判对率不变 | 学会少写推理，或开始退化 | 看最短回答、截断比例；长度继续降且判对率开始掉才是退化 |
| 熵低位时行为侧近似 KL 和最大 logprob 差同时放大 | 低概率 token 对数值误差敏感，或每步更新变大让陈旧部分变大 | 按版本差分开统计；同一权重比两个引擎的 logprob |
| 失稳后自行恢复，几十步后又来一轮、幅度更大 | 处在不稳定边缘 | 记录每轮峰值，看是否单调变大 |
| 崩溃时熵从极低突然升高 | 策略从过度确定一下子被打散 | 熵的报警同时设上下两侧 |
| 崩溃后判对率恢复，但长度、熵都和崩溃前不同 | 恢复到另一个策略 | 崩溃后的数据不和崩溃前或其他组直接比 |
| token clip 比例千分之一，比值最大值却有数倍 | 比例和均值看不到个别极端 token | 同时记录比值的最大值或高分位 |
| PPO 预热期 EV 走平，actor 开始学后回落 | 目标随策略移动；EV 上限也在变 | 分开看两个时期的 EV |
| 两组梯度范数差两倍 | 一组开了批级优势归一化 | 先对齐归一化口径再比 |
| 分段统计里早期步数缺失 | 日志只取了尾部若干行 | 核对步数范围；从指标平台取完整曲线 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 每步只更新一次最稳 | 这次 k1 最不稳；但 k1/k4 同时差信任域、optimizer step 次数和每步 batch 大小，单 seed，机制没证明 |
| k4 稳定 = clip 在起作用 | k4 的 token clip 比例只有约千分之一；要只关 clip 做单变量验证 |
| GRPO 熵降与更新次数无关（10 月 21 日的读法） | 方向相同，深度差很多：k1 塌得远比 k4 低 |
| 行为侧近似 KL 变大 = 训推引擎数值差变大 | 异步时还混着陈旧一版的差距；更新变猛时它也会变大 |
| 失稳后自己恢复了就没事 | 振荡一轮比一轮大，第三轮真的崩了 |
| 崩溃后恢复 = 回到原来的模型 | 回答短约四成、熵完全不同，是另一个策略 |
| 熵上涨就要叫停 | 看组合：熵涨 + 判对率降才报警；GSPO 越线后停住、判对率不变 |
| 熵只会往一个方向坏 | 先塌缩（多样性丧失），崩溃时反冲（不稳定） |
| critic 预热期 EV 走平，之后就可靠 | actor 开始学后目标在移，EV 会回落，要单独看 |
| clip 比例小 → 比值都贴着 1 | 看最大值；个别 token 可以偏离到数倍 |
| GSPO clip 近三成比 GRPO 千分之一“剪得多太多” | 一个是序列级、区间万分之几，一个是 token 级，不是同一个量 |
| PPO 没有 token 级比值 / k = 1 时 PPO 也会 clip | 三种算法共用同一个 actor loss；k = 1 时 r ≡ 1，谁都不 clip |

## 7. 一分钟复习

1. 学习率升满后 GSPO 低侧 clip 在 1/4～1/3 波动、没失控；熵越线后停在高约三成的水平，判对率不跌 → 不是变散。
2. k1 失稳链：长度骤降 → 熵塌 → 行为侧近似 KL / 最大差 / RS 比例放大 → 梯度范数升 → 回落 → 再来一轮更大 → 崩：熵反冲、长度塌、梯度范数尖峰、判对率跌 → 恢复到另一个策略。
3. 熵报警要上下两侧都设；失稳振荡一轮比一轮大就是在边缘。
4. 行为侧近似 KL = 训推数值差 + 陈旧一版；更新变猛时也会放大，按版本差拆开看。
5. “k = 1 更稳”这次不成立；但 k1/k4 捆绑三个差别、k4 clip 只有千分之一、单 seed → “没 clip 所以崩”只是假说。
6. PPO：预热 30 步左右 EV 走平；actor 学起来后 EV 回落（目标在移）；熵降最快、梯度范数一路涨 → 盯。
7. 三种算法共用一个 actor loss；k = 1 时 r ≡ 1 谁都不 clip；π_prox/π_behave 一直在。clip 比例小 ≠ 比值都贴着 1。

## 8. 自测问题

### 问题 1

一组 GRPO 的读数依次出现：回答长度十几步内减半 → 熵降到别组一半以下 → 行为侧近似 KL 放大约十倍 → 梯度范数升高 → 自行回落。此时判对率一直稳定。该怎么判断？接下来盯什么？

期望回答：还不算崩，但这是典型的不稳定前兆。判对率是滞后指标，不能因为它稳定就放心。接下来盯两件事：一是同样的循环会不会再来、峰值是不是一轮比一轮大；二是长度会不会继续往极端走，同时判对率开始下跌。熵的报警上下两侧都要设，因为崩溃那一刻熵可能从极低反冲到很高。

### 问题 2

行为侧近似 KL 在熵很低、学习率刚升满、梯度范数变大的这几步里放大了一个数量级。能直接归因为“推理引擎和训练引擎的数值差被放大”吗？怎么区分？

期望回答：不能。异步时 π_prox/π_behave 同时包含训推数值差和陈旧一版两个来源。熵低会让低概率 token 对 logit 误差更敏感（d log p / dz = 1 − p），这会放大数值差；但学习率升满、梯度范数变大会让相邻两版策略差得更远，陈旧部分也会放大。区分办法：按版本差分开统计（陈旧度为 0 的样本只剩数值差），或者同一权重下直接比两个引擎的 logprob。

### 问题 3

k = 1 的 GRPO 崩了、k = 4 没崩，k4 的 token clip 比例约千分之一。能否得出“k = 4 的 clip 让训练更稳，所以应该用多个 minibatch”？

期望回答：不能直接得出。k1 与 k4 同时差三件事：有没有信任域、每批几次 optimizer step、每步梯度用的 batch 大小。clip 只剪了约千分之一的 token，若它是稳定的原因，只能通过剪掉极少数极端 token 起作用，需要只关掉 k4 的 clip 做单变量验证；而且只有一个 seed。能说的只是：在这个配方下把 k 从 1 提到 4 没有伤害稳定性，“k 越小越稳”不是普遍规律。

### 问题 4

PPO 的 critic 预热期 EV 约 30 步走平到 0.3 左右，actor 开始更新后 EV 回落到一半。是预热不够吗？

期望回答：不一定。预热只解决“起点不是噪声”。actor 开始学之后判对率快速上升，critic 要拟合的是当前策略下的回报，目标一直在移；同时 EV 上限（题间通过率方差 ÷ 奖励总方差）也随通过率分布变化。所以要分开看两个时期的 EV，并结合 V 均值是否仍跟得上回报均值、critic loss 是否发散来判断。

### 问题 5

PPO 有没有 token 级的重要性比值？minibatch 个数 = 1 时 PPO 会 clip 吗？这时还剩什么修正？

期望回答：有，r_t = π_θ(a_t)/π_old(a_t)，每个 token 一个，GRPO 用的是同一个 loss，只是优势来源不同；GSPO 把它换成回答内几何平均。minibatch 个数 = 1 时更新那一刻 π_θ 与 π_prox 是同一组参数，r ≡ 1，clip 永不触发，loss 退化为普通策略梯度。剩下的是异步修正 π_prox/π_behave：与 minibatch 个数无关、一直乘在 loss 里、不参与 ε 裁剪，越界 token 被 RS 排除。所以 k = 1 缺的是信任域，不缺离策略修正。

### 问题 6

四组放在一张表里比较时，至少要先对齐哪些口径？

期望回答：横轴按 actor 实际更新步数（PPO 扣掉 critic 预热）；批级优势归一化开关一致，否则梯度范数不能比大小；token 级和序列级 clip 比例分开读；确认数据是完整的全部步数，不是只取了日志尾部；单 seed 下百分之二三的判对率差距不算结论，只比稳定性的定性差别。

## 9. 尚未解决与后续路线

- k1 失稳的单变量拆分：只关 k4 的 clip；或 k1 下把学习率降到与 k4 每批总位移相当；多 seed 确认 k1 的失稳能否复现；
- 行为侧近似 KL 的来源拆分：按版本差分开统计，或同权重比两个引擎；
- 熵塌缩到反冲的机制：为什么极低熵的策略会突然被打散（与 10 月 9～16 日“崩溃形态为何表现为熵上升”是同一个待办）；
- PPO 熵降最快、梯度范数一路上涨：跑到 300 步看会不会失稳；关掉批级归一化后梯度范数的量级；
- critic 在长程多轮 agent 任务上能否体现逐 token 信用分配的价值；
- 独立测试集上 GSPO 与 GRPO-k4 是否真的没差别（本轮未开评测与保存）。
