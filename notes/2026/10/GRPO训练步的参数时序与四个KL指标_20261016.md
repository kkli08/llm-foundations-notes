## 1. 先给结论

- **按“一个训练步里先后发生什么”记参数**：采样 → 打分 → 重算 → 算 Advantage → 算 Loss → 同步。每个旋钮只在其中一两段生效。
- **top-k / top-p 只在采样那一刻起作用**：决定哪个 token 被采出来，之后所有环节都不知道发生过截断。温度不一样，训练端重算时也会除以 T。
- **一次训练步里有五个分布**：π_behave、π_prox、π_θ、π_ref，以及真正采样用、却没人记录的截断分布 q。
- **两个比值管两件事**：`π_θ/π_prox`（带 clip）管“同一批数据更新多次时别走太远”；`π_prox/π_behave`（带拒绝采样）管“数据是旧权重、另一套引擎采的”。整批只更新一次时，前者恒为 1、clip 不触发，后者是唯一还在起作用的 off-policy 修正。
- **名字带 “KL” 的指标至少有四个，只有一个是 KL 正则**：其余三个是诊断量，不需要 Ref。认指标要看“比较的是哪两个分布”，不要看名字。
- **Ref 只为 KL 正则存在**：KL 系数为 0、也不开 KL loss 时，有的框架根本不创建 Ref 模型。
- **重算不替换推理端 logprob**：重算产出的是 π_prox，它让行为侧权重有了分子；π_behave 仍是分母。

## 2. 前置概念

### 2.1 一个训练步里的五个分布

| 符号 | 谁算的、何时算 | 截断了吗 | 用在哪 |
|---|---|---|---|
| π_behave | 推理引擎采样时顺带返回（采样时的权重版本） | 否，raw（截断前、通常也在温度前） | 行为侧权重的分母、拒绝采样、KL 奖励里的“当前策略”项 |
| q | 推理引擎真正采样用的分布：截断后在核内重新归一化 | **是** | 只决定采出哪个 token，**没有任何一方记录** |
| π_prox | 训练引擎用当前权重、不求梯度重算 | 否 | PPO ratio 的分母、行为侧权重的分子 |
| π_θ | 训练引擎带梯度的前向 | 否 | PPO ratio 的分子，梯度从这里走 |
| π_ref | 冻结的起跑 Checkpoint 前向 | 否 | 只用于 KL 正则 |

（三个训练侧分布的来历见 [10 月 15 日 §2.1](单次更新下两个比值的分工与Clip的真实作用_20261015.md)；四类 logprob 的最早定义见 [7 月 24 日 §5.9](../07/训练与RL后训练基础_20260724.md#59-相同-token-的四类-logprob到底指什么)。）

### 2.2 组内 z-score

同一道题的 G 条轨迹：$\hat r_i = (r_i - m)/(s + \varepsilon)$，每条轨迹算出一个值，这条轨迹里**模型生成的每个 token 都用这一个值**，环境返回的 token 不参与训练。例子：`[1,1,0,0,0,0,0,0]` 得到答对 ≈ +1.62、答错 ≈ −0.54，按条数求和为 0；全错组整组为 0（推导见 [同日崩溃机制 §2.1](截断采样与批级归一化的双条件崩溃机制_20261016.md#21-组内-z-score-怎么算grpo-唯一提取信号的一步)）。

## 3. 完整原理

### 3.1 总图

```text
① 采样（推理引擎）
   logits ──÷T──► softmax = π ──top-k──► ──top-p──► 核内重新归一化 = q ──► 采一个 token
                                                                      └─► 记录 log π_behave（raw，截断前）
   每题 G 条 × 每步若干题；权重可能落后训练端若干版本（受最大离策略版本差约束）
        │
② 打分：一条轨迹一个 Reward，挂在最后一个生成 token 上
        │
③ 重算（训练引擎，当前权重，不求梯度）
   log π_prox = log_softmax(logits / T)   ← 完整词表，不截断
   log π_ref                              ← 只有开 KL 时才算
        │
④ 算 Advantage（固定下来，不再求导）
   a. 组内 z-score：r̂ = (r − m)/(s + ε)
   b. KL 奖励（若 KL 放在 reward 里）：每个 token 加 −β·(log π_behave − log π_ref)
   c. GAE（V ≡ 0，γ = λ = 1）：A_t = r̂ + 从 t 到结尾的 KL 奖励之和 ≈ 广播
   d. 批级归一化（可选）：整批所有 token 做 (A − μ)/σ，只算一次，然后才切 minibatch
        │
⑤ 算 Loss（训练引擎，带梯度）
   r = π_θ / π_prox，clip 到 [1 − ε, 1 + ε]
   pg = max(−A·r, −A·clip(r))
   pg ×= w，w = π_prox / π_behave；w 过大的 token（或序列）被拒绝采样 mask 掉
   loss = 有效 token 的 pg 之和 / 有效 token 数（token 等权；也可改成轨迹等权）
        │
⑥ 优化器一步 → 新权重同步给推理引擎 → 下一轮
```

### 3.2 每个旋钮在哪一段生效

| 旋钮 | 生效段 | 做什么 | 容易忽略的点 |
|---|---|---|---|
| 温度 T | ① 采样、③ 重算 | logits 除以 T 再 softmax；T < 1 更尖，T > 1 更平 | 推理端 raw logprob 常按 T = 1 记录，T ≠ 1 时 w 会系统性偏离 1（[10 月 14 日](采样截断与Logprob口径的训推偏差_20261014.md)、[10 月 15 日实测](温度偏差实测与KL放置位置_20261015.md)） |
| top-k | 只在 ① | 只保留概率最高的 k 个 | 也是一种截断，和 top-p 同一类问题；中间链路可能悄悄丢掉这个参数 |
| top-p | 只在 ① | 从高到低累加到 p 就停 | 截断之后所有环节都不知道发生过截断 |
| 每题采样数 G | ①、④a | 组的大小 | 同题样本在 batch 里必须相邻，按连续 G 条切组 |
| KL 系数 β | ③、④b（或 ⑤） | 约束离起跑模型多远 | 放 reward 还是放 loss，约束的对象不同（[10 月 15 日](KL估计器与放置位置的设计动机_20261015.md)） |
| γ、λ | ④c | 无 Critic 时保持 1，等于广播 | 广播之外唯一多做的事是把 KL 奖励沿序列累加 |
| 批级归一化 | ④d | 整批 token 平移 + 缩放 | 对 GRPO 是重复的第二次归一化（[同日崩溃机制](截断采样与批级归一化的双条件崩溃机制_20261016.md)） |
| clip ε | ⑤ | 限制同一批数据多次更新的累积偏移 | 整批只更新一次时 r ≡ 1，永不触发 |
| 拒绝采样上限 | ⑤ | w 过大时 mask 掉 token 或整条序列 | 平时几乎不触发，出问题时是防线 |
| minibatch 数 | ⑤ | 一批数据更新几次 | 与 Advantage 无关，Advantage 在切分前已算好 |
| 最大离策略版本差 | ①、⑥ | 允许数据比训练端旧几个版本 | 决定 w 的典型偏离程度（[Staleness 窗口](权重同步版本语义与Staleness窗口_20261008.md)） |

### 3.3 单次更新时，Loss 退化成什么

整批只更新一次、π_prox 又是同一份权重刚算的，则求梯度的那一刻 π_θ ≡ π_prox：

```text
r ≡ 1，clip 永不触发
梯度 = −A × w × ∇log π_θ(这个 token)
```

真正起作用的只剩 **A 的大小和符号** 与 **行为侧权重 w**。r 恒为 1 仍不能删，它是梯度的来源（[10 月 15 日 §3.1](单次更新下两个比值的分工与Clip的真实作用_20261015.md)）。

### 3.4 `π_prox / π_behave` 有什么用

**解决什么问题**：策略梯度的前提是样本来自正在求梯度的那个策略。异步训练打破了它：样本可能是旧版本权重生成的；即使同版本，推理引擎和训练引擎的数值也不完全一样。

**怎么修正**：重要性采样。每个 token 的 loss 乘 $w = \pi_\text{prox}/\pi_\text{behave}$：当前策略下更可能出现的 token 权重放大，反之缩小。w 极端时重要性采样方差爆炸，所以再加一道拒绝采样，按 token（w 超过上限）或按序列（几何平均超过上限）把样本排除出 loss。

**开了重算还有意义吗**：有，而且正是重算让它成为可能。重算产出 π_prox，让 `π_θ/π_prox` 变成 1，同时给了 `π_prox/π_behave` 一个干净的分子。整批只更新一次时，它是唯一还在起作用的 off-policy 修正。

**实际起多大作用**（定性）：

- 健康期：平均值几乎是 1，但逐 token 的范围不小；拒绝采样几乎不触发；
- 崩溃期：训推差异突然变大，行为侧近似 KL 明显偏负，拒绝采样开始成批过滤 token。这时它在当安全阀；
- 序列级权重比逐 token 权重贴近 1 得多：几何平均把正负偏差抵消了。

**这道防线的漏洞**：分母是 raw logprob（T = 1、未截断），不是样本真正被采出来的 q。T ≠ 1 时，温度带来的偏差会被当成“数据旧了”来加权；截断带来的 1/Z 则完全看不见（[同日崩溃机制 §3.5](截断采样与批级归一化的双条件崩溃机制_20261016.md#35-截断不在-ratio-里而在样本里被纠正的误解)）。

**实现上要核对的一点**：有的实现只在配置了拒绝采样时才把 w 乘进 loss；不配时 π_behave 根本不进入策略 loss。读框架时要确认这一点，不要默认它一直在修正。

### 3.5 名字带 “KL” 的四个指标（被纠正的混淆）

用户把“算 KL 正则”和“行为侧近似 KL”混成了一件事。log 比值的平均近似等于两个分布之间的 KL（k1 估计），所以框架里很多诊断量都叫 “approx_kl” 一类的名字。按“比较的是哪两个分布”区分：

| 指标（名字因框架而异） | 比较的是 | 用途 | 需要 Ref 吗 |
|---|---|---|---|
| 更新幅度近似 KL | log π_θ − log π_prox | 诊断：这一步走了多远；单次更新时恒为 0 | 不需要 |
| 行为侧近似 KL | log π_prox − log π_behave | 诊断：数据有多旧 + 训推差多少；也是 w 与拒绝采样的来源 | 不需要 |
| 训推直接差 | log π_behave − log π_θ | 诊断：训练模型与推理时的差异 | 不需要 |
| KL 奖励 / KL loss | log π_behave（或 π_θ）− log π_ref | **KL 正则**：不让模型离起跑模型太远 | **需要** |

只有最后一行是 KL 正则，也只有它需要 Ref。Ref 是冻结的起跑模型，作用就是提供 π_ref 这个锚点。所以“行为侧近似 KL 不为 0”说的是训推不一致，和“模型离初始权重多远”是两回事。

两个读数规则：

- **物理上不能为负的量出现负值**，先查定义是不是差了一个版本（[10 月 15 日](温度偏差实测与KL放置位置_20261015.md)）；
- **行为侧近似 KL 在 T = 1 时也不该正好是 0**：两套引擎的正常数值差，期望是一个极小的负数。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 更新幅度近似 KL 与 clip 比例每步都是 0 | 整批只更新一次，r ≡ 1 | 改成两个 minibatch 后应变为非 0 |
| 行为侧近似 KL 在 T < 1 的运行里明显为正 | 分子按 T、分母按 raw | 同一模型只改温度对照 |
| 崩溃后拒绝采样过滤比例突然上升 | 训推差异变大，是崩溃的结果 | 看它是否晚于熵上升出现 |
| 配置里写了 Ref，却没有 Ref 的显存和前向 | KL 系数为 0 且未开 KL loss，框架跳过创建 | 查启动日志里是否构建了 Ref |
| 改了 top-k 却没效果 | 参数在中间链路被丢弃 | 逐段核对推理引擎实际收到的采样参数 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| top-p/top-k 也参与训练端的 logprob 计算 | 只在采样时决定样本；训练端在完整词表上算 |
| 温度只影响采样 | 训练端重算时也除以 T；推理端 raw logprob 却常按 T = 1 记 |
| 名字里有 KL 就是 KL 正则 | 只有 KL 奖励/KL loss 是正则，其余是诊断量 |
| 算行为侧近似 KL 需要 Ref | 只用 π_prox 和 π_behave |
| 开了重算，推理端 logprob 就没用了 | 它仍是行为侧权重的分母 |
| 行为侧权重一直在修正 off-policy | 有的实现只在配置拒绝采样时才乘进 loss |
| 截断信息会传给训练端 | 截断后所有环节都不知道；真正的 q 没有任何一方记录 |
| Advantage 在每个 minibatch 里重新算 | 整批算一次、固定，然后才切 minibatch |

## 7. 一分钟复习

1. ① 采样（T、top-k/p，记 π_behave）→ ② 打分 → ③ 重算 π_prox、π_ref → ④ 组内 z-score、KL 奖励、GAE 广播、（批级归一化）→ ⑤ r·clip × w、拒绝采样 → ⑥ 同步。
2. top-k/p 只在 ①；T 在 ① 和 ③；截断之后没人知道发生过截断。
3. 五个分布：π_behave、q（没人记录）、π_prox、π_θ、π_ref。
4. 两个比值：`π_θ/π_prox` 管多次更新，单次更新恒为 1；`π_prox/π_behave` 管陈旧度与训推差，是唯一在起作用的修正。
5. 四个“KL”：三个诊断、一个正则；只有正则需要 Ref。

## 8. 自测问题

### 问题 1

按时间顺序说出 T、top-p、组内 z-score、批级归一化、clip、行为侧权重各在哪一段生效。

期望回答：T 在采样与重算；top-p 只在采样；组内 z-score 与批级归一化在算 Advantage（批级归一化在 GAE 之后、整批一次）；clip 与行为侧权重在算 Loss。

### 问题 2

整批只更新一次时，loss 里真正起作用的是什么？

期望回答：A 的大小和符号，以及行为侧权重 w（含拒绝采样）。r ≡ 1，clip 不触发，但 r 仍是梯度来源。

### 问题 3

行为侧近似 KL 和 KL 正则有什么区别？哪个需要 Ref？

期望回答：前者比较 π_prox 与 π_behave，诊断陈旧度与训推差，也是 w 的来源；后者比较当前策略与 π_ref，约束离起跑模型的距离。只有后者需要 Ref。

### 问题 4

为什么说行为侧权重这道防线有漏洞？

期望回答：分母是 raw logprob，不是真正采样用的 q。T ≠ 1 时温度偏差被当成陈旧度加权；截断的 1/Z 完全不可见，核外的词也从不出现在 batch 里。

## 9. 尚未解决与后续路线

- 分母改用真实采样分布（温度后、截断后的 logprob）对在线 PPO/GSPO 的影响，以及 TIS/MIS 类训推偏差修正；
- 多 minibatch 时 clip 与行为侧权重的相互作用；
- 序列级与 token 级拒绝采样的取舍。
