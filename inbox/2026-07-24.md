### 本次新增理解

- 预训练、SFT 与 RL 后训练不是三种完全不同的模型架构，而是同一模型在不同数据、目标和训练闭环下的不同阶段。
- Reward 不是一段新的“标准答案文本”，而是对生成结果的评价信号；Advantage 再把这个评价变成“这次行为相对基准好多少”的更新方向。
- Actor 与 Rollout Engine 可以持有同一套模型能力，但职责不同：前者负责反向传播和更新参数，后者负责高吞吐生成；参数更新后必须同步权重。
- MTP 在训练侧是“学习预测更远的后续 token”，在推理侧通常服务于“先草拟多个 token，再由主模型验证”，两侧相关但不能混为同一个步骤。
- 推测解码不仅涉及 token 是否被接受，还涉及 KV Cache 或其他模型状态如何提交、丢弃或回滚。
- 混合 Attention 模型可能同时维护普通 KV Cache 和其他递归状态；所有状态必须对应同一个 token 边界。

### 本次新增理解

- Old、Current 和 Reference Logprob 应在同一条已生成 Response 的相同 token 位置上比较；
- Prompt token 会参与 Forward，但策略 Loss 通常通过 Mask 聚焦需要学习的 Response token；

- KL 约束限制 Actor 偏离 Reference 过快；Reference 不是用于失败回滚的 Checkpoint。

### 本次新增理解

- 一条 RL Trajectory 不只有回答文字，还会携带 Response Token、Old Logprob、Loss Mask、Reward 和权重版本等训练元数据；
- 同一 Response Token 可能同时有 Old、Prox、Current、Reference 四类 Logprob，它们分别承担采样记录、单轮更新锚点、带梯度训练和参考策略约束等职责；
- `ratio = exp(current_logp - prox_logp)` 表示当前策略相对本轮更新锚点改变了多少；
- Advantage 决定希望概率上升还是下降，Policy Loss 把这个方向变成可反向传播的标量；
- PPO Clip 限制一次局部更新幅度，KL 约束限制 Actor 相对冻结 Reference 的策略漂移，二者不是同一机制；
- Logprob、KL、Entropy、Clip Ratio 属于算法稳定性指标，不等同于吞吐、显存和 GPU 利用率等系统性能指标；
- 组内回答 Reward 全部相同时，相对归一化得到的学习信号通常会很弱。
