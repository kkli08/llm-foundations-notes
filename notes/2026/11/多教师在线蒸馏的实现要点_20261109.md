## 0. 今天最终要解决的问题

1. （15:54）**帮我看一下目前遗留的 MOPD 分支大概是什么情况，具体的实现是什么样的？**

## 1. 先给结论

- **现状**：早期的大量调试提交被压成两个叠放的 PR，一个是多教师框架，一个是多模态五教师配方。框架 PR 还开着，没有评审，和主干冲突；配方 PR 已关闭。功能上能跑起来，但五教师训练还没有稳定跑完过 100 步，效果没有被证明。
- **按域路由，不是集成**：每条轨迹按数据来源只交给一个教师打分，不是多个教师对同一条做 ensemble。
- **优势**：`A = clip(sg(log π_T − log π_S), ±c) + α · A_task`，套进现有的 PPO-clip。α = 0 就是纯蒸馏；α 乘的是任务 RL 的优势，不是原始结果奖励。
- **精确配额不补位**：用最大余数法把域比例换成每个 batch 里各域的精确条数；一个槽位失败，用同一条样本重试，不拿别的域补，也不凑不完整的 batch。
- **补齐用真样本、丢分数**：条数不能被数据并行数整除时，复制一条真实轨迹补齐，补出来的分数直接丢掉。
- **数值检查要所有 rank 一起做、一起报错**：否则一个 rank 报错退出，其他 rank 会挂死在下一个集合通信上。
- **logp 和 mask 差一位**：位置 t 的 logp 对应的是 token t+1，mask 要先错一位再用。
- **防 NaN 分两层**：算比值前把无效位置的 logp 置零、log-ratio 截断；优化器那一步跨 rank 检查更新是否成功，失败就抛错，不让调度器、版本号和权重导出继续推进。PR 版本漏了后一层。
- **能跑起来不等于效果被证明**：同一份权重在两个引擎上算 logp 的一致性检查没通过；奖励解码没跳过特殊 token，格式分全部失效。

## 2. 前置概念

### 2.1 MOPD 的优势（复习）

| 项 | 含义 | 出处 |
|---|---|---|
| `sg(log π_T − log π_S)` | 逐 token 的蒸馏信号，期望是负的反向 KL | [10 月 26 日 §2.2](../10/在线蒸馏OPD与多教师MOPD_20261026.md#22-为什么-r_t-的期望就是负的反向-kl) |
| stopgrad | 差值当优势（权重），不是直接当 loss 求导 | [10 月 27 日 §3.1](../10/OPD损失的梯度陷阱与两种蒸馏分支_20261027.md#31-joint-分支detach-的教师项求导后消失) |
| `α · A_task` | 把蒸馏和结果奖励连成连续谱 | [10 月 29 日 §3.2](../10/MixRL与MOPD的分工以及只RL一次_20261029.md#32-生产版-mopd-不是纯蒸馏最容易忽略的一点) |

这次读到的实现和这三篇一致。多出来的是 `clip(·, ±c)`：教师和学生在个别 token 上分歧极大时，单个 token 的优势会非常大，截断防止它主导整步更新。

### 2.2 精确配额与比例采样

（整理时的理解）

| 采样方式 | 每个 batch 的域比例 | 失败后怎么办 | 风险 |
|---|---|---|---|
| 按比例随机抽 | 在目标附近波动 | 常见做法是拿别的样本补位 | 失败率高的域被系统性少采 |
| 精确配额 | 每个 batch 都严格等于目标 | 同一条重试，不补位 | 一个槽位一直失败就整步报错 |

补位的问题和 [10 月 21 日：按结果丢样本的选择偏差](../10/按结果丢样本的选择偏差与OpenAI兼容接口的字段契约_20261021.md) 同形：**"失败"和"内容"相关时，丢掉再补等于改了分布。**

最大余数法的例子：256 条，比例 0.25 / 0.25 / 0.20 / 0.15 / 0.15。

```text
256 × 比例   = 64, 64, 51.2, 38.4, 38.4
先取整数部分 = 64, 64, 51,   38,   38   → 合计 255，差 1
余数         = 0,  0,  0.2,  0.4,  0.4  → 余下的 1 条给余数最大的一项
结果         = 64, 64, 51,   39,   38
```

### 3.1 分支现状

| 线 | 内容 | 状态 |
|---|---|---|
| 早期 | 文本域的单、双教师在线蒸馏，以及第一版五教师多模态配方，上百次调试提交 | 已停，最后一条汇总了 NaN、OOM、奖励解码、缓存清理等修复 |
| 框架 PR | 多教师框架，十几个文件 | 开着，没有评审，和主干冲突 |
| 配方 PR | 五教师数据、流程、奖励和配方，叠在框架 PR 上 | 已关闭 |

两个 PR 的说明都写着测试放在本地分支上，没有推到远端。合并成本：主干之后又多了几十个提交，有 9 个文件两边都改过，包括训练器、actor 和配置这些核心文件。PR 里没有测试，按仓库规则合不进去。

### 3.2 算法：按域路由，不是集成

- 每条轨迹按数据来源这个字段，只路由给负责这个来源的那一个教师；
- 优势按 §2.1 计算，代入现有的 PPO-clip 目标；
- 配置校验：和旧的单教师配置互斥；路由字段目前写死为数据来源；只支持 token 级重要性采样；不能同时开 KL loss。

（整理时的理解）按域路由的含义是"每个领域有一个专家老师"，学生在每个领域只向那个领域的老师学。集成则是同一条回答听多个老师的平均意见，两者的信号和成本都不同。

### 3.3 配额与采样

- 用最大余数法把比例换成每个 batch 里各域的精确 prompt 数（§2.2）；
- 绕开原来按比例拼 batch 的逻辑，按固定的输入槽位逐个提交生成；
- 某个槽位失败时**用同一条样本重试**，最多 3 次，仍然失败就直接报错；
- 不用别的域补位，也不凑一个不完整的 batch，所以混合比例在每一步都严格成立；
- 代价：只支持离线模式，在线模式、动态 batch、动态过滤都会被直接拒绝。

### 3.4 教师打分与分布式补齐

打分发生在参考模型和教师之后、actor 更新之前：

1. 按路由把轨迹分组，并检查配额有没有偏；
2. 每个教师按顺序 forward（5 个教师串行，这是一个吞吐上的局限）；
3. 如果某组条数不能被数据并行数整除，**复制第一条真实轨迹来补齐，补出来的分数直接丢掉**；
4. 最后一次性把教师 logp 写回。

（整理时的理解）补齐时用真样本、不用全零或随机输入，是为了让补出来的那一条走的计算路径和真实样本一样，不会因为空输入触发别的分支或数值问题；分数丢掉，是为了不让重复样本改变权重。

### 3.5 数值防护：在哪一层拦

| 层 | 做法 | 防什么 |
|---|---|---|
| 打分之后 | 在 GPU 上检查 mask 覆盖的位置是不是都是有限值，再在所有 rank 之间做一次规约，统一结论 | 一个 rank 发现问题就自己报错退出，其他 rank 会挂死在下一个集合通信 |
| mask 对齐 | mask 先错一位再拿来检查 | 位置 t 的 logp 对应 token t+1，不错位会检查错位置 |
| 算比值之前 | 无效位置的 logp 先置零，log-ratio 截断到 ±20 | exp 溢出成 inf |
| 纯蒸馏时 | 不碰任务优势 | `0 × NaN = NaN`：系数是 0 也挡不住 NaN |
| 优化器那一步 | 所有 rank 同步检查"更新是否成功"和梯度范数，出问题就抛错 | 坏梯度被应用后，调度器、版本号和权重导出照常推进，坏权重被推给推理引擎 |

最后一层是核实时发现的问题：早期分支里有这段保护，PR 版本和主干都没有。早期调试里出现过"NaN 梯度被应用、坏权重被导出到推理引擎"，PR 版本可能会再出现。

（整理时的理解）前四层拦的是"这一步的数"，最后一层拦的是"这一步的副作用"。在线训练里，一次更新之后还有版本号 +1、权重同步、推理引擎加载，**数值检查要放在任何副作用之前，失败时整条链都不能前进。** 这和 [7 月 29 日：在线权重版本事务与 fail-closed](../07/MTP模型状态流与在线权重事务_20260729.md#7-在线同步的版本事务)、[11 月 5 日：0 × NaN 与学习率 0 挡不住 NaN](GPU映射错位与NaN归因_20261105.md#36-reward-nan把三类异常分开)、[10 月 15 日：集合通信前不能提前返回](../10/KL估计器与放置位置的设计动机_20261015.md#37-为-ppo-审一遍归一化组件四条通用检查) 是同一组规律。

### 3.6 工程配套

- 教师可以直接加载预先转换好的分布式 checkpoint 权重；
- 几个教师之间如果共享显卡，按依赖的拓扑顺序初始化；
- 每个教师可以单独设置是否 offload；
- 每一步结束时，要求所有分布式张量的缓存都完整清理掉，没清理干净就直接报错。

最后一条是把"资源泄漏"从慢慢积累的 OOM，变成第一步就暴露的错误。

### 3.7 "能跑起来"离"效果被证明"有多远

根据分支里的文档整理（没有查集群日志）：

| 阶段 | 结果 |
|---|---|
| 文本单、双教师 | 跑通过几十步到一百多步，但其中一组训练数据被污染，只能证明系统是稳的 |
| 数值一致性 | 同一份权重在两个训练引擎上分别算 logp 的对比，结果是不通过 |
| 五教师 | 一路解决了视频解码、actor OOM、统计与 RPC 死锁、定时器死锁，然后第 0 步反向出现 NaN；加了截断后又遇到教师 OOM；最近一次跑到约第 19 步后失败或被取消 |
| 奖励 | 奖励解码没有跳过特殊 token，格式分全部失效 |

结论：**还没有一次可信的 100 步五教师训练。**

（整理时的理解）这张表本身是一个读进度的模板：系统稳、数值一致、奖励正确、效果提升是四件事，前一件不成立，后面的读数都不可信（[10 月 29 日：测量不可信则后续分析全部失效](../10/截断主导下的训练Reward不升与输出预算_20261029.md)）。

另外，主干上旧的单教师路径里又看到了 10 月 27 日分析过的问题：惩罚项里的教师项被 detach，求导后只剩 `∇log π`。当天的说明被截断，结论以 [10 月 27 日 §3.1](../10/OPD损失的梯度陷阱与两种蒸馏分支_20261027.md#31-joint-分支detach-的教师项求导后消失) 为准。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 某个域在训练里越来越少 | 失败后用别的域补位 | 每步统计各域条数 |
| 一个 rank 报错，其他 rank 卡住 | 检查结论没在所有 rank 间统一 | 看其他 rank 停在哪个集合通信 |
| 检查报 NaN 的位置对不上 | mask 没错一位 | 对齐 logp 和 token 的下标 |

| 格式分全是 0 | 解码没跳过特殊 token | 看解码后的原文 |
| 训练几步后 OOM | 缓存没清 | 每步结束检查缓存是否清空 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 多教师就是多个老师打分取平均 | 这里是按域路由，每条只给一个老师 |
| α 乘的是结果奖励 | 乘的是任务 RL 的优势 |
| 失败了拿别的样本补上就行 | 会改掉域的比例和分布 |
| 补齐用空样本最省事 | 用真样本补，分数丢掉 |
| 本 rank 发现 NaN 就本地报错 | 要所有 rank 统一结论一起报错 |
| 学习率或系数为 0 就安全 | 0 × NaN 仍是 NaN |
| 跑起来了就快好了 | 系统稳、数值一致、奖励正确、效果提升是四件事 |

## 7. 一分钟复习

1. 按域路由：每条轨迹按数据来源只交给一个教师。
2. `A = clip(sg(log π_T − log π_S), ±c) + α · A_task`；α = 0 是纯蒸馏。
3. 最大余数法：256 × (0.25, 0.25, 0.2, 0.15, 0.15) → 64 / 64 / 51 / 39 / 38。
4. 失败用同一条样本重试，不补位、不凑不完整的 batch。
5. 不能被 DP 整除：复制真样本补齐，丢掉补出来的分数。
6. 有限值检查所有 rank 一起做、一起报错；mask 先错一位。
7. 算比值前置零加截断；纯蒸馏不碰任务优势。
8. 优化器层检查更新是否成功，失败就不推进调度器、版本和导出。
9. 现状：框架 PR 冲突、没测试；还没有可信的 100 步五教师训练。

## 8. 自测问题

### 问题 1

MOPD 的多教师是怎么分工的？优势怎么算？

期望回答：按数据来源路由，每条轨迹只交给负责这个来源的一个教师，不是集成。逐 token 优势是 `clip(sg(log π_T − log π_S), ±c)`，再加 `α × 任务 RL 优势`，代入 PPO-clip；α = 0 是纯蒸馏。差值要 stopgrad 后当优势用，截断防止个别分歧极大的 token 主导更新。

### 问题 2

为什么用精确配额而不是按比例随机抽？失败时为什么不补位？手算 256 条、比例 0.25 / 0.25 / 0.2 / 0.15 / 0.15。

期望回答：按比例抽，每个 batch 的域比例会波动；失败后拿别的样本补位，失败率高的域会被系统性少采，等于改了分布。精确配额用同一条样本重试，不补位、不凑不完整 batch。256 × 比例 = 64、64、51.2、38.4、38.4，整数部分合计 255，余下 1 条给余数最大的一项，得到 64 / 64 / 51 / 39 / 38。

### 问题 3

分布式打分时有哪三处容易出错？

期望回答：一是条数不能被数据并行数整除时，要复制真实轨迹补齐、丢掉补出来的分数；二是有限值检查要在所有 rank 之间统一结论再一起报错，否则一个 rank 退出、其他 rank 挂死在下一个集合通信；三是 mask 要先错一位，因为位置 t 的 logp 对应 token t+1。

### 问题 4

PR 版本漏掉的那层保护是什么？为什么要放在副作用之前？

期望回答：优化器那一步要在所有 rank 上同步检查更新是否成功和梯度范数，出问题就抛错。在线训练里一次更新之后还有调度器推进、版本号 +1、权重导出到推理引擎；如果坏梯度被应用后这些照常推进，坏权重就会被推给推理引擎。数值检查要在任何副作用之前，失败时整条链都不前进。
