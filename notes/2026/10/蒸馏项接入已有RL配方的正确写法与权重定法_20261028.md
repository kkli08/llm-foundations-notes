## 1. 先给结论

- **“没加进 loss”和“没进梯度”是两件事**：教师项的**数值**在 loss 里、日志里也有读数；但它 detach 后对 θ 是常数，反向传播后整项消失。审查这类问题要问“求导后还剩什么”，而不是“loss 里有没有它”。
- **需要 off-policy 修正的理由与奖励来源无关**：只要“写答案的模型”≠“被更新的模型”，就需要重要性比值；有比值就需要刹车。所以“纯蒸馏和 PPO 不搭边”对**目标**成立，对**数据**不成立。叫它“PPO 保护”是用词不准，准确说是 **off-policy 修正的保护**。
- **比值其实是两段，分别由两道刹车管**：版本之间那段由 clip 管，推理端与训练端之间那段由拒绝采样管。整段替换 loss 的写法把两段乘在一起用，却哪一段都没管。极端 token 上比值可达 e⁶ ≈ 400 倍。
- **成熟实现提供两条正确接法**：① 当奖励用——逐 token 蒸馏值 detach 后取负当优势，送进已有的裁剪 surrogate loss；② 当监督 loss 用——只能用 k2 / k3 / top-k 正向 KL，**显式禁止 k1**，并把这条禁令写进**配置校验**。
- **数值用哪个估计器、梯度用哪个，可以分开选**（straight-through）：前向按 k3 读数、反向换成 k2 的梯度，目的就是“读数好看 + 梯度方向对”。
- **蒸馏权重 β 不是绝对值，是两项梯度的相对比例**：定的是 `β·E|log π_θ − log π_T|` 与 `E|A|` 的比。< 0.3 是正则、≈ 1 是等量、≫ 1 近似纯蒸馏。别人的默认值不能照搬，更不能照搬“为一个不起作用的 loss 调出来的值”。
- **要定 β 先补指标**：优势只记带符号均值时，归一化后接近 0，看不出量级；必须记 |δ|、|A| 的均值与最大值，以及 |δ| 超阈的占比。
- **蒸馏项天然前强后弱**，但长尾 token 上 δ 可以很大（教师认为极不可能时），所以要看尾部分布，必要时截断。
- **修这类 bug 有三个连带影响**：旧基线失效（以前的“KD + RL”其实就是纯 RL）、旧测试把错误行为写死、修复本身带来行为变化（原先被保留的样本现在会被过滤）。三件都要显式写出来。
- **接新算法项之前先 diff 基线配方的开关粒度**：序列级重要性采样会把逐 token 的优势抹平，而逐 token 的蒸馏项不受比值粒度影响。

## 2. 前置概念

### 2.1 比值的两段与两道刹车

写答案的那份模型（行为策略）和正在更新的模型之间，比值可以拆成两段：

```text
π_θ / π_behave  =  (π_θ / π_prox) × (π_prox / π_behave)
                    └── 同一批内多次更新 ──┘ └── 陈旧 + 训推数值差 ──┘
                         由 clip 管                由拒绝采样 / clamp 管
```

| 段 | 来源 | 谁管 |
|---|---|---|
| π_θ / π_prox | 一批数据切成多个 minibatch 依次更新，后面的 minibatch 模型已经变过 | 比值裁剪（clip） |
| π_prox / π_behave | 异步 rollout 落后几个版本 + 推理引擎与训练引擎算出的 logp 本就有数值差 | 拒绝采样（超上限 mask 掉）或 clamp |

完整推导见 [异步离策略的三个来源与 IS/RS](异步离策略的三个来源与IS和RS_20261019.md#32-异步为什么不是严格-on-policy三个来源) 与 [解耦 PPO 的两段比值相乘](异步训练下的Minibatch个数与解耦PPO来源_20261020.md)。**这两道刹车针对的是比值本身，和奖励从哪来完全无关。**

### 2.2 蒸馏项与 RL 项在梯度上怎么相加

修好之后，每个 token 的梯度是两项之和：

```text
RL 项：      A_t · ∇log π_θ                         组内归一化后 E|A| 约在 1 附近
蒸馏项：  β · δ_t · ∇log π_θ        其中 δ_t = log π_θ(o_t) − log π_T(o_t)
```

β 就是蒸馏权重。两项的形状完全一样（都是“系数 × ∇log π”），所以 β 的意义只有一个：**让 `β·E|δ|` 相对 `E|A|` 落在想要的比例上**。

## 3. 完整原理

### 3.1 “没加进 loss”还是“没进梯度”（当天的第一个追问）

问题问的是“教师算出来的那一项是不是没加到最后的 loss 里”。答案是：**加进去了**——loss 的数值里有它，日志里的蒸馏项读数也有值。坏掉的是梯度：

```text
∂/∂θ [ log π_θ(o) − log π_T(o) ] = ∇log π_θ(o) − 0 = ∇log π_θ(o)
```

教师项已 detach，对 θ 是常数，求导即消失。类比：loss 写成 `x − 5` 还是 `x − 100`，对 x 的梯度都是 1，减掉的常数是多少无关紧要。

同一个 token 的两种情形对照（学生给采到的 token A 的 logp 是 −1）：

| 情形 | 教师给 A 的 logp | loss 值 | 现有写法的梯度 | 正确的梯度 |
|---|---|---|---|---|
| 教师很认可 A | −0.1 | −0.9 | ∇log π_θ(A) | −0.9 × ∇log π_θ(A)：提高 A 的概率 |
| 教师很不认可 A | −10 | +9 | ∇log π_θ(A)，与上一行**完全相同** | +9 × ∇log π_θ(A)：大幅压低 A |

两行的 loss 值相差 10，梯度却一模一样——这就是“值变了梯度没变”的样子。而且剩下的那一项把每个采到的 token 一律往下压同样的量，在自己的样本上期望恰好为 0（score function 恒等式），平均下来只剩噪声。完整推导与 k1/k2/k3 的梯度对照见 [10 月 27 日 §3.1～3.2](OPD损失的梯度陷阱与两种蒸馏分支_20261027.md#31-joint-分支detach-的教师项求导后消失)。

**通用教训**：审 loss 时，“这一项在不在 loss 里”“日志里有没有读数”都不是证据，**唯一的问题是对参数求导后还剩什么**。

### 3.2 为什么纯蒸馏也需要 off-policy 的刹车（当天两次没看懂的点）

一句话：**目标和 PPO 没关系，但“数据来自旧模型”这个问题和 PPO 一模一样，而处理这个问题需要的正是 PPO 那套刹车。**

分三步看：

**第一步，理想情况。** 学生写答案 → 教师打分 → 学生更新。写答案的和被更新的是同一个模型，什么修正都不需要。此时比值恒为 1，这一节的问题都不存在。

**第二步，实际情况：写答案的和被更新的不是同一个模型。**

- 答案是推理引擎里那份学生写的，异步下它可能落后 1～2 个版本；
- 即使版本相同，推理引擎和训练引擎算出的概率也有数值差；
- 一批数据还可能切成多个 minibatch 依次更新。

所以代码给每个 token 乘了修正系数 `ratio = 现在的学生给这个 token 的概率 / 当时写答案那份学生给的概率`。绝大多数 token 的 ratio 在 0.9～1.1，没问题。

**第三步，问题只出在少数 token 上。** 例如某 token 写答案时概率约 0.03%、现在的学生给到 13%：

```text
ratio = e^(−2 − (−8)) = e^6 ≈ 403
```

这**一个** token 的梯度被放大约 400 倍，可能压过整批数据。走 PPO 路径时它会先被拒绝采样 mask 掉、再被 clip 裁剪；整段替换 loss 的纯蒸馏路径里，它原样进入更新。

所以：**“纯蒸馏不需要 PPO”说的是目标函数；它需要的是 off-policy 修正，而框架里实现 off-policy 修正的那套代码恰好长在 PPO loss 里。** 如果真的严格 on-policy（落后 0 个版本、只有 1 个 minibatch、训推数值一致），ratio ≈ 1，这个问题确实不存在——但异步默认配置正好不满足这三条。

### 3.3 参数“看上去是开着的”比没写更危险

这两道刹车的参数照常写在 actor 配置段里，看上去是开启状态。但纯蒸馏分支用自己的公式**整段覆盖**了前面算好的 loss，于是：

- 参数被解析了、校验通过了、日志里也能打印出来；
- 实际的 loss 根本没经过它们。

这与 [继承来的配置字段写了不生效](OPD损失的梯度陷阱与两种蒸馏分支_20261027.md#37-可配置项的三类)、[配置丢值要看消费端](生成长度上限的意义与长跑对照的读数口径_20261023.md) 是同一类问题：**“配置里写了”到“被消费端读到并生效”之间有好几道缝**。审查时要顺着“谁读了这个值、读完之后它参与了哪一步计算”走到底。

### 3.4 成熟实现的两条正确接法，以及把禁令写进配置校验

对照一个成熟开源框架的蒸馏实现，蒸馏项接进 loss 只有两种方式，由一个开关切换：

| | 当奖励用（默认） | 当监督 loss 用 |
|---|---|---|
| 怎么算 | 逐 token 蒸馏值先 **detach**、取负号当作 advantage，再送进已有的裁剪 surrogate loss（同时带上行为侧权重） | 直接对蒸馏值反传 |
| 可用的估计器 | 推荐 k1，此时 advantage = log π_T − log π_θ | 只能 k2、k3 或 top-k 正向 KL，**禁止 k1** |
| 教师怎么起作用 | 作为 advantage 的大小，乘在 ∇log π 前面 | k2 的梯度是 (log π_θ − log π_T)·∇log π，教师留在系数里 |
| 与任务奖励组合 | loss = 任务 loss + 系数 × 蒸馏 loss，蒸馏 loss 本身已是上面两种正确写法之一 | 同左 |

两条路**都让教师进入梯度**，区别只是“教师当优势”还是“教师当监督目标”。

最值得抄的是最后一句：**“k1 + 非 policy-gradient 写法”在配置校验里直接报错**，报错理由正是“k1 loss 对参数的梯度不依赖教师的 logprob”。已经知道的梯度陷阱，与其写在文档里，不如做成**启动即失败**的校验——文档会被跳过，校验不会（同 [快速失败优于只告警](训练守护的拆解与推理侧弹性扩缩容_20261027.md#31-拆解顺序先便宜且后面都要用的最难的放最后)）。

### 3.5 数值用一个估计器、梯度用另一个（straight-through）

同一框架还支持 `k3+` 这类写法：**前向数值按 k3 算，反向梯度换成 k2 的**。

- 动机：k3 作为 KL 的数值估计无偏、非负、方差小，读数好看；但它进 loss 的梯度对应**正向** KL；k2 的数值有偏，梯度却是精确的反向 KL 梯度（对照表见 [k1/k2/k3 四种写法的期望梯度](OPD损失的梯度陷阱与两种蒸馏分支_20261027.md#32-正确的两种写法k2-进-loss或把-r_t-当优势)）。
- 做法：`loss = k2 + (k3 − k2).detach()`。前向等于 k3，反向等于 ∇k2。
- 通用化：**“我想看的数”和“我想传的梯度”不必是同一个表达式**。凡是“这个估计器读数好、那个估计器梯度对”的场合，都可以用这个技巧，而不是在两者之间二选一。

### 3.6 数值保护：loss 截断与 logp 下限

同一实现默认带两个常数保护：蒸馏 loss 截断（量级 10）、logp 下限（量级 −10）。这不是调参，而是承认一件事：**教师在长尾 token 上会给出极端分数**，而 δ 直接当系数乘在梯度上。没有这两个保护时，单个长尾 token 就能主导一次更新。

### 3.7 蒸馏权重 β 怎么定

**β 没有通用值，它本质上是两项梯度之间的相对比例**（§2.2）。要定的是 `β·E|δ|` 对 `E|A|` 的比：

| 比例 | 含义 |
|---|---|
| 小于约 0.3 | 教师只起正则 / 引导作用，主导的仍是奖励 |
| 约等于 1 | 教师和奖励分量相当 |
| 远大于 1 | 几乎就是纯蒸馏 |

两个“不能照搬”的参考值：

- 别的框架联合模式下的默认系数（量级 1.0）是在**它自己的优势尺度**下定的；
- 本地原有的默认值（量级 0.005）是配着那个**不起作用**的 loss 调出来的——给一个期望梯度为 0 的项调权重，调出来的数没有任何意义。

还有两点与长跑稳定性有关：

- **蒸馏项天然前强后弱**：学生越接近教师，δ 越小，这一项自动衰减。不需要人工衰减调度。
- **长尾 token 风险**：教师认为极不可能的 token（例如 log π_T = −20）会给出很大的 δ。所以 smoke 里除了看均值，还要看 **δ 的尾部**；尾部确实很重时再加截断（§3.6）。

可操作的定法：smoke 跑 2～3 步，读出 δ 与 |A| 的量级，把 β 定在“蒸馏分量约为 RL 分量的 0.3～1 倍”。按量级估计多半落在 0.1～1 之间，具体数要等测出来再定。**先测量再定值，而不是先定值再解释。**

### 3.8 要定 β 先把指标补上

这里有一个很容易踩的坑：**优势通常只记带符号的均值**，而组内 / 批级归一化之后它接近 0 —— 从这个读数完全看不出 |A| 的量级，也就无法定 β。

要补的是：

| 指标 | 为什么要 |
|---|---|
| E\|δ\|、max\|δ\| | 蒸馏项的量级与尾部 |
| E\|A\| | RL 项的量级（带符号均值无效） |
| \|δ\| 超过 1 / 5 / 10 的 token 占比 | 判断尾部有多重、要不要截断 |
| 教师前向每步的额外耗时 | 成本归因 |

通用教训：**要比较两项的相对大小，就必须记录绝对值或分位数；均值会被符号抵消。** 这类只为定参服务的日志应该放在实验包里，不进主干代码。

### 3.9 教师位置对齐：只 roll 一部分张量就会错位

另一个相关实现里的对齐问题，失败机制值得单独记：

- 训练时第 t 个位置预测的是 token t+1，所以逐 token 的量需要统一移位；
- 代码在计算优势时移位了掩码和学生 logp，**却没有移位教师 logp**；
- 结果：第一个 token 的教师分数和 0 比，后面每个 token 都和**前一个** token 的教师分数比。

这不会报错，数值也在合理范围里，只是整条序列的信号全错一位。检查方法仍是 [把学生自己当教师，R 应恒为 0](在线蒸馏OPD与多教师MOPD_20261026.md#35-接入训练与测试体系时的检查点)——错位时这个恒等式立刻不成立。

**通用教训**：同一口径的逐 token 张量（掩码、学生 logp、教师 logp、奖励、优势）必须**在同一处、一起**移位；分散在多处移位，新增一个张量时就会漏。

### 3.10 修这类 bug 的三个连带影响

**① 旧基线失效。** 修好之后蒸馏权重第一次真正生效，于是以前跑出的“KD + RL”曲线实际上就是纯 RL——**不能当蒸馏基线**，权重也要重新调。修 bug 会让一批历史结论的语义变化，这件事必须主动写出来，否则后面的人会拿它当对照。

**② 旧测试把错误行为写死了。** 已有测试把旧的（错误的）梯度当成期望值 pin 住：期望“joint 分支的梯度与教师无关”、期望“纯蒸馏不裁剪”。修复必然让它们失败。处理方式是：

- 按新语义重算期望值（手算结果要与新代码实际输出一致，而不是把实际输出抄进测试）；
- 保留该测试原本真正想守的性质（掩码行为、跨 microbatch 的分母不变）；
- **区分“测试固化了 bug”和“原作者有意的设计”**——不确定时在改动说明里点名，交给维护者判断，而不是默默改掉。

**③ 修复带来的行为变化要点明。** 原测试的注释说明：拒绝采样之后，旧的蒸馏分支仍**保留**那个被判为过时的 token；修好之后纯蒸馏会和 RL 一样把它去掉。这是“让蒸馏走同一套保护”的必然结果，但也可能是原先有意为之。**一次 bug 修复的说明里，应该同时写“修了什么”和“顺带改变了什么”。**

### 3.11 接新项之前先 diff 基线配方的开关粒度

规划“在已有长跑配方上加一组新算法”时，当天一条很具体的教训：

- 基线本身**已经**是序列级重要性采样（不开 ref、不做批级归一化），所以序列级算法那一组只需要改 clip 范围、loss 聚合方式和每批更新次数——**差异比预想的小**；
- 但带 critic 的那一组**必须改回 token 级**重要性采样，否则逐 token 的 GAE 优势会被按序列取平均而抹平（同 [critic 逐 token 优势被序列级平均抹掉](GSPO与PPO组合时的优势形状与GSPO-token_20261021.md)）；
- 逐 token 的蒸馏项是在 PPO loss 之外单独按 token 算的，**不受比值粒度影响**，所以蒸馏那一组只多一个教师。

**规律：比值粒度、优势粒度、loss 聚合粒度是三个独立开关**（见 [三个独立开关](GSPO开关解耦与按轮序列比值_20261019.md)），加任何新项之前先把基线的三个粒度写出来，再看新项落在哪一层。“只改算法名”往往同时动了好几层。

另外两条同类前置核实：共卡的附加模型（教师、critic）要确认卸载开关在基线里是开还是关；**没有在某个硬件 / 站点上跑过，就不能假设能跑**（同 [换硬件先 diff 该硬件可用配方](GSPO对照实验的Clip比例读法与学习率预热口径_20261021.md#37-换硬件后的两处后端设置推理卡死与反向-nan)）。

### 3.12 长跑成本的结构：步时由环境执行主导

规划多组对照时顺带确认的成本结构（多轮 agentic 任务、长上下文）：

```text
每步 ≈ rollout（约 4000 s，与环境执行强相关） + 训练（约 250 s）
100 步 ≈ 5 天 / 组；四组并行 ≈ 四倍节点数、同样的 5 天
```

- **rollout 占绝大部分**，而其中大半时间是会话在环境里执行（量级 65%），trainer 大部分时间在等；
- 推论一：**优化训练侧对步时几乎无感**，要缩短步时得动环境并发与长尾；
- 推论二：这个量级的实验，排队 + 跑完是**天级**的，所以“先 smoke 2～3 步量出 δ 与 |A|”不是流程负担，而是唯一能在定权重上少错一轮的办法；
- 推论三：汇报方案时要先把“这是 N 个节点 × 约 5 天”说清楚，让决策的人知道代价（同 [成本先拆再优化](路由回放的引用所有权校验位置与开销拆解_20261013.md#34-取回为什么慢先拆开再优化)）。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 蒸馏项日志有值，曲线却和纯 RL 几乎一样 | 值进了 loss，梯度里没有教师 | 换一个教师看梯度是否变化；小词表按精确期望手算 |
| 纯蒸馏偶发梯度尖峰 | 比值两段相乘且无裁剪，长尾 token 比值可达数百倍 | 统计该分支内比值的最大值与分位数 |
| 配置里 clip / 拒绝采样写着却不起作用 | 分支用自己的公式整段覆盖了 loss | 顺着消费端找：谁读了这个值、读完参与了哪一步 |
| 长尾 token 主导一次更新 | δ 直接当系数，教师在罕见 token 上给极端分数 | 看 \|δ\| 超过 1/5/10 的占比；加 loss 截断与 logp 下限 |
| 想定 β 却发现看不出量级 | 优势只记带符号均值，归一化后接近 0 | 补记 \|A\|、\|δ\| 的均值与最大值 |
| 教师信号整体错一位、但不报错 | 移位只对部分逐 token 张量做了 | 学生自己当教师，检查 R 是否恒为 0 |
| 修完 loss 后旧测试大面积失败 | 旧测试把错误梯度写成期望值 | 手算新语义的期望值；区分“固化 bug”与“有意设计” |
| 加一组“只换算法”的对照，结果差异很大 | 同时动了比值粒度、优势粒度、loss 聚合 | 先把基线三个粒度写出来再 diff |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| “教师对梯度不起作用”= 教师项没加进 loss | 加进去了，值和日志都有；求导后消失 |
| loss 里有这一项、读数在变，就说明它在起作用 | 唯一的判据是对参数求导后还剩什么 |
| 纯蒸馏是 on-policy 蒸馏，和 PPO/GRPO 不搭边（**当天两次没懂**） | 目标无关，但数据来自旧模型这件事完全相同，需要同一套刹车 |
| 这组保护叫“PPO 保护” | 是 off-policy 修正的保护，与奖励来源无关 |
| 配置里参数写着就说明保护开着 | 分支可能整段覆盖 loss，参数被解析但不参与计算 |
| 估计器要么选读数好的、要么选梯度对的 | 可以前向用一个、反向用另一个（straight-through） |
| 蒸馏权重可以照搬别人的默认值 | 它是相对比例，取决于本地的优势尺度；为无效 loss 调出的值更没有意义 |
| 蒸馏项要配衰减调度 | 学生趋近教师时 δ 自然变小，本来就前强后弱；要管的是长尾不是衰减 |
| 优势的均值能代表优势的量级 | 归一化后带符号均值接近 0，必须看绝对值或分位数 |
| 修 bug 只需说明改了什么 | 还要说明旧结论失效、旧测试为何改、顺带改变了什么行为 |
| “只换算法名”的对照只差一个变量 | 比值粒度 / 优势粒度 / loss 聚合是三个独立开关，容易被一起动 |

## 7. 一分钟复习

1. 教师项 detach 后进 loss：**值在、梯度没**。审 loss 只问“求导后还剩什么”。
2. 同一 token 教师认可与否，loss 差 10，梯度完全相同 → 这就是“值变梯度不变”。
3. 纯蒸馏需要刹车的理由与奖励无关：写答案的模型 ≠ 被更新的模型 → 要比值 → 要刹车。叫 **off-policy 修正的保护**。
4. 比值两段：π_θ/π_prox 由 clip 管、π_prox/π_behave 由拒绝采样管；整段替换 loss = 两段相乘且都不管；e⁶ ≈ 400 倍。
5. 两条正确接法：detach 当优势送进裁剪 loss；或 k2/k3 当监督 loss（禁 k1）。**把 k1 禁令写进配置校验**。
6. straight-through：前向 k3、反向 k2 → 数值与梯度可以分开选。
7. 数值保护：蒸馏 loss 截断（约 10）、logp 下限（约 −10）。
8. β = 相对比例：`β·E|δ|` 对 `E|A|`；< 0.3 正则、≈ 1 等量、≫ 1 近纯蒸馏；smoke 先量再定（多半 0.1～1）。
9. 定 β 先补指标：带符号均值被抵消 → 记 |A|、|δ| 的均值/最大值与 |δ| 超 1/5/10 的占比。
10. 蒸馏项前强后弱（δ 自然变小）；风险在长尾。
11. 教师错位：只 roll 了掩码和学生 logp、没 roll 教师 logp → 每个 token 和前一个比；用“学生当教师 R ≡ 0”查。
12. 修 bug 三连带：旧“KD+RL”基线其实是纯 RL；旧测试写死了错误梯度；修复顺带改变了过滤行为。
13. 加新项先 diff 基线的三个粒度；步时由环境执行主导（rollout 约 4000 s vs 训练约 250 s）→ 优化训练侧无感，先 smoke 再长跑。

## 8. 自测问题

### 问题 1

“教师对梯度完全不起作用”，是不是说教师项没有加进最终 loss？用一个 token 的两种情形说明。

期望回答：不是，加进去了，loss 值和日志读数都有。教师 logp 已 detach、对 θ 是常数，求导后整项消失，只剩 ∇log π_θ。同一个被采到的 token，教师给 −0.1 与给 −10 时 loss 值差 10，但梯度完全相同；正确写法应在梯度前乘上 (log π_θ − log π_T)。判据是“求导后还剩什么”，而不是“loss 里有没有它”。

### 问题 2

纯蒸馏的目标和 PPO 无关，为什么它仍然需要比值裁剪和拒绝采样？

期望回答：因为写答案的模型不是被更新的模型——异步 rollout 落后 1～2 个版本、推理引擎与训练引擎的 logp 有数值差、一批数据切成多个 minibatch 依次更新。所以要乘重要性比值；有比值就有极端值风险（例如 e⁶ ≈ 400 倍），需要刹车。这套保护针对的是比值，与奖励来源无关，叫“off-policy 修正的保护”更准确。若严格 on-policy（0 版本差、1 个 minibatch、训推一致）则不需要。

### 问题 3

比值 `π_θ/π_behave` 可以拆成哪两段？各由什么机制管？整段替换 loss 的写法错在哪？

期望回答：拆成 (π_θ/π_prox) × (π_prox/π_behave)。前一段来自同一批内多次更新，由 clip 管；后一段来自陈旧与训推数值差，由拒绝采样或 clamp 管。整段替换 loss 的写法把两段乘在一起直接用，两道刹车都没经过，而参数还照写在配置里，看上去是开着的。

### 问题 4

把蒸馏项接进已有 RL loss 的两条正确写法分别是什么？为什么要把“k1 + 监督写法”做成配置报错？

期望回答：① 逐 token 蒸馏值 detach 后取负当 advantage，送进已有的裁剪 surrogate loss，裁剪、拒绝采样、聚合权重全部复用；② 当监督 loss 用，但只能用 k2 / k3 / top-k 正向 KL。k1 进 loss 的梯度不依赖教师 logprob，期望为 0，是已知陷阱；写在文档里会被跳过，做成启动即失败的配置校验才挡得住。

### 问题 5

`loss = k2 + (k3 − k2).detach()` 想达到什么效果？这反映了什么通用技巧？

期望回答：前向数值等于 k3（无偏、非负、方差小，读数好看），反向梯度等于 ∇k2（精确的反向 KL 梯度）。通用技巧是“想看的数”和“想传的梯度”不必是同一个表达式，可以用 straight-through 分别选择，而不是二选一。

### 问题 6

蒸馏权重 β 该怎么定？为什么不能直接用别人的默认值，也不能用本地原有的默认值？

期望回答：β 是蒸馏项与 RL 项梯度的相对比例，要定的是 β·E|δ| 对 E|A| 的比：< 0.3 为正则、≈ 1 为等量、≫ 1 近似纯蒸馏。别人的默认值是在它自己的优势尺度下定的；本地原有的默认值是配着一个期望梯度为 0 的 loss 调出来的，没有意义。做法是 smoke 跑 2～3 步量出 δ 与 |A| 的量级，再把 β 定在 0.3～1 倍分量上（量级多半 0.1～1）。

### 问题 7

要定 β，为什么优势的常规读数不够用？要补哪些指标？

期望回答：优势通常只记带符号均值，归一化后接近 0，正负相互抵消，看不出量级。要补 E|δ|、max|δ|、E|A|，以及 |δ| 超过 1/5/10 的 token 占比（判断尾部是否需要截断），还有教师前向的额外耗时。通用原则是比较两项相对大小必须用绝对值或分位数。

### 问题 8

修好这类 loss bug 后，有哪三件连带影响必须写进说明？

期望回答：① 旧基线失效——以前的“KD + RL”曲线因为权重不起作用，实际上就是纯 RL，不能当蒸馏基线，权重要重调；② 旧测试把错误梯度写成了期望值，必须按新语义手算期望，并区分“测试固化了 bug”与“原作者有意设计”；③ 修复顺带改变了行为——原先被保留的、经拒绝采样判为过时的 token，现在会和 RL 一样被过滤，这一点要主动点明。

## 9. 尚未解决与后续路线

- smoke 实测 δ 与 |A| 的量级，确定 β，并判断尾部是否需要截断；
- 教师与 actor 共卡时初始化是否 OOM、教师前向每步的额外耗时占比；
- 两条正确接法（当优势 vs 当监督 loss）在同一配方下的效果差别，目前只有理论对照；
- 教师 tokenizer 校验、教师温度与 actor 采样温度的对齐、生命周期收尾（关闭时销毁教师）仍未补齐；
- 长跑对照的四组设计仍待确认：基线三个粒度的 diff 已清楚，但新硬件 / 新站点上的可行性没有证据；
- 多轮 agentic 任务里，蒸馏信号与轮次级信用分配怎么配合（只用当前 token 的 γ = 0 近似在长轨迹上的影响）。
