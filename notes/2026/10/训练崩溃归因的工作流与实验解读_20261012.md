## 1. 先给结论

- **KL 不是根因，之前的主因假设被否定**：只把 KL 系数改为 0 的一臂照样崩，症状完全相同，只是晚了十几步；而崩溃起点本身就有约 10 步以上的运行间方差，“晚崩”不能当作 KL 能延缓崩溃的证据。
- **梯度范数暴涨是崩溃的结果，不是原因**：全零组时任务 Advantage 为 0；带 KL 的配置还剩被批归一化放大的 KL 项，梯度范数飙到几百；不带 KL 的直接为 0。
- **稳/崩对照把嫌疑缩到批级 Advantage 归一化**：两组稳定的都没做，两组崩的都做了。但这只是相关性——稳定组同时改了很多别的东西，必须单变量验证。
- **先止血、再定位**：交付可以先用已验证稳定的配置并注明差异；定位清楚才能改默认配置，避免别人再踩坑。
- **每个实验先写预测**；能直接观测机制的诊断指标比“改了之后不崩”更有说服力；打包实验要警惕隐藏的混杂。

## 2. 前置概念

### 2.1 先行指标为什么先动

| 指标 | 直觉 | 反映 |
|---|---|---|
| 熵 | 模型下笔时有多“犹豫”：概率集中还是摊开 | 策略分布正在被怎样改 |
| 梯度范数 | 每一步把参数推多远 | 这批数据里信号有多强、方向是否异常 |
| Reward | 车还在不在路上 | 改完之后的结果 |

Reward 晚动有两层原因：

1. **行为有累积**：分布被拉平一点，任务不会马上失败，累积到一定程度行为才坏；
2. **异步训练的延迟**：样本由落后若干版本的权重生成，Reward 曲线反映的是几步之前那个模型（[Staleness 窗口](权重同步版本语义与Staleness窗口_20261008.md)）。

比喻：熵是方向盘的抖动，梯度范数是每次打方向盘的力度，Reward 是车还在不在路上。读图规则（相对自身早期、看连续 3～5 步趋势、多指标同看）见 [10 月 10 日 §3.1～3.3](RL训练健康检查顺序与熵的两种失败方向_20261010.md#31-健康检查的六步顺序)。

另一个易错点：“样本长度”类图表统计的是整条样本（含历史与环境输出），崩溃时仍有上万；要看每轮输出长度（[两个“长度”](AgentRL的Reward崩溃与归因实验_20261009.md#21-多轮-agent-轨迹的两个长度)）。

### 2.2 移植配方里的几类开关

整套移植的那一臂相对原配置改了这些（另有学习率预热、权重衰减、单轮生成上限等模板差异，是否一并带过去需要核实——若带了，改动项就不止文档里写的那几项）：

| 开关 | 所在环节 | 作用 |
|---|---|---|
| 采样温度 1.0 → 0.8 | 采样 | 分布更尖、探索更少；训练端算 Logprob 时同样除以温度，两边口径一致 |
| KL 系数 → 0 | 打分 | 不再往 Reward 里加 KL 惩罚；可以不再构建参考模型 |
| 关闭批级 Advantage 归一化 | Advantage | 只保留组内比较的结果 |
| 提高 Clip 上界（clip-higher，DAPO 做法） | Loss | 非对称 Clip：允许把原本低概率的好 Token 一步提得更多，用来防止熵塌缩 |
| 重要性采样改为序列级（GSPO 做法） | Loss | Ratio 取整条轨迹的几何平均，整条一起被 Clip，不再逐 Token 判断 |
| 拒绝采样改为序列级、放宽上限 | Loss | 按整条轨迹过滤“太陈旧或训推不一致”的样本 |
| 梯度规约用 FP32 | 更新 | 数值精度设置，严格说不算算法，但会影响稳定性 |

外部稳定配置还有两项值得理解：

- **收紧 Clip 下界**（例如 0.15）：压低概率时单步最多降得更少，更保守；
- **很小的梯度裁剪阈值**（与正常梯度范数同量级）：几乎每步都在生效，相当于给每步更新封顶。

## 3. 完整原理

### 3.1 两条归因臂的结果怎么读

| 臂 | 结果 | 能推出什么 |
|---|---|---|
| 原配置（对照） | 四五十步后崩 | — |
| 只关 KL | 晚十几步崩，症状相同 | KL 不是根因；“晚崩”在运行间方差内 |
| 整套移植 | 跑满不崩 | 有可用的稳定配置；分不清哪一项起作用 |

整套移植那一臂也有两点要留意：

- 熵一开始就降到很低并保持（[熵的另一种失败方向](RL训练健康检查顺序与熵的两种失败方向_20261010.md#33-熵持续往下掉多样性丧失)）；
- 末段每轮输出反而在变长，触发长度上限的比例从不到 1% 升到 3～10%，方向与崩溃相反。只跑了 100 步，看不出后续，建议延长到 150 步观察。

这修正了 [10 月 9 日 §3.3](AgentRL的Reward崩溃与归因实验_20261009.md#33-可疑诱因kl-进-reward--γλ1-的隐式长度惩罚假设) 的主因假设和 [10 月 10 日 §3.4](RL训练健康检查顺序与熵的两种失败方向_20261010.md#34-两组都把-kl-设成-0能推出什么) 的“共同改动最可疑”：两组都改了 KL，但只关 KL 的那组照样崩——共同改动不一定是起作用的那一项。

### 3.2 拿外部稳定配置做对照

外部稳定配置是很好的线索来源，但要分清它能证明什么：

- **结构性差异**：任务类型、起点模型（可能是自己前一轮 RL 的 Checkpoint）、样本粒度（按轮还是按整条轨迹）、Loss 加权、每步题数与采样数都不同。它稳，只能用来**缩小范围**，不能直接证明某一项是根因；
- **代码也要对齐**：配置在主线上可能因字段不认识直接报错，说明用的不是主线。把配置里所有字段逐个和各分支的配置定义对一遍，可以缩小到候选分支；但**“字段都认识”只说明兼容，不能证明是同一份代码**；最终要拿到对方工作区的 HEAD 和未提交改动；
- **工作区是“现在的”**：即使找到对方的仓库，也不保证和当时跑实验时逐行一致；要精确复现，最好请对方推成分支；
- **对照代码时沿主链走**：Reward → Advantage → Loss。这次逐段比下来，PPO 损失函数一致，真正差别在 Advantage 怎么算、Loss 怎么加权、零方差组是否丢弃；而这些主线大多已经支持，只是原配置没用。

### 3.3 归因工作流

| 步骤 | 做什么 |
|---|---|
| 1 定义问题 | 哪个指标、第几步、几组实验里出现、能否复现；只出现一次的先确认能复现 |
| 2 先排除 infra | 训推 Logprob 是否一致、权重同步版本、样本 Staleness、截断与 EOS 处理、环境报错；很多“算法不稳定”其实是数据或系统 bug |
| 3 找对照 | 尽量找同模型、同任务、最接近的稳定配置；人、历史实验、其他规模的模型都是来源 |
| 4 先行指标与自动止损 | 熵、梯度范数、每轮输出长度、零方差组占比、重要性权重；超阈值自动停，别让崩掉的实验空烧算力 |
| 5 最便宜的验证 | 离线分析已有日志 → 短步数单变量 → 全量长跑；每个实验先写预测，跑到能区分结果的步数就停 |
| 6 直接证据 | 加诊断指标，观测机制涉及的那个量，而不只是“改了之后不崩” |
| 7 修复、回归、沉淀 | 长跑确认（至少到最晚崩溃步的 1.5 倍以上），改默认配置或代码，写结论；最好能在配置校验阶段直接拦住 |

当前进度对照：现象、时间线与先行指标、稳/崩对照、差异清单都已完成，卡在“单变量缩小”。

### 3.4 第一轮三组实验与预先写下的预测

都以崩溃的原配置为基础，跑到能越过对照崩溃区间的步数：

| 实验 | 只改什么 | 若它是根因，应看到 |
|---|---|---|
| E1 | 关闭批级 Advantage 归一化 | 不崩，熵不上升 |
| E2 | 去掉 Top-p/Top-k 截断，让采样分布等于训练分布 | 不崩；用于排除训推不一致 |
| E3 | 整套换成外部稳定配置的算法组合（按轨迹给 Advantage、轨迹等权、KL 为 0、收紧 Clip、小梯度裁剪） | 不崩；验证这套组合能否迁移到本任务 |

“不崩”的判定要留余量：除了活没活着，还要看熵是否不超过早期水平的约 1.3 倍、每轮输出是否维持在正常量级。

### 3.5 解读时要提前想好的四个陷阱

1. **打包实验隐含了单变量**：按轨迹在 Rollout 侧算好 Advantage 的路径，根本不会经过训练侧的批级归一化。所以 E3 同时包含了 E1 的改动——E3 不崩时，除非 E1 崩了，否则不能说是加权、粒度或 Clip 起了作用。
2. **小梯度裁剪可能只是压住症状**：崩溃前兆就是梯度范数上升，一个几乎每步都生效的裁剪会把这个信号直接截掉。E3 稳定也可能是被压住，根因还在。
3. **两个单变量可能都稳定**：按 [机制推导](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#44-截断采样让它不再无害假说)，崩溃可能需要“批级归一化的平移”与“截断采样”同时存在。E1 去掉前者、E2 去掉后者，两组可能都不崩；这时结论是“两者的交互是根因”，而不是“训推不一致是关键”。修复上去掉批级归一化依然最简单，采样参数可以保留。
4. **声明的参数不一定真的生效**：准备 E2 时追代码发现，请求里的 Top-k 根本没有传到推理引擎，之前所有实验的 Top-k 实际都是不限的，E2 实际只测了 Top-p。改参数前要追到实际执行路径（[配置—执行证据链](../08/推理性能的配置执行证据链_20260812.md#2-四层证据链)）。

### 3.6 第二轮怎么走

| 第一轮结果 | 下一步 |
|---|---|
| E1 不崩 | 根因指向批级归一化。可再拆成“只保留减均值”和“只保留除标准差”两组，区分是平移还是放大起作用；修法三选一：去掉批级归一化、让零方差组不参与批统计、像外部配置那样整组丢弃零方差组 |
| E1 崩、E3 不崩 | 问题在加权、粒度或 KL 与归一化的组合上，在 E3 的改动里继续二分 |
| 都崩 | 回头看截断采样与温度；差异集合已很小，很快能收敛 |

E1 崩了也有信息：说明单去掉这一项不够，从整套移植那一臂往回逐项排查。

诊断指标（需要改代码，可留到第二轮）：归一化前 Token 加权均值 m 随步数的曲线（看符号是否在熵上升前由负转正）、归一化后零方差组的 Advantage 均值、训练端在非结尾位置给 EOS 的平均概率。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 改了某项后晚崩了十几步 | 在运行间方差之内 | 与所有对照中最晚崩溃步比，或重复多个 Seed |
| 崩溃后梯度范数一组几百、一组为 0 | 前者剩被放大的 KL 项，后者无任何信号 | 对照两组是否带 KL |
| 外部配置在主线上加载报错 | 用的不是主线代码 | 字段逐个对照各分支的配置定义，再取对方 HEAD 与未提交改动 |
| 打包实验不崩 | 可能隐含了单变量实验的改动 | 检查打包路径是否绕过了被测环节 |
| 改了采样参数结果没变化 | 参数可能没传到引擎 | 追到实际执行路径 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 关 KL 后晚崩了十几步，说明 KL 能延缓崩溃 | 崩溃起点本来就有这么大的运行间方差 |
| 梯度范数暴涨导致了崩溃 | 它是崩溃后的结果：全零组 + 批级归一化放大残余 KL |
| 两组都改了某项、两组都稳，就是它 | 只关它的一臂照样崩；共同改动不一定是起作用的那一项 |
| 别人的配置稳，照搬差异项就能定位根因 | 任务、起点模型、样本粒度不同；只能缩小范围 |
| 配置字段都能识别，就是同一份代码 | 只说明兼容；还要核对 HEAD 与未提交改动 |
| 打包实验不崩，就是打包里的“新”改动起作用 | 打包路径可能已隐含单变量改动 |
| 加了小梯度裁剪后稳了，问题就解决了 | 可能只是把先行信号截掉，根因还在 |
| 两个单变量实验都不崩，说明两个都是原因 | 更可能是两者交互；修复时去掉其中一个就够 |

## 7. 一分钟复习

1. KL 不是根因；梯度范数暴涨是结果。
2. 稳/崩对照指向批级归一化，但相关不等于因果，要单变量验证。
3. 先止血（稳定配置交付）、再定位（改默认配置）。
4. 七步：定义 → 排除 infra → 找对照 → 先行指标与止损 → 便宜验证（先写预测）→ 直接证据 → 修复回归沉淀。
5. 四个陷阱：打包隐含单变量、裁剪掩盖症状、交互效应、参数没生效。

## 8. 自测问题

### 问题 1

只关 KL 的一臂比对照晚崩十几步，为什么不能说 KL 能延缓崩溃？

期望回答：同一配置的崩溃起点本来就相差约 10 步以上，每组只跑一次，晚十几步在运行间方差范围内；要越过所有对照中最晚的崩溃步，或多 Seed 重复，才能下结论。

### 问题 2

外部长跑稳定的配置，能否直接告诉你根因？

期望回答：不能。它与我们在任务、起点模型、样本粒度、Loss 加权上都不同，只能缩小嫌疑范围；还要确认对方实际用的代码，字段兼容不等于同一份代码。

### 问题 3

“整套换成稳定组合”的实验不崩，为什么不能直接说是加权或 Clip 起了作用？

期望回答：按轨迹给 Advantage 的路径绕过了批级归一化，隐含了单变量实验的改动；小梯度裁剪也可能只是截掉了先行信号。只有单变量实验崩了，打包实验不崩，才能把原因指向打包里的其他改动。

### 问题 4

为什么去掉批级归一化、去掉截断采样两组都可能不崩？这时结论是什么？

期望回答：机制推导上，崩溃需要批级归一化的平移与截断采样同时存在，去掉任一个都可能消除偏移。结论是两者的交互导致崩溃；修复去掉批级归一化即可。

- 诊断指标（m 曲线、零方差组 Advantage、非结尾位置 EOS 概率）需要改代码加入；
- 整套移植那一臂末段输出变长的趋势需要更长训练确认；
- 外部配置中“整组丢弃零方差组”“按轨迹等权”的单独效果尚未测试；
- DAPO（clip-higher 等）、GSPO（序列级重要性采样）的完整设计动机仍待系统学习。
