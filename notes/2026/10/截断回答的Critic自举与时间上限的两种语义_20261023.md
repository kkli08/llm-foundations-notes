## 0. 今天最终要解决的问题

按提问与发现顺序：

1. （巡检发现）数学任务上 PPO critic 的目标均值为什么明显高于这批回答的平均判分？EV 为什么一直在 0？
2. 这个“critic 截断”具体是什么问题？
3. 论文和 verl 等框架里，截断的时候 critic 的 V 是怎么处理的？
4. 修复后怎么证明生效？为什么第 1 步看不出差别？

## 1. 先给结论

- **“判 0 分 + 末尾补 V”是一个自相矛盾的组合**：被长度截断的回答先按截断时的内容判 0 分，GAE 又在末尾补上 critic 对末位的预测 V。γ = λ = 1 时，这条回答每个 token 的目标都变成 0 + V(末位)，也就是 **critic 自己的输出**——没有真实分数把它拉回来，值可以往任何方向漂。
- **读数签名**：在“答错、截断的回答更长”的任务上，不补 V 时按 token 加权的目标均值只会**低于**按回答平均的判分；实际却明显高于（约 0.9 对约 0.6）→ 有东西在往目标里加值。同时 EV 长期 ≈ 0；截断只有约 1% 的另一个任务，EV 正常上升。
- **对 actor 的后果**：截断回答的优势 ≈ 目标 − 当前 V ≈ 0，不奖不罚；GRPO 下截断回答 0 分、组内归一化后明显为负，模型被推着写短。PPO 丢掉了“写超长要罚”的信号，PPO 与 GRPO 的对比会偏，回答还可能越写越长。
- **理论依据（Pardo et al., 2018）**：时间上限有两种——上限是**任务的一部分**，到点就按当时结果算分，是终止状态，未来价值为 0；上限**只为训练方便**，环境本可继续，才用 V 补上“后面本来能拿的分”（partial-episode bootstrapping）。LLM 的生成上限截断后直接判分、不会续写，属于前一种。
- **主流框架的做法**：verl、OpenRLHF、TRL 的 GAE 在回答末尾 nextvalue 都是 0，不区分截断与正常结束；对截断的处理都放在 **reward** 上（缺 EOS 扣分、DAPO 的过滤或软惩罚）。
- **补 V 什么时候说得通**：截断回答的 reward 被**屏蔽**（不判分）时，V 作为“本来会得多少”的替身。想要“不因截断受罚”，正确做法是把截断样本从 actor 和 critic 的 loss 里**都去掉**，而不是补 V。
- **为什么以前没暴露**：旧的截断判定每批只标中最长那一行（[10 月 19 日 §3.1](训练口径的隐性错误与读数签名_20261019.md#31-截断判定为什么会变成最长那一行)），补 V 最多影响一条；改成逐条真实截断标记（本身是正确的修复）后，补 V 覆盖了约三分之一回答、近一半 token。**修对上游的判定，会把下游依赖它的旧语义一起放大。**
- **修复的验证窗口**：critic 零初始化时 V ≈ 0，补上的值也是 0，第 1 步修复前后完全一样；要等 critic 学会预测（修复前在第 4～6 步目标超过判分）才分得开。

## 2. 前置概念

### 2.1 GAE 在回答末尾的 nextvalue

接着 [10 月 20 日 §3.2](PPO的Critic价值估计GAE参数与工程适配_20261020.md) 的记号：

```text
δ_t = r_t + γ·V_{t+1} − V_t        A_t = δ_t + γλ·A_{t+1}        G_t = A_t + V_t
末位 T：V_{T+1} = nextvalue
  正常结束：nextvalue = 0
  补 V：    nextvalue = V_T（critic 对末位的预测，不带梯度）
γ = λ = 1 时：G_t = Σ_{s≥t} r_s + nextvalue
```

只有末端奖励、忽略逐 token 的 KL 项时：正常结束的回答 G_t = R；截断回答判 0 且补 V 时 G_t = 0 + V_T。critic 的 MSE 让 V_t 去逼近 G_t，于是在截断回答上是“用自己的预测教自己”。这和 [λ < 1 时 G 里混进 critic 自己的估计](PPO的Critic价值估计GAE参数与工程适配_20261020.md) 是同一种自引用，但这里即使 λ = 1 也逃不掉，而且**没有任何真实奖励**参与。

### 2.2 截断回答的 reward 处理 × critic 末尾处理

| reward 怎么处理截断回答 | critic 末尾 | 是否一致 | 对长度的作用 |
|---|---|---|---|
| 照常判分（判 0） | 不补（nextvalue = 0） | 一致：截断就是终局 | 强力压缩长度；verl / OpenRLHF / TRL 的默认 |
| 照常判分（判 0） | 补 V | **矛盾**：先罚 0，再用 V 抵消；critic 拟合自己 | 惩罚被抵消，长度不受压 |
| 屏蔽 reward（不判分） | 补 V | 说得通：V 顶替缺失的分数 | 不罚截断 |
| 过滤出 loss（DAPO Overlong Filtering） | actor 与 critic 都不训练这些样本 | 一致 | 不压长度，可能越写越长 |
| 软惩罚（DAPO Soft Overlong Punishment） | 不补 | 一致 | 折中 |
| 缺 EOS 固定扣分（TRL `missing_eos_penalty`） | 不补 | 一致 | 压缩长度 |

## 3. 完整原理

### 3.1 critic 在追自己的影子

- 数学任务上约三分之一回答被截断，但它们都是最长的，**按 token 算占了近一半**。critic 的 loss 按 token 平均，这一半 token 的目标就是它自己的旧预测。
- 自引用的目标没有固定点约束：critic 把 V 往上调，下一步截断回答的目标也跟着往上走。修复前的读数正是这样——目标均值几步内从约 0.4 涨到约 0.9，而判分均值一直在约 0.6。
- 另一半 token（正常结束的回答）有真实的 0/1 目标，但被自引用的那一半稀释，critic 学不会区分好坏 → EV ≈ 0。截断约 1% 的任务里自引用部分很小，EV 正常从 0 升到 0.1～0.4。

### 3.2 “目标均值 > 判分均值”什么时候才算签名

critic 目标按 **token** 平均，判分按 **回答** 平均。不补 V、γ = λ = 1、KL 项只会让目标变小时：

```text
目标均值 ≈ Σ_i L_i·R_i / Σ_i L_i        判分均值 = Σ_i R_i / N
答错/截断的回答更长（L 大的 R = 0） ⇒ 目标均值 < 判分均值
答对的回答更长（L 大的 R = 1）      ⇒ 目标均值 > 判分均值，正常
```

所以这个签名**只在“错的更长”的任务上有效**。当天另一个多模态任务里答对的回答反而更长（约 4.5K 对 2.4K token），修复后目标均值仍高于判分，这不说明有问题。排除其他来源时还要确认：reward 偏置为 0、缩放为 1、KL 项只会拉低目标。

### 3.3 对 actor 的后果（actor 开始更新以后）

| | 截断回答的优势 |
|---|---|
| PPO + 补 V | 目标 = 0 + V(末位)，例如 0.9；减去当前位置的 V（也约 0.9）→ ≈ 0，不奖不罚 |
| GRPO | 截断回答 0 分，同组平均例如 0.6 → 归一化后明显为负 → 推着写短 |

同一天的 GSPO 运行里，截断比例十步内从约三分之一降到一成左右，正是“截断 = 0 分”这个信号在起作用。PPO 带着这个问题就丢掉了它。critic 预热期 actor 冻结，问题只影响 critic；actor 开始更新前修复，只需重做预热，不会污染 actor。

### 3.4 时间上限的两种语义

Pardo et al., *Time Limits in Reinforcement Learning*（ICML 2018）：

| 上限的性质 | 例子 | 到达上限时的状态 | 正确做法 |
|---|---|---|---|
| 任务的一部分（time-aware） | 考试到点收卷；LLM 回答截断后直接判分 | 终止状态 | 未来价值 = 0；若想让策略知道剩余时间，把剩余时间放进状态 |
| 只为训练方便（time-unaware） | 游戏跑满 1000 步强制重开，但游戏本可继续 | 非终止，只是被打断 | partial-episode bootstrapping：用 V(s_T) 补上后面本来能拿的分 |

判别问题只有一个：**到达上限之后，这条轨迹还会不会以某种方式继续、并拿到后续奖励？** LLM 单轮回答被截断后按截断内容判分，不会续写 → 终止。补 V 的写法是按第二种处理的。

反过来，多轮 agent 任务“每轮一行”布局下的**行末**（[10 月 20 日 §3.6](异步训练下的Minibatch个数与解耦PPO来源_20261020.md#36-按轮比值与-ppo按轮比值无关一行是什么关系最大)）不是终局——下一轮还会继续、奖励在最后才给。那里用下一轮的 V 做 bootstrap 属于第二种，是合理的。同一个“行末补 V”，对不对取决于这一行之后轨迹是否还在继续。

### 3.5 论文与框架怎么处理截断

**代码**（对话时查看的当前源码，以所用版本为准）：

| 框架 | GAE 在回答末尾 | 对截断的特殊处理 |
|---|---|---|
| verl | 循环前 nextvalue = 0，末尾不补 | 不区分截断与正常结束 |
| OpenRLHF | 末位 nextvalue = 0；values 先乘了 action mask | 没有 EOS / 截断标记参与 GAE |
| TRL PPO | 末位 0 | `missing_eos_penalty`：没写出 EOS 的回答在打分上直接扣分 |
| 当前框架（修复前） | 截断回答补 V(末位) | 另有“截断回答 reward 清零 / 屏蔽”的开关 |

**论文**的讨论都在“截断的回答怎么打分”，而不是“补不补 V”：

- Huang et al., *The N+ Implementation Details of RLHF with PPO*（2024）：没写出 EOS 的回答给固定惩罚分，沿用早期 RLHF 代码的做法；TRL 的 `missing_eos_penalty` 即此。
- DAPO（2025）：截断回答一律 0 分会引入噪声（推理可能是对的，只是写长了）→ Overlong Filtering（不参与 loss）与 Soft Overlong Punishment（接近上限逐步扣分）（[10 月 13 日 §3.1](GRPO变体与两层归一化的拆解_20261013.md#31-原版-grpo-的已知问题与对应变体)）。
- VC-PPO / VAPO（2025）：讨论长思维链下 critic 怎么训，没专门讨论截断；value 预训练即 critic 预热，critic 用 λ = 1 让末端奖励不被衰减（[10 月 21 日](PPO_Critic的价值头初始化两种预热与EV上限_20261021.md)）。

### 3.6 为什么以前没暴露：修对上游判定会放大下游旧语义

| 阶段 | 截断判定 | 补 V 覆盖面 | 表现 |
|---|---|---|---|
| 原始 | 按“长度 == padding 宽度”，每批最多标中最长那一行，常常标错 | ≤ 1 条 / 批 | 看不出 |
| 改为推理端逐条导出的真实截断标记 | 正确 | 数学任务约 1/3 回答、近一半 token | critic 失控、EV ≈ 0 |

10 月 19 日的修复本身是对的，但当时默认了“截断要 bootstrap”这条下游语义。一般化：**修一个判定的输入时，要顺着数据流把所有消费这个判定的下游语义重审一遍**；输入变准之后，原本被错误输入“掩护”的语义问题会以更大规模暴露。

### 3.7 修法与验证

**修法**：只在“截断回答的 reward 被屏蔽”的模式下补 V；默认模式（截断照常判分）把截断当终点。另一种写法是彻底去掉补 V，与 verl / OpenRLHF / TRL 完全一致，但会改变屏蔽模式的行为。两种写法在默认模式下完全等价；选前者是为了只修当前配置的问题、不改别的模式（改别的模式要单独说明）。

**单元级数值检查**：把 critic 的预测全设成 0.9，一条正常结束、判 1 分的回答，一条截断、判 0 分的回答：

| 模式 | 正常回答的目标 | 截断回答的目标 |
|---|---|---|
| 默认（照常判分） | 全为 1 | 全为 0（不再加 0.9） |
| 屏蔽 reward | 全为 1 | 全为 0.9（行为不变） |

用一个**非零**的常数 V 做检查，才能区分补与不补；用零初始化的 V 检查不出来。

**端到端为什么第 1 步看不出**：critic 价值头零初始化（[10 月 21 日 §2.1](PPO_Critic的价值头初始化两种预热与EV上限_20261021.md)），第 1 步旧预测 ≈ 0，补上的值也是 0，修复前后目标一样。修复前的运行在第 4 步目标超过判分、第 6 步涨到约 0.9。修复后的读数：

| 时期 | 目标 vs 判分 | critic 估值 | EV |
|---|---|---|---|
| 第 1～8 步 | 始终低于或贴着判分 | 稳定在约 0.5，偶有一步跳动后回落，没有单调上涨 | 约 0 |
| 第 9～14 步 | 仍不高于判分 | 稳定 | 从约 0.2 逐步升到约 0.4 |

**为什么要重启而不是接着跑**：critic 已经学到了被抬高的目标，接着跑等于从错误的起点继续预热；重启只损失预热期的时间，因为 actor 还没开始更新。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| critic 目标均值几步内超过判分均值并继续涨 | 截断回答的目标 = critic 自己的预测 | 先确认任务里错的回答更长；按截断 / 未截断分开统计目标均值 |
| 截断多的任务 EV ≈ 0，截断少的任务 EV 正常上升 | 近一半 token 的目标是自引用 | 只用未截断回答算 EV 对照 |
| actor 学起来后 PPO 截断比例不降、长度变长，GRPO 却在变短 | 截断回答优势 ≈ 0，长度信号消失 | 看截断回答的平均优势是否 ≈ 0 |
| 修好截断判定后 critic 突然变差 | 判定变准，下游补 V 覆盖面从一条变成三分之一 | 顺数据流列出所有消费截断标记的地方 |
| 修复后第 1 步与修复前完全一样 | V 零初始化，补上的值为 0 | 用非零常数 V 做数值检查；端到端看 critic 学会预测之后的几步 |
| 多模态任务修复后目标均值仍高于判分 | 答对的回答更长，token 加权偏向正确回答 | 比较对 / 错回答的平均长度 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 截断 ≠ 结束，有 critic 时都要用末位 V bootstrap（10 月 19 日的说法） | 要看上限的语义：截断后照常判分 = 终止，nextvalue = 0；只有 reward 被屏蔽、或轨迹之后还会继续时才补 V |
| 判 0 分再补 V 是“双保险” | 两者互相抵消：先罚 0，再用 V 把惩罚补回来，critic 还在拟合自己 |
| 补 V 是 RL 的标准做法，LLM 也该照搬 | 那是为“只为训练方便的时间上限”设计的；verl / OpenRLHF / TRL 都在末尾取 0 |
| 想不因截断受罚，就补 V | 正确做法是把截断样本从 actor 和 critic 的 loss 里都去掉（DAPO 过滤） |
| critic 目标均值高于判分均值一定是 bug | 只在“错的回答更长”时是签名；答对更长的任务里是正常的 token 加权效应 |
| 修复后第 1 步没变化，说明修复无效 | V 零初始化时补上的就是 0；要看 critic 学会预测之后 |
| 把上游判定修对不会有副作用 | 会把下游依赖它的旧语义一起放大，要顺数据流重审 |
| 多轮任务每轮一行的行末也不该补 V | 那里轨迹还会继续，补下一轮的 V 属于“被打断”的情形，是合理的 |

## 7. 一分钟复习

1. 截断回答判 0 + 末尾补 V → γ = λ = 1 时目标 = V(末位) = critic 自己的预测；截断回答最长，按 token 占近一半 → critic 漂、EV ≈ 0。
2. 签名：错的回答更长时，不补 V 的 token 加权目标均值只会低于判分均值；高于 → 有值被加进来。答对更长的任务不适用。
3. actor 后果：截断回答优势 ≈ 0，不罚写超长；GRPO 判 0 → 负优势 → 推短。
4. Pardo 2018：上限是任务一部分 → 终止、nextvalue = 0；只为训练方便 → 补 V。LLM 截断后直接判分 → 终止。多轮“每轮一行”的行末属于后者。
5. verl / OpenRLHF / TRL 末尾都取 0；截断只在 reward 上处理（缺 EOS 扣分、DAPO 过滤 / 软惩罚）。补 V 只在 reward 被屏蔽时说得通。
6. 修对截断判定（最长行 → 逐条标记）把补 V 从一条放大到三分之一：修上游要顺数据流重审下游。
7. 验证：非零常数 V 的数值检查；V 零初始化 → 第 1 步看不出，等 critic 学会预测后的几步。

## 8. 自测问题

### 问题 1

γ = λ = 1、只有末端 0/1 奖励。一条被截断、判 0 分的回答，GAE 末尾补上 V(末位) = 0.9。这条回答每个 token 的 critic 目标是多少？critic 在这条回答上学到了什么？

期望回答：每个 token 的目标都是 0 + 0.9 = 0.9，也就是 critic 自己的旧预测。critic 的 MSE 让各位置的 V 去逼近自己末位的预测，没有任何真实奖励参与，于是只能“追自己的影子”：它把 V 往哪调，下一步目标就跟到哪，值可以任意漂移。

### 问题 2

某任务 critic 目标均值约 0.9、这批回答平均判分约 0.6，reward 无偏置、无缩放，KL 项只会拉低目标。能否据此断定目标里混进了额外的值？还需要确认什么？

期望回答：还要确认这个任务里答错 / 截断的回答比答对的长。目标按 token 平均、判分按回答平均；错的更长时，不补 V 的 token 加权目标均值只会低于判分均值，高于就说明有值被加进来。如果答对的回答更长，目标均值高于判分是正常的 token 加权效应，不能作为证据。

### 问题 3

为什么 LLM 单轮回答的生成上限属于“终止”，而多轮 agent 任务每轮一行布局下的行末可以用下一轮的 V 做 bootstrap？

期望回答：判别问题是“到达边界之后轨迹还会不会继续、拿到后续奖励”。单轮回答被截断后按截断内容直接判分、不会续写，属于 Pardo 的“上限是任务一部分”，未来价值为 0。多轮任务的一行只是一轮，之后还有下一轮、奖励在最后才给，行末只是被布局切开，属于“被打断”，用后续的 V 估计未来价值是合理的。

### 问题 4

想实现“截断的回答不因为写长而被罚”，有人提议给截断回答补 V。这样对吗？应该怎么做？

期望回答：不对。如果截断回答仍判 0，补 V 只是把惩罚抵消、让 critic 拟合自己；如果 reward 已被屏蔽，补 V 能顶替缺失的分数，但 critic 的目标仍来自自己的预测。DAPO 的做法是把截断样本从 loss 里去掉（Overlong Filtering）；对 PPO 来说要从 actor 和 critic 的 loss 里都去掉，或者改用接近上限逐步扣分的软惩罚。

### 问题 5

修复后第 1 步的 critic 目标与修复前完全相同。这能说明修复无效吗？怎样尽早证明修复生效？

期望回答：不能。价值头零初始化，第 1 步旧预测 ≈ 0，补上的值也是 0，两边目标必然一样。单元级用非零常数 V（如全设 0.9）构造一条截断回答，检查默认模式下目标为 0、屏蔽模式下目标为 0.9；端到端要看 critic 学会预测之后的几步（修复前在这个窗口目标开始超过判分），确认目标不再超过判分、估值不再单调上涨、EV 开始上升。

### 问题 6

一次修复把“截断判定”从“每批最长的那一行”改成推理端逐条导出的真实标记，结果 PPO critic 变差了。这说明修复错了吗？

期望回答：不说明。判定本身修对了；问题在下游“截断就补 V”的旧语义。原来判定每批最多标中一条，补 V 几乎不起作用；判定变准后，长推理任务约三分之一回答、近一半 token 都走上补 V，旧语义的问题被放大暴露。教训是修一个判定的输入时，要顺数据流重审所有消费它的地方。

## 9. 尚未解决与后续路线

- actor 开始更新后，修复后的 PPO 能否像 GRPO 一样把截断比例压下去；与 GRPO / GSPO 的长度、判对率对照；
- 截断多的长推理任务上，critic 的 EV 最终能到多少；EV 上限（[10 月 21 日 §3.5](PPO_Critic的价值头初始化两种预热与EV上限_20261021.md)）与截断比例的关系；
- PPO 下 DAPO 式过滤（actor 与 critic 都排除截断样本）与“判 0 不补 V”的效果对比；
- 多轮 agent 每轮一行布局下，行末 bootstrap 与轮间奖励传播的具体设计（[10 月 20 日 §3.6](异步训练下的Minibatch个数与解耦PPO来源_20261020.md#36-按轮比值与-ppo按轮比值无关一行是什么关系最大)）。
