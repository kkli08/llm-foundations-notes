## 1. 先给结论

- **温度口径偏差真实存在，来源是温度，不是模型或陈旧度**：同一模型只改温度，T = 1 时均值是一个极小的负数，T < 1 时明显为正，且与陈旧度几乎不相关。偏差随熵下降而收缩。
- **它很小，不是崩溃的原因**：序列级几何平均把逐 token 的正负偏差平均掉，序列权重贴近 1，拒绝采样上限一次都没触发。但做在线 PPO/GSPO 之前，这个分母仍然要先修正。
- **训推不一致出现在熵上升之后**，所以它是崩溃的结果，不是诱因。
- **批级归一化作用在每一个 token 上**，不只影响零方差组。零方差组只是变化最显眼的地方：它从 0 变成了非 0。另外，它对整个训练 batch 只算一次，算完才切 minibatch。
- **两次归一化的对象不同**：组内归一化的是每条回答的 reward，按条数统计；批级归一化的是每个 token 的 advantage，按 token 统计。
- **“GRPO 还要 GAE 吗”，同事说对了一半**：在 V ≡ 0、γ = λ = 1 下，GAE 只是把分数广播到每个 token。它唯一多做的事，是把 KL reward 沿序列累加了进去。这是 PPO-RLHF 的 KL 放法，和 GRPO 论文的放法不同，但本身不算写错。

## 2. 前置概念

### 2.1 近似 KL 均值的符号本身就是证据

记 p 为记录下来的分布、r 为另一个分布。若样本 y 确实按 p 采出：

```text
E_{y~p}[ log r(y) − log p(y) ] = −KL(p ‖ r) ≤ 0
E_{y~p}[ log p(y) − log r(y) ] = +KL(p ‖ r) ≥ 0
```

下面两种读数都用到这条性质（整理时补充的推导）：

- `log π_prox − log π_behave` 的均值：只要 token 真按 π_behave 采出，它就应该是一个**小负数**。T = 1 时实测确实如此，这个小负数就是两套引擎正常的数值差。
- 如果它**稳定为正**，说明 token 不是按记录的 π_behave 采出的，而是按一个更尖的分布 q（除过温度）采出。此时均值约等于 `KL(q‖π_behave) − KL(q‖π_prox)`，在 π_prox ≈ q 时约等于 `KL(q‖π_behave)`，量的就是温度造成的差距。
- 同理，KL 进 reward 时用的 k1 = `log π_behave − log π_ref`，在样本真来自 π_behave 时期望非负。**均值持续为负，说明记录的分布和实际采样的分布已经对不上。**

### 2.2 分清两次归一化

沿用 [两处归一化与统一的配置结构](GRPO变体与两层归一化的拆解_20261013.md#37-两处归一化与统一的配置结构)：

| | 归一化对象 | 形状 | 统计口径 |
|---|---|---|---|
| 组内 Reward 归一化 | 每条回答的 reward | 每行 1 个数 | 组内，按条数 |
| 批级 Advantage 归一化 | 每个 token 的 advantage | 每行 seq_len 个数 | 整个 batch，按 token |

## 3. 完整原理

### 3.1 先定判断标准，再看数字

动手拉数据之前，先把“什么算支持、什么算否定”写下来，免得看到数字后再找理由：

- 这个均值本来就混着两部分：正常的 off-policy 漂移（样本落后几个版本），以及推理引擎和训练引擎之间的数值误差。所以 T = 1 也不会正好是 0。
- **支持“温度口径问题”**：T ≠ 1 的运行稳定地比 T = 1 高出一截；在陈旧度接近 0 的步上差距仍在；方向为正。T < 1 时被采到的多是高概率 token，它们在 π_prox 里更大。
- **否定或降级**：两边量级差不多，或者差距随陈旧度一起涨落。

选对照时，**同一模型、只改温度**比跨模型对比干净得多：跨模型对比混着模型规模、配方等一堆变量，同模型对照只剩温度一个变量。这就是 [单变量对照](Rollout瓶颈下的GPU利用率与对照变量_20261009.md) 在读数验证上的用法。

### 3.2 验证结果怎么读

| 观察 | 解读 |
|---|---|
| T = 1 的所有运行稳定在一个极小的负值 | 正常的训推数值差，符合 §2.1 的 `−KL ≤ 0` |
| T < 1 的运行明显为正，与陈旧度的相关性接近 0 | 偏差来自温度口径，不是陈旧度。方向与 [10 月 14 日 §3.2](采样截断与Logprob口径的训推偏差_20261014.md#32-推理端-raw-logprob-与温度不一致) 的推测一致 |
| 随训练推进、熵下降，偏差从开始时的值缩到几分之一 | 分布越尖，温度对被采样 token 概率的影响越小。极端情况是 one-hot 分布，除不除温度都一样 |
| 序列级权重只在 1 附近很窄的范围内，拒绝采样上限从未触发 | 几何平均 = exp(逐 token log 比值的平均)。高概率词偏大、低概率词偏小的部分在平均中相互抵消，只剩一个百分之一量级的整体偏移 |

结论分三层：

1. **存在**：代码行为确认，方向和机制都对得上；
2. **量级**：在序列级权重下约为百分之一量级的系统偏差，解释不了崩溃；
3. **仍应修**：在线 PPO/GSPO 要依赖 `π_prox/π_behave` 做修正（[单次更新时它是唯一生效的修正](PPO的Critic与Clip在单次更新下的退化_20261013.md#33-关键推论单次更新时-clip-退化)），分母口径必须先对。

还有一个**盲区**：T = 1 时截断掉的那部分概率质量（`1/Z`），这个指标看不到，因为分子分母都是“不截断”的值。这部分只能靠改 top-p 的单变量实验间接检验。

### 3.3 顺带得到的两条读数

- **单次更新时 ratio ≡ 1 被实测坐实**：所有运行的每一步，`π_θ` 与 `π_prox` 之间的近似 KL 和 clip 比例都是精确的 0，连浮点噪声都没有。这说明两者在数值上完全相同，clip 从未触发。这是 [10 月 13 日 §3.3](PPO的Critic与Clip在单次更新下的退化_20261013.md#33-关键推论单次更新时-clip-退化) 推论的直接证据。
- **物理上不可能出现的读数，直接指向定义错误**：陈旧度不可能为负。如果它的均值稳定为负，最可能的解释是计算时用的参考版本差了一个，比如把“当前版本 − 1”当成了近端版本。看到不可能的数时，先怀疑定义，而不是怀疑系统行为。

### 3.4 训推不一致是崩溃的结果还是诱因：看先后

在一次崩溃的运行里，几个指标按步排列的先后是：

1. 熵先开始上升；
2. 过了好几步，训推近似 KL 才离开正常的小负值；
3. 再往后，它跳到很大的负值（按 §2.1，这时记录的分布与实际采样已经严重对不上）。

指标出现得比它的“前兆”晚，它就只能是结果，不能是诱因。这和 [崩溃前兆的先后](AgentRL的Reward崩溃与归因实验_20261009.md#38-同期对照的逐步观察) 是同一种读法：按步看，多指标同看。

### 3.5 批级归一化：影响的不只是零方差组（被纠正的误解）

用户的理解是：“按 token 做的批级 Advantage 归一化，真正影响的是零方差组。”这只对了一半。

`(x − m)/s` 作用在 batch 里**每一个 token** 上：

- **减 m**：所有 token 平移同一个常数，有信号的组也被平移；
- **除 s**：所有 token 按同一个倍数放大，有信号的组也被放大。

之所以在零方差组上最显眼，是因为那里发生了**性质变化**：本来是 0、不产生梯度，现在变成非 0、会推动模型。在有信号的组里，它只改变大小和相对比例。比如 m < 0 时，答错的长回答受到的惩罚会变轻。

**位置也要纠正**：这一步不是在 PPO 的 minibatch 里做的，而是在算 Advantage 时对**整个训练 batch 只做一次**，然后才切 minibatch。两者在 minibatch 数为 1 时刚好一样大，但概念上要分开。

**1/s 像自动增益（AGC）**：输入信号变弱时，它自动把音量调大，噪声也一起被放大。在 RL 里，这等价于有效学习率随着训练信号变少而自动变大，形成“信号越少 → 步子越大 → 越容易塌”的正反馈。平移与放大的推导见 [10 月 12 日 §4～§5](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#5-批级归一化第二件事除标准差--按信号稀缺程度放大步长)。全部组都是零方差时，只剩极小的 KL 项会被放大到单位方差，见 [10 月 9 日 §3.2](AgentRL的Reward崩溃与归因实验_20261009.md#32-为什么归零后回不来批归一化放大残余信号)。

### 3.6 归一化的到底是什么：不是 token 的 reward

用户问：“到底归一化什么？是每个 token 的 reward 吗？”

不是。批级归一化的对象是 **advantage**，也就是“这个 token 该被强化还是削弱、力度多大”。在 GRPO（无 critic、γ = λ = 1）下，一个 token 的 advantage = 所在回答组内归一化后的分数 + 从这个 token 到结尾累积的 KL 项。KL 项很小，所以**同一条回答里每个 token 的 advantage 几乎都一样，相当于那条回答的分数被复制了 |y| 份**。

最小手算：一组两条回答，组内归一化后答对的 +0.7（3 个 token），答错的 −0.7（5 个 token）。

```text
按条数：  (+0.7) + (−0.7)                           = 0       → 均值 0
按 token：+0.7 +0.7 +0.7 −0.7 −0.7 −0.7 −0.7 −0.7   → 均值 (2.1 − 3.5)/8 = −0.175
```

组内归一化保证的是“按条数均值为 0”；批级归一化改用按 token 统计，长回答被多算了几遍，均值就不再是 0。m 平移就是从这里来的。更完整的两组例子见 [10 月 13 日 §3.6](GRPO变体与两层归一化的拆解_20261013.md#36-手算不归一化-vs-按-token-vs-按轨迹)。

### 3.7 零方差组从哪来

用户问：“为什么会出现零方差组？是这组要么全对、要么全错？”对。零方差组就是同一道题的 G 条回答拿到**完全相同的 reward**，组内标准差为 0。常见细分为两类：

- **全零组**：G 条全是 0 分，通常是全错，也可能是全部超时或出错；
- **同分非零组**：G 条拿到相同的非零分，多半是全对（[同分非零也没有任务 Advantage](RL训练健康检查顺序与熵的两种失败方向_20261010.md)）。

原因很直接：题目对当前模型来说太难，就全错；太简单，就全对。只有难度适中的题才会有对有错，产生组内对比信号。

两条读数上的规律：

- **健康期零方差组就不少**，以全对为主。所以 m 平移从一开始就作用在一大片 token 上，不是崩溃时才出现的边缘情况；
- **崩溃过程中构成会翻转**：从“多半全对”变成“几乎全是全错”。有信号的组迅速消失，正是 1/s 放大最剧烈的阶段。

这也是“零方差组整组丢弃”（[DAPO 动态采样](GRPO变体与两层归一化的拆解_20261013.md#31-原版-grpo-的已知问题与对应变体)）的另一层好处：这些组本来就不提供 GRPO 信号，却占了 batch 名额，还参与按 token 的统计。丢掉之后，m 平移和分母被稀释的问题都会变小。

修法按改动从小到大：关掉批级归一化；只除 s、不减 m（放大仍在）；改成按条数统计 m 和 s（零方差组不再被平移）。拆分实验设计见 [10 月 13 日 §3.9](GRPO变体与两层归一化的拆解_20261013.md#39-怎样只用配置把平移和缩放拆开)。

### 3.8 “GRPO 还要什么 GAE”：GAE 在这里退化成了广播

同一段 GAE 代码不区分 PPO 和 GRPO。在 GRPO 配置下有两个条件：没有 critic，V 全为 0；γ = λ = 1。代入：

```text
δ_t = r_t + γ·V_{t+1} − V_t = r_t                       （V ≡ 0）
A_t = Σ_k (γλ)^k · δ_{t+k} = r_t + r_{t+1} + … + r_T      （γ = λ = 1）
```

这就是 reward-to-go：没有 critic，也没有 λ 带来的偏差。任务 reward 只放在最后一个 token 上，所以每个 token 拿到的都是同一个值，即组内归一化后的分数，和 GRPO 论文里的 Â 完全一样（[GRPO = V ≡ 0 的 GAE 特例](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#22-grpo-就是配置出来的-ppo)）。

所以这段循环对任务 reward 只起“广播”作用。**它在 GRPO 下唯一多做的事，是把逐 token 的 KL reward 也沿序列累加了进去**。同事指出的问题实际出在这里，而不在“用了 GAE”本身。

### 3.9 KL 的两种放法：完整对比

[10 月 13 日 §3.1](PPO的Critic与Clip在单次更新下的退化_20261013.md#31-ref-与-kl-的两种放法) 只给了最小对比，这里补全：

| | KL 进 Loss（GRPO 论文） | KL 进逐 token Reward（PPO-RLHF 写法） |
|---|---|---|
| 放在哪 | Loss 里的独立项 `−β·KL` | 每个 token 的 reward 加 `−β·KL`，再走 GAE |
| 估计器 | k3，对 π_θ 求导 | k1 = `log π_behave − log π_ref`，detach，只通过策略梯度起作用 |
| token t 受到的约束 | 只管自己这个 token | 从 t 到结尾所有 token 的 KL 之和 |
| 约束的是 | 每个 token 的平均 KL | 整条序列的 KL 总量，长回答被罚得更多 |
| 和归一化的关系 | 不受影响 | 不参与组内归一化，但参与批级归一化，会被 1/s 放大 |

KL 进 Reward 是 InstructGPT 那一路 PPO-RLHF 的标准做法，本身不算写错，只是优化的目标不同。放到多轮 Agent 场景里有两点要注意：

- 一整条多轮轨迹拼成一行时，**第一轮的 token 会累积后面所有轮的 KL**，长度效应比单轮更强（[隐式长度惩罚的假设](AgentRL的Reward崩溃与归因实验_20261009.md#33-可疑诱因kl-进-reward--γλ1-的隐式长度惩罚假设)）；
- 全部组都是零方差时，批级归一化会把只剩 KL 的 advantage 放大到单位方差。

**量级判断**：健康期累积到首 token 的 KL reward 只占 advantage 的百分之几；而且完全不加 KL 的对照运行同样崩了。所以 KL 的放置位置不是这次崩溃的根因。崩溃后 k1 均值变负，按 §2.1 是训推失配的又一证据，不是 KL 本身的问题。

### 3.10 KL 进 Loss 的实现缺口

即使框架已经支持论文写法（k3 进 loss），也要检查三个缺口：

1. **两种开关能同时打开且不报错**：KL 进 reward 的系数 > 0 时又开了 KL loss，KL 会被加两次。应当互斥校验；
2. **ref 的温度不跟 actor 同步**：loss 形式用 actor 温度下的 π_θ 去和 ref 比，若 ref 的温度固定为 1，T ≠ 1 时**就算模型完全没变，KL 也不为 0**。这与 §3.2 的温度口径问题是同一类错误：比较两个分布前，先确认它们是在同一温度、同一截断下算出来的；
3. **聚合分母口径**：KL 项的分母要和主 loss 用同一种聚合方式（token 等权或轨迹等权），否则两项的相对权重会随长度分布漂移。

反过来，KL 进 reward 这条路径在常见配置下温度是对得上的：推理端返回的 raw logprob 是 T = 1，ref 默认也是 T = 1。

**建议**：GRPO/GSPO 显式二选一：

- 不要 KL：关掉 KL 系数，不建 ref（省掉一次 ref 前向和显存）；
- 要 KL：KL 进 reward 的系数设 0，只开 loss 形式，也就是论文写法。

带 critic 的 PPO 保留 KL 进 reward 是标准做法。

- 与 [Reward 崩溃与归因实验](AgentRL的Reward崩溃与归因实验_20261009.md) 相关：KL 长度效应的量级在健康期很小，且无 KL 对照同样崩溃，支持 [KL 不是根因](训练崩溃归因的工作流与实验解读_20261012.md)。
- 本次新增了什么：近似 KL 均值符号的判读；同模型只改温度的对照；熵下降使温度偏差收缩；几何平均抵消逐 token 偏差；“不可能的读数 → 定义错误”；KL 两种放法的完整对比与三个实现缺口。
- 哪些地方修正了旧理解：批级归一化不只影响零方差组；它在整个 batch 上算一次，不在 minibatch 里；被归一化的是 advantage，不是 token 的 reward；“GRPO 用了 GAE”本身没问题，问题在 KL 被累加。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| `log π_prox − log π_behave` 均值在 T = 1 时为极小负数 | 两套引擎的正常数值差，符合 `−KL ≤ 0` | 多个 T = 1 运行是否稳定在同一量级 |
| 同模型 T < 1 时该均值为正 | 记录的是 T = 1 的 raw 分布，实际按更尖的分布采样 | 同模型只改温度对照，看与陈旧度是否相关 |
| 温度偏差随训练推进变小 | 熵下降、分布变尖，温度影响减弱 | 把偏差和熵画在同一张图上 |
| 序列级重要性权重几乎恒为 1 | 几何平均抵消了逐 token 的正负偏差 | 看逐 token 比值的最大/最小值 |
| 近似 KL 与 clip 比例每步精确为 0 | 整批只更新一次，π_θ ≡ π_prox | 改成多 minibatch 或多 epoch 后应变非 0 |
| 陈旧度均值为负 | 参考版本定义差了一个 | 对照版本号的计算公式 |
| KL 进 reward 的 k1 均值为负 | 记录的分布与实际采样分布对不上 | 与训推近似 KL 的异常时间对齐 |
| T ≠ 1 时模型没变，KL loss 却不为 0 | ref 温度没跟 actor 同步 | 检查 ref 实际使用的温度 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 训推近似 KL 在 T = 1 时应为 0 | 应为极小负数：正常数值差，期望 = −KL ≤ 0 |
| 近似 KL 偏离 0 就是陈旧度造成的 | 先看与陈旧度是否相关；同模型只改温度可以把温度单独拆出来 |
| 逐 token 有 1.2 / 0.7 的偏差，序列级权重也会偏很多 | 几何平均让正负偏差相互抵消，只剩很小的整体偏移 |
| 崩溃时训推不一致飙升，所以它是诱因 | 它在熵上升之后才出现，是结果 |
| 按 token 的批级归一化只影响零方差组 | 影响每个 token；零方差组只是从 0 变非 0 最显眼 |
| 批级 Advantage 归一化在 minibatch 里做 | 对整个训练 batch 只算一次，再切 minibatch |
| 批级归一化归一化的是每个 token 的 reward | 归一化的是 advantage；reward 在组内按条数归一化 |
| 零方差组只来自全错 | 全对也是；健康期往往以全对为主 |
| GRPO 用了 GAE 就是写错了 | V ≡ 0、γ = λ = 1 时 GAE 只是广播；问题在 KL 被沿序列累加 |
| KL 进 reward 是错误写法 | 是 PPO-RLHF 的标准写法，约束的是序列总 KL；GRPO 论文放在 loss 里 |
| 同时开两种 KL 只是“更保险” | KL 被加两次，应互斥 |

## 7. 一分钟复习

1. 按 p 采样时 `E[log r − log p] = −KL ≤ 0`：近似 KL 稳定为正，或 k1 均值为负，说明记录的分布 ≠ 采样分布。
2. 先写判断标准再看数字；同模型只改温度，比跨模型对比干净。
3. 温度偏差：T < 1 为正，随熵下降收缩，几何平均后只剩百分之一量级。存在、很小、仍应修；`1/Z` 看不到。
4. 指标比它的前兆晚出现 → 它是结果。读数物理上不可能 → 先查定义。
5. 批级归一化作用于每个 token，在整个 batch 上算一次；1/s 像 AGC，有效学习率随信号变少而变大。
6. 零方差组 = 全对或全错；健康期以全对为主，崩溃时翻转成全错。
7. GRPO 下的 GAE 就是广播；KL 进 reward 约束序列总量、会被 1/s 放大；KL 进 loss 只管当前 token。二选一，不要同时开。

## 8. 自测问题

### 问题 1

推理端返回 T = 1 的 raw logprob，采样温度 0.8，训练侧重算时除以温度。没有任何 off-policy 时，`log π_prox − log π_behave` 的 token 均值应该是正还是负？T = 1 时呢？为什么？

期望回答：T = 0.8 时为正，因为 token 按更尖的 q 采出，均值约等于 `KL(q‖π_behave)`；T = 1 时为极小负数，因为样本按 π_behave 采出，期望等于 `−KL(π_behave‖π_prox)`，只反映数值差。

### 问题 2

逐 token 比值可以偏到 1.2 或 0.7，为什么序列级重要性权重却几乎恒为 1？这个偏差还要修吗？

期望回答：几何平均 = exp(逐 token log 比值的平均)，高概率词的正偏差和低概率词的负偏差相互抵消，只剩很小的整体偏移，熵低时更小。仍要修，因为单次更新时 `π_prox/π_behave` 是唯一生效的修正，分母口径必须正确。

### 问题 3

“按 token 的批级 Advantage 归一化只影响零方差组”，错在哪？

期望回答：减 m、除 s 作用在每个 token 上，有信号的组同样被平移和放大，例如 m < 0 时答错的长回答受罚变轻。零方差组只是从 0 变成非 0，性质变化最显眼。此外它在整个 batch 上只算一次，不在 minibatch 里。

### 问题 4

同事说：“KL 写进 reward 里一起走了 GAE，GRPO 还要什么 GAE。”怎么回答？

期望回答：GAE 在 V ≡ 0、γ = λ = 1 下退化成 reward-to-go，对任务 reward 只是广播，和论文的 Â 一样。真正的差别是 KL 被沿序列累加：token t 背着从 t 到结尾的 KL 总和，长回答罚得多，还参与批级归一化被 1/s 放大。这是 PPO-RLHF 写法，不算错，但 GRPO 论文把 k3 KL 放在 loss 里。建议二选一：不要 KL，或只用 loss 形式。

### 问题 5

KL loss 在 T = 0.8 的运行里，模型参数刚初始化、和 ref 完全相同，KL 却不为 0。最可能是什么原因？

期望回答：π_θ 按 actor 温度 0.8 计算，ref 仍按默认温度 1 计算，两个分布的温度口径不同。

## 9. 尚未解决与后续路线

- 截断的 `1/Z` 与“被截词拿不到负 Advantage”仍无直接证据，待改 top-p 的单变量实验；
- 去掉批级归一化、改 top-p 的两组长跑对照仍在进行中，结论待出；
- 修正 `π_behave` 口径（返回处理后 logprob）与路由回放、MTP 的兼容性待评估；
- k1、k2、k3 三种 KL 估计器的偏差/方差与梯度性质：已在当晚补录 [KL 估计器与放置位置的设计动机](KL估计器与放置位置的设计动机_20261015.md)（10 月 16 日补录），k2 的梯度性质仍待推导；
- 按条数统计 m 和 s 作为可选开关的实际效果待验证。
