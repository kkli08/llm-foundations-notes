### RLVR 问题

- Actor 是另一个模型，还是同一个模型家族在训练系统中的角色？
- Old Policy 与 Reference 都像“旧模型”，为什么不能混为一谈？
- 如果 Reference 是 W0、Rollout 是 W5、训练后 Actor 是 W6，三类 Logprob 分别在什么时候由谁计算？
- Reference 与初始预训练模型、RL 起点 Checkpoint、Checkpoint 回滚分别是什么关系？
- Reward 上升是否足以证明 RLVR 训练变好？还应观察哪些指标？

### RLVR 易混淆点

- 曾把 Actor 泛化为“模型本身”，没有区分模型家族、Checkpoint 与运行时角色。
- 曾把 Reference 理解成 Reward 的加权器或训练效果判定器。
- 曾认为旧策略 Logprob 没有明显用途。
- 曾把 Current Logprob 理解成“Actor 更新为 W6 后才得到的 Logprob”，颠倒了 Loss 与参数更新的因果顺序。
- 曾把 Reference 的固定起点直接等同于最原始预训练模型。

### RLVR 核心理解

- Actor、Reference 与 Rollout 可以来自同一模型家族甚至同一个 RL 起点 Checkpoint，但分别承担可训练策略、冻结行为锚点和高吞吐采样副本的角色。
- Reference 通常固定在 RL 开始时选定的策略 Checkpoint；这个起点可能已经经过 SFT 或其他训练，不一定是原始预训练模型。
- Old Policy 是实际生成当前批次 Response 的行为策略。它会随批次变化；实现中可以保存 Old Logprob 和权重版本，而不必长期保留完整旧模型副本。
- 在 W0/W5/W6 示例中，Reference W0 计算 Ref Logprob，Rollout W5 生成 Response 并记录 Old Logprob；Actor 首次计算带梯度的 Current Logprob 时通常仍是 W5。Current Logprob 进入 Loss 后才通过 Backward 和 Optimizer 把 Actor 更新到 W6。
- 如果一个批次进行多个优化小步，Old 与 Reference Logprob 通常固定，Current Logprob 会随 Actor 参数更新而重新计算。
- W6 必须同步给 Rollout，下一批样本才真正来自新策略。
- Reference/KL 只回答策略偏离固定锚点多少，不能单独证明能力变好；判断 RLVR 效果需要结合任务/固定评测、策略偏离和训练健康指标。

### MTP 问题

- MTP 的全称是什么？它是训练目标还是推理优化？
- 训练时模型为什么知道未来 Token 是正确 Label？
- NTP 的下一个 Token Label 与 MTP 的更远 Token Label 怎样从同一条序列构造？
- Cross-Entropy Loss 是否是预测 Token ID 与正确 Token ID 的数值距离？
- Forward、Loss、Backward、Gradient 和 Optimizer 分别负责什么？
- MTP 参数有梯度但不在 Optimizer 中，是否仍会被更新？
- 为什么训练好的 MTP 参数既要覆盖 Checkpoint 持久化，又要覆盖推理权重转换与 Rollout Weight Sync？

### MTP 易混淆点

- 曾把“模型在 Forward 时不能看未来”误解成“训练程序也不知道未来 Label”。
- 曾把 Loss 直观理解成两个 Token 编号之间的距离。
- 曾把 Backward 与 Optimizer 都理解成“修改权重”，没有分清计算梯度和执行更新。
- 曾认为 Adam 负责计算梯度；实际上梯度由自动求导和 Backward 产生。
- 尚未建立 MTP 从 Label、Loss、参数更新到 Checkpoint 和推理同步的完整链路。

### MTP 核心理解

- MTP 是 Multi-Token Prediction。训练侧为当前位置增加更远未来 Token 的预测目标；训练出的能力可以在推理侧用于产生 Draft Token，但训练目标和推理验证不是同一个步骤。
- 完整训练序列本来就包含未来 Token。Causal Mask 阻止当前位置的表示在 Forward 中偷看未来；训练程序仍可把未来位置的真实 Token 作为 Label。
- NTP 与不同步长的 MTP Label 可以由同一 Token 序列按不同 Offset 移位得到，不需要人工为每个位置重新标注。
- Cross-Entropy 关注正确 Token 获得的概率，单位置直觉是 `-log P(正确 Token)`；Token ID 是类别编号，编号差没有可训练的语义距离。
- Forward 产生预测，Loss 定义目标，Backward 沿计算图求每个参数的梯度，Optimizer 才真正更新参数。
- `loss.backward()` 通常把梯度累积到 `parameter.grad`，不会立即改变参数；`optimizer.step()` 读取梯度并更新 Optimizer 参数组中的参数。
- MTP 参数只有同时参与 Forward/Loss、获得梯度、进入 Optimizer 参数组，才会在训练中更新；更新后还要分别覆盖 Checkpoint 持久化路径，以及面向 Rollout 的权重映射/同步路径。在线同步不一定经过 Checkpoint 文件。
