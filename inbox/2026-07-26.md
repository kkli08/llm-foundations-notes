### 今天的问题

- Actor 是另一个模型，还是同一个模型家族在训练系统中的角色？
- Old Policy 与 Reference 都像“旧模型”，为什么不能混为一谈？
- 如果 Reference 是 W0、Rollout 是 W5、训练后 Actor 是 W6，三类 Logprob 分别在什么时候由谁计算？
- Reference 与初始预训练模型、RL 起点 Checkpoint、Checkpoint 回滚分别是什么关系？
- Reward 上升是否足以证明 RLVR 训练变好？还应观察哪些指标？

### 今天暴露出的易混淆点

- 曾把 Actor 泛化为“模型本身”，没有区分模型家族、Checkpoint 与运行时角色。
- 曾把 Reference 理解成 Reward 的加权器或训练效果判定器。
- 曾认为旧策略 Logprob 没有明显用途。
- 曾把 Current Logprob 理解成“Actor 更新为 W6 后才得到的 Logprob”，颠倒了 Loss 与参数更新的因果顺序。
- 曾把 Reference 的固定起点直接等同于最原始预训练模型。

### 整理后的核心理解

- Actor、Reference 与 Rollout 可以来自同一模型家族甚至同一个 RL 起点 Checkpoint，但分别承担可训练策略、冻结行为锚点和高吞吐采样副本的角色。
- Reference 通常固定在 RL 开始时选定的策略 Checkpoint；这个起点可能已经经过 SFT 或其他训练，不一定是原始预训练模型。
- Old Policy 是实际生成当前批次 Response 的行为策略。它会随批次变化；实现中可以保存 Old Logprob 和权重版本，而不必长期保留完整旧模型副本。
- 在 W0/W5/W6 示例中，Reference W0 计算 Ref Logprob，Rollout W5 生成 Response 并记录 Old Logprob；Actor 首次计算带梯度的 Current Logprob 时通常仍是 W5。Current Logprob 进入 Loss 后才通过 Backward 和 Optimizer 把 Actor 更新到 W6。
- 如果一个批次进行多个优化小步，Old 与 Reference Logprob 通常固定，Current Logprob 会随 Actor 参数更新而重新计算。
- W6 必须同步给 Rollout，下一批样本才真正来自新策略。
- Reference/KL 只回答策略偏离固定锚点多少，不能单独证明能力变好；判断 RLVR 效果需要结合任务/固定评测、策略偏离和训练健康指标。
