### 对话或资料摘录

- 只把 KL 系数改为 0 的一臂照样崩，只是晚了十几步；崩溃起点本来就有约 10 步以上的运行间方差，所以“晚崩”不能当作 KL 能延缓崩溃的证据；此前“KL 进 Reward 造成隐式长度惩罚”的主因假设被否定；
- 原配置崩溃后梯度范数飙到几百，关 KL 的一臂崩溃后梯度范数为 0：全零组时任务 Advantage 为 0，前者还剩被批归一化放大的 KL 项，后者什么都没有——梯度范数暴涨是崩溃的结果，不是原因；
- 整套移植稳定配方的一臂跑满 100 步不崩，但熵一开始就降到很低并保持；末段每轮输出反而变长、触发长度上限的比例上升，方向与崩溃相反，需要更长的观察窗口。

- 这个模型似乎是用 GRPO 跑的，代码对比里说“PPO 损失函数一样”，这和 PPO 关系大吗？
- 我本质上还不太了解 GRPO、PPO 具体怎么做（偏 infra 背景）。

### 对话或资料摘录

- GRPO 与 PPO 的区别只在 Advantage 从哪来；拿到 Advantage 后都用同一个带 Clip 的 surrogate loss；
- 没有 Critic（Value 全 0）、γ=λ=1、Reward 只在末 Token、Reward 先组内归一化时，GAE 退化成“每个 Token 拿整条轨迹的组内归一化 Reward”，就是 GRPO；
- 同属 GRPO 的实现差异：KL 是否进 Reward、是否再做批级归一化、Loss 按 Token 还是按轨迹等权、零方差组保留还是丢弃。

## 14:56｜批级 Advantage 归一化为什么会出问题

>
> 来源：Claude Code 会话 `9be5c822`

### 今天的问题

- 第一轮三个单变量实验分别在算法里起什么作用？
- E1（去掉批级归一化）还是没理解，能不能补上下文、讲深一点？
- 对 GRPO 的整体流程没有宏观认知，讲到细节时理解模糊。
- 所以现在是：稳定的组都没做批级归一化，不稳定的都做了，要验证单改这一项能不能稳？

### 对话或资料摘录

- 组内归一化后每组 Advantage 按条数平均为 0，但批级归一化按 Token 加权取均值，成功与失败轨迹长短不同时均值 m ≠ 0；减 m 后零方差组从 0 变成非 0；
- 减 m 等于给所有 Token 加同一常数；On-policy 下它的期望梯度为 0（就是 Baseline），但 Top-p/Top-k 截断采样时变成系统偏移，可能抬高长尾（含 EOS）概率（推导出的假说）；
- 除 s 让有信号的 Token 越少、步长越大；
- 先前讲解两次被修正：零方差组被“压低”还是“推高”取决于 m 的符号，而 m 的符号随训练动态变化；KL 项“1e-3 量级”是每 Token 的值，进 Advantage 后会沿后续 Token 累加；
- 稳定组都没做批级归一化只是相关性，必须单变量验证。
