## 推荐使用方式

### 白天：只管捕获

学习过程中，不要求马上把内容写得很完整。将原始材料追加到：

```text
inbox/YYYY-MM-DD.md
```

可以记录：

- 今天和 Codex 讨论的问题；
- 自己尚未确定的理解；
- 命令、日志和实验现象；
- 想在下班前整理的问题；
- 值得长期保留的结论。

在 Codex 中也可以直接说：

```text
把刚才这段学习内容追加到 llm-foundations-notes 当天的 inbox。
```

### 下班前：自动整理

工作日下班前的自动任务会：

1. 同步 GitHub 最新状态；
2. 阅读总索引、快速复习页和最近几篇正式笔记；
3. 阅读当天 `inbox`；
4. 去重、纠错并补齐上下文；
5. 生成当天正式笔记；
6. 更新总索引和复习队列；
7. 运行基础检查；
8. 提交并推送到 GitHub。

如果当天没有实质性 `inbox` 内容，任务不会凭空生成学习记录，也不会创建无意义提交。

### 第二天：先复习再学习

建议开始新内容前依次阅读：

```text
reviews/QUICK_REVIEW.md
→ 前一天正式笔记的“一分钟总结”
→ 前一天正式笔记的“自测问题”
→ 当天新内容
```

## 仓库结构

```text
llm-foundations-notes/
├── README.md                    # 使用说明和入口
├── INDEX.md                     # 日期索引、主题索引
├── AUTOMATION.md                # 自动整理规范
├── inbox/                       # 当天未整理的原始记录
│   └── README.md
├── notes/                       # 已整理的正式笔记
│   └── YYYY/MM/
├── reviews/
│   └── QUICK_REVIEW.md          # 快速复习与间隔复习队列
└── templates/
    └── daily-note.md            # 每日正式笔记模板
```

## 核心原则

- 原始记录和正式笔记分离；
- 正式笔记必须有日期、主题和复习摘要；
- 不重复堆砌旧内容，而是建立链接；
- 不确定内容明确标记，不把推测写成事实；
- 一次实验尽量只改变一个主要变量；
- GitHub 中的内容以 Markdown 为主，保证手机和电脑都能快速阅读；
- 每次自动提交只包含本知识库范围内的文件。
