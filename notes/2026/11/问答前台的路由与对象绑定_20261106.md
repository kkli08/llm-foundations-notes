## 0. 今天最终要解决的问题

按提问顺序：

1. 线上现在已经有可以和慢轨 agent 对话的功能了吗？有设置选项可以开关是吗？
2. 这个功能最好也是先在设置里加个开关，默认打开，也可以显式关闭。
3. 打开试用。
4. **感觉对话有个小问题，不知道是不是因为没写 skills，现在对话在外层，问一些弱相关的问题还是没有特别智能。比如问"现在能和你对话了吗"，回答都是"你说的是指哪个实验或哪个服务"。下一步想把私聊前台做得更智能。**
5. 批准评测。

第 4 问用户同时说了不要动的部分：噪音控制和话题内的分析都很好。

## 1. 先给结论

- **投递通了不等于好用**：占位卡第一次在真实 IM 上走通，回答却只会反问。
- **限额要改变模型的下一步**：次数到了只回"已经查过了"，模型换词继续查，循环没停。
- **冒烟题暴露不了说法问题**：题目里的实验名都能精确匹配。
- **用户的猜测对了一半**：和没写 skill 有关，但更直接的原因是路由只有三个出口。
- **模型要有关于自己的资料**：否则"你能做什么"既不是实验问题，也答不上来。
- **固定话术只给兜底**：无关问题也要告诉用户能问什么。
- **弱相关问题可以短答，但要标明没查日志**：涉及具体实验的结论仍必须有引用。
- **评测集不为通过而改**：47 题 41 题符合预期，没过的写进已知限制。
- **引用校验查不出绑错对象**：别的作业的失败写进证据包，引用照样能过。
- **猜到的身份不算证据**：按时间匹配到的作业，候选只有一个也不算确定。
- **修法收敛在删代码**：四轮审查，规则越改越简单。
- **开关要说清三件事**：什么时候生效、没生效时显示什么、关了之后谁回答。
- **失败即拒绝的检查要验证前提**：读不到来源字段就不答，前提是用户消息确实带这个字段。

## 2. 前置概念

### 2.1 路由决定模型能给出什么回答

模型的输出被代码收敛成几种类型（回答、证据不足、无关、反问）。**类型集合就是能力边界**：一个问题落不到合适的类型里，模型再聪明也只能选最接近的那个。

### 2.2 绑定（Binding）

问答要先确定"这句话问的是哪个对象"，后面所有证据都按这个对象取。绑定错了，后面每一步都是对的，结论却是另一个实验的。

| 绑定依据 | 可信度 |
|---|---|
| 系统记录的标识（作业号、名字完全匹配） | 高 |
| 用户在话题里问（话题绑定实验） | 高 |
| 模型从说法推断 | 中，要说明 |
| 按时间范围猜 | 低，不能当证据 |

## 3. 完整原理

### 3.1 第一次真人试用

用户问线上能不能对话，总控答：代码已部署，功能没打开，开关是配置文件里的一项，不在设置卡片里。

用户打开试用后，前两题的结果：

| 看什么 | 结果 |
|---|---|
| 占位卡和回填 | 第一次在真实 IM 上走通，十几秒 |
| 流式 | 无报错 |
| 告警分析 | 不受影响 |
| 回答 | 两题都没答出来，最后反问是哪个实验 |

执行者**只看工具调用的参数形状和回复类型，不读问题和回答的正文**，就定位了原因：

```text
第 1 次列实验：正常，模型已经拿到列表
第 2 次带关键词查：结果为空
第 3 次起撞上"每题最多 2 次"：只收到"已经查过了"，模型换词继续试，直到步数用完
```

**这个限额本来是防循环的，循环没停，后面的搜索反而全失败了。** 第二题调了 12 次工具全是这一个。

规律：**只拒绝不指路，模型会换个说法再试。** 限额要改变模型的下一步。这补充了 [提示词是建议，工具层才是约束](实验问答的入口与通知语义_20261105.md#39-自由文本比引用风险高)：工具层的约束也分好坏，返回的文字要告诉模型接下来能做什么，到了第二次就直接收走工具（[`tool_choice=none`](慢轨Agent的工具循环与离线评测_20261104.md#34-预算与强制收尾)）。

| 修法 | 内容 |
|---|---|
| 第一次被拒 | 告诉模型用已有列表回答或追问，它还能转去读日志 |
| 第二次被拒 | 结束调用工具，直接收尾 |
| 查询放宽 | 按多个词匹配，全词对不上时退回匹配一部分并说明 |
| 空结果 | 说明按什么匹配，提示从已列出的实验里挑 |
| 澄清卡片 | 最多列 5 个候选，**只来自系统数据，不用模型写的文字**；回序号或名字的一部分就能定位 |

之前冒烟没暴露，是因为题目里的实验名都能精确匹配。**测试题是开发者写的，真人的说法不一样。** 话题路径因为实验已知，第一条话题提问约 25 秒、5 步答完，3 条引用全部通过，很干净。

### 3.2 用户的判断：没写 skill 吗

用户问是不是因为没写 skill。总控的回答：**这和没写 skill 有关，但更直接的原因是前台路由太窄，模型能力不是问题。**

| 问题 | 当时的情况 |
|---|---|
| 路由 | 只有回答实验问题、判定无关、反问三个出口 |
| 自身知识 | 模型没有任何介绍这个系统的资料 |
| 结果 | "现在能和你对话了吗"既不算实验问题，也不知道怎么答自己，落到了反问 |

这是 [评价 agent 前先复原信息环境](调查Agent的质量归因与Harness设计_20261105.md#32-归因先看模型到底看到了什么)在前台的版本：出口不存在、资料不存在，模型没有选择。

### 3.3 前台怎么改（修订 11 月 5 日）

| 问题类型 | 处理 |
|---|---|
| 关于系统自身 | 按一篇短文档回答，不调实验工具 |
| 实验概况 | 列状态 |
| 具体实验 | 确实需要指定时才反问，并列候选 |
| 弱相关知识 | 简短回答，标明是通用知识、未读日志 |
| 闲聊或无关 | 礼貌一句，并告诉用户能问什么 |

几条边界：

- **只改私聊**：话题路径和告警路径字节级比对保持不变，用户说好的部分不动；
- **涉及具体实验的结论必须有引用**：不只靠提示词，代码层也兜底；
- **自身文档就是用户说的 skill**：写清能力、边界、数据来源和用法。（整理时的理解）这条符合 [11 月 5 日 §3.6](实验问答的入口与通知语义_20261105.md#36-自部署模型要不要写-skill)的判据，而且这类问题确实高频。

11 月 5 日写的是"无关问题回一句固定的话"，这里改成**说明能问什么**：固定话术只适合兜底，用户问"你能做什么"时，这正是要回答的问题。

### 3.4 私聊评测怎么读

用户批准了一次真实模型评测，范围是串行、不发 IM、不改线上配置，告警分析在跑时让路。执行者先去总控的会话记录里核实了用户原话（[批准要回到原话](多Agent并行开发的编排与核实_20261104.md#33-转述的批准不算批准)）。

| 指标 | 结果 |
|---|---|
| 47 题符合预期 | 41 题 |
| 耗时 | p50 约 4 秒，最大约 22 秒 |
| 502 | 0 次 |
| 用户举的例子 | 都按文档回答了，约 4 秒 |
| 编造实验事实 | 没发现；读过日志的回答都有通过校验的引用 |

没过的 6 题也有分类：

| 情况 | 读法 |
|---|---|
| 类型判对，文字被门禁拦回固定话术 | 门禁靠词表，这是已知限制 |
| 直接答了唯一在跑的实验，并写明实验名 | 可能其实是对的，只是不符合期望 |
| 不存在的实验回"没有符合条件的实验" | 内容如实，不在评测集的期望里 |

**评测集没有为了通过而改**，这些写进了改动说明。这和 [门槛先写死](慢轨Agent的工具循环与离线评测_20261104.md#37-离线评测怎么设计)一致。

### 3.5 问 A 答 B：猜到的身份不算证据

这是问答打开前最严重的问题。有一类实验的目录按时间戳命名，记录里没有作业号，系统只能按时间范围找候选作业。问题在于：

```text
问实验 A → 按时间匹配到作业 B → B 的失败告警和日志尾部进了证据包 → 模型如实引用 → 引用校验通过
```

**引用校验查的是"这一行存在"，不是"这一行属于被问的实验"。** 这是 [代码查一致性不查真假](Agent系统的权限分层与事务性副作用队列_20261102.md#316-代码检查的是一致性不是真假)的又一个具体形状，也是 [引用全对不等于结论对](调查Agent的质量归因与Harness设计_20261105.md#31-第一条真实告警引用全对根因错了)的第二种原因：第一种是证据不够，这一种是证据属于别的对象。

四轮对抗审查的过程：

| 轮 | 修法 | 审查发现 |
|---|---|---|
| 1 | 候选多于一个时不绑定 | 1 条阻断：证据包照样写入别的作业的失败；4 条高优先级，包括自己的回归（问 B 时说"没有记录结束原因"） |
| 2 | 这类实验的作业信息一律不算证据，候选一个也不算；快轨候选多于一个时不认领 | 2 条阻断 2 条高优先级：结局报错行；回归：已结束的显示成"训练中" |
| 3 | 一律不认领，单候选也不认领；加"状态不确定" | 1 条阻断：为查旧作业加的行占用了实验名，问名字答成旧提交 |
| 4 | **删代码**：不再建这些行 | 没有确认的新缺陷；非此类实验随机差分几千轮 0 差异 |

几点：

- **查线上再定范围**：几十个实验里只有 3 个这类目录，都已结束，没有绑错的告警。所以用一条简单规则，不加持久字段；
- **规则越来越简单**：从"候选几个时怎样"变成"按时间匹配的一律不算"；
- **不确定要有自己的状态**：不借用"训练中"或"观测中断"（[错误被转换成合法取值](../10/自定义检查与框架契约不一致及故障阶段的结论边界_20261030.md#312-静默失败的三个具体形状)的反面）；
- **范围超出批准要说**：总控同意的是"候选多于一个"，最终范围更大，写进"合入后需要注意"并告诉总控；
- **代价写明**：看板可能多一行，真实作业的失败显示在作业自己的行上。

这条线和 [脱敏审查收敛](脱敏的回退证明与审查收敛_20261106.md#38-审查什么时候算收敛)是同一个规律：换成简单规则才收敛。

### 3.6 开关要说清三件事

用户先问有没有开关，答案是有，但在配置文件里，而且关闭有两个不直观的地方：改回 0 只是不再收新消息，已排队的题还会答完；要立刻停只能删配置文件，告警分析也会一起停。

用户要求：设置里加开关，默认打开，能显式关闭。实现后的语义：

| 问题 | 设计 |
|---|---|
| 什么时候生效 | 总开关和用户设置都打开才生效 |
| 老设置文件 | 读出来算打开 |
| 总开关没开或进程不在线 | 按钮写"未生效"，说明谁来回答，不显示"开启" |
| 关闭后 | 不读消息、不调模型；规则模板回私聊 |
| 关闭后的话题 | **没人回**，因为规则模板读不到话题，卡片上写明 |
| 排队的题 | 每题前重读设置，不再调模型；正在答的那题答完 |
| 设置文件读不到 | 沿用上一次的值；刚启动就读不到算关闭 |

**"默认打开"要多想一步**：总开关一打开，用户没操作过也会调模型。所以打开前要先真机确认这个按钮。

（整理时的理解）开关的设计问题不是"有没有"，而是：**它表达的状态和系统实际状态一致吗？关了之后用户的消息去哪了？** 这和 [颜色要和判断的证据匹配](实验问答的入口与通知语义_20261105.md#33-上色之前先拆状态)同一个道理。

### 3.7 失败即拒绝的检查要验证前提

为防止答到别的会话，话题消息的来源字段不是这个一对一会话时不答，**读不到也不答**。

这是对的默认，但它有一个前提：平台返回的话题消息要带这个字段。不带的话，话题问答会全部不工作，而且表现为"什么都不发生"。

| 阶段 | 证据 |
|---|---|
| 打开前探针 | 现有话题的消息都带，但全是机器人发的 |
| 真机 | 用户的第一条话题提问走通，确认用户消息也带 |

**机器人的消息带字段，不代表用户的也带。** 执行者把这条列进真机确认，第一条真实提问才关掉这个未知。这和 [Available 不等于就绪](推理服务上线的容量估算与鉴权验证_20261105.md#36-available-不等于就绪)一样，要测真实路径。

### 3.8 输出过滤的取舍

回答里的链接要去掉，防止模型输出钓鱼链接。这个过滤修了几轮，有几处通用的教训：

| 问题 | 例子形状 | 处理 |
|---|---|---|
| 吃掉后文（最重要） | 链接后紧跟中文标点时，后面的诊断内容一起被删 | 只去掉链接本身 |
| 误删网段和路径 | `10.0.0.0/8`、`logs.bak/` | 收窄判定 |
| 澄清绕过 | 结论写成反问就绕开"未读日志"标注 | 只看句子结尾 |

留下的已知项也写明了：有的形状拦不住，有的修法会误伤，例如 `train.py/eval.py` 和恶意链接分不开。**规则式过滤的代价要写出来，不是假装没有。** 真实日志近三万行里只有 1 行输出变化。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 回答总是反问 | 路由出口太少或查询太严 | 看工具轨迹和回复类型 |
| 同一工具被调十几次 | 限额只拒绝不指路 | 看被拒后的下一步 |
| 问 A 答 B 且带引用 | 证据按猜到的身份取 | 核对证据来源的作业 |
| 已结束的显示训练中 | 把"不确定"映射到现有状态 | 加显式的不确定状态 |
| 话题里消息没人回 | 来源字段读不到，或开关关了 | 看日志里拒绝的原因 |
| 问名字答成旧提交 | 新加的行占了实验名 | 差分对比 |
| 诊断内容被删 | 过滤吃掉了链接后的文字 | 真实日志比对 |
| 按钮写开启但没人答 | 只看用户设置 | 同时看总开关和进程心跳 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 回答不智能就是模型不行 | 先看路由和资料 |
| 写个 skill 就解决了 | 路由出口太窄时，有资料也没地方用 |
| 工具层加限额就能防循环 | 只拒绝不指路，模型会继续试 |
| 冒烟全过就能给真人用 | 冒烟题的说法是开发者写的 |
| 引用通过校验就是这个实验的 | 校验只查这行存在 |
| 候选只有一个就可以绑定 | 按时间猜到的都不算证据 |
| 默认打开风险小 | 总开关一开就开始调模型 |
| 关掉开关就立刻停 | 正在答的、排队的要看设计 |
| 机器人消息带字段，用户消息也带 | 要真机确认 |
| 评测没过就改评测集 | 没过的写进已知限制 |

## 7. 一分钟复习

1. 投递通了不等于好用；第一次真人试用才暴露说法问题。
2. 限额要改变模型的下一步：第一次指路，第二次收工具。
3. 澄清候选只来自系统数据，不用模型写的文字。
4. 路由出口 = 能力边界：系统自身、概况、具体实验、弱相关、闲聊。
5. 自身文档就是 skill；弱相关短答并标明未读日志；具体实验必须有引用。
6. 固定话术只兜底；无关问题说明能问什么。
7. 引用校验查不出绑错对象。
8. 按时间猜到的身份不算证据，单候选也不算；不确定要有自己的状态。
9. 四轮收敛在删代码；范围超出批准要说。
10. 开关三件事：何时生效、未生效时显示什么、关了之后谁回答。
11. 失败即拒绝要验证前提：用户消息也带字段吗。

## 8. 自测问题

### 问题 1

第一次试用两题都反问，原因是什么？为什么限额没有防住循环？

期望回答：第一次列实验正常，第二次带关键词查为空，第三次起撞上每题 2 次的限额，只收到"已经查过了"，模型换词继续试到步数用完。限额只拒绝不指路，没有改变模型的下一步。修法是第一次被拒告诉它用已有列表回答或追问，第二次被拒直接收走工具；查询放宽，反问时列系统数据里的候选。

### 问题 2

用户问是不是因为没写 skill，总控怎么答？改了什么？

期望回答：有关，但更直接的原因是路由太窄：只有回答、无关、反问三个出口，又没有介绍自身的资料，所以"能和你对话吗"落到了反问。改成先分五类，加一篇自身文档，弱相关问题短答并标明未读日志，无关问题说明能问什么。只改私聊，话题和告警路径字节级不变。

### 问题 3

为什么问 A 答 B 时引用还能通过校验？这和第一条真实告警的"引用全对、根因错"有什么不同？

期望回答：证据按猜到的作业取，别的作业的失败写进了证据包，引用校验只查这一行存在，不查这一行属于被问的实验。第一条告警是证据不够，这次是证据属于别的对象，都说明引用校验是必要条件。

### 问题 4

问答绑定为什么走了四轮？最后的规则是什么？

期望回答：前几轮修"候选多于一个时怎样"，每轮都有新路径把结局或证据报到错的实验，还带来回归。最后的规则是按时间匹配到的作业一律不算证据，单候选也不认领，加"状态不确定"，删掉为旧作业建的行。先查线上只有 3 个这类实验，所以不加持久字段。规则变简单才收敛。

### 问题 5

开关默认打开时要想清哪些事？

期望回答：总开关和用户设置都开才生效；未生效时不能显示开启，要说明谁来回答；关闭后私聊走规则模板，话题没人回，要写明；排队的题不再调模型，正在答的答完；设置读不到时沿用上次，刚启动读不到算关闭。默认打开意味着总开关一开就调模型，所以先真机确认按钮。

### 问题 6

话题消息读不到来源字段就不答，这个检查有什么风险？怎么验证？

期望回答：这是对的默认，但前提是平台的话题消息带这个字段，否则话题问答全部不工作，表现为没有反应。打开前的探针只看到机器人消息带，用户消息要试用时才知道，所以列进真机确认，第一条真实提问确认了。

## 9. 尚未解决与后续路线

- 超过 30 秒的长回答、手机和桌面渲染、链接是否可点都没有真机确认。
- 私聊优化的改动当天没有合入，要重测。
- 门禁靠词表，会误拦"你能做什么"这类问题；闲聊时读文档工具可能空转。
- 看板和主卡仍跟着旧的作业字段走，这类实验可能显示猜错的作业。
- 多人使用时的权限没有设计。
- 服务当天已下线，问答退回规则记录。
