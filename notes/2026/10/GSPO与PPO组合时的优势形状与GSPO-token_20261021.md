## 0. 今天最终要解决的问题

按提问顺序：

1. 设计文档说 PPO 和 GSPO 可以组合——但 GSPO 是“按组算重要性采样”，和 PPO 关系不大吧？
2. 开源框架（verl）会显式禁止 GSPO 和 critic 同时开吗？
3. 没太懂：verl 的 GSPO 和我们实现的区别就是重要性比值吧？我们和 verl、和论文不一样？
4. verl 是给了选项，可以选“按每条回答”还是“按每个 token”算优势吗？
5. GSPO 的配置写成“在 GRPO 基础上加序列级比值、改 loss 聚合方式”，这是对齐 verl 的吗？

## 1. 先给结论

- **GSPO 和 PPO 管的是两件事**：PPO 的 critic 决定**优势从哪来**（每个 token 一个 A_t）；GSPO 决定**重要性比值按什么粒度算**（整条回答一个 s_i）。代码上正交。
- **被纠正①**：GSPO 的比值是**按序列**算的（一条回答所有 token 对数比值取平均再 exp），不是按组；“组”体现在优势上——沿用 GRPO 的组内归一化。
- **被纠正②**：两种实现的**比值数值完全相同**，裁剪也都作用在 s_i 上；区别在**优势怎么乘进去**——先把一条回答内的优势平均成 Ā 再乘 s_i（论文主版本 GSPO），还是每个 token 用 s_i × A_t（论文变体 GSPO-token）。
- **同一条回答内优势都相同时，两种写法在目标、裁剪、梯度上完全等价**；GRPO 设置下就是这种情况，所以单独用 GSPO 时两边没有对错之分。
- **配 critic 时才分道扬镳**：critic 给的是逐 token 的 A_t = G − V_t，先平均会把“哪一步写错了”抹掉，只剩一个序列级 baseline——作用接近 GRPO 的组内均值，却多付了训练 critic 的成本。要么改成 GSPO-token 写法，要么两者二选一。
- **verl 没有禁止组合，也没有“按回答/按 token”的专门开关**：比值粒度（loss 模式）与优势估计器是两个独立开关，GSPO loss 只有 GSPO-token 一种写法，优势在回答内是否相同由优势估计器决定；loss 聚合方式是第三个开关，与优势形状无关。
- **“加两项就是 GSPO”不完整**：还要配合万分之几的裁剪区间、不做批级优势归一化、关掉 KL。KL 进 reward 时逐 token 的惩罚会让回答内各 token 的优势略有不同，两种写法也会出现微小差别。

## 2. 前置概念

### 2.1 一条回答的 loss 里有三样东西

$$
\mathcal{L}_i = \text{聚合}_{t}\Big[\ \text{clip}(\text{比值})\ \times\ \text{优势}\ \Big]
$$

| 部件 | 由谁决定 | GRPO | GSPO | PPO |
|---|---|---|---|---|
| 比值 | 比值粒度开关 | 按 token：r_t | 按序列：s_i = exp(mean_t log r_t) | 按 token：r_t |
| 优势 | 优势估计器 | 组内归一化，广播到每个 token（回答内相同） | 同 GRPO | GAE / critic，逐 token 不同 |
| 聚合 | loss 聚合开关 | 常见为所有 token 等权 | 先序列内平均、再序列间平均 | 视配置 |

三个部件各管一件事。容易混的是第三个：**loss 聚合**决定“各 token / 各回答在总 loss 里占多大权重”，和“优势在回答内是不是同一个值”无关（[两个“按 Token”](GRPO变体与两层归一化的拆解_20261013.md)是同类混淆）。

### 2.2 GSPO-token 的写法

$$
s_{i,t} = \mathrm{sg}[s_i]\cdot\frac{\pi_\theta(y_{i,t})}{\mathrm{sg}[\pi_\theta(y_{i,t})]},\qquad \mathcal{L}_i \propto \sum_t s_{i,t}\,A_{i,t}
$$

sg 是 stop-gradient。数值上 s_{i,t} = s_i；梯度上每个 token 走自己的 ∇log π_θ(y_{i,t})，并乘上**自己的** A_{i,t}。实现时常写成对数形式：`log s_{i,t} = log π − sg[log π] + sg[序列平均 log 比值]`。

## 3. 完整原理

### 3.1 “GSPO 按组算重要性采样，和 PPO 关系不大”（问题 1）

用户的大方向对：两者管的不是一件事，原文“两者可以组合”的说法不准确。一处用词纠正：

| 用户的说法 | 更准确的说法 |
|---|---|
| GSPO 按**组**算重要性比值 | 按**序列**：一条回答内 token 对数比值取平均，作为这条回答的比值；“组”是优势的组内归一化 |
| 和 PPO 关系不大 | 代码上正交、可以同时打开；但在“先平均优势”的实现里，同时打开会抹掉 critic 的价值（§3.3），实际应二选一 |

### 3.2 verl 会不会禁止组合（问题 2）

不会。要不要 critic 只看优势估计器是不是 GAE（或显式启用 critic）；用不用 GSPO 只看 policy loss 模式；配置校验里没有把两者关联起来的检查。在 verl 里两者确实正交、组合也有意义，因为它的 GSPO loss 是 GSPO-token 写法，逐 token 的优势直接乘进去。

### 3.3 区别不在比值，而在优势怎么乘（问题 3，被纠正）

用户以为“区别就是重要性比值”。实际：

1. **比值**：两边、论文三者都是序列级几何平均 s_i，裁剪也都对 s_i 做；
2. **优势**：先平均（Ā × s_i）vs 逐 token（A_t × s_i）；
3. **和论文的关系**：论文本来就有两个版本——主版本每条回答一个 Â_i（先平均的实现对应它），GSPO-token 允许每个 token 不同（verl 对应它）；论文说明两者在回答内优势相同时目标、裁剪、梯度完全一样。

**什么时候不一样**：回答内各 token 的优势不同时。最典型的是 PPO 的 critic。例：一条 3 个 token 的回答，设 s = 1：

| | token 1 | token 2 | token 3（这一步写错了） |
|---|---|---|---|
| critic 给的优势 A_t | +0.6 | +0.6 | −0.9 |
| GSPO-token：A_t 逐个乘 | 往上推 | 往上推 | **往下压** |
| 先平均：Ā = (0.6 + 0.6 − 0.9)/3 = +0.1 | 轻微往上推 | 轻微往上推 | **也轻微往上推** |

先平均把“第 3 步是错的”这条信息平均掉了，而逐 token 信用分配正是 critic 最有价值的地方（[PPO 能否比 GRPO 更好地分配功劳](PPO的Critic与Clip在单次更新下的退化_20261013.md#35-ppo--gae-能否比-grpo-更好地分配功劳)）。剩下的 Ā 只是每条回答一个数的 baseline，效果接近 GRPO 的组内均值。

**两种处理**：

| 做法 | 效果 |
|---|---|
| 改成 GSPO-token 写法（对话中推荐） | GRPO 设置下结果不变；配 critic 时逐 token 优势保留，GSPO 与 PPO 真正正交 |
| 只加一条校验：序列级比值与 critic 同时开时告警或报错 | 改动最小，但等于承认两者不能组合 |

这和 [10 月 19 日 §3.5](GSPO开关解耦与按轮序列比值_20261019.md#35-按轮比值只改比值的分组advantage-不变用户的判断正确一处用词校正) 的判据是同一条：**序列单位比优势的粒度粗时才需要 GSPO-token**——那次粗的是“整条多轮轨迹 vs 每轮优势”，这次是“整条回答 vs 每个 token 的 critic 优势”。

### 3.4 有没有“按回答 / 按 token 算优势”的选项（问题 4）

没有专门的选项。GSPO loss 只有 GSPO-token 一种写法，它对两种优势形状都成立，所以不需要额外开关；优势在回答内是否相同由**优势估计器**决定：

| 优势估计器 | 回答内的优势形状 | 配上 GSPO 等价于 |
|---|---|---|
| GRPO、RLOO、REINFORCE++ 等结果奖励类 | 整条回答的奖励求和 → 组内归一化 → 同一个数广播到每个 token | 论文主版本 GSPO |
| GAE（需要 critic） | 从后往前递推，每个 token 不同 | GSPO-token，逐 token 信用分配保留 |

对照到“先平均”的实现：开关结构一样（比值粒度 ↔ loss 模式；优势模式 + 是否配 critic ↔ 优势估计器），区别只在于开了序列级比值后，loss 内部替你强制选了“按回答”。

### 3.5 “加两项就是 GSPO”对不对（问题 5）

逐项对照开源示例，完整的 GSPO 配置是一组设置，缺一项就不是论文的设置：

| 作用 | 设置 |
|---|---|
| 比值按序列 | 序列级比值开关 |
| loss 聚合 | 先序列内平均、再序列间平均 |
| 裁剪区间 | 下限约 3e-4、上限约 4e-4（[小三个数量级的 √L 估算](GSPO开关解耦与按轮序列比值_20261019.md#32-为什么-gspo-的-clip-要小约三个数量级)） |
| 优势 | 组内减均值、除标准差，之后**不再做批级归一化** |
| KL | 不进 reward、不进 loss |
| dual-clip 常数 | 示例里设了，但 GSPO 的 loss 函数根本不读它，设不设等价 |

所以“在 GRPO 基础上加序列级比值和聚合方式”这句话本身没错，但不完整；区别表里应把小裁剪、关批级归一化、关 KL 一起写上，并给出与开源框架参数名的对照。

**实现差别何时显形**：关掉 KL 时回答内每个 token 的优势完全相同，先平均与 GSPO-token 算出来一样；打开 KL 进 reward（逐 token 的 −β·KL 让各 token 的优势略有不同）或配 critic 时，两边才会不一样。

### 3.6 写参数手册时顺带确认的三件事

整理三种算法的参数手册时，对照代码核实了几处“读文档容易误会”的地方：

1. **奖励到优势的处理顺序**（常见实现）：奖励先加偏置、乘缩放 → 按 ±上限裁剪 → 奖励归一化（如按组）→ 放到回答最后一个 token → 加逐 token KL → GAE → （可选）批级优势归一化。读一个开关时先找它在这条链的哪一段（[一个训练步里各参数的生效段](GRPO训练步的参数时序与四个KL指标_20261016.md)）。
2. **参数说明和代码行为不一致时按代码写**：例如“截断回答记 0 分”的开关，帮助文字写的是“排除出训练”，实际只是把奖励记为 0，这条回答仍参与梯度（还会拿到负优势）；“记 0 分”与“排除”对梯度的影响完全不同（[截断 ≠ 结束](训练口径的隐性错误与读数签名_20261019.md)）。
3. **critic 学习率的代码默认值可能不能直接用**：通用默认值（如 1e-3）比 critic 常用量级（约 1e-5）大两个数量级，手册里要注明必须显式设置。

| 现象 | 原因 | 如何验证 |
|---|---|---|
| PPO + GSPO 的效果和 GRPO 差不多，却多花了 critic 成本 | 序列级比值实现先把逐 token 优势平均成一个数 | 打印 loss 内实际乘上去的优势，看回答内是否已变成常数 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| GSPO 按组算重要性比值 | 按序列（回答内几何平均）；组内归一化的是优势 |
| verl 与我们的 GSPO 区别在比值 | 比值数值相同；差在优势是先平均还是逐 token 乘 |
| 先平均的实现和论文不一致 | 对应论文主版本；verl 对应论文的 GSPO-token 变体 |
| 代码正交 = 组合有意义 | 先平均的实现会抹掉 critic 的逐 token 信息，组合意义不大 |
| 有一个开关选“按回答/按 token 算优势” | 由优势估计器决定；loss 聚合方式是另一回事 |
| 加上序列级比值和聚合方式就是 GSPO | 还要万分之几的裁剪区间、关批级归一化、关 KL |
| 参数帮助文字就是行为 | 以代码为准；“记 0 分”≠“排除出训练” |

## 7. 一分钟复习

1. 三个独立部件：比值粒度（GSPO 管）、优势来源（critic / 组内归一化管）、loss 聚合（权重管）。
2. GSPO 比值按序列，不按组；“组”在优势。
3. 两种实现比值相同；差在 Ā × s_i（主版本）还是 A_t × s_i（GSPO-token）；回答内优势相同时完全等价。
4. critic 例子：+0.6 / +0.6 / −0.9 → 平均 +0.1，写错的那步也被往上推 → 先平均抹掉 critic 的价值。
5. 判据：序列单位比优势粒度粗（多轮每轮优势、critic 逐 token 优势）时才需要 GSPO-token。
6. 完整 GSPO：序列比值 + 序列内再序列间平均 + 3e-4/4e-4 + 不做批级归一化 + 关 KL；KL 进 reward 会让两种写法略有差别。

## 8. 自测问题

### 问题 1

有人说“GSPO 是按组算重要性比值，所以和 PPO 的 critic 无关”。这句话哪里对、哪里要纠正？

期望回答：对的是两者管的是不同的事——critic 决定优势，GSPO 决定比值粒度，代码上正交。要纠正的是 GSPO 的比值按序列算（回答内 token 对数比值的平均再 exp），“组”体现在优势的组内归一化；而且在“先把回答内优势平均”的实现里，同时开会抹掉 critic 的逐 token 信息。

### 问题 2

一条 3 token 的回答，critic 优势为 +0.6、+0.6、−0.9，序列比值 s = 1。分别用“先平均优势”和 GSPO-token 写法，三个 token 的概率各往哪个方向推？

期望回答：先平均 Ā = +0.1，三个 token 都被轻微往上推，包括写错的第 3 个；GSPO-token 逐 token 乘，前两个往上推、第 3 个往下压。

### 问题 3

为什么在 GRPO 设置下，把 GSPO 实现从“先平均”改成 GSPO-token 不会改变任何结果？什么时候会改变？

期望回答：GRPO 的优势是整条回答一个数广播到每个 token，回答内优势相同，平均等于没变，两种写法在目标、裁剪、梯度上都等价。当回答内优势不同时才改变：配 critic（GAE 逐 token）、按轮优势的多轮轨迹、或 KL 进 reward 让逐 token 惩罚不同。

### 问题 4

verl 里怎样得到“论文主版本 GSPO”和“逐 token 信用分配的 GSPO”？需要哪个开关？

期望回答：不需要专门开关。GSPO loss 只有 GSPO-token 一种写法；配结果奖励类优势估计器（GRPO/RLOO 等）时优势回答内相同，等价于主版本；配 GAE（需要 critic）时每个 token 优势不同，就是逐 token 信用分配。loss 聚合方式管权重，与此无关。

## 9. 尚未解决与后续路线

- 是否把“先平均”的实现改成 GSPO-token，让 GSPO 与 PPO 真正可组合；改后在 GRPO 设置下做一次逐步数值对照；
- PPO + GSPO-token 与 PPO（token 级比值）的效果对比——critic 的逐 token 优势配序列级比值是否仍有稳定性收益，尚无实验；
- KL 进 reward 时两种写法差别的实际量级。
