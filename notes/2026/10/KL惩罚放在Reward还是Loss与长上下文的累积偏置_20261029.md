## 1. 先给结论

- **他说的是对的，而且这就是 GRPO 原论文的做法**：原论文把 `β·D_KL` 直接写在目标函数里、逐 token 平均。KL 进 reward 是更早的 RLHF 约定，那时回复只有几百 token、而且带 critic。
- **"累积"的准确含义**：折扣与 GAE 的 λ 都是 1、GRPO 没有 critic（价值恒为 0）时，GAE 退化成纯 reward-to-go，于是**第 t 个 token 的优势里压着从它到序列结尾的所有 KL 之和**。第一个 token 背整条回答的 KL，最后一个几乎不背。
- **这不是噪声，是随位置单调变化的系统性偏置**。长上下文下它的量级可以比任务奖励大一到两个数量级。
- **k1 还额外贡献一个随机游走项**：即使策略与 ref 完全重合（真 KL = 0），有符号单样本估计的逐 token 求和也是随机游走，标准差随 √T 增长。
- **"reward 不涨"的机制在组内归一化那一步**：减组均值只消掉组内公共部分，组内长度差变成一个强度不可控的长度惩罚；**除组标准差是致命的一步**——此时优势的方差几乎全来自长度 / KL 噪声而不是答对答错，真正的正确性信号被压缩一到两个数量级，梯度里只剩"别写太长"和纯噪声。
- **教科书 PPO 里有两样东西挡着它**：折扣 < 1 让 reward-to-go 收敛，critic 的价值基线把累积项吸收掉。**GRPO 把两样都去掉了。**
- **还有一个叠加效应**：reward 归一化只作用于任务奖励，KL 项是在那之后以原始量纲加进去的，不参与组内中心化，所以不会被压到 ±1 的尺度。
- **结论不是"框架写错了"**，而是 KL 进 reward 与「无 critic + γ=λ=1 + 长序列」三条同时成立时**不兼容**。
- **切到 loss 侧有四个坑没有代码挡着**：必须配 ref（否则第一个训练 step 才抛错）、reward 侧系数必须归零（否则罚两次）、loss 侧系数默认 0（只开开关等于白开且无警告，且**不能照抄 reward 侧的值**）、**ref 为空 + 非零 reward 侧系数会造出一个随长度累积的假正奖励**。
- **默认值与示例配置会分叉**：示例里几乎全把 reward 侧系数设为 0，而代码默认值是 0.1 —— 配置没显式写就吃到对长上下文灾难性的值。

## 2. 前置概念

### 2.1 两种落点

对参考模型的 KL 约束有两个完全不同的落点：

| | KL 进 reward | KL 进 loss |
|---|---|---|
| 怎么写 | 每个 token 的 reward 加上 `−β·KL_t`，和最终的结果奖励一起进优势估计 | 不动 reward，loss 上加一项 `β·mean_t(KL_t)` |
| 作用对象 | 优势（经过 GAE / 组内归一化） | 梯度（直接对 logits 求导） |
| 每个位置的权重 | 由优势估计器决定 | 一样（逐 token 平均） |
| 与长度的关系 | **随位置累积** | 无关 |
| 常用估计器 | k1（有符号、无偏、方差大） | k3（非负、方差小） |
| 出处 | 早期 RLHF（短回复 + critic） | GRPO 原论文 |

两条路在实现上是**独立开关**，可以同时打开 —— 于是 KL 被罚两次（§3.9）。

### 2.2 为什么 GRPO 下 GAE 会退化成 reward-to-go

GAE 的一般形式依赖 `δ_t = r_t + γV_{t+1} − V_t`。GRPO 里：

- 没有 critic，价值恒为 0 → `δ_t = r_t`；
- 折扣 γ = 1、λ = 1。

于是

```text
A_t = Σ_{s≥t} r_s
```

把 §2.1 的 reward 构成代进去：

```text
A_t = R_结果 − β · Σ_{s=t}^{T} KL_s
     └ 只在最后一个 token ┘  └ 从 t 到结尾的累加 ┘
```

**任务奖励只加在最后一个 token 上，所以每个位置都拿到同一个 `R_结果`；而 KL 是每个 token 都有，所以累加项随位置单调变化。** 这就是"累积"的全部来源。推导见 [GRPO = V≡0、γ=λ=1、Reward 在末 Token 的 GAE](GRPO流程与批级Advantage归一化的偏移机制_20261012.md)。

## 3. 完整原理

### 3.1 累积偏置的量级：两组估算

**估算一（输出预算 8192、β = 0.001、每 token KL 约 0.05 nats）：**

| 位置 | 累积 KL 惩罚 | 答对时的优势 | 答错时的优势 |
|---|---|---|---|
| 第 1 个生成 token | −0.41 | +0.59 | −1.41 |
| 中间 | −0.20 | +0.80 | −1.20 |
| 最后一个 token | ≈ 0 | +1.00 | −1.00 |

任务奖励经组内归一化后约 ±1，所以这个偏移吃掉了前面 token **约四成**的信号。把每 token KL 提到 0.1，偏移约 0.82 → **答对回答的前几个 token 优势接近 0，再大一点就翻成负的**，等于告诉模型"这条答对的回答，开头写错了"。

**估算二（256K、β = 0.1、每 token KL 0.005）：**

```text
均值项 ≈ 0.1 × 256000 × 0.005 ≈ 128      而结果奖励只有 0~1
```

比任务奖励大**两个数量级**。这就是同事说的"前面的 reward 都是 length 决定的"——准确讲是**优势被 KL 累加项主导，而累加项的主要变化来源是长度**。

### 3.2 k1 额外贡献一个随机游走项

上面只算了均值。k1 = `old_logp − ref_logp` 是**有符号的单样本估计**：期望对，方差大。两件事同时发生：

- 均值项：如 §3.1；
- **方差项**：即使策略和 ref 完全重合（真 KL = 0），`Σ_t (logp_t − ref_logp_t)` 也是一个**随机游走**，标准差 ≈ √T·σ。取 σ ≈ 0.3、T = 256K：

```text
√256000 × 0.3 ≈ 152      再乘 β = 0.1 → ≈ 15
```

也比 ±1 的任务奖励大一个数量级。**所以长上下文下，即使策略根本没有偏离 ref，累加项也会把优势淹掉。**

通用规律：**无偏但有方差的逐 token 估计，一旦被"沿序列求和"使用，噪声按 √T 增长，而它要对抗的信号往往不随 T 增长。** 短序列能用的估计器，长序列不一定能用。

### 3.3 为什么表现成"reward 跑很久不涨"（当天真正没懂的那一步）

累积偏置本身只是"优势被平移"，还不足以解释曲线平。真正的机制在**组内归一化**的两步里：

**第一步，减组均值：只消掉组内公共部分。**

同一个 prompt 的一组回答里，各样本长度不同 → `Σ KL` 不同 → 长的那条在**每一个 token 上**都被压低。这就是"越长的越抑制"。而且这个长度惩罚的强度是

```text
β × 平均每 token KL × 组内长度差
```

三个因子里没有一个是设计者打算用来惩罚长度的 —— **它是一个完全不可控的隐式长度惩罚**。

**第二步，除组标准差：致命的一步。**

此时优势的方差几乎全部来自长度 / KL 噪声，而不是答对答错。除以这个标准差，等于把真正的正确性信号（±1 量级）压缩到 **1/15 ~ 1/100**。于是梯度里几乎只剩两样东西：

- "别写太长"（来自长度差那一项）；
- 纯噪声（来自 §3.2 的随机游走）。

**reward 曲线就平了。** 注意这不是"学得慢"，而是"真信号被按比例压掉"——加大学习率也不会恢复，因为噪声被同比例放大。

对照 [批级归一化除以 σ 拆掉刹车](截断采样与批级归一化的双条件崩溃机制_20261016.md#310-修订主因是除以-σ-拆掉了刹车)：那里是"除以 σ 让幅度恒为 1、拆掉了天然刹车"，这里是"除以 σ 把真信号压到噪声量级"。**同一个操作（归一化）在不同的方差来源下有完全不同的后果，所以要先问"这一批方差主要来自什么"。**

### 3.4 换成 KL 进 loss 为什么就没有这个问题

```text
kl_loss = Σ_t∈mask k3(logπ_θ, logπ_ref) / 有效 token 数
loss    = policy_loss + β · kl_loss
```

三点都变了：

- **优势里只有 `R_结果`** → 组内归一化看到的方差就是答对 / 答错的方差，信号不会被稀释；
- **每个位置权重一样**（microbatch 内逐 token 平均）→ 与序列长度无关，不存在"前面的 token 背后面的账"；
- **估计器可以换成 k3**（非负、方差小），而不是必须用有符号的 k1。

代价是语义变了：KL 进 reward 约束的是**序列总偏离量**（前面的 token 要替后面的偏离买单，这在**有 critic**时是合理的信用分配），进 loss 只管**当前 token**。完整对比见 [KL 的两种放法](温度偏差实测与KL放置位置_20261015.md#39-kl-的两种放法完整对比)。

### 3.5 为什么教科书 PPO 不出这个问题

KL 进 reward 在**短回复 + 有 critic**的 RLHF 设定下是没问题的，有两道防线：

| 防线 | 作用 |
|---|---|
| 折扣 γ < 1 | 让 reward-to-go 收敛，远处的 KL 被 γ^k 衰减掉，累加项不随长度线性增长 |
| critic 的价值基线 | `δ_t = r_t + γV_{t+1} − V_t` 里，V 会把累加的 KL 吸收进基线、相互抵消 |

**GRPO 把两样都去掉了**：没有 critic，且为了不引入隐式长度惩罚而把 γ 取 1（见 [只有末端奖励时 γ<1 = 长度惩罚](PPO的Critic价值估计GAE参数与工程适配_20261020.md)）。于是累加项完整地暴露在优势里。

这里有一个很值得记的结构：**γ = 1 是为了避免长度惩罚才选的，而它恰好让 KL 累加变成了另一种更严重、更不可控的长度惩罚。** 两个选择单看都对，组合起来出问题。

### 3.6 一个叠加效应：KL 项不参与组内中心化

reward 归一化（组级）只归一化**任务奖励**；KL 项是在那之后以**原始量纲**加进去的。后果：

- 任务奖励被压到 ±1 的尺度；
- KL 累加项保持它原本的量级（§3.1 的 128）。

所以两者的量级差不是"恰好"这么大，而是**被归一化口径固定下来的**：任务奖励永远是 ±1，KL 项随长度和 β 自由增长。

通用教训：**归一化只作用于它显式接管的那一项；在它之后加进来的项不受保护，量级要单独核对。** 同类问题见 [两处归一化的层级](GRPO变体与两层归一化的拆解_20261013.md)。

### 3.7 切到 loss 侧的四个坑

实现上两条路通常都已经在主干里，但 `__post_init__` 这类配置校验往往完全不校验 KL 相关的组合：

| # | 坑 | 失败时的样子 |
|---|---|---|
| 1 | **必须配 ref 模型** | 不是启动时拦住，而是在**第一个训练 step 的 loss 里**抛异常 —— 排队几十分钟后才炸 |
| 2 | **reward 侧系数必须设成 0** | 两条路同时生效，KL 被罚两次，没有任何警告 |
| 3 | **loss 侧系数默认是 0** | 只打开开关、不设系数 = 白开，曲线上什么都看不出 |
| 4 | **ref 为空 + 非零 reward 侧系数 = 假正奖励** | 见 §3.8，最危险的一个 |

第 3 条还有一句容易错的：**loss 侧系数不能照抄 reward 侧的值**。reward 那条路的实际强度被序列长度放大了约 L 倍，两者没有简单换算关系 —— 要按常见范围（约 0.001～0.04）扫一遍。

### 3.8 ref 缺失时的假正奖励（第 4 个坑单列）

ref logp 缺失时被填成全 0，于是：

```text
k1 = old_logp − ref_logp = old_logp − 0 = old_logp        （负数）
reward = −β × k1 = −β × old_logp                          （正数！）
```

**本该是惩罚的项变成了奖励，而且是"按 token 概率发奖励"、还随长度累积。** 模型学到的是"写更多、更有把握的 token"——一个纯粹由缺省值造出来的目标。

这类坑的共同形状：**"缺失"被填成了一个在数值上合法、在语义上完全错误的值**（这里是 0），而下游公式照常计算、不报错。同类见 [配置丢值要看消费端](生成长度上限的意义与长跑对照的读数口径_20261023.md)、[字段名不一致 → 静默全 0](附加模型的显存编排与判分服务设计_20261026.md#34-规则判分能不能用先让标准答案和自己比)。

**防法**：缺失就应该**拒绝启动**，而不是填默认值 —— 同 [把已知陷阱写成启动即失败的配置校验](蒸馏项接入已有RL配方的正确写法与权重定法_20261028.md#34-成熟实现的两条正确接法以及把禁令写进配置校验)。

### 3.9 默认值与示例配置的分叉

当天扫了一遍示例配置，发现一个值得单独记的现象：

- **示例里几乎全是 reward 侧系数 = 0**（唯一的非零是一个小模型例子的 0.001），loss 侧开关**没有任何示例开启** → 也就是说官方长 CoT RLVR 例子的实际做法是**根本不加 KL**（DAPO / Dr.GRPO 那一派：长 CoT RLVR 本来就希望策略远离 ref）；
- **但代码里的默认值是 0.1** —— 对长上下文是灾难性的（§3.1 的 128 就是用它算的）。

于是出现一个很隐蔽的失效模式：**配置没有显式写这个字段，就会吃到一个所有示例都不用的默认值。** 读示例得到的印象（"大家都不加 KL"）和不写字段的实际行为（β = 0.1）正好相反。

通用教训：**"示例配置的共识"不等于"代码默认值"。** 判断一个参数的实际取值，只能看自己配置的解析结果，不能看别人的示例，也不能看文档。同 [参数说明与代码不一致时以代码为准](GSPO与PPO组合时的优势形状与GSPO-token_20261021.md#36-写参数手册时顺带确认的三件事)。

顺带一个小发现：某个枚举的两个选项名走的是**同一行公式**，填哪个都一样 —— 参数手册里的"可选值"数量不代表实际行为数量。

### 3.10 怎么确认这是不是本次 run 的病因

三个检查，成本都很低，按顺序做：

| # | 检查 | 判据 |
|---|---|---|
| 1 | 逐 token KL reward 指标的绝对值 **× 平均长度**，与任务奖励的量级比 | 前者大一个数量级以上 → 基本确定 |
| 2 | 优势与回答长度的相关性 | 强负相关 → 长度惩罚占主导 |
| 3 | 把 reward 侧系数设成 0 跑同配置对照，其他全不动 | 单变量对比，一两个 smoke step 就能看出优势分布变没变 |

第 1 条的要点是**那个指标通常是按 token 记录的，必须自己乘上长度**才能和序列级的任务奖励比。只看指标本身会觉得"很小、没问题"。

### 3.11 长上下文下的建议优先级

```yaml
# 第一步：必须。先把 reward 侧的累加关掉
reward 侧 KL 系数: 0

# 第二步：确实需要 KL 正则（防 reward hacking / 保能力）时再开
loss 侧 KL 开关: true
loss 侧 KL 系数: 0.001        # 量级，要扫
loss 侧 KL 估计器: 低方差那个（k3）
```

**只想让 reward 涨起来，就只做第一步**，第二步保持关闭 —— 这是目前所有长 CoT 示例的配置。

## 5. 工程中的具体表现

| 模型逐渐倾向写短回答，正确率没跟上 | 组内长度差变成不可控的长度惩罚 | 优势与长度的相关性；长度分布随步数 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| "KL 累积"是指 KL 本身越跑越大 | 指**同一时刻**第 t 个 token 的优势里含有从 t 到结尾的 KL 之和，是空间上的累加不是时间上的漂移 |
| KL 进 reward 只是让优势整体偏小一点 | 它随位置单调变化，是系统性偏置；长上下文下量级可比任务奖励大一到两个数量级 |
| 只要策略不偏离 ref，KL 项就可以忽略 | 真 KL = 0 时 k1 的求和仍是随机游走，std ≈ √T·σ |
| reward 不涨是"学得慢"，调大学习率就行 | 真信号被除以 σ 按比例压掉，噪声同比例放大，加学习率无效 |
| 是框架写错了 | 在短回复 + 有 critic 的设定下这个写法是对的；它与"无 critic + γ=λ=1 + 长序列"不兼容 |
| γ = 1 是个保守无害的选择 | γ = 1 是为了避免长度惩罚才选的，却让 KL 累加变成更严重、更不可控的长度惩罚 |
| reward 归一化会把 KL 项也压到 ±1 | 它只归一化任务奖励，KL 项在那之后以原始量纲加入 |
| 示例配置都不加 KL，所以不写这个字段也不会加 | 代码默认值可能是 0.1；"不写"等于吃默认值，和示例共识正好相反 |
| loss 侧系数可以照抄 reward 侧 | reward 路径的有效强度被长度放大约 L 倍，没有简单换算关系 |
| 看 KL reward 指标的数值就能判断它大不大 | 它通常按 token 记录，必须乘平均长度才能和序列级的任务奖励比 |

## 7. 一分钟复习

1. 两个落点：进 reward（`−β·KL_t` 进优势估计）/ 进 loss（`β·mean_t(KL_t)` 直接加）。
2. γ=λ=1 + 无 critic → GAE 退化成 reward-to-go → **`A_t = R_结果 − β·Σ_{s≥t} KL_s`**，第一个 token 背整条。
3. 量级：8192 / β=0.001 / 每 token 0.05 → 首 token −0.41（吃掉四成信号）；256K / β=0.1 / 0.005 → **128** vs 奖励 0~1。
4. k1 的随机游走：真 KL = 0 也有 std ≈ √T·σ → 256K 时约 **15**。无偏有方差的估计不能沿序列求和。
5. reward 为什么平：减均值 → 组内长度差 = 不可控长度惩罚（强度 = β × 平均 KL × 长度差）；**除 σ → 真信号压到 1/15～1/100**。
6. 教科书 PPO 的两道防线：γ<1 让累加收敛、critic 基线把累加吸收。GRPO 两个都没有。
7. γ=1 本是为了避免长度惩罚，却换来一个更严重的长度惩罚 —— 两个单看都对的选择组合出问题。
8. KL 项不参与组内中心化 → 任务奖励恒 ±1、KL 项随长度自由增长。
9. 进 loss 没问题的三个理由：优势里只剩 R、每位置等权、可用低方差 k3。
10. 四个坑：没 ref 要到第一个 step 才抛错；reward 侧系数要归零否则罚两次；loss 侧系数默认 0（且不能照抄，相差约 L 倍）；**ref 缺失填 0 → 惩罚翻成按概率发的正奖励、还随长度累积**。
11. 示例共识 ≠ 代码默认值：示例全是 0，默认值 0.1 → 不写字段比写错更危险。
12. 三个确认：KL reward 指标 **× 平均长度** vs 任务奖励；优势与长度的相关性；β = 0 的单变量对照。

## 8. 自测问题

### 问题 1

"长上下文得把 KL 放 loss 里，因为在 reward 里会累积"——把这句话展开成公式，并说明"前面的 reward 都是 length 决定的"是什么意思。

期望回答：GRPO 里折扣与 λ 都是 1、没有 critic（价值恒 0），所以 GAE 退化成 reward-to-go：`A_t = Σ_{s≥t} r_s = R_结果 − β·Σ_{s=t}^{T} KL_s`。任务奖励只加在最后一个 token 上，每个位置都拿到同一个值；KL 每个 token 都有，所以第 t 个 token 的优势里压着从 t 到结尾的所有 KL 之和，第一个 token 背整条回答的。长上下文下这个累加项的量级（如 256K、β=0.1、每 token 0.005 → 128）远超 0~1 的任务奖励，于是优势主要由累加项决定，而累加项的主要变化来源是序列长度 —— 这就是"前面的 reward 由 length 决定"。

### 问题 2

累积偏置只是把优势平移，为什么会导致 reward 曲线平着不动？说出组内归一化的两步各做了什么。

期望回答：第一步减组均值只能消掉组内公共部分，组内样本长度不同导致 ΣKL 不同，长的那条在每个 token 上都被压低，形成强度为 `β × 平均每 token KL × 组内长度差` 的不可控长度惩罚。第二步除组标准差是致命的：此时优势方差几乎全来自长度 / KL 噪声而非答对答错，除以它等于把 ±1 量级的正确性信号压缩到 1/15～1/100，梯度里只剩"别写太长"和纯噪声。注意这不是学得慢，加大学习率无效，因为噪声被同比例放大。

### 问题 3

即使策略与 ref 完全重合，KL 累加项也不可忽略，为什么？这反映了什么通用规律？

期望回答：k1 = `old_logp − ref_logp` 是有符号的单样本估计，期望对但方差大。真 KL = 0 时逐 token 求和是一个随机游走，标准差 ≈ √T·σ；取 σ≈0.3、T=256K 得约 152，乘 β=0.1 后约 15，比 ±1 的任务奖励大一个数量级。通用规律：无偏但有方差的逐 token 估计一旦被"沿序列求和"使用，噪声按 √T 增长，而它要对抗的信号往往不随 T 增长 —— 短序列能用的估计器，长序列不一定能用。

### 问题 4

为什么同样的 KL-in-reward 写法在教科书 PPO 的 RLHF 设定下没有问题？

期望回答：两道防线。折扣 γ < 1 让 reward-to-go 收敛，远处的 KL 被 γ^k 衰减，累加项不随长度线性增长；critic 的价值基线在 `δ_t = r_t + γV_{t+1} − V_t` 里把累加的 KL 吸收进基线、相互抵消。另外早期 RLHF 的回复只有几百 token。GRPO 去掉了 critic，又为了避免隐式长度惩罚把 γ 取 1，两道防线都没有了。所以这不是写错，是与"无 critic + γ=λ=1 + 长序列"的组合不兼容。

### 问题 5

切换到 loss 侧 KL 时，有哪四个坑没有代码挡着？其中最危险的那个的失败机制是什么？

期望回答：① 必须配 ref，否则不是启动时报错而是第一个训练 step 的 loss 里抛异常；② reward 侧系数必须归零，否则两条路同时生效、KL 被罚两次；③ loss 侧系数默认为 0，只开开关等于白开且无警告，而且不能照抄 reward 侧的值（reward 路径的有效强度被长度放大约 L 倍）；④ 最危险的是 ref 为空 + 非零 reward 侧系数：ref logp 缺失被填成全 0，于是 k1 = old_logp（负数），reward = −β × old_logp 变成正数，等于按 token 概率发奖励、还随长度累积，模型学到"写更多、更有把握的 token"。防法是缺失就拒绝启动，而不是填默认值。

### 问题 6

"示例配置里大家都不加 KL，所以我不写这个字段也不会加"——这句话错在哪？

期望回答：示例共识与代码默认值是两件事。示例里几乎全把 reward 侧系数显式写成 0（长 CoT RLVR 本来就希望策略远离 ref），但代码默认值是 0.1 —— 不写字段就吃到这个所有示例都不用、且对长上下文灾难性的值。判断一个参数的实际取值只能看自己配置的解析结果，不能看别人的示例也不能看文档。

### 问题 7

要确认某个 run 的 reward 不涨是不是 KL 累加造成的，最省事的三个检查是什么？第一个检查里最容易算错的是什么？

期望回答：① 逐 token KL reward 指标的绝对值 × 平均长度，与任务奖励的量级比，前者大一个数量级以上基本确定；② 看优势与回答长度的相关性，强负相关即长度惩罚占主导；③ 把 reward 侧系数设成 0 跑同配置单变量对照，一两个 smoke step 就能看出优势分布变没变。最容易算错的是第一个：那个指标通常按 token 记录，必须自己乘上平均长度才能和序列级的任务奖励比，只看指标本身会误以为"很小、没问题"。

## 9. 尚未解决与后续路线

- loss 侧系数的实际取值要扫（0.001～0.04 量级），目前只有"不能照抄 reward 侧"这一条结论；
- 本次受影响的是长上下文 + 非零 reward 侧系数的那类配方；已在跑的对照组把 KL 完全关掉，所以不受影响 —— 但"完全不加 KL"的长程后果（能力保持、reward hacking）没有证据；
- "优势与长度强负相关"这个判据还没有在真实 run 上量过，阈值未知；
- KL 进 loss 之后，序列级约束的丧失有什么代价（前面的 token 不再替后面的偏离买单）在长 CoT 上没有对照；
- ref 缺失填 0 这类"缺失被填成语义错误的合法值"，应该在哪一层统一拦住（配置校验 / 数据契约 / 消费端断言）还没有统一做法。
