## 0. 今天最终要解决的问题

按提问顺序：

1. 同事那个新数据集大概有多少道题？他跑的时候每步平均跑几道、跑了几步？
2. 他用的是百 B 级的模型，说长跑了几步 reward 没升高 —— 帮我分析 reward 为什么可能没升高。

## 1. 先给结论

- **前三个数当时拿不到，就说"拿不到"**，并说明怎么量（数据文件行数、每步题数 × 每题采样数、实际步数），再给一个旧配方的参照量级。不替别人的 run 编数字。
- **排第一的检查是"他说的 32K 是上下文窗口还是输出预算"**：同类配方里上下文窗口 32768 而输出预算只有 4096 —— 真正卡住长推理的是**输出预算**。**只把上下文加到 128K 而不同步加大输出预算，不会有任何改善。** 这条一句话能查，可能解释全部现象，还直接决定"选 64K 还是 128K"要不要花这个钱。
- **截断同时改变 reward 的天花板和梯度方向**，这是两件事：
  - 天花板：`batch reward ≈ 未截断比例 × 未截断者的正确率` → **它主要跟踪截断率，不跟踪真实能力**；
  - 梯度方向：组内"截断记 0"与"完成记 1"的对比，教给模型的是**把答案写短**，不是算对。
- **自然推理长度本来就长的大模型，没多少空间靠"写短"提分** → 两条路都走不通，reward 就卡住。
- **零方差组占比过高时，"reward 没升"的实质是"几乎没有梯度"**：一半截断极易产生大量"全截断 = 全 0"的组，有效 batch 远小于名义 batch。
- **判分系统性误判是测量问题，不是学习问题**，而且能单独解释曲线平。最隐蔽的一点：**解析失败记 0 和答错在曲线上长得一模一样**。
- **误判率先查**：如果判分不可信，这条 reward 曲线本身没有意义，后面所有分析都白做。所以它和输出预算那条要**最先**做。
- **排查顺序按"能不能不花 GPU 查清"排**，不按"听起来多像根因"排。

## 2. 前置概念

### 2.1 上下文窗口与输出预算是两个独立上限

| | 上下文窗口 | 输出预算 |
|---|---|---|
| 限制什么 | prompt + 已生成的总长度上限 | 本次最多新生成多少 token |
| 典型取值差异 | 32768 | 4096 |
| 谁先触发 | 长 prompt / 多轮累积时 | **单轮长推理时几乎总是它先触发** |
| 加大它的代价 | KV 显存、注意力开销 | 步时（最长回答决定步时） |

**关键推论：如果截断是输出预算触发的，那么把上下文窗口从 32K 提到 128K 完全没有用**，只是白付 KV 显存和并行度的代价。注释里常见的生产配方甚至是"输出 4096 配上下文 8192"——两者差一倍是常态，不是配置错误。

这一层与 [生成长度上限到底决定什么](生成长度上限的意义与长跑对照的读数口径_20261023.md) 衔接：那篇讲"上限 + 截断处理 = 长度预算"，本篇补的是**"上限"本身是两个数，先确认是哪一个在起作用**。

### 2.2 截断 → 判不出 → 记 0 的链条

```text
输出预算耗尽 → 回答没写到最终答案 → 判分程序抽不到答案 → 记 0 分
                                                        ↓
                                            与"算错了也记 0"完全无法区分
```

这条链的每一环都不报错。后果分两路，§3.2 与 §3.4 分别展开。

## 3. 完整原理

### 3.1 先确认"32K"是哪个数（排第一的检查）

优先级最高的理由有三个：

1. **一句话就能查**（看解析后的有效配置里两个字段的实际值）；
2. **可能解释全部现象**：若瓶颈在输出预算，那么"一半截断"与"reward 不涨"都顺理成章；
3. **直接决定下一笔钱**：若要上长上下文，先知道该加哪个上限 —— 加错了那一个等于白烧一周的卡。

**通用方法**：听到"我们跑的是 N K"时，先问"N 指的是哪一个上限"。同名数字指向不同字段，是读数混杂的常见来源（同 [同名指标先核对定义](生成长度上限的意义与长跑对照的读数口径_20261023.md)）。

### 3.2 截断同时改变天花板和梯度方向

**天花板那一侧：**

```text
batch reward ≈ 未截断比例 × 未截断者的正确率
```

于是这条曲线**主要跟踪截断率**。截断率从 50% 降到 40%，reward 会涨 —— 但模型的数学能力可能一点没变。反过来，能力真涨了而截断率不动，reward 也几乎不动。**把它当能力指标读，就是在读一个被截断率支配的量**（同 [截断率下降会抬高训练 Reward](Benchmark对照的负载等价与读数混杂_20261009.md#32-截断伪造的-reward-涨幅)）。

**梯度方向那一侧（更关键）：**

组内归一化下，同一题的 8 条回答里"截断记 0"和"完成记 1"形成对比 → 正优势给了**完成的**那几条、负优势给了**截断的**那几条。而截断与否的主要区分特征是**长度**。所以模型学到的是：

> 把答案写短，以便写完。

不是"算对"。这是一个**真实存在的学习信号**，只是它优化的目标不是我们想要的。

**为什么大模型在这里特别卡：** 百 B 级模型自然推理长度本来就长，它没有多少空间靠"写短"提分 —— 短到能写完就答不对，长到能答对就写不完。两条路都堵着，于是 reward 平着不动。

| 观察 | 含义 |
|---|---|
| 截断率在降、reward 没动 | 在学"写短"，但正确率没跟上 |
| 截断率也不动 | 输出预算硬顶住了，连"写短"这条路都没走通 |
| 截断率在降、reward 在涨 | **不能归功于能力**，先把截断率一起汇报 |

这一节与 [输出变短的两个原因：信号 vs 偏差](截断惩罚的逐Token分布与输出变短的两个原因_20261026.md#34-输出变短的两个原因一个是信号一个是偏差) 的关系：那篇区分的是"长的 reward 低 = 信号"与"长的被陈旧度丢 = 偏差"；本篇的"截断记 0 → 推短"属于前者（是真信号），但它是**由资源上限人为造出来的**信号，不是任务本身想表达的偏好。

### 3.3 零方差组：有效 batch 远小于名义 batch

组内归一化下，8 条**全对或全错**的组优势恒为 0、**完全不贡献梯度**。一半截断的情形下极易出现大量"全截断 = 全 0"的组，真正有信号的只剩中间难度、且恰好能写完的题。

```text
名义 batch：每步 N 题 × 8 条
有效 batch：仅"混合组"（既有对又有错）那部分
```

**如果混合组只占个位数百分比，"reward 没升"的实质就是"几乎没有梯度"。** 这时任何关于"学到了什么"的讨论都提前失效了。

怎么查：全对组 / 全错组 / 混合组各占多少，以及随步数怎么变。注意**全对与全错要分开统计**——两者都贡献 0 梯度，但含义相反（一个是题太简单、一个是题太难或全被截断），合并成"零方差组比例"会丢掉这个区分（同 [零方差组的构成翻转](温度偏差实测与KL放置位置_20261015.md#35-批级归一化影响的不只是零方差组被纠正的误解)）。

### 3.4 判分系统性误判：这是测量问题，不是学习问题

这一条最容易被忽略，但它**能单独解释"reward 平着不动"**，而且一旦成立，前面所有分析都没意义。三个机制：

| 机制 | 后果 |
|---|---|
| 新数据集里多部分答案占参考答案一半以上，而原判分规则要求数值完全相同 | 把对的判成错，正确率被系统性低估 |
| 判分模型有回复但解析不出结论 → **记 0 分** | 解析失败与答错在曲线上**完全无法区分** |
| 本地精确匹配兜底读的参考答案字段名与新数据集不同 | 兜底**静默失效**，判分模型成为唯一判分来源，放大上面两条 |

第三条是典型的"字段名不一致 → 静默全 0"（同 [规则判分的自比检查](附加模型的显存编排与判分服务设计_20261026.md#34-规则判分能不能用先让标准答案和自己比)）。三条叠起来，曲线可以又低又平，而模型其实在进步。

怎么查：判分失败率 / Unknown 比例，加上**抽 50～100 条人工复核**。人工复核这一步不能省 —— 自动指标查不出"规则本身是错的"这类问题。

**排查顺序上的推论：判分可信度要和输出预算一起最先查。** 一个测量不可信的实验，调参、换算法、加卡都是在优化噪声。对应 [Judge 奖励的失败语义](Judge奖励的失败语义与成本结构_20261028.md) 的"判不了 ≠ 判错"：那篇讲怎么设计才不出这个问题，本篇讲已经出了之后怎么认出来。

### 3.5 步数太少 + 学习率预热

一个踩过的坑：**离线配方的学习率预热占掉了前一半步数**。所以"跑了几步"如果是十几步量级，很可能还在预热区，模型几乎没动。

判据：看实际的学习率曲线，而不是看配置里写的预热比例 —— 按比例的预热是以**调度器以为的总步数**为基数的（同 [学习率预热按调度器以为的总步数算](GSPO对照实验的Clip比例读法与学习率预热口径_20261021.md#35-学习率预热按调度器以为的总步数算)）。

### 3.6 批次难度噪声：要比就比跨遍同位置

batch 均值主要随**题目难度**波动，相邻几步的跳动多在噪声内。可比的是**不同遍次里相同批次位置的同一批题**；按整遍平均比会被"本来就容易、早已到顶"的题稀释。

这一条在终端任务上已经吃过教训并被纠正过一次（整遍平均看不到进步 → 按批次位置配对后结论反转，难题涨了 8～15 个百分点）。完整方法见 [训练曲线的 Epoch 周期与训练前后评测设计](训练曲线的Epoch周期与训练前后评测设计_20261028.md)。**本篇不重复，只强调它在"几步就说没升高"的场景下尤其致命**：几步之内的差异几乎全是难度噪声。

### 3.7 策略在动，但方向 reward 没覆盖

看熵、KL、clip 比例、梯度范数。如果这些明显在变而 reward 平，说明模型在学 reward **没打分**的东西：

- 更短（§3.2 的信号）；
- 更少格式错误；
- 更少截断。

另外训练采样温度 ≈ 1 时 reward 会**滞后于低温评测** —— 策略变尖之后，贪心 / 低温下的正确率可能已经先好了。**只有固定题集上的低温评测才能回答"到底有没有进步"**（同 [训练 Reward 不升的读法](训练Reward不升的读法_20261028.md)）。

### 3.8 如果对方开了批级优势归一化

那就不只是"不升"的问题：**批级归一化 + 截断采样同时存在会导致崩溃**。机制是零方差组被整体推成同号优势、标准差又被大片 0 压小，放大倍数随"有信号组占比"漂移 = 随数据组成变化的隐式学习率。完整推导与修订见 [截断采样 × 批级归一化的双条件崩溃机制](截断采样与批级归一化的双条件崩溃机制_20261016.md)。

本篇只加一句**排查层面**的用法：**问清对方有没有开批级归一化，是区分"不升"与"要崩"的分水岭**。同样的截断率，开着它的 run 要按崩溃前兆来盯（熵、梯度范数），没开的才是单纯的信号稀释。

### 3.9 排查顺序与索要清单

按**性价比**排序（能不花 GPU 查清的优先），不按"听起来多像根因"排：

| 顺序 | 要的东西 | 回答什么 | 成本 |
|---|---|---|---|
| 1 | 输出预算的实际取值 + 截断率曲线 | 是不是输出预算问题；加上下文有没有用 | 看配置，零成本 |
| 2 | 判分失败率 / Unknown 比例 + 50～100 条人工复核 | 这条曲线可不可信 | 无 GPU |
| 3 | 零方差组占比（全对 / 全错**分开**） | 有没有梯度 | 无 GPU |
| 4 | 熵 / KL / clip 比例 / 梯度范数曲线 | 策略在不在动、动向哪 | 已有读数 |
| 5 | 数据集行数、每步题数、实际步数、学习率 schedule 与预热占比 | 是不是还在预热区、一遍多少步 | 无 GPU |

**当天的判断**：第 1 条和第 4 条（输出预算 + 判分规则）最可能是真因，而且**互相叠加** —— 输出预算卡住长推理，判分规则又把多部分答案误判成错，两者一起会让 reward 既低又平。两条都不需要 GPU 就能查清。

### 3.10 手上没有数字时怎么回答

当天前三个问题（数据集题数、每步题数、步数）的正确答法是三段：

1. **明说拿不到**，以及为什么拿不到（规模与内部统计留在受控环境、数据本体在集群上）；
2. **说明怎么量**：数据文件行数；每步题数 × 每题采样数；实际跑到的步数；
3. **给一个参照量级**，并明确标注它是**旧配方**的数、不是对方的 run。

**不要用参照值替代真实值去做推断。** 这与 [证据层级](../../09/从局部融合到长跑对照的证据层级_20260930.md) 是同一条原则：分析可以基于假设，但假设必须和已核实的事实在文字上分开。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 把上下文从 32K 提到 128K，截断率没变 | 瓶颈在输出预算，不在上下文窗口 | 看解析后配置里两个上限的实际值 |
| reward 曲线和截断率曲线几乎镜像 | reward ≈ 未截断比例 × 未截断者正确率 | 两条曲线叠在一起看 |
| 回答越来越短，正确率没涨 | 组内"截断记 0 vs 完成记 1"教出"写短" | 长度分布随步数；按长度分桶看正确率 |
| 大模型 reward 完全平，小模型同配方能涨 | 大模型自然推理长，没有靠写短提分的空间 | 比两者的长度分布与截断率 |
| 名义 batch 很大但梯度范数很小 | 大量全截断 = 全 0 组，有效 batch 极小 | 全对 / 全错 / 混合组占比 |
| reward 又低又平，但人工看回答质量在变好 | 判分规则把多部分答案误判成错 | 抽 50～100 条人工复核 |
| 判分失败率在变，曲线上看不出来 | 解析失败记 0 与答错不可区分 | 单独记 Unknown / 解析失败比例 |
| 换了数据集后兜底判分好像没生效 | 参考答案字段名不一致，兜底静默失效 | 用标准答案自比，通过率应接近 1 |
| 十几步就断言"没升高" | 还在学习率预热区 + 难度噪声 | 看实际学习率曲线；跨遍同位置配对 |
| 熵 / 梯度范数明显在动而 reward 平 | 在学 reward 没打分的东西 | 固定题集低温评测 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| "我们跑的是 32K"是一个明确的数 | 至少有两个上限（上下文窗口、输出预算），长推理里几乎总是输出预算先触发 |
| 加大上下文窗口就能让模型想得更久 | 不同步加大输出预算时完全无效，只白付 KV 显存与并行度代价 |
| 训练 reward 低说明模型能力差 | 它 ≈ 未截断比例 × 未截断者正确率，主要跟踪截断率 |
| 截断只是让 reward 偏低 | 它同时改变梯度方向：组内对比教出"写短"，这是真信号 |
| 截断率下降带来的 reward 上涨是进步 | 不能归功于能力；汇报 reward 必须带上截断率 |
| 零方差组只是浪费了一点样本 | 它们贡献 0 梯度；占比高时"reward 不升"的实质是"几乎没有梯度" |
| 零方差组比例是一个指标 | 全对与全错含义相反（题太简单 vs 太难或全截断），必须分开统计 |
| 判分误判会让曲线变乱 | 它会让曲线又低又平，和"学不动"无法区分；且解析失败与答错完全同形 |
| 先调算法、调超参，判分以后再说 | 测量不可信时所有调参都在优化噪声；判分可信度要最先查 |
| 跑了十几步看不到涨说明方法不行 | 可能还在预热区；且几步之内的差异几乎全是批次难度噪声 |
| 没有对方的数字就先按经验值推断 | 要明说拿不到、说明怎么量、参照值标注清楚是旧配方的，不能替代真实值 |

## 7. 一分钟复习

1. **先问"32K 是哪个上限"**：上下文窗口 vs 输出预算，典型 32768 vs 4096；长推理几乎总是后者先触发 → **只加前者不会有任何改善**。
2. `batch reward ≈ 未截断比例 × 未截断者正确率` → **跟踪截断率，不跟踪能力**。汇报 reward 必带截断率。
3. 截断改的是两样：天花板（上式）+ **梯度方向**（组内"截断 0 vs 完成 1"→ 教写短）。
4. 大模型没有靠写短提分的空间：短到能写完就答不对，长到能答对就写不完 → 平。
5. 三组判读：截断率降 + reward 平 = 在学写短；截断率也不动 = 预算硬顶；两个都在动 = 别归功于能力。
6. 一半截断 → 大量全 0 组 → **有效 batch ≪ 名义 batch**；混合组只剩个位数百分比时，实质是"没有梯度"。全对 / 全错**分开记**。
7. 判分误判是**测量**问题：多部分答案 vs 精确相等；**解析失败记 0 与答错同形**；兜底字段名不一致 → 静默失效。
8. **测量不可信 → 后面全部分析失效** → 判分可信度与输出预算一起最先查，都不用 GPU。
9. 十几步不能下结论：预热可能占前一半步数；几步差异几乎全是难度噪声 → 跨遍同位置配对。
10. 策略在动而 reward 平 = 在学 reward 没打分的东西；T≈1 的 reward 滞后于低温评测。
11. 问清**有没有开批级优势归一化**：开着 + 截断 = 要崩（按前兆盯），没开 = 单纯信号稀释。
12. 没有数字时三段答：明说拿不到 → 怎么量 → 参照量级并标注是旧配方。

## 8. 自测问题

### 问题 1

同事说"我们跑的是 32K，一半回答被截断，想提到 128K"。为什么这句话里最该先确认的不是 128K 要多少卡？

期望回答：先确认"32K"指的是上下文窗口还是输出预算。这是两个独立上限，同类配方里上下文窗口 32768 而输出预算只有 4096，长推理几乎总是输出预算先触发。如果截断是输出预算造成的，把上下文窗口提到 128K 完全没有用，只白付 KV 显存和并行度的代价。这条一句话就能查（看解析后的有效配置），而资源估算是在它之后才有意义的。

### 问题 2

为什么"训练 reward 不涨"在一半截断的情形下不能当成"模型没学到东西"？分别说出天花板和梯度方向两侧的机制。

期望回答：天花板侧，`batch reward ≈ 未截断比例 × 未截断者的正确率`，所以曲线主要跟踪截断率而不是能力：截断率不动时能力涨了也看不出来。梯度方向侧，组内归一化下同一题的"截断记 0"与"完成记 1"形成对比，而区分两者的主要特征是长度，所以模型学到的是把答案写短而不是算对——这是真实的学习信号，只是优化的不是我们想要的目标。百 B 级模型自然推理长度本来就长，短到能写完就答不对、长到能答对就写不完，两条路都堵着，于是曲线平。

### 问题 3

"零方差组占比高"为什么会把问题的性质从"学得慢"变成"没有梯度"？为什么全对组和全错组必须分开统计？

期望回答：组内归一化下全对或全错的组优势恒为 0、完全不贡献梯度，所以有效 batch 只有混合组那部分。一半截断时极易出现大量"全截断 = 全 0"的组，混合组可能只剩个位数百分比——此时"reward 没升"的实质就是几乎没有梯度，讨论"学到了什么"已经提前失效。全对与全错都贡献 0 梯度但含义相反：一个是题太简单（已到顶），一个是题太难或全被截断（信号拿不到），合并成一个比例会丢掉这个区分，也看不出健康期与崩溃期之间的构成翻转。

### 问题 4

判分系统性误判为什么能单独解释"reward 平着不动"？它的三个机制是什么？为什么它要排在排查顺序的最前面？

期望回答：三个机制——① 新数据集里多部分答案占参考答案一半以上，而原判分规则要求数值完全相同，把对的判成错；② 判分模型有回复但解析不出结论就记 0 分，于是解析失败与答错在曲线上完全无法区分；③ 本地精确匹配兜底读的参考答案字段名与新数据集不同，兜底静默失效，判分模型成为唯一来源并放大前两条。三条叠起来曲线可以又低又平而模型其实在进步。它要排最前面是因为这是测量问题而不是学习问题：测量不可信时，调参、换算法、加卡都是在优化噪声。查它只需要判分失败率 / Unknown 比例加 50～100 条人工复核，不花 GPU。

### 问题 5

同样是"一半截断 + reward 不涨"，为什么要先问对方有没有开批级优势归一化？

期望回答：因为这决定了问题的性质。没开时是单纯的信号稀释，表现为"不升"；开着时批级归一化 + 截断采样是已知的双条件崩溃组合——零方差组被整体推成同号优势、标准差又被大片 0 压小，放大倍数随有信号组占比漂移，相当于随数据组成变化的隐式学习率，结果不只是不升而是会崩。所以开着的 run 要按崩溃前兆来盯（熵、梯度范数、长度），处置方式完全不同。

### 问题 6

对方问"数据集多少题、每步几道、跑了几步"，而你拿不到这些数字，正确的回答是什么形状？

期望回答：三段。① 明说拿不到以及为什么（规模与内部统计留在受控环境、数据本体在集群上）；② 说明怎么量：数据文件行数、每步题数 × 每题采样数、实际跑到的步数；③ 给一个参照量级，并明确标注它是旧配方的数、不是对方那次 run 的。关键是不要用参照值替代真实值去做推断——分析可以基于假设，但假设必须和已核实的事实在文字上分开。

## 9. 尚未解决与后续路线

- 输出预算与上下文窗口的实际取值还没拿到，"输出预算是主瓶颈"目前是最可能的候选而不是结论；
- 截断率曲线、零方差组占比、判分失败率三组读数都还没拿到；
- "不截断时的回答长度分布"（超 64K / 超 128K 各占多少）是决定 64K 还是 128K 的关键输入，仍需向对方索要；
- 本篇排查的几条与 [KL 累加](KL惩罚放在Reward还是Loss与长上下文的累积偏置_20261029.md) 那一条谁是主因没有区分开；两类都能单独产生"又低又平"，需要单变量对照分离；
- "混合组占比低于多少就算没有梯度"没有量化阈值；
- 判分规则对多部分答案的改造方案（规范化、分项给分、部分分）还没有设计。
