# MTP 全局 Token 归一化与多深度梯度

> 内容日期：2026-09-09～09-11；当前语义收敛于 2026-09-11；整理时间：2026-09-11（北京时间）。
>
> 本篇回答你这周反复追问的两件事：每个有效 token 最后贡献多少梯度？detach 到底隔离谁？不复制具体公司实现。

## 1. 先看一次更新，而不是先背倍率

一份 rollout 序列到训练侧后，先确定样本边界和 mask，形成多个 microbatch；主分支算 PPO，MTP 分支算未来 token 的 CE，合成目标后反向、累积梯度，再由 optimizer 更新。

MTP 在这里学习“给定上下文预测实际序列里的未来 token”。它不自动使用 PPO advantage/reward weighting，也不直接把推理接受率作为可微目标。降低辅助 CE 可能帮助 draft，但真实接受率和净加速还要到 rollout 侧测量。

你需要区分：

- **数什么**：哪些位置有效？
- **平均什么**：按 token、按 trajectory，还是按 microbatch 等权？
- **反传到谁**：主干、共享表、MTP 各 depth 哪些连通？
- **框架又乘除什么**：累积、并行平均、混合精度缩放。

## 2. 一个小例子：平均数不能随便再平均

以下是教学数据，不是实验结果：

| Microbatch | 有效 token 数 | 平均 CE | CE 总和 |
|---|---:|---:|---:|
| A | 2 | 1 | 2 |
| B | 8 | 3 | 24 |

对两批平均 loss 再等权平均：`(1+3)/2=2`。

按这 10 个 token 平均：`(2+24)/10=2.6`。

若目标是“每个有效 token 等权”，应当得到 2.6。把两批合并或换一种 microbatch 划分，结果都应不变。前一种方法不是数学错误，而是选择了不同的权重：A 中每个 token 被赋予了更大权重。

更直接的实现思想是：每个 microbatch 提供自己的加权 CE 总和，除以**整次更新共享的分母**，最后求和。

## 3. 不同 MTP depth 为什么需要不同分母

令基础 NTP 在位置 t 预测 `x[t+1]`，MTP depth d 预测 `x[t+d+1]`。越远的目标越容易越过本条序列末尾，因此有效位置数可能更少。

对每个 depth 定义：

$$
N_d=\sum_{i\in\text{整次更新}}m_{i,d},\qquad
L_{MTP}=\frac{\lambda}{D}\sum_{d=1}^{D}
\frac{\sum_i m_{i,d}\,CE_{i,d}}{N_d}.
$$

- m 是训练权重/有效 mask；默认二值时 N 是有效 token 数。
- 每个 depth 先按自己的 N 求均值，再用 λ/D 合成。
- PPO 与 MTP 有效位置不同，不能直接拿 PPO 的分母给所有 MTP depth。
- 全零 mask 的 depth 必须显式得到零贡献，避免除零；是否重新分配其他 depth 权重是另一个算法选择，不能默默改变。

有小数 mask 时，`sum(mask)` 是总权重，`count_nonzero(mask)` 是位置个数。例如 `[0.5, 0.5]` 前者为 1、后者为 2。所谓“与 PPO 一致”必须说明是默认二值 mask 的 token 加权原则，不是完整算法和所有过滤规则都共用。

## 4. DP 和 CP：分母要数一遍，不多也不少

DP 是不同数据副本；CP 是同一序列的不同位置分片。关键不是看到 CP 就一定 all-reduce，而是**当前手里的统计是否已经包含完整序列**。

教学例子：DP 两份数据各有 6、4 个有效 token，CP=2。

| 计数时数据在哪 | 正确处理 |
|---|---|
| 每个 CP rank 都有本份完整 mask | 每份先得到 6 或 4，再只跨 DP 求和，N=10 |
| 每个 CP rank 只有不重叠的位置切片 | 将这些切片的计数跨 DP×CP 求和，N=10 |

第一种再跨 CP 求和会得到 20，重复数了同一批 token。第二种漏掉 CP 则少数了一部分位置。

因此可将所有 depth 的完整 mask 计数提前组成 `[D]` 向量，一次跨 DP 汇总，在各 microbatch 中复用。这里节省的是反复数 token 的小同步，**不代表 labels/mask 的跨 CP 边界移位、模型通信、TP 词表统计和梯度同步都消失**。

“先在完整序列准备各 depth 目标，再选取本卡位置”还可能减少监督目标的边界交换，但需要重新接入 helper，并保持 packing/padding/response 边界。它与仅预计算分母是两项改动，不能混报为已实现。

## 5. 已经除以 token 数，为什么还会乘 DP

因为数学目标和框架的执行缩放是两层。

假设目标是全局和除以 N，但随后梯度同步还会按参与 rank 平均。不补偿，就相当于多除一次 rank 数。microbatch schedule 和 optimizer loss scale 也有各自的乘除。

一个特定二元组 loss callback 路径可以出现如下组合，P=DP、C=CP、M=microbatch 数、S=optimizer loss scale：

$$
(P S M)\times(C/M)\times\frac{1}{PC}\times\frac{1}{S}=1.
$$

这是**带前提的完整抵消检查**，不是所有框架通用口诀。必须核对真实版本的 schedule、DDP、optimizer 和自定义 grad-scale；配置名叫 per-token 也可能选择另一套 callback 协议。复习时先问最终想要什么梯度，再逐项核对哪里额外乘除。

## 6. 显式辅助 loss 与 AutoScaler 是两种接线

你之前问 ContextVar 是否在跨卡传 loss。不是：它通常是同一进程内传递当前调用上下文的机制，不是通信协议，也不直接决定梯度。

辅助梯度可采用两类组织：

| 接线 | 前向看见什么 | 必查点 |
|---|---|---|
| 自定义 autograd 注入（如某些 AutoScaler） | 主输出数值保持不变，辅助 loss 作为内部输入 | backward 注入的梯度系数是否正确、是否跟随 loss scale |
| 显式可微辅助 Tensor | 主输出另有 auxiliary loss，再在 callback 与主 loss 相加 | Tensor 是否属于本次 forward，归一化与缩放是否重复 |

不能仅凭日志里主 loss 数值没变，断言 MTP 没训练；也不能因为显式加了 loss，断言梯度尺度一定对。需要独立参考目标的梯度对照，尤其用非单位 loss scale 和不等长 microbatch。

9 月 11 日讨论收敛到显式辅助 Tensor、整次更新 `[D]` 分母与共享更新倍率。此前“逐 microbatch 均值＋AutoScaler 注入”是旧实现快照，不能当成新版本说明；这次不仅是代码整理，也改变了训练权重语义。

## 7. detach：前向继续用，反向不沿这条边回去

H0 来自主干，E 是 token embedding 表，W 是共享 LM-head；H1、H2 是两次 MTP 计算的 hidden。

若目标是“只让辅助 CE 训练 MTP，同时保留 depth 间递归梯度”，则：

- 在 MTP 入口隔离 H0 对主干的反向连接；
- 辅助分支使用的 E/W 不贡献共享参数梯度；
- **H1→H2 保持连接**，让 depth 2 的 loss 也能训练产生 H1 的计算；
- PPO 主分支仍保留原来的 H0 计算图。

detach 不改变本次 forward 的向量值，也不会把整张共享权重表冻结到其他 loss 都无法更新。只 detach E/W 不足以隔离主干，因为 H0 路径还在；每个 depth 都 detach H 又会切掉跨 depth 的梯度。

另外，[全局裁剪](MTP多深度梯度与全局裁剪_20260903.md)可能让 MTP 梯度间接改变主干更新幅度。直接辅助梯度为零，不等于整个 optimizer step 与 MTP-off 一模一样。

## 8. 什么证据才足够

本周已经具备独立整批 CE、真实 CPU autograd/checkpoint、模拟 DP×CP、不同划分和 mask 的数值证据；最新代码也完成一次真实 Actor update。二者证明的层次不同：

1. CPU 对照证明构造的目标与梯度在覆盖范围内一致。
2. 一步 GPU smoke 证明该实际入口能够执行。
3. 真实多卡调度、collective、optimizer 与独立参考的数值等价，还需要定向验证。
4. 吞吐/显存收益要单独测量，不能由测试数量或一条完成日志推出。

## 一分钟复习

每个 depth 的分子是整次更新的有效 CE 总和，分母是对应 mask 权重总和。DP/CP 不重复计数，框架缩放完整抵消。detach 隔离的是图上的边，不是取消前向读取；保留深度链与隔离主干可以同时成立。
