## 0. 今天最终要解决的问题

为什么一段数值等价的代码，经编译变换后可能走向不同的矩阵乘法实现？

## 1. 先给结论

- 编译器将原地操作函数化（改写为纯函数操作）后，会为逻辑上的新结果推导布局；shape 不变不代表 stride 不变。
- 长度为 1 的维度允许多个合法 stride，因它的索引恒为 0。这不代表该 tensor 不连续，也不说明存在“默认最大 stride”规则。
- 下游分派除 shape 外还可能检查 stride、dtype、batch 维度及 `requires_grad`。所以源码里的 `matmul` 不能证明实际走 `mm` 或 `bmm`。
- 归因应从编译图到运行时边界再到 trace 串成证据链；单次观察只解释该输入、该版本与该条件。

## 2. 前置概念

### 2.1 Shape、stride 与连续性

shape 描述每一维长度；stride 描述沿一维移动一个索引时的存储偏移。若某维长度为 1，其索引只能为 0，因此不同 stride 都可保持同一组元素寻址。连续性是框架按其规则判断的布局属性，不能仅因某个 stride 数字很大就断定 tensor 不连续。

### 2.2 函数化与算子分派

函数化把带副作用的原地操作表示成无副作用的数据流，便于编译、重算和图变换。该改写保持数值语义，却可能改变中间结果的布局。后续算子分派根据实际输入性质选择实现；高层 API 名称不是底层 kernel 的承诺。

## 3. 完整原理

设梯度矩阵为 (G\in\mathbb{R}^{N\times V})，权重为 (W\in\mathbb{R}^{V\times d})，则 hidden 梯度为：

\[
dH=GW.
\]

将 (G) 表示为 `[N, 1, V]` 与二维 `[N, V]` 可以具有相同数学含义。若编译过程把原地缩放改成产生新值的缩放，新的 `[N,1,V]` 结果可能具有不同的 singleton 维 stride。该布局对逐元素值无影响，却可能不满足某个实现用于“折叠为二维矩阵”的额外条件。于是同一高层矩阵乘法表达式可能走不同路径。

这不是“编译器一定额外分配内存”，也不是“任何 singleton stride 都会导致回退”。物理分配仍可被融合或复用；是否回退由具体框架版本和完整运行时条件决定。

## 5. 工程中的具体表现

| 现象 | 可能原因 | 如何验证 |
|---|---|---|
| 同一 API 的 kernel 变了 | 编译后输入布局或梯度条件不同 | 记录编译图、运行时 shape/stride/dtype/`requires_grad` 和 trace |
| singleton 维 stride 很大 | 仍可能是合法布局 | 检查实际寻址语义与框架连续性判断 |
| 二维路径未被采用 | 某个 shape/stride/梯度前提未满足 | 找到分派条件；做最小对照，只改变一个条件 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| shape 一样，执行路径一定一样 | stride、dtype、梯度状态和编译阶段也可能影响分派 |
| singleton 维的异常 stride 等于不连续 | 其仍可被框架判为连续；要检查实际定义 |
| 函数化一定新增物理 buffer | 它先产生逻辑结果；融合和复用决定物理存储 |
| `bmm` 总比 `mm` 慢 | 两者适用结构不同；必须在匹配负载下测量 |

## 7. 一分钟复习

1. 数值等价、shape 相同，不等于中间布局与底层 kernel 相同。
2. singleton 维能容纳多个合法 stride；不要把它直接等同于不连续或错误。
3. 从源码 API 到性能结论至少需要：编译图、运行时边界、trace 和匹配对照。

## 8. 自测问题

### 问题 1

为什么函数化后不应直接断言“多分配了一块显存”？

期望回答：函数化定义逻辑数据流与结果布局；物理分配还会受融合、内存复用和后端实现影响。

### 问题 2

为什么一个长度为 1 的维度可有不同 stride？

期望回答：该维索引始终为 0，不会访问不同偏移；但下游实现仍可能把 stride 作为分派条件。

## 9. 尚未解决与后续路线

- 若某条路径发生回退，逐项固定 shape、stride、dtype、权重梯度状态与编译模式，再测数值/梯度等价和端到端影响。
- 不把一个框架版本中的分派规则推广为通用规律。
