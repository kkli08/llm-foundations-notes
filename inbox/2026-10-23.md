### 今天的问题

- 这个 critic 截断具体是什么问题？
- 论文和 verl 里，截断的时候 critic 的 V 是怎么处理的？

### 对话或资料摘录

- 巡检发现：数学任务（约三分之一回答被长度截断）上，PPO critic 的目标均值明显高于这批回答的平均判分，EV 一直在 0 附近；截断约 1% 的多模态任务 EV 正常上升；
- 原因：截断回答判 0 分，GAE 末尾又补上 critic 对末位的预测 V → 这些回答每个 token 的目标都变成 critic 自己的输出；截断回答都是最长的，按 token 占近一半；
- 后果：actor 开始学之后，截断回答的优势 ≈ 0，不奖不罚；GRPO 下截断回答 0 分、优势明显为负 → PPO 丢掉了“写超长要罚”的信号；
- 为什么以前没暴露：旧的截断判定每批只标中最长那一行；改成逐条真实截断标记（本身是对的）之后，补 V 覆盖了约三分之一回答；
- 理论：Pardo et al. 2018 区分“上限是任务一部分（终止）”和“上限只为训练方便（应补 V）”；LLM 生成上限截断后直接判分、不会续写，属于前者；
- verl、OpenRLHF、TRL 的 GAE 在回答末尾 nextvalue 都是 0，不区分截断；对截断的处理都放在 reward 上（缺 EOS 扣分、DAPO 过滤或软惩罚）；
- 修法：只在“截断回答的 reward 被屏蔽”的模式下补 V；数值检查：V 全设 0.9，截断回答（判 0）目标应全为 0；
- 修复后第 1 步看不出差别：critic 初始预测 ≈ 0，补上的值也是 0；修复前的运行在第 4～6 步才分开。

>

### 今天的问题

- 对这种分 32K、96K 上下文的任务，如果选择自然 EOS，max 上下文有什么意义？就算开了 96K 可能大部分也不会到 96K。

### 对话或资料摘录

- 上限是边界不是目标：决定超长回答怎么判分、资源按多长准备；到不到上限取决于长度分布的尾部；
- 同样 32K：几何题任务几乎碰不到；长推理数学任务起步约三分之一碰顶；多轮 agent 的总上下文累加工具输出，上限决定能做多少轮；
- 上限 + 截断处理 = 长度预算：判 0 强力压缩长度；过滤（DAPO）不压长度；软惩罚折中；评测上限应与训练一致；
- 重复停不下来的回答开多大都会顶满，上限越大烧越多；
- 成本由长尾决定：KV cache、每 micro-batch token 上限、长上下文要更多卡；rollout 等最长那几条，步时跟着截断率走；
- 比较 32K 与 96K 看三个指标：碰上限比例、答对回答的最大长度、未截断回答的平均长度趋势。

- 第 1 步约 97% 的组所有样本同分 → 几乎没有学习信号，真正的比较从后面开始；

- critic 目标按 token 平均、reward 按回答平均：答对回答更长时目标均值高于 reward 是正常的；
- critic 与 actor 共卡时，actor 常驻显存会让 critic 初始化 OOM → 先把 actor 移出再加载 critic；轮流上下卡增加步时 → 只比稳定性读数；
