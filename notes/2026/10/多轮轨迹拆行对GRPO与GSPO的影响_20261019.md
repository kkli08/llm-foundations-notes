## 0. 今天最终要解决的问题

按提问顺序：

1. GSPO 的“序列到底指什么”这个问题，只在 agentic 场景出现吗？其他 online 场景呢？还是说 online RL 都是 agentic？
2. 一条多轮轨迹，主干是整条轨迹一行、按轨迹算 Advantage；另一种做法是每轮 LLM 调用一行、Advantage 仍按整条轨迹给。对 GRPO 有什么区别？我的理解是只有 GSPO 算序列 ratio 时才有区别，其他没区别。

## 1. 先给结论

- **online 是接入方式，不是任务类型**：rollout 由外部平台驱动即为 online，它可以是单轮数学题，也可以是带工具的多轮 agent（与 [10 月 14 日 §3.5](GSPO序列级比率与PPO论文精读_20261014.md#35-online到底指什么) 一致）。
- **两个 GSPO 问题适用范围不同**：“序列指一轮还是整条会话”只在多轮时有歧义；“loss 按 token 聚合，长回答权重大”在所有场景都存在。
- **用户对了一半**：只要每个 token 拿到的 Advantage、看到的上下文、loss 权重都不变，把一条轨迹拆成几行**不改变** GRPO 的梯度。拆行本身只改变“序列级操作”的数学。
- **但现实中的两条路径捆绑了更多差异**：loss 加权方式、Advantage 管线、序列级操作（不只 GSPO，还有序列级拒绝采样）、系统成本与对“历史改写”的适应能力。其中 loss 加权对 GRPO 影响最大，和 GSPO 无关。
- **对齐两条路径时要把四点拆开**，各自决定，不要整套切换；否则对照实验分不清是哪一项起的作用。

## 2. 前置概念

### 2.1 两种导出粒度

| | 整条一行（concat） | 每轮一行（individual） |
|---|---|---|
| 一行装什么 | 整个会话：所有助手轮都在这一行里训练，工具/环境输出被 mask | 一次 LLM 调用：完整历史作为 prompt，只训练这一轮的输出 |
| 一行的“序列” | 整条多轮轨迹 | 一轮 |
| Reward / Advantage 单位 | 整条轨迹 | 仍是整条轨迹，复制到这条轨迹所有行的所有 token |

### 2.2 GRPO 一个 token 的梯度

$$
g_t = A \cdot \nabla \log \pi_\theta(y_t \mid \text{上下文}_t) \times \text{loss 权重}_t
$$

三个量（A、上下文、权重）决定一切；“它在第几行”不出现在公式里。

## 3. 完整原理

### 3.1 问题一：GSPO 的“序列”歧义出现在哪些场景

GSPO 的序列比值 $s_i = \exp(\text{mean}_t \log r_t)$ 在实现里通常按“打包后的一行”求平均，所以“一行装什么”决定了“序列”是什么（论文与实现的差别见 [10 月 14 日 §3.7](GSPO序列级比率与PPO论文精读_20261014.md#37-实现与论文的三处差别)）。

| 场景 | 一行是什么 | “序列”歧义 | 按 token 聚合的长度偏置 |
|---|---|---|---|
| 单轮 RLVR（出题 → 一次回答 → 判分） | 那一次回答 | 无：序列 = 回答 = Reward 单位 | **有** |
| 多轮、但只导出被打分的那一轮 | 被打分的那一轮，前几轮只作上下文 | 基本无：一行一轮，Reward 也给这一轮 | **有** |
| 多轮 agent，整条一行 | 整条轨迹 | **有**：某一轮偏得厉害，会被其他轮的 token 平均掉 | **有，最明显** |
| 多轮 agent，每轮一行、Advantage 按整条轨迹 | 一轮 | **有**：序列比值的单位（一轮）≠ Reward 单位（整条） | **有** |

长度偏置的例子：一组两条序列，100 和 10000 个 token，Advantage 大小相同。论文“每条序列等权”时各占 50%；按 token 聚合时长的那条占 10000/10100 ≈ 99%。长思维链的单轮任务同样会有几百到几万 token 的差距，所以这一点不限于 agentic。它本身是有争议的设计选择：GRPO 原文与 GSPO 论文按序列平均，DAPO 特意按 token 聚合以免长篇错误回答被罚得太轻（[两个“按 Token”](GRPO变体与两层归一化的拆解_20261013.md#33-两个不同的按-token被纠正的误解)）。写着 GSPO，就要明确选哪一种。

另一个要先定的设计问题：若要按整条会话聚合、数据却按轮导出，就需要一个显式的“会话/序列 id”来分组，不能再依赖“一行 = 一条序列”的打包边界。

### 3.2 问题二：拆行为什么本身不改变 GRPO（用户判断正确的那一半）

整条一行时，第 k 轮助手 token 的上下文是“前面所有轮 + 本轮已生成部分”；每轮一行时，这一行的 prompt 就是同样的历史。只要：

1. 两种做法给这个 token 的 A 相同（都是整条轨迹的组内归一化值）；
2. 上下文 token 完全一样；
3. loss 权重一样；

则 §2.2 的梯度逐项相同，加总也相同。拆行改变的只有那些**以“行”为单位做的运算**，即序列级操作（§3.5）。

### 3.3 差别一：loss 加权（影响最大，与 GSPO 无关）

现实中两条路径往往绑定了不同的聚合方式：

- **按 token 等权**：所有有效 token 求和再除以 token 总数，助手 token 越多的轨迹在梯度里占比越大；
- **按轨迹等权**：每个 token 权重 = 1 ÷ 这条轨迹的可训练 token 数，每条轨迹总权重相同。

例子：一组两条轨迹，A 成功、2 轮、共 2000 个助手 token，B 失败、10 轮、共 20000 个；组内归一化后 A = +1、B = −1。

| | A（+1）占的梯度份量 | B（−1）占的梯度份量 |
|---|---|---|
| 按 token 等权 | 2000/22000 ≈ 9% | ≈ 91% |
| 按轨迹等权 | 50% | 50% |

多轮 agent 任务里失败轨迹往往更长（空转到轮数上限），按 token 等权时梯度主要花在“压低长失败轨迹”上，成功的短轨迹几乎推不动（与 [10 月 12 日 Loss 加权表](GRPO流程与批级Advantage归一化的偏移机制_20261012.md) 同一现象）。这是两种做法在 GRPO 本身上最实质的区别，而它来自聚合方式，不来自拆行。

### 3.4 差别二：Advantage 管线

| 环节 | 一种常见的 GAE 路径 | 一种“rollout 侧直接给 Advantage”的路径 |
|---|---|---|
| 组内标准差 | 无偏（除以 G−1） | 有偏（除以 G）；G = 8 时两者差 √(8/7) ≈ 1.07 倍 |
| KL | 可进 reward，且前面轮次的 token 会累积后面所有轮的 KL（[KL 放置](KL估计器与放置位置的设计动机_20261015.md)） | 无 |
| 批级归一化 | 可能开着，带来平移与放大（[双条件崩溃](截断采样与批级归一化的双条件崩溃机制_20261016.md)） | 跳过 |

这部分差异来自所走的代码路径，同样与“按轮拆分”无关。把整套路径换掉的对照实验，结果不同的原因可能是 §3.3、§3.4 里的任何一项，单看这一组分不开（[打包实验的隐含混杂](训练崩溃归因的工作流与实验解读_20261012.md#35-解读时要提前想好的四个陷阱)）。

### 3.5 差别三：序列级操作——不只 GSPO

拆行真正改变数学的地方，是所有“以行为单位求几何平均或判定”的操作：

- **GSPO 序列比值**（π_θ/π_prox 一侧）：每批只更新一次时恒为 1、不生效（[10 月 15 日 §3.2](单次更新下两个比值的分工与Clip的真实作用_20261015.md#32-gspo-在-r--1-时为什么和-token-级梯度一样)）；
- **序列级拒绝采样与重要性权重**（π_prox/π_behave 一侧）：**单次更新时也生效**。整条一行时，几何平均覆盖整条轨迹，某一轮严重偏离会被其他轮稀释，很难被过滤；按轮拆开后，出问题的那一轮会被单独 mask。token 级拒绝采样没有这个区别。

所以用户说的“只有 GSPO 才有区别”要扩成“只有序列级操作才有区别，而序列级拒绝采样此刻就在起作用”。

### 3.6 差别四：系统成本与“历史只追加”假设

**计算成本**：整条一行时历史前缀天然共享，一条轨迹只前向一次；每轮一行时，每行都要把完整历史当 prompt 重新前向。示例：初始 prompt 4k，每轮新增 1k 输出 + 2k 工具结果，共 10 轮：

```text
整条一行：4k + 10 × 3k = 34k token
每轮一行：Σ_{i=1..10} [4k + (i−1)·3k + 1k] = 50k + 135k = 185k token  ≈ 5.4 倍
```

前缀共享的“树训练”能把这部分省回来，但它往往与 Context Parallel 不兼容，而长上下文恰恰需要 CP（[PP、CP 与 SP](PP_CP_SP的切分对象与通信代价_20261009.md)）。

**对非线性历史的适应能力**：整条一行隐含假设“每一轮的输入 = 上一轮的完整 token + 新内容”。agent 一旦压缩或改写上下文（例如接近上限时把早期内容摘要掉），这个假设就不成立：若新输入比上一轮还短，实现通常能发现；若前缀内容变了但长度更长，没有额外校验时会**静默地用错上下文**训练。每轮一行时，每一行就是推理时实际发出的那次请求，天然没有这个问题。

### 3.7 小结表

| 区别 | 改变 GRPO 梯度吗 | 是拆行本身造成的吗 |
|---|---|---|
| 1. loss 加权（token 等权 vs 轨迹等权） | 是，影响最大 | 否，是绑定的聚合方式 |
| 2. Advantage 管线（std、KL、批级归一化） | 是 | 否，是绑定的代码路径 |
| 3. 序列级操作（GSPO 比值、序列级拒绝采样） | 是 | **是** |
| 4. 计算成本、历史改写 | 否（系统层面） | 是 |

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 换成每轮一行的做法后训练行为明显不同 | 同时换了 loss 加权、Advantage 管线 | 四点逐项单变量对照 |
| 成功的短轨迹似乎推不动 | token 等权下长失败轨迹占大头 | 按轨迹统计梯度份量；试轨迹等权 |

| 每轮一行时训练变慢数倍 | 每行重复前向完整历史 | 统计训练前向 token 总数 |
| agent 压缩上下文后训练异常但不报错 | 整条一行假设历史只追加 | 逐轮比对实际请求与拼接后的前缀 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| online RL 就是 agentic RL | online 是接入方式，单轮任务也可以 online |
| 序列定义问题所有场景都有 | 只在多轮时有；长度偏置才是所有场景都有 |
| 拆行只影响 GSPO | 影响所有序列级操作，含此刻就生效的序列级拒绝采样 |
| 两种导出方式的 GRPO 差别就是拆行 | 最大差别是绑定的 loss 加权和 Advantage 管线 |
| 每轮一行只是换了组织方式，成本不变 | 每行重复前向历史，示例里约 5.4 倍 |
| 整条拼接总能还原真实上下文 | 历史被改写时可能静默用错上下文 |

## 7. 一分钟复习

1. online = 接入方式；“序列”歧义只在多轮，长度偏置处处都有（100 vs 10000 token → 50/50 vs 1/99）。
2. 梯度 = A × ∇log π(token | 上下文) × 权重；三者不变则拆行不变。
3. 捆绑差异四项：loss 加权（最大）、Advantage 管线、序列级操作（拆行唯一改数学处）、系统成本与历史改写。
4. 序列级拒绝采样单次更新也生效：整条一行会稀释坏的那一轮。
5. 每轮一行前向 ≈ Σ 历史长度，示例 34k → 185k；树训练可省但常与 CP 冲突。

## 8. 自测问题

### 问题 1

为什么说“把多轮轨迹拆成每轮一行”本身不改变 GRPO 的梯度？成立条件是什么？

期望回答：每个 token 的梯度只由 A、上下文和 loss 权重决定。只要拆行后三者不变（A 都是整条轨迹的值、prompt 就是同样的历史、权重口径一样），逐 token 梯度相同，加总也相同。

### 问题 2

一组里成功轨迹 2000 token（A = +1），失败轨迹 20000 token（A = −1）。token 等权与轨迹等权下各自的梯度份量是多少？对多轮 agent 训练意味着什么？

期望回答：token 等权约 9% / 91%，轨迹等权 50% / 50%。token 等权时梯度主要用于压低长失败轨迹，成功短轨迹几乎推不动。

### 问题 3

每批只更新一次时 GSPO 序列比值不生效，那拆行还会改变什么？

期望回答：序列级拒绝采样 / 重要性权重（π_prox/π_behave 一侧）仍生效。整条一行时几何平均覆盖整条轨迹，坏的那一轮被稀释；按轮拆开后能单独过滤。

### 问题 4

为什么整条一行的做法在 agent 压缩上下文时可能出问题？

期望回答：它假设每轮输入是上一轮的完整 token 加新内容。历史被改写且长度更长时，没有校验就会静默地用拼接出来的错误上下文训练；每轮一行用的是实际请求，没有这个问题。
