## 1. 先给结论

- **崩溃需要两个条件同时成立**：截断采样提供**方向**，批级归一化把它**放大成正反馈循环**。单变量对照里，去掉任意一个条件，同一时间点出现的那次小波动都会自己消退；只有两者都在的那组越过波动后持续恶化。每组只有一次运行，这是目前最合理的解释，还不是定论。
- **关键在“常数 Advantage 的期望梯度”**：
  - 从模型自己的分布 π 采样时，$\mathbb{E}_{a\sim\pi}[\nabla\log\pi(a)] = 0$。给每个 token 加同一个常数 c，期望梯度为 0，只是噪声，这就是 Baseline 的原理；
  - 从截断后的分布 q 采样时，$\mathbb{E}_{a\sim q}[\nabla\log\pi(a)] = \nabla\log Z \neq 0$。同一个常数变成了一个固定方向的推力。
- **抵消发生在整批几十万个 token 求和时，不在单个 token 内部**：每个位置只采样一次，单个 token 的推力方向随机；期望为 0 的推力加总后互相抵消，带同向偏差的推力加总后累积。
- **Advantage 的影响不局限于那一个 token**：通过 softmax 影响同一位置的整个词表，通过共享参数影响所有上下文。
- **截断不在重要性比值里**（被纠正的误解）：比值的分子和分母都是完整分布；截断改变的是“哪些 token 被采出来”。正确的分母应是 q = π/Z，但没有任何一方记录 q。
- **PPO 做批级归一化，是为了固定整体尺度、把均值拉回 0**（被纠正的误解）：不是让每个 token 的更新幅度一致。长短轨迹的权重归 loss 的聚合方式管，不归 Advantage 归一化管。
- **同一个设计，放在 PPO 里合理，原样带进 GRPO 就变成重复的第二次归一化**，还会碰上 GRPO 特有的零方差组。

## 2. 前置概念

### 2.1 组内 z-score 怎么算（GRPO 唯一提取信号的一步）

同一道题采样 G 条轨迹，各得一个 Reward：

$$
\hat r_i = \frac{r_i - m}{s + \varepsilon},\qquad m = \text{组均值},\ s = \text{组标准差}
$$

$\hat r_i$ 放在这条轨迹最后一个生成 token 上，经 V ≡ 0、γ = λ = 1 的 GAE 广播给这条轨迹的每个生成 token（环境返回的 token 不训练）。多轮会话拼成一条序列时，所有轮次的生成 token 共用这一个值。

| 组内 8 条的 Reward | m | s（无偏） | 答对的轨迹 | 答错的轨迹 |
|---|---|---|---|---|
| 2 对 6 错 `[1,1,0,0,0,0,0,0]` | 0.25 | ≈ 0.463 | ≈ **+1.62** | ≈ **−0.54** |
| 全错 `[0,…,0]` | 0 | 0 | — | **0** |

第一组按条数求和：2 × 1.62 − 6 × 0.54 ≈ 0。**每组按条数加起来总是 0**，只学组内的相对好坏；全错组整组为 0，本来不产生任何梯度。完整流程见 [GRPO 训练步的参数时序](GRPO训练步的参数时序与四个KL指标_20261016.md)。

### 2.2 Advantage 怎么进 loss

```text
loss = −(1/N) · Σ_每个有效token  A_t · ratio_t · w_t        （ratio 再被 clip）
单次更新时 ratio ≡ 1，每个 token 对梯度的贡献是  A_t · w_t · ∇log π_θ(a_t | s_t)
```

含义：在上下文 $s_t$ 下，把实际采到的 $a_t$ 的概率往上推（A > 0）或往下推（A < 0），力度按 A 算。它的影响范围有两层：

- **同一位置的整个词表**：$\log\pi(a_t)$ 是全词表 softmax 的结果，推高 $a_t$ 的 logit，就按比例压低其余所有词（logit 形式 $\Delta z \propto A(e_{a_t} - \pi)$，见 [10 月 12 日 §3](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#3-advantage-在梯度里到底做什么)）；
- **其他轨迹、其他 token**：所有 token 的梯度加总成一次参数更新，参数是共享的，所以一个 token 的推力会通过参数影响所有上下文。

## 3. 完整原理

### 3.1 第一步：批级归一化让零方差组拿到同一个常数

批级归一化对整批所有有效 token 做 $(A - \mu)/\sigma$，μ 和 σ **按 token 计数**。组内 z-score 只保证每组**按条数**为 0；答错的轨迹更长时，按 token 加权的 μ 偏负（[10 月 12 日 §4.1](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#41-token-加权均值为什么不是-0)）。于是零方差组每条轨迹的每个 token 都拿到

$$
c = \frac{0 - \mu}{\sigma} > 0 \quad(\mu < 0\ \text{时})
$$

“答错轨迹更长，所以 μ 偏负”是从长度差推出来的，没有直接测量 μ。

### 3.2 第二步：不截断时，这个常数平均为 0

被采到的 token 拿到 $c\,\nabla\log\pi(a)$。若 a 真从 π 采：

$$
\mathbb{E}_{a\sim\pi}\big[c\,\nabla\log\pi(a)\big] = c\sum_a \pi(a)\frac{\nabla\pi(a)}{\pi(a)} = c\,\nabla\!\sum_a\pi(a) = c\,\nabla 1 = 0
$$

直观例子：某位置四个候选 A/B/C/D 的概率是 57% / 28% / 10% / 5%。在整批里，这种“白送的奖励”落到哪个词上的频率正好和它原本的概率成正比，所以分布被整体等比例推，等于没动。

注意“频率”是对整批成千上万个同类位置而言的。每个位置只采样一次，单个 token 的推力方向是随机的；**抵消发生在加总时**（对话里最初用“同一位置采 100 次”来讲，这一点有误导，已更正）。

### 3.3 第三步：截断后，同一个常数变成固定方向的推力

top-p / top-k 截断后，实际从核内重新归一化的分布采样：对核内集合 S，$q(a) = \pi(a)/Z$，$Z = \sum_{a\in S}\pi(a)$；核外 $q = 0$。

$$
\mathbb{E}_{a\sim q}\big[\nabla\log\pi(a)\big] = \sum_{a\in S}\frac{\pi(a)}{Z}\cdot\frac{\nabla\pi(a)}{\pi(a)} = \frac{\nabla Z}{Z} = \nabla\log Z \neq 0
$$

还用上面的例子：截断后 D 永远采不到，样本只落在 A、B、C 上，A、B 被奖励的频率高于它们原本的份额，D 只能被动地被压低。**这个改动和答对还是答错毫无关系**，只取决于 c 的符号：c > 0 时推高核内总概率 Z，c < 0 时反过来抬高核外长尾。logit 形式就是 [10 月 12 日 §4.4](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#44-截断采样让它不再无害假说) 的 $c\,(q - \pi)$，两种写法等价。

训练端纠正不了：它在完整分布上算 logprob，不知道采样时做过截断（§3.5）。

### 3.4 第四步：批级归一化把偏差放大成循环

批级归一化像一个扩音器：

- **σ 变小，c 变大**：零方差组越多，有信号的 token 越少，σ 越小（[1/√p 放大](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#5-批级归一化第二件事除标准差--按信号稀缺程度放大步长)）；
- **全错组越多，带着 c 的 token 越多**。

两种情况的循环增益不同：

| 条件 | 扩音器放大的是什么 | 一次小波动之后 |
|---|---|---|
| 不截断 + 批级归一化 | 期望为 0 的噪声 | 没有持续方向，波动自己回落 |
| 截断 + 批级归一化 | 固定方向的推力 | 全错组变多 → 推力变大 → 模型被推偏 → 全错组更多……增益 > 1，直到全部组都全错 |
| 截断 + 不做批级归一化 | 无：零方差组的 A 就是 0 | 没有“白送的奖励”，波动回落 |

单变量对照与此一致：几组运行在同一时间附近都出现了一次全错组占比的小幅上升；只有“截断 + 批级归一化”那组越过之后几步内持续攀升，直到所有组全错；关掉其中任一项的两组都回落、跑完计划步数。参照用的另一套稳定配置也没开批级归一化。

**一句话：截断让误差有了方向，批级归一化把它放大成停不下来的循环，缺一个都不成。**

### 3.5 截断不在 ratio 里，而在样本里（被纠正的误解）

用户的理解是“ratio 的分子是带截断的新分布，分母是采样时的分布”。实际两边都是完整分布：

| 量 | 来自 | 截断了吗 |
|---|---|---|
| 分子 π_θ（以及 π_prox） | 训练引擎在完整词表上 softmax | 没有 |
| 分母 π_behave | 推理引擎返回的 raw logprob | 没有（截断前、温度前，见 [10 月 14 日](采样截断与Logprob口径的训推偏差_20261014.md)） |
| 真正采样用的 q | 推理引擎截断后重新归一化 | **是，但没人记录** |

截断真正影响的是**哪个 token 被采出来**。重要性比值本来就是用来纠正“采样分布 ≠ 训练分布”的；要正确纠正，分母应该填 q(a) = π(a)/Z。现在分母填的是 π(a)：

- **比值看起来约等于 1、很正常**：少乘的那个 Z 被藏起来了；
- **核外的词根本不进 batch**：没采到就没有 loss 项，比值再怎么算也表达不了“这些词本该被采到”。

**截断不是让比值算错，而是让样本本身有偏；比值的分母填的是 π 而不是 q，没能把这个偏差纠回来。**

### 3.6 PPO 为什么要做批级归一化（被纠正的误解）

PPO 有 Critic 时，每个 token 的 Advantage 逐个不同：

$$
A_t = \sum_{k\ge 0}(\gamma\lambda)^k\,\delta_{t+k},\qquad \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

整体尺度随 Reward 量级和 Critic 误差漂移。批级归一化把整批所有 token 当样本做 $(A-\mu)/\sigma$，**所有 token 共用同一个 μ 和 σ**，解决两件事：

1. **固定整体尺度**：学习率固定时，Advantage 的尺度就是有效步长；尺度漂大更新过猛，漂小几乎不学；
2. **把均值拉回 0**：Critic 估偏时整批 A 可能都为正，等于把所有采到的 token 一起推高，策略很快过度确定（熵塌缩）；减掉均值后大约一半推高、一半压低，梯度方差也更小。

用户的猜测“为了让长短不一的轨迹里每个 token 影响一致”需要纠正：

- **它不让每个 token 的更新幅度一致**：这是一个统一的仿射变换，保留的是 token 之间的**顺序**和**差值的相对大小**，同步缩放。
- **对话里“比例关系不变”的说法也要修正**：减均值会改变比值，均值附近的 token 还会变号。例如 `[10, 20, 30, −40]`，μ = 5、σ ≈ 26.9（总体标准差），归一化后约 `[+0.19, +0.56, +0.93, −1.67]`：顺序不变，差值等比例缩小，但 10 : 20 不再是 1 : 2。变号正是“减均值”想要的效果。
- **长短轨迹的权重归 loss 聚合方式管**：token 等权时长轨迹的总影响更大，轨迹等权时每条轨迹权重相同（[两个“按 Token”](GRPO变体与两层归一化的拆解_20261013.md)）。批级归一化的 μ、σ 按 token 统计，反而让长轨迹在统计量里占更大权重，这正是 §3.1 偏移的来源。

不做批级归一化，PPO 通常也能训，只是对 Reward 尺度和学习率更敏感、前期 Critic 不准时更容易不稳定。它是常用的稳定技巧，不是必需品。

### 3.7 同一设计，为什么在 PPO 合理、在 GRPO 有害

| | PPO（有 Critic） | GRPO（无 Critic） |
|---|---|---|
| Advantage 形态 | 逐 token 连续变化 | 每条轨迹一个常数，广播到每个 token |
| 之前做过归一化吗 | 没有，批级归一化是唯一一次 | 已做过组内 z-score，再做一次是重复 |
| 会不会出现整组全 0 | 几乎不会 | 组内 Reward 相同就是 0，多轮 Agent 任务里占比可观 |
| 批级归一化的实际效果 | 对一个连续分布平移、缩放 | 变成“按长度加权的跨组归一化”：零方差组被平移成非 0；零方差组越多，σ 越小、更新越大 |

框架里这个默认组合的来历：同一个框架的 GRPO 与 PPO 共用同一个 Actor，GRPO 只是一组配置（没有 Critic、γ = λ = 1），自带的 GRPO 示例默认就是“组内 Reward 归一化 + 批级 Advantage 归一化”一起开，沿用自 PPO。对照开源的 veRL：它的 GRPO Advantage 只做组内 z-score，批级白化只出现在 GAE（带 Critic 的 PPO）路径里，和原版 GRPO 一致。

为什么这个默认组合在单轮数学题上不明显出问题（推测，未验证）：单轮回答长度差异小、零方差组少，两个副作用都弱；多轮 Agent 任务失败轨迹明显更长、零方差组又多，副作用被放大。

### 3.8 尚未解释：推力的方向与崩溃形态对不上

$c\,\nabla\log Z$ 在 c > 0 时推高核内总概率，直觉上应让分布更尖、熵下降；实际崩溃时观察到的是**熵上升**，最终“一开口就输出 EOS”。目前能确认的只是“截断提供方向、归一化放大”，还不能解释“为什么偏成这个样子”。两个候选方向：

- **μ 的符号翻转**（[10 月 12 日 §4.2、§4.5](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#45-为什么可能塌缩成-eos假说) 的假说）：失败形态从长篇空转变成“一开口就结束”后，按 token 加权的 μ 由负转正，c 变负，长尾（含 EOS）被抬高、熵上升；
- **混合组的偏差**：截断下有信号组的 $\hat r$ 本身也带偏差，与零方差组的常数叠加。

区分方法：画出归一化前 μ 的符号随训练步的变化，看它是否在熵开始上升前由负转正。

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 开批级归一化就一定崩 | 还需要截断采样提供方向；单变量对照里关掉截断也不崩 |
| 给所有 token 加同一个常数一定有害 | 从 π 采样时期望梯度为 0，是 Baseline；截断后变成 $c\,\nabla\log Z$ |
| “抵消”发生在一个 token 的词表内部 | 每个位置只采一次；抵消发生在整批 token 加总时 |
| 改一个 token 的 Advantage 只影响它自己 | 经 softmax 影响整个词表，经共享参数影响所有上下文 |
| 截断体现在 ratio 的分子或分母里 | 两边都是完整分布；截断改变的是样本，正确分母应是 q = π/Z |
| PPO 批级归一化是为了让每个 token 更新幅度一致 | 是固定整体尺度、均值归 0；长度权重归 loss 聚合 |
| 归一化保留 token 之间的比例 | 保留顺序与差值的相对大小；减均值会改变比值，甚至变号 |
| PPO 的批级归一化是按轨迹做的 | 按 token 做；PPO 的 Advantage 本来就逐 token 不同 |
| 框架默认开着，说明 GRPO 就该这么配 | 是沿用 PPO 的配置；原版 GRPO 与 veRL 的 GRPO 都只做组内 z-score |

## 7. 一分钟复习

1. 崩溃 = 截断（方向）× 批级归一化（放大）；去掉任一个，同一次波动自己消退。
2. $\mathbb{E}_\pi[\nabla\log\pi] = 0$，$\mathbb{E}_q[\nabla\log\pi] = \nabla\log Z$：常数 Advantage 在截断下有方向。
3. 抵消发生在整批加总时；Advantage 经 softmax 与共享参数影响别的 token。
4. 截断不在 ratio 里：分子分母都是完整分布，偏差在样本里，没人记录 q。
5. PPO 批级归一化：固定尺度 + 均值归 0；长度权重归 loss 聚合；放进 GRPO 就成了重复的第二次归一化。

## 8. 自测问题

### 问题 1

为什么同样开着批级归一化，top_p = 1（且不限 top_k）的那组不崩？

期望回答：零方差组拿到的常数 c 乘的是 $\nabla\log\pi(a)$。从 π 采样时它的期望为 0，放大的只是噪声；截断后期望变成 $\nabla\log Z$，才有固定方向。没有方向，放大器就形成不了正反馈。

### 问题 2

推导 $\mathbb{E}_{a\sim q}[\nabla\log\pi(a)]$，并说明 c > 0 和 c < 0 时分别把概率往哪里推。

期望回答：$\sum_{a\in S}(\pi/Z)(\nabla\pi/\pi) = \nabla Z/Z = \nabla\log Z$。c > 0 推高核内总概率、压低长尾；c < 0 反过来抬高长尾。

### 问题 3

“ratio 的分子是截断后的分布，所以 ratio 改变了 token 分布”，错在哪？

期望回答：分子是训练引擎在完整词表上的 π_θ，分母是推理引擎的 raw logprob，都没截断。截断改变的是被采出来的样本；正确的分母应是 q = π/Z，现在填的是 π，所以偏差没被纠正。

### 问题 4

PPO 的批级归一化解决什么问题？为什么它不是“让每个 token 更新幅度一致”？

期望回答：固定整体尺度（等效学习率）、把均值拉回 0（避免整批同向推导致熵塌缩）。它对所有 token 用同一个 μ、σ 做仿射变换，保留顺序和差值的相对大小；长短轨迹的权重由 loss 聚合方式决定。

### 问题 5

一个 token 的 Advantage 会影响其他轨迹吗？通过什么？

期望回答：会。所有 token 的梯度加总成一次参数更新，参数在所有上下文间共享；同一位置还通过 softmax 影响整个词表。
