# 每日收集箱

`inbox` 用于保存当天尚未整理的原始材料。

## 文件命名

每天使用一个文件：

```text
inbox/YYYY-MM-DD.md
```

例如：

```text
inbox/2026-07-24.md
```

## 推荐格式

```markdown
# 2026-07-24 原始学习记录

## 09:40｜Batch 和并发的区别

> 记录时间：2026-07-24 09:40
>
> 内容归属日期：2026-07-24
>
> 整理状态：未整理

### 今天的问题

- Batch 和并发到底有什么区别？
- Continuous Batching 为什么能提高吞吐？

### 对话或资料摘录

- …

### 我的当前理解

- …

### 实验与日志

- 配置：
- 现象：
- 预期：
- 未解释的问题：

### 下班前希望整理

- …

## 21:10｜KV Cache 的新问题

> 记录时间：2026-07-24 21:10
>
> 内容归属日期：2026-07-24
>
> 整理状态：未整理

- …
```

每个独立主题使用一个带时间的二级标题，并保留三项元数据：

```text
记录时间：内容实际记录或发生的北京时间
内容归属日期：这条知识应该属于哪一天
整理状态：未整理 / 已整理 / 已补录
```

18:25 之后新增的条目仍写在当天文件中。次日 09:25 补漏任务处理成功后，会将状态改成类似：

```text
整理状态：已补录
归档日期：2026-07-24
补录时间：2026-07-25 09:25
正式笔记：../notes/2026/07/2026-07-24.md
```

如果第二天早上才想起昨晚的内容，请把“内容归属日期”明确写成前一天。只要在 09:25 前进入前一天 Inbox，补漏任务仍会把它归入前一天正式笔记。

## 记录原则

- 白天先追求“不要遗漏”，不要求语言完整；
- 每个主题尽量记录北京时间，尤其是 18:25 之后的内容；
- 默认“内容归属日期”等于记录发生的自然日；跨日补写时显式填写前一天；
- 保留自己的问题和错误理解，它们很适合做复习题；
- 命令、配置、指标要尽量原样记录；
- 不要在 Inbox 中保存密码、Token、Cookie、私钥或公司敏感数据；
- 自动任务完成整理后会保留原始文件，并更新每个条目的整理状态；
- 没有实质内容时不要创建空 Inbox。
