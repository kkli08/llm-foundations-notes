### 今天的问题

- 为什么终端已经设置代理，Codex 桌面端仍可能无法联网？
- 怎样让家庭网络可用，同时不改变公司网络的日常行为？
- 怎样验证“代理节点可用”和“国内流量仍然直连”？

### 我的当前理解

- 本地代理程序只是监听回环地址；仅启动后台服务不会自动接管系统流量。应用是否走代理，取决于应用自己的代理设置、进程环境变量或 macOS 系统代理。
- `HTTP_PROXY` / `HTTPS_PROXY` 只影响读取这些环境变量的当前进程及其子进程，适合终端中的 Codex CLI；它们不会自动改变已经运行的桌面应用。
- Codex 桌面端更适合通过 macOS 的 HTTP/HTTPS 系统代理接入。为了不影响公司网络，应使用显式的家庭启停命令，而不是在 shell 启动时自动打开系统代理。
- 分流应在本地代理的路由层完成：需要外部访问的域名走代理，国内和私有地址直连。这样应用只需要连接一个本地入口，不必分别维护路由规则。
- 关闭系统代理只停止应用把请求交给本地代理；后台代理服务继续待命通常不会产生业务流量，也不会主动劫持连接。

### 本次落地与验证

- 代理配置先经过命令行语法校验，再作为当前用户的登录自启服务运行。
- 分别用外部 API、桌面产品站点和国内站点做了连通性检查；外部目标返回了可解释的 HTTP 响应，国内目标正常返回成功状态。
- 为终端提供 `proxy_on` / `proxy_off`，为家庭场景提供 `home_proxy_on` / `home_proxy_off`；家庭开关同时控制当前终端与 macOS 系统代理。
- 公司网络下没有执行家庭开启命令，并复核系统 HTTP/HTTPS 代理仍处于关闭状态。

### 安全边界

- 知识库不保存远端服务器地址、用户标识、密钥材料、内部域名、完整配置或本机绝对路径。
- 原始配置只保存在本机受限权限文件中；公开笔记只记录可复用的网络作用域和验证方法。
- 回家后先开启并验证，必要时重启 Codex 桌面端；返回公司后显式关闭家庭系统代理。
