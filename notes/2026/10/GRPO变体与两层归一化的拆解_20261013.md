## 1. 先给结论

- **GRPO = PPO 去掉 Critic，用同题 G 次采样的平均分充当“预期得分”**：用推理算力换掉训练侧一整个模型，代价是 Credit Assignment 从 Token 粒度退化到轨迹粒度。
- **GRPO 的变体（Dr.GRPO、DAPO、GSPO、RLOO、LitePPO……）大多只差在三处**：Advantage 怎么归一化、Loss 怎么聚合、Clip 怎么设。
- **有两处归一化、两个不同的“按 Token”**：
  - Reward 归一化（组内比较，GRPO 的核心）作用在每条轨迹一个数上；
  - Advantage 归一化（可选后处理，最早为 PPO 设计）作用在每个 Token 一个数上；
  - Loss 的 Token 等权聚合是另一件事：不改 A 的值，只改每条轨迹在梯度里的权重。
- **“按 Token”不是批级归一化里单独的一步，而是统计均值和标准差时的计数口径**。
- **平移只来自按 Token 计数；缩放两种口径都有**：按轨迹统计时均值恰为 0，只剩统一缩放，零方差组保持 0。

## 2. 前置概念

### 2.1 为什么能去掉 Critic

PPO 里 Critic 给出“预期得分”V，Advantage = 实际 − 预期。GRPO 的观察：对一道题，“当前模型的预期得分”可以**直接用采样估计**——同一道题让当前模型做 G 次，平均分就是它的估计。

```text
PPO：  A = 实际得分 − Critic 预测的 V
GRPO： A = (实际得分 − 同题 G 次的平均分) / 同题 G 次的标准差
```

| | PPO | GRPO |
|---|---|---|
| “预期”从哪来 | Critic 预测 | 同题采 G 次取平均 |
| 额外成本 | 一个与 Actor 同样大的模型：显存 + 前向 + 反向 | Rollout 量变成 G 倍 |
| 精细度 | 能区分轨迹内哪一步好坏 | 整条轨迹共用一个分数 |
| 主要风险 | Critic 不准时 Advantage 本身就错；稀疏 0/1 Reward 下尤其难训 | G 次全对或全错时没有信号（零方差组） |

LLM 场景下推理有高吞吐引擎，多采几次通常比多训一个同等大小的 Critic 更划算，也更稳定；代价是长程多轮任务里功劳分配变粗。

### 2.2 原版 GRPO（DeepSeekMath）

1. 每道题用当前模型采 G 个回答（论文中 G = 64）；
2. 每个回答打分 r_i；
3. 组内归一化 `Â_i = (r_i − mean(r)) / std(r)`，发给这个回答的每个 Token；
4. Loss 用 PPO Clip 形式，外加直接写进 Loss 的 KL：

$$
J = \frac{1}{G}\sum_i \frac{1}{|o_i|}\sum_t \min\!\big(\text{ratio}\cdot\hat A_i,\ \text{clip}(\text{ratio},1-\epsilon,1+\epsilon)\cdot\hat A_i\big) \;-\; \beta\,\mathrm{KL}(\pi_\theta\,\|\,\pi_{\text{ref}})
$$

先在每条回答内按长度平均，再在组内平均；KL 用 k3 估计。

| | PPO | 原版 GRPO |
|---|---|---|
| 预期得分 | Critic | 组内平均 |
| Advantage 粒度 | 每个 Token 不同（GAE） | 整条回答一个值 |
| KL 放在哪 | 并入 Reward | 作为 Loss 的一项 |
| Loss 聚合 | Token 平均 | 先回答内按长度平均，再组内平均 |

## 3. 完整原理

### 3.1 原版 GRPO 的已知问题与对应变体

| 问题 | 机制 | 修补方案 |
|---|---|---|
| **长度偏差** | `1/|o_i|` 让长回答里每个 Token 分到的 Advantage 被摊薄：一条 2000 Token 的错误回答，每个 Token 只被罚 1/2000，反而鼓励“错的时候写长一点” | Dr.GRPO、DAPO：所有 Token 等权（全批 Token 平均） |
| **难度偏差** | 除以组 std：G = 8 只对 1 次时 std 小，那次成功 A ≈ +2.47；4/8 时只有 ±0.93。极难和极易的题被放大 | Dr.GRPO：不除以 std |
| **零方差组无信号** | G 次全对或全错时 A 全为 0，算力白费 | DAPO 动态采样：丢弃这类组，补采新题 |
| **熵塌缩** | 对称 Clip 限制了低概率好 Token 的上升空间 | DAPO clip-higher（注意：整批只更新一次时不生效，见 [PPO 笔记 §3.3](PPO的Critic与Clip在单次更新下的退化_20261013.md#33-关键推论单次更新时-clip-退化)） |
| **截断回答的 Reward 有噪声** | 被长度截断的回答直接记 0 分，但它不一定是错的 | DAPO 超长惩罚：接近上限时逐步扣分 |
| **Token 级 ratio 噪声大** | 尤其 MoE 模型，单 Token ratio 抖动大 | GSPO：ratio 改成整条序列的几何平均 |
| 均值里包含了自己 | 组均值把当前样本也算进去，有轻微偏差 | RLOO：用其余 G − 1 个的均值 |

难度偏差的数值（G = 8，std 用 n − 1）：1/8 成功时均值 0.125、std ≈ 0.354，成功那条 A = 0.875/0.354 ≈ 2.47；4/8 时 std ≈ 0.535，A ≈ ±0.93。

### 3.2 多轮 Agent 场景下 GRPO 的特殊之处

- **一个“回答”是整个会话**：几十轮命令与输出拼成一条序列，`loss_mask` 只在模型自己说的 Token 上为 1；Reward 只在最后给一次，**所有模型 Token 拿到同一个 A**，轨迹内“改错文件”那一步区分不出来。
- **Token 等权 vs 轨迹等权**：按 Token 平均时，一条 20k Token 的空转失败轨迹对梯度的影响是一条 2k Token 成功轨迹的 10 倍；改成轨迹等权则每条轨迹权重相同。
- **“组”在 infra 上是一个约束**：同题 G 个会话必须全部跑完才能算这一组的 Advantage，一个卡住整组等（[PPO 有没有组内长尾](PPO的Critic与Clip在单次更新下的退化_20261013.md#36-ppo-有没有组内长尾)）。
- **为什么单轮短任务上批级归一化无害、多轮任务上可能有害**：单轮短回答组内长度相近，Token 加权均值约等于 0；多轮任务成功与失败轨迹的 Token 数可差一个数量级，常数平移变得显著。

### 3.3 两个不同的“按 Token”（被纠正的误解）

提问时把“验证批级归一化”理解成“验证按 Token 归一化会不会导致 Reward 归 0”。方向接近，但有两个不同的“按 Token”：

| | ① 批级 Advantage 归一化 | ② Loss 的 Token 等权聚合 |
|---|---|---|
| 在流水线哪一步 | 算 Advantage：改 A 的**值** | 算 Loss：决定每条轨迹在梯度里的**权重** |
| “按 Token”体现在哪 | 均值 m 和标准差 s 按 Token 数加权统计 | Loss 对所有 Token 取平均，长轨迹 Token 多所以权重大 |
| 结果 | 所有 A 平移一个常数，并按信号多少缩放 | A 不变，但长轨迹主导梯度方向 |

两者根源相同：长轨迹在按 Token 统计时分量更大。更准确的表述是：**那个单变量实验验证的是“按 Token 统计的批级归一化”是否导致崩溃**；Reward 归 0 是崩溃的终态，不是直接测量对象；② 需要另外单独测。

### 3.4 从 Reward 到最终 Advantage 的五步

| # | 操作 | 形状 |
|---|---|---|
| 1 | Reward 预处理：`(r + bias) × scaling`，再截断到一个范围；可选的超长惩罚也在这里 | `[bs]`，每条轨迹一个数 |
| 2 | **Reward 归一化（组内）**：按连续 G 条切组，组内减均值、除 std；std 为 0 时结果为 0 | `[bs]` |
| 3 | **展开到 Token**：每个 Token 先填 KL 小 Reward，再把第 2 步的分数加到最后一个 Token 上 | `[bs, seqlen]` |
| 4 | **GAE**（V = 0，γ = λ = 1）：从后往前累加，跳过环境输出的 Token；结果约等于“第 2 步分数 + 后续 KL 之和” | `[bs, seqlen]` |
| 5 | **Advantage 归一化（批级）** | `[bs, seqlen]` |

前两步一条轨迹一个数；第 3 步之后同一条轨迹的值被复制到它的每个模型 Token 上。到第 5 步时，20k Token 的轨迹在张量里占 20k 个位置，2k Token 的只占 2k 个。

### 3.5 批级归一化内部的操作

整个 batch 最终只算出两个标量 m 和 s：

```text
输入：A [bs, seqlen]，loss_mask [bs, seqlen]（1 = 模型 Token）

a  转成 float64
b  求均值：sum(A·mask) 与 count = sum(mask)，跨数据并行 Rank 汇总
          → m = sum / count                       ← count 数的是 Token
c  去中心：A_c = (A − m) · mask                   ← 非模型 Token 置 0
d  求方差：sum(mask·(A − m)²)，跨 Rank 汇总
          → s = sqrt(平方和 / (count − 1))         ← 同样按 Token 计数
e  缩放：  A' = A_c / (s + eps)
f  转回 float32
```

“按 Token”就体现在 b 和 d 的 count 上：每个 Token 一票，哪条轨迹 Token 多，它对 m 和 s 的影响就大。

### 3.6 手算：不归一化 vs 按 Token vs 按轨迹

两组，每组 4 条（G = 4），长度以 k Token 为单位：

- 组 1（有信号）：Reward `[1, 1, 0, 0]`，长度 `[2, 2, 6, 6]`；组内归一化（std 用 n − 1 ≈ 0.577）后 A = ±0.866；
- 组 2（全错）：Reward `[0, 0, 0, 0]`，长度 `[6, 6, 6, 6]`；A = 0。

| | 组 1 成功 | 组 1 失败 | 组 2（零方差） | m | s |
|---|---|---|---|---|---|
| 不做批级归一化 | +0.87 | −0.87 | **0** | — | — |
| **按 Token 统计** | **+2.00** | −1.33 | **+0.33** | −0.17 | 0.52 |
| 按轨迹统计 | +1.41 | −1.41 | **0** | 0 | 0.61 |

- 按 Token：40k 个 Token 中失败 12k、成功只有 4k，m 被拉到负数；减 m 后成功被放大到 +2.0，失败缩小到 −1.33，零方差组从 0 变成 +0.33；
- 按轨迹：组内归一化已保证每组按条数正负相抵，**m 恰为 0，没有平移**，只剩统一缩放；零方差组保持 0。（表中 s 按 n 计；若用 n − 1，s ≈ 0.65，缩放约 ×1.32，结论不变。）

由此，批级归一化的两个操作是两种不同的效应：

- **平移**（来自 m）：完全由按 Token 计数造成，按轨迹统计时不存在；
- **缩放**（来自 s）：两种口径都有；有信号的轨迹越少，s 越小，放大越多（[1/√p 放大](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#5-批级归一化第二件事除标准差--按信号稀缺程度放大步长)）。

### 3.7 两处归一化与统一的配置结构

Advantage 归一化**不是 GRPO 专有**，最早为 PPO + Critic 设计（Critic 给出的 Advantage 尺度会漂）；它也**不是“算每组 Advantage”那一步**，组内比较在 Reward 归一化完成。两处常用同一个配置结构，字段完全一样，所以容易混：

```text
reward [bs] → ① Reward 归一化 → 展开到 Token + KL + GAE → ② Advantage 归一化 → Loss
（每轨迹一个数）  （仍每轨迹一个数）                          （每 Token 一个数）
```

| | ① Reward 归一化 | ② Advantage 归一化 |
|---|---|---|
| 作用对象 | 原始 Reward，`[bs]` | 最终 Advantage，`[bs, seqlen]` |
| 位置 | GAE 之前 | GAE 之后、Loss 之前 |
| 计数单位 | **一条轨迹一票** | **一个 Token 一票** |
| 在 GRPO 里的角色 | **核心**：组内比较在这里 | 可选后处理，原版 GRPO 没有 |

两处做的是同一个运算 `输出 = (x − M) / (S + eps)`：

| 字段 | 可选值 | 含义 |
|---|---|---|
| 均值层级 `mean_level` | batch / group / 无 | 减去什么：全批均值、本组均值、不减（M = 0） |
| 标准差层级 `std_level` | batch / group / 无 | 除以什么：全批 std、本组 std、不除（S = 1） |
| 组大小 | 整数，一般等于每题采样数 | **按 batch 中连续的 G 条切组**，同题样本必须相邻 |
| 留一均值 | 是 / 否 | 组均值排除自己（RLOO） |
| 无偏 std | 是 / 否 | 分母用 n − 1 还是 n；G = 8 时相差约 7% |
| eps | 小浮点数 | 防除零；零方差组的 `x − M` 本身为 0，结果仍为 0 |

两个细节：

- std 围绕所选的 M 计算；不减均值时，它实际是围绕 0 的**均方根**，作用仍是统一缩放；
- **易踩的坑**：没写出来的字段取默认值（常见默认是 batch）。只写“均值层级 = group”时标准差层级会变成 batch，算法就从 GRPO 变成了 LitePPO。改归一化配置时，**两个层级都要显式写出**；整个字段写成“无”表示跳过这一步。

### 3.8 常见算法 = 两处归一化的组合

| 算法 | Reward 归一化（均值 / std） | Advantage 归一化 | 一句话 |
|---|---|---|---|
| 原版 GRPO | group / group | 无 | 组内减均值、除 std |
| 一些框架的默认 GRPO 模板 | group / group | **batch / batch** | 多一层按 Token 的批级归一化 |
| Dr.GRPO | group / **无** | 无 | 不除 std，去难度偏差 |
| RLOO | group（留一）/ 无 | 无 | 用其余 G − 1 条的均值作基线 |
| LitePPO | group / **batch** | 无 | 组内减均值，除以全批按轨迹统计的 std |
| PPO（有 Critic） | 通常无 | batch / batch | 不分组；Advantage 来自 Critic + GAE，再批级归一化稳定尺度 |

其他影响 Advantage 的参数，按流水线顺序：

| 参数 | 作用 |
|---|---|
| Reward 偏置 / 缩放 / 截断 | 归一化前对 Reward 做仿射变换和截断；0/1 Reward 下基本不起作用 |
| 超长惩罚 | DAPO 做法：接近长度上限的回答扣分 |
| 未输出 EOS 记 0 | 被截断的轨迹 Reward 强制为 0 |
| KL 系数 / 估计器 | KL 惩罚的强度与估计方式 |
| γ / λ | 无 Critic 时保持 1，即把最终 Reward 广播给每个 Token |
| Advantage 直接给定 | Advantage 由 Rollout 侧算好传入，**跳过上面全部步骤，包括两处归一化** |
| Loss 加权方式 | 不改 A 的值，只决定 Token 等权还是轨迹等权 |

最后一行与倒数第二行解释了 [打包实验隐含单变量](训练崩溃归因的工作流与实验解读_20261012.md#35-解读时要提前想好的四个陷阱)：Rollout 侧直接给定 Advantage 的那组，天然也没有批级归一化。

### 3.9 怎样只用配置把“平移”和“缩放”拆开

批级归一化本身的统计永远按 Token 计数，但有三种做法：

1. **只保留缩放，去掉平移（按 Token 的均方根）**：Advantage 归一化设为“均值无 / std batch”；
2. **按轨迹做全局缩放**：Reward 归一化设为“均值 group / std batch”，Advantage 归一化关掉。Reward 归一化作用在 `[bs]` 上，所以这里的 batch std **天然按轨迹统计**；效果相当于 §3.6 最后一行，无平移、零方差组保持 0，还顺带去掉了“每组除自己 std”的难度偏差（即 LitePPO）；
3. **改代码在第 5 步按轨迹统计**（例如每条轨迹只取一个 Token 参与 m 和 s），可保留 KL 那部分按 Token 变化的结构；做法 2 通常已足够。

对应的拆分实验：

| 实验 | 平移 | 缩放 |
|---|---|---|
| 关掉批级归一化 | 无 | 无 |
| 做法 1 | 无 | 有（按 Token） |
| 做法 2 | 无 | 有（按轨迹） |

- 做法 1、2 都稳定：问题出在**平移**（按 Token 统计 m），与 [常数平移 + 截断采样](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#44-截断采样让它不再无害假说) 的推测吻合；
- 做法 1、2 也崩：信号变少时的**缩放放大**本身就足以导致崩溃。

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 改了“均值层级”后算法行为整体变了 | 另一个层级取了默认值 | 打印生效配置，两个层级都显式写出 |
| 组内归一化结果错乱 | 同题样本在 batch 中不相邻，按连续 G 条切组切错 | 检查 batch 内样本顺序与题目 ID |
| 单轮短任务上批级归一化无害，多轮任务上可疑 | 多轮任务成功/失败轨迹长度差一个量级，Token 加权均值显著偏离 0 | 记录归一化前的 m |
| 换了 Advantage 计算路径后批级归一化相关现象消失 | 直接给定 Advantage 跳过了两处归一化 | 核对 Advantage 是否经过训练侧归一化 |
| 难题偶然一次成功后该轨迹更新很猛 | 除组 std 的难度偏差 | 比较组内成功数与 A 的大小 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| GRPO 是与 PPO 完全不同的算法 | 是 PPO 去掉 Critic，用组均值当基线 |
| “按 Token 归一化”是批级归一化里的一步 | 是均值与标准差的计数口径 |
| 批级归一化的“按 Token”和 Loss 的 Token 等权是一回事 | 前者改 A 的值，后者改轨迹权重；要分开测 |
| 验证批级归一化 = 验证会不会导致 Reward 归 0 | 验证的是它是否导致崩溃；归 0 是终态 |
| Advantage 归一化是 GRPO 专有、就是组内比较 | 它是 PPO 系列通用后处理；组内比较在 Reward 归一化 |
| 只写一个层级，另一个保持原状 | 未写字段取默认值，可能悄悄换了算法 |
| 批级归一化按轨迹统计也会平移 | 组内归一化后按条数正负相抵，m 恰为 0，只剩缩放 |
| 除以组 std 只是改尺度 | 会放大极难/极易题（难度偏差） |

## 7. 一分钟复习

1. GRPO = PPO − Critic，预期得分 = 同题 G 次的平均；换来 G 倍采样和轨迹级粒度。
2. 变体只差三处：怎么归一化、怎么聚合、怎么 Clip；Dr.GRPO 去 `1/|o|` 与 std，DAPO 动态采样 + clip-higher + 超长惩罚，GSPO 序列级 ratio，RLOO 留一。
3. 两处归一化：Reward（`[bs]`，轨迹一票，GRPO 核心）、Advantage（`[bs, seqlen]`，Token 一票，可选）。
4. 统一运算 `(x − M)/(S + eps)`；两个层级都要显式写。
5. 平移只来自按 Token 计数；按轨迹统计 m = 0、只剩缩放。
6. 拆平移与缩放：只留 std（按 Token）、Reward 层除全批 std（按轨迹）。

## 8. 自测问题

### 问题 1

为什么原版 GRPO 的 `1/|o_i|` 会鼓励“错的时候写长一点”？

期望回答：每条回答内部先按长度平均，长回答里每个 Token 分到的负 Advantage 被摊薄；同样是错，写得越长每个 Token 受罚越少。

### 问题 2

用 §3.6 的例子说明：为什么按 Token 统计会让零方差组变非 0，而按轨迹统计不会？

期望回答：按 Token 时失败 Token 远多于成功 Token，m < 0，减 m 后零方差组的 0 变成 −m/s > 0；按轨迹时每组按条数正负相抵，m = 0，零方差组仍为 0。

### 问题 3

Reward 归一化设“均值 group / std batch”，为什么这个 batch std 是按轨迹统计的？

期望回答：Reward 归一化作用在 `[bs]` 向量上，一条轨迹只有一个数，每条轨迹一票。

### 问题 4

只把 Reward 归一化的均值层级改成 group，可能发生什么？

期望回答：未写出的标准差层级取默认值（常为 batch），算法从 GRPO 变成 LitePPO；必须两个层级都显式写。

## 9. 尚未解决与后续路线

- 平移与缩放拆分实验的结果；
- Loss 的 Token 等权 vs 轨迹等权尚未单独测试；
- DAPO 动态采样与零方差组丢弃对组内长尾的影响；
- GSPO 序列级 ratio 在多次更新设置下的效果，以及 MoE 下 Token 级 ratio 噪声的来源。
