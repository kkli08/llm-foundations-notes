>
> 来源：Claude Code 会话 `5c527551`（同内容另见会话 `dfaebc2d`）

### 今天的问题

- 异步训练是不是就应该每批只更新一次（minibatch 个数 = 1），不然怎么和 off-policy 对齐？
- “解耦 PPO”是某个框架提出的，还是早就有的概念？
- minibatch 个数 > 1 时权重同步还是只做一次，版本号的粒度应该不变吧？
- 最大离策略版本差的底层到底怎么对应更新次数？minibatch 个数不同，它会拒掉不同的样本吗？
- 所以 minibatch 个数 > 1 只影响一个训练步里 optimizer 更新的次数？
- 有人说更新次数多了会影响 off-policy 效果，对吗？

### 对话或资料摘录

- 不要求每批只更新一次：异步陈旧由 π_prox/π_behave（IS/RS）处理，同批多次更新的漂移由 π_θ/π_prox 的 clip 处理；两段相乘正好是 π_θ/π_behave；
- 解耦 PPO 出自 Hilton、Cobbe、Schulman 的 *Batch size-invariance for policy optimization*（2021 预印本，NeurIPS 2022）：把旧策略的“IS 修正”和“clip 中心”两个角色拆开；原文用权重滑动平均做 π_prox，异步 LLM RL 框架改为直接用更新前参数重算；
- 被用户纠正：版本号只在每个训练步的权重同步时 +1，与 minibatch 个数无关；同样的 N 在不同 minibatch 个数下准入规则完全一样；“落后 1 个版本的参数差距约变成 k 倍，要收紧 N”只是未验证的推测，且已由按 logprob 计算的 IS/RS 处理，收紧 N 的建议撤回；
- minibatch 个数 > 1 改变：PPO 比值与 clip 生效、每次 step 的梯度噪声、梯度裁剪次数；不变：版本号、同步频率、准入规则、rollout、advantage（整批一次）、π_prox（重算一次）、学习率调度（按训练步）；
- 版本号唯一直接进 loss 的地方是按版本插值近似 π_prox；
- “更新次数多影响 off-policy”有道理但可权衡、可测量：用每批只更新一次 vs 多次的同算法对照来回答，看行为侧近似 KL、过滤比例、各 minibatch 的近似 KL 与 clip 比例。

> 来源：Claude Code 会话 `dfaebc2d`

### 今天的问题

- 从 rollout 开始简洁地捋一遍 PPO；
- “critic 算价值”具体是怎么算的？
- 拿数据去拟合 critic 是怎么做的、为什么要拟合？
- GAE 就是逐 token 计算相对优势的流程吧？
- γ 和 λ 一直不清楚是什么意思、有什么用；
- 拟合是不是就是 R 和 V 做 MSE、更新 value head 的参数？

### 对话或资料摘录

- critic = 同主干 + `hidden → 1` 的价值头；把整行原样做一次不求梯度的前向，每个位置一个 V；
- 4 个 token 的手算例子：A = R − V，G = A + V；
- 拟合 = 对 G 做 MSE 回归，带 value clip；同一前缀的 8 条回答目标是 0/1，MSE 最小点是均值 = 通过率 = GRPO 组均值；
- 被纠正：目标是 G 不一定是 R（λ < 1 时含自己的估计，即 TD）；更新的是整个 critic，不只是价值头；
- γ：未来奖励每步打几折，γ < 1 在只有末端奖励时等于惩罚长回答；λ：信结果还是信 critic，λ = 1 无偏高方差，λ = 0 低方差但全靠 V；critic 刚初始化时先用 λ = 1。
