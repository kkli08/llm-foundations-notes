## 1. 先给结论

- **价值头初始化有两条路**：有奖励模型时整个 critic 从奖励模型初始化；RLVR（规则 0/1 奖励）没有奖励模型，只能用 actor 权重 + 新的 `Linear(hidden, 1)`。新头的初始化各家不统一：N(0, 0.02)、PyTorch 默认、N(0, 1/(d+1))、全零都有先例。
- **常规初始化下初始 V 可能远超奖励范围**：V = w·h，std(V) ≈ σ_w·‖h‖；最后一层隐状态模长上百时，σ_w = 0.02 就能给出十几的 V，而奖励只有 0/1——头几步 actor 拿到的优势大半是 critic 的噪声。
- **初始化不是关键，critic 预热才是**：长思维链 RLVR 的论文普遍先单独训 critic 50～100 步，去掉后效果大幅下降。
- **两种“预热”要分开**：学习率预热（学习率从 0 升到目标值，多数框架默认 0 或很短）与 critic 预热（冻结 actor、只训 critic N 步，框架有开关但默认关）。
- **零初始化 = 软预热**：V = 0 时 A = R，经批级白化相当于“减整批平均奖励”的 REINFORCE，信号合理；随机初始化时 actor 从第 1 步就被噪声推着走。
- **critic 预热期间仍要做权重同步**：生产侧容量按版本号发放，版本停住 rollout 就停，训练随之卡死。
- **DDP 包装时按“当时存在的参数”登记四件事**：梯度缓冲、DP 梯度同步、分布式优化器切分、参数广播。被纠正：不在缓冲里的参数不只是“不好拿”，而是**根本不会被训练**；缓冲在显存里，不是 cache。
- **EV 没有统一阈值**：0/1 奖励下回答开头的 EV 上限 ≈ 各题通过率之间的方差 ÷ 奖励总方差，远小于 1；判据是 EV 稳定 > 0 且走平、critic loss 走平、V 均值与回报均值对上。
- **PP 下的坑是共享词嵌入**：小模型的输入词嵌入与输出头共用一个矩阵，PP > 1 时最后一个 stage 存一份副本、每步与第一个 stage 求和梯度；critic 把副本换成 [1, hidden] 的价值头，共享标志不关就形状不匹配。

## 2. 前置概念

### 2.1 价值头的几种初始化

| 做法 | 适用 | 初始 V |
|---|---|---|
| 整个 critic 从奖励模型初始化 | 有奖励模型的 RLHF（InstructGPT 一系） | 一开始就会打分 |
| actor 权重 + 新头，N(0, 0.02)（HF 默认 `initializer_range`） | RLVR，常见默认 | 偏大 |
| actor 权重 + 新头，PyTorch 默认 `Linear` 初始化（U(±1/√d)，std = 1/√(3d)） | 同上 | 偏大，和 0.02 同量级 |
| actor 权重 + 新头，N(0, 1/(d+1)) | 同上（例如 OpenRLHF 在 critic 与 actor 同权重时） | 接近 0 |
| 新头全零 | OpenAI 早期 RLHF 代码 | 正好 0 |

为什么偏大：w 的各分量独立、方差 σ_w² 时，V = w·h 的标准差是 σ_w·‖h‖。d = 4096 时 1/√(3d) ≈ 0.009、1/(d+1) ≈ 2.4e-4——后者小两个数量级，V 一开始基本是 0。

### 2.2 EV 与辅助指标

$$
\text{EV} = 1 - \frac{\mathrm{Var}(G - V)}{\mathrm{Var}(G)}
$$

在有效 token 上计算。直观上是拿“critic 的预测误差”和“永远猜平均值的误差”比：EV = 1 完全准；EV = 0 和猜平均值一样（critic 至少要做到这一步才有用）；EV < 0 比猜平均值还差，等于往优势里加噪声。**趋势比绝对值重要**：应从 0 以下往上走，并稳定在 0 以上。

| 指标 | 含义 | 正常的样子 |
|---|---|---|
| critic loss | ½(V − G)² 的平均（带 value clip） | 逐步下降；目标 G 随策略变化，绝对值不能跨实验比 |
| 预测 V 与目标 G 的范围（均值/最小/最大） | 两者是否在同一尺度 | 逐渐重合；奖励在 0～1 时 V 也该收到这附近 |
| value clip 比例 | V 单次更新超过 ±c 被截的比例 | 接近 0；长期偏高说明 critic 变化太猛 |
| critic 梯度范数 | — | 平稳，尖峰说明不稳 |
| actor 的 reward 曲线 | 和同配置 GRPO 基线比 | critic 再准，最终也是为了 actor |

一个更直观、但需要额外记录的诊断：回答第一个 token 上的 V，应接近这道题多次采样的平均得分（[MSE 最小点 = 通过率](PPO的Critic价值估计GAE参数与工程适配_20261020.md#34-为什么-v-会学成做对的概率)）。

## 3. 完整原理

### 3.1 价值头怎么初始化（问题 1）

- **加载方式和主流一致**：critic 从 actor 的 HF 权重加载，词表头（lm_head）因为形状 [词表, hidden] 与价值头 [1, hidden] 不符被跳过，价值头保持新初始化；若 checkpoint 里本来就是 1 行的头（之前导出的 critic），就正常加载。FSDP 系的实现常用“num_labels = 1 的 token 分类模型”，lm_head 成为用不上的权重，效果相同。
- **RLVR 只能走“actor 权重 + 新头”**：没有奖励模型；新头怎么初始化没有公认最好的做法，有实验报告“SFT 模型 + 随机头”与“从奖励模型初始化”最终收敛得差不多。
- **建议**：把头的初始化改成接近 0（零初始化或 std = 1/(d+1)），改一行即可；但主要手段是配合 critic 预热（§3.3）。

**零初始化会不会卡住学习**（整理时补充的推论）：价值头 w = 0 时，对 w 的梯度是 (V − G)·h，不为 0，头第一步就会动；对主干隐状态的梯度是 (V − G)·w = 0，所以主干在第一次更新时拿不到 critic loss 的梯度，等 w 离开 0 之后才开始。这和 LoRA 把 B 置零是同一个道理：一侧为零，另一侧仍有梯度，不会对称地卡死。

### 3.2 DDP 包装时登记了什么（问题 2、6）

为什么必须在包装之前换头（[10 月 20 日 §3.7](PPO的Critic价值估计GAE参数与工程适配_20261020.md#37-给-rl-框架加-critic算法几乎现成工程闭环要补) 已给出结论），展开是：分布式训练框架的 DDP 在包装那一刻把“当时存在的参数”登记下来，做四件事——

1. **梯度缓冲**：所有可训练参数的梯度放进一块连续显存，每个参数的主梯度（如 `main_grad`）指向其中一段；
2. **DP 梯度同步**：反向结束后对整块缓冲做一次 all-reduce 或 reduce-scatter；
3. **分布式优化器切分**：按这块缓冲切片，每张卡只负责更新自己那一片参数和优化器状态；
4. **参数广播**：包装时从 rank 0 广播参数，保证各副本起点一致。

**用户的理解与校正**（问题 6）：“提前换头就是为了让 value head 的参数在缓冲里也占个位置，别处需要梯度时好拿”——核心对，两点更准确：

| 用户的说法 | 更准确的说法 |
|---|---|
| 放在 GPU cache 里 | 在**显存**里；包装时按当时有哪些参数一次性分配，之后不会扩容 |
| 别处需要时“好拿” | 不在缓冲里，梯度不同步、优化器不认识它（读不到主梯度直接报错）——不是“不好拿”，而是**根本不会被训练** |

开源实现的做法一致：在模型创建的回调里换头（发生在包装之前），或建模型时直接建价值头。多模态模型的语言解码器挂在外壳的子属性下时，要先解包再换。

### 3.3 两种预热：学习率预热与 critic 预热

**学习率预热**（问题 4）：基本没有，或很短。

| 来源（转述） | 学习率预热 |
|---|---|
| verl 默认、TRL | 0 |
| InstructGPT、NeMo 系 | 约 10 步 |
| OpenRLHF | 总步数的 3%，配合 cosine 衰减 |
| DeepSpeed-Chat | 约 100 步 |

按比例给的预热要注意基数：比例乘的是调度器认为的总步数，可能远大于实际要跑的步数（[同日 GSPO 笔记 §3.5](GSPO对照实验的Clip比例读法与学习率预热口径_20261021.md#35-学习率预热按调度器以为的总步数算)），那次实验在第 20 步学习率只有目标值的 3%，critic 能否学好根本无从判断。

**critic 预热**（问题 5）：冻结 actor、只训 critic N 步。框架普遍有开关但默认 0（例如 verl 的 critic warmup 默认 0、示例配方设 20）；做长思维链 + 规则奖励的论文把它当关键步骤：VC-PPO 比较了 50/100/150 步、取 100，VAPO 用 50 步、报告去掉后效果大幅下降。这两篇还把 critic 与 actor 的 λ 分开（critic 用 1.0，actor 用 0.95 或随长度自适应）。

**“前几十步能不能直接当预热”**——取决于价值头的初始化：

| 初始化 | 不加专门预热会怎样 |
|---|---|
| 随机，初始 V 远超奖励范围 | 不行：A = R − V 基本是噪声，actor 从第 1 步就被噪声推着走；critic 在学，actor 也在被带偏（VC-PPO 认为这是长思维链下 PPO 崩溃的原因之一） |
| 零初始化 | 基本可以：V = 0 时 A = R，经批级白化相当于减整批平均奖励的 REINFORCE（思路接近 [GRPO 减组内平均](GRPO流程与批级Advantage归一化的偏移机制_20261012.md#22-grpo-就是配置出来的-ppo)）；actor 拿到合理信号，critic 同时在学，前几十步成了“软预热”；代价是 critic 学好之前优势方差较大 |

**加一个 critic 预热开关**（用户确认要加、与开源框架对齐、作为可选项）：

- 默认 0，现有行为完全不变；
- 前 N 步跳过 actor 更新和 actor 的学习率步进，其余照常：rollout → critic 算 V → GAE → critic 更新；
- **权重同步不能跳**：actor 权重虽然没变，但生产侧容量按版本号发放（`(版本差上限 + 当前版本 + 1) × batch`，[容量公式](权重同步版本语义与Staleness窗口_20261008.md)），版本号停住，rollout 就不再接新样本，训练随之卡死；开源框架在预热期也照常刷新推理权重；
- **好处**：actor 开始更新时 critic 已能给出有意义的 V；预热期 actor 版本不变，rollout 数据全是 on-policy，critic 的拟合目标稳定，反而更容易学；
- **代价**：这 N 步只花时间不提升策略；rollout 很慢的任务里 N 要调小，或先解决生成慢的问题。

### 3.4 param_offload：时间换显存（问题 3）

- 是可选参数，默认关，通常由两个开关配合：“闲置时要不要卸载”与“怎么卸载”（把参数拷到 CPU、释放梯度缓冲）；另有把优化器状态放到 CPU 的选项。只开前者、而后者指向一条已被关闭的实现路径时会直接报错（[初始化成功 ≠ 第一步能跑完](PPO的Critic价值估计GAE参数与工程适配_20261020.md#37-给-rl-框架加-critic算法几乎现成工程闭环要补)）。
- 目的不完全是提高利用率，而是**让 actor、critic、ref 挤在同一批卡上**，谁闲着谁让出显存；不开就要给 critic 单独分卡，或显存足够大让它常驻。
- **会影响速度**：多出加载/卸载的拷贝时间，大致与模型大小成正比；小模型上约占单步的几个百分点。显存宽裕的小模型可以让 critic 常驻省下这几秒；大模型长上下文显存紧张时应保留。

### 3.5 EV 到多少算预热够了：没有统一阈值

**1. 业界按固定步数预热，不设 EV 阈值**：论文与框架的预热开关都是填步数，没有“EV 到多少算完”的标准。

**2. 0/1 奖励下 EV 本来就到不了 1**：在回答开头，critic 最多只能知道“这道题难不难”，即这道题的通过率 p_i；它解释不了同一道题这次对、下次错的随机性。由全方差分解：

$$
\mathrm{Var}(R) = \underbrace{\mathrm{Var}_i(p_i)}_{\text{题与题之间}} + \underbrace{\mathbb{E}_i[p_i(1-p_i)]}_{\text{同题内的随机性}},\qquad
\text{EV}_\text{开头} \le \frac{\mathrm{Var}_i(p_i)}{\mathrm{Var}(R)}
$$

例（数字是假设的）：平均通过率 10%，答对的集中在四分之一的题上，这些题通过率 40%，其余全错——

- 题间方差 = 0.25 × 0.4² − 0.1² = 0.03；
- 总方差 = 0.1 × 0.9 = 0.09（= 0.03 + 0.25 × 0.4 × 0.6）；
- 开头的 EV 上限 ≈ 0.33。

越往回答后面，前缀透露的信息越多（比如已经写出了答案），整体 EV 会高一些，但也远不到 1。上限取决于题目难度分布，数据集之间差别很大，所以固定阈值不靠谱。

**3. 实际判据：三个信号同时满足**

- EV 稳定大于 0 且不再上升（例如最近 10 步滑动平均走平）；预热结束时还在明显上升就加长预热；
- critic loss 不再下降；
- V 的均值与回报的均值对上，说明 critic 至少学会了整体基准线。

**套到当天的小规模验证**：大模型 6 步里 EV 从 0 升到约 0.2 且还在涨，说明 2 步预热远不够；小模型 batch 只有几十条、通过率又低，EV 在 0 附近，这个规模判断不了。建议正式实验先按论文量级设 50 步左右，同时看 EV 曲线：20～30 步就平了下次缩短，50 步还在涨就加长。更直观的参照是按 prompt 分组、每步算出上式的“EV 上限”，看 critic 达到上限的百分之多少。

### 3.6 PP 下的共享词嵌入：为什么第一个 stage 也要对上形状

**PP 支持难不难**（问题 7）：大部分不难——换头的回调跳过不是最后一个的 stage（判断有没有输出层），换头校验也只查最后一个 stage，各几行；坑在共享词嵌入，以及 critic 在 PP 下的前向与 loss 路径从没跑过、需要一次 PP=2 的 GPU 验证兜底。

**什么叫共享词嵌入**（问题 8 的 b）：语言模型两头各有一个大矩阵——

- 输入端的词嵌入 E：token id → 向量，相当于按 id 查表的一行；
- 输出端的 lm_head：最后的向量 → 每个词的分数。

两者形状都是 [词表, hidden]。小模型为了省参数让两头用同一个矩阵（tie word embeddings），这一个矩阵可能占全部参数的四分之一左右；大一些的型号通常不共享。

**为什么第一个 stage 也牵涉进来**（问题 8 的 a）：

| | PP = 1 | PP = 2 |
|---|---|---|
| E 在哪 | 两端在同一张卡上，用的就是同一个 E | stage 1 用 E 做输入；stage 2 读不到 stage 1 的 E，于是**也存一份 E 的副本**做输出 |
| 一致性怎么保 | 不需要 | 每步把首、尾两份 E 的梯度求和（all-reduce），让两份始终相同；求和时尾端取的是“输出层权重” |
| critic 换头后 | 价值头和 E 无关，没问题 | 尾端的“输出层权重”已是 [1, hidden] 的价值头，首端是 [词表, hidden]，共享标志还开着时会去求和 → 形状不匹配，报错或卡死 |

critic 本来就不需要共享，修法是**建 critic 时关掉共享标志**：梯度求和这一步直接跳过；存 checkpoint 时也不会再拿 E 的副本去顶替价值头。注意关掉共享会改变权重映射（输出层原本映射到词嵌入，关掉后去找独立的 lm_head，而共享权重的 checkpoint 里可能没有），需要实测；外层包装把共享标志做成只读属性时，要在内层语言模型上改。这和 [MTP 在 PP 下需要 Embedding 副本](PP_CP_SP的切分对象与通信代价_20261009.md#32-mtp-在-pp-下怎样工作) 是同一套机制。

**各并行维度下价值头怎么处理**：

| 切分 | 价值头的处理 |
|---|---|
| TP | 输出只有 1 维，切不了，每张卡一份完整副本；固定种子初始化保证一致（零初始化天然一致） |
| SP | 每张卡算一段序列；价值头标记为序列并行参数，梯度在 TP 组内求和；输出的 V 再拼回整条序列（[复制参数的梯度](PP_CP_SP的切分对象与通信代价_20261009.md#38-sp-补充传的是激活值不是参数)） |
| CP | 各卡算自己那段的 V 再拼起来，梯度由 DDP 在 DP×CP 组内同步，无特殊处理 |
| PP | 价值头只在最后一个 stage；共享词嵌入的模型要关掉共享 |
| EP（MoE） | 价值头是普通稠密层，不进专家的缓冲，原理上没问题（未测） |

**换型号要考虑什么**（问题 2 的最后一问）：代码只依赖几个前提——建模工具支持这个型号并在建模时调用回调；顺着包装属性能找到带输出层的语言模型；加载时按形状跳过 lm_head（通用逻辑，与型号无关）；critic 关掉 MTP。只是权重或层数变了不用改；外壳结构改名、MTP 变成必须开启、建模工具还不支持新型号时，构建期的校验应直接报错而不是悄悄训错。每上一个新型号先跑一次小规模验证。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 初始 V 是奖励范围的十几倍 | 新头用 N(0, 0.02) 等常规初始化，‖h‖ 上百 | 打印首步 V 的范围；改零初始化后首步 V = 0、EV = 0 |
| EV 长期为负，头几步 actor 不稳 | V 是噪声，A = R − V 被噪声主导 | 零初始化或 critic 预热后对比 |
| critic 预热一开训练就卡住不动 | 预热期跳过了权重同步，版本号停住，生产侧不再放行 | 查版本号是否随训练步推进 |
| 预热期 actor 该不动却动了 | 只跳过 optimizer step 没跳学习率步进，或反之 | 日志逐步打印是否跳过 actor 更新与学习率 |
| PP > 1 的 critic 在梯度同步时报形状错误或卡死 | 共享词嵌入标志开着，尾端价值头与首端词嵌入求和 | 建 critic 时关共享；查首尾 stage 的参数形状 |
| 预热 50 步但第 20 步学习率只有 3% | 按比例的学习率预热乘了一个很大的总步数 | 打印调度器的总步数与逐步学习率 |
| offload 后每步多出几秒 | 参数在 CPU 与 GPU 之间拷贝 | 显存宽裕时关掉 offload 对比 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 价值头随便随机初始化就行 | 常规初始化下初始 V 可能远超 0/1 奖励范围；改成接近 0，并配合 critic 预热 |
| 零初始化会让 critic 学不动 | 头的梯度 (V − G)h 不为 0；只有主干在第一步拿不到 critic 梯度 |
| “预热”就是学习率预热 | 还有 critic 预热：冻结 actor 只训 critic，两者独立 |
| critic 预热期 actor 没变，不用同步权重 | 容量按版本号发放，不同步会卡死生产侧 |
| 提前换头是为了梯度“好拿”，放在 cache 里 | 梯度缓冲在显存里；不在缓冲里的参数根本不会被同步和更新 |
| offload 是为了提高利用率、不影响速度 | 时间换显存，让多模型共卡；拷贝时间与模型大小成正比 |
| EV 要接近 1 才算 critic 学好 | 0/1 奖励下开头的上限 ≈ 题间方差 / 总方差；看是否稳定 > 0 且走平 |
| critic 权重都在最后一个 stage，和第一个 stage 无关 | 共享词嵌入时尾端存副本、每步与首端求和梯度 |

## 7. 一分钟复习

1. 价值头初始化：有 RM 从 RM 来；RLVR 用 actor + 新头；std(V) ≈ σ_w‖h‖ → 常规初始化 V 偏大；改成接近 0。
2. 零初始化：头有梯度 (V − G)h，主干第一步无梯度；V = 0 → A = R → 白化后 ≈ 减整批均值的 REINFORCE = 软预热。
3. 两种预热：学习率预热（默认 0～10 步，比例要看基数）≠ critic 预热（冻结 actor 训 critic 50～100 步，长 CoT 论文的关键步骤）。
4. critic 预热期跳过 actor 更新与学习率步进，但照常同步权重（容量按版本号）；数据全 on-policy，critic 目标稳定。
5. DDP 包装登记四件事：梯度缓冲、DP 同步、优化器切分、参数广播；不在缓冲里 = 不会被训练。
6. EV：= 0 和猜平均一样，< 0 加噪声；上限 ≈ Var(p_i)/Var(R)；判据：EV > 0 且走平 + loss 走平 + V 均值 ≈ 回报均值。
7. 共享词嵌入：输入 E 与 lm_head 同矩阵；PP > 1 时尾端存副本、每步求和梯度；critic 关掉共享。

## 8. 自测问题

### 问题 1

价值头权重按 N(0, 0.02²) 初始化，最后一层隐状态模长约 300。初始 V 的标准差大约是多少？对 0/1 奖励的 PPO 有什么后果？

期望回答：std(V) ≈ 0.02 × 300 = 6，V 的范围可达十几，远超 0/1 奖励；头几步 A = R − V 主要是 critic 的噪声，actor 被噪声推着走。应改成接近 0 的初始化并配合 critic 预热。

### 问题 2

价值头零初始化后，第一次 critic 更新时价值头和主干各自拿到什么梯度？为什么不会卡住？

期望回答：对头权重 w 的梯度是 (V − G)·h，不为 0，头会动；对主干隐状态的梯度是 (V − G)·w = 0，主干第一步拿不到 critic 梯度，等 w 离开 0 后才开始。一侧为零、另一侧仍有梯度，不会卡死。

### 问题 3

critic 预热期间 actor 权重不变，为什么仍要做权重同步？

期望回答：生产侧容量按版本号发放，约为 (版本差上限 + 当前版本 + 1) × batch 减去已接受与在途；版本号不推进，容量不再增长，rollout 不再接新样本，训练会卡死。

### 问题 4

“提前换 value head，是为了让它的梯度在缓冲里有个位置，别处要用时好拿”——这个说法哪里要修正？

期望回答：核心对。要修正两点：缓冲是包装时按当时参数一次性分配的连续显存，不是 cache、不会扩容；不在缓冲里的参数不会参加 DP 梯度同步、不被分布式优化器切分和更新、也不参加包装时的广播，所以不是“不好拿”，而是根本不会被训练。

### 问题 5

平均通过率 10%，四分之一的题通过率 40%、其余全错。回答开头的 EV 上限约是多少？由此说明什么？

期望回答：题间方差 = 0.25 × 0.16 − 0.01 = 0.03，总方差 = 0.1 × 0.9 = 0.09，上限 ≈ 0.33。说明 0/1 奖励下 EV 本来就远到不了 1，且上限随难度分布变化，不能用固定阈值判断预热结束，要看 EV 是否稳定 > 0 且走平、loss 走平、V 均值与回报均值对上。

### 问题 6

critic 的权重都在最后一个 PP stage，为什么 PP = 2 时小模型会在梯度同步时报形状错误？怎么修？

期望回答：小模型共享词嵌入，PP = 2 时最后一个 stage 也存一份 E 的副本做输出，每步与第一个 stage 的 E 求和梯度；critic 把尾端的输出层换成 [1, hidden] 的价值头，共享标志还开着，求和时一边 [1, hidden]、一边 [词表, hidden]。修法是建 critic 时关掉共享，跳过这步求和；并实测权重映射在关掉共享后是否仍能正确加载。

## 9. 尚未解决与后续路线

- 正式 critic 预热长跑的 EV 曲线：多少步走平，据此调整预热步数；
- 按 prompt 分组的“EV 上限”指标，用于看 critic 达到上限的比例；
- critic 与 actor 分开设 λ（critic 1.0、actor 0.95 或随长度自适应）的效果；
- 被截断的回答要不要用 V bootstrap：数学题被截断其实就是答题失败，可能应当作结束（待定）；
- PP 与 VPP、非标准建模路径下 critic 的支持；EP（MoE）下价值头的验证；
- 同配置下 PPO 与 GRPO/GSPO 的 reward 曲线对照。
