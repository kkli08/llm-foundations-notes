## 1. 先给结论

- **GRPO 与 PPO 只在“Advantage 从哪来”上不同**；拿到 Advantage 之后，更新策略用的是同一个带 Clip 的 surrogate loss。所以“两边 PPO 损失函数一样”说的是共用部分，两边跑的其实都是 GRPO。
- **GRPO 唯一的学习信号是“同一道题多次尝试之间的差别”**。一步里只有“组内归一化”在提取信号，其余各步都是管道：要么原样保留它，要么扭曲它。
- **批级 Advantage 归一化 = 减一个常数 + 乘一个缩放**：
  - 减均值：均值按 Token 加权，成功与失败轨迹长短不同时不为 0，于是**原本为 0 的零方差组也拿到了非 0 Advantage**；
  - 除标准差：有信号的 Token 越少，标准差越小，**剩下的信号被放大得越多**。
- **常数平移在 On-policy 下无害，截断采样下有害（假说）**：样本真从 π 采时，常数平移的期望梯度为 0；Top-p/Top-k 截断后不再为 0，会系统性地挪动头部与长尾的概率，可能同时解释熵上升和“一开口就 EOS”。

## 2. 前置概念

### 2.1 GRPO 一步的六段流水线

以多轮 Agent 任务为例，一个训练步：

| 段 | 做什么 | 产物 |
|---|---|---|
| 1 采样 | 推理引擎用当前（或稍旧）权重，对同一道题独立尝试 G 次；每次是一个多轮会话 | 每条轨迹的 Token、`loss_mask`（模型 Token 记 1，环境返回记 0）、采样时的 Logprob |
| 2 打分 | 跑测试，通过记 1、不通过记 0 | 每条轨迹一个标量 Reward |
| 3 组内归一化 | 同题 G 个 Reward 做 `(r − 组均值) / 组std`，结果复制到这条轨迹的每个模型 Token | 每 Token 的 Advantage |
| 4 批级归一化（可选） | 整批所有模型 Token 的 Advantage 再减均值、除标准差 | 改写后的 Advantage |
| 5 算 Loss | `ratio = π_θ / π_old`，Loss = `−min(ratio·A, clip(ratio)·A)` 的平均 | 标量 Loss |
| 6 更新 | 反向、梯度裁剪、优化器一步，权重同步回推理引擎 | 新权重版本 |

第 3 段的例子（G = 8，3 条通过）：

```text
reward:    [1, 1, 1, 0, 0, 0, 0, 0]      组均值 0.375，组std ≈ 0.48
advantage: [+1.29 ×3, −0.77 ×5]          每条轨迹内所有模型 Token 共用这个值
```

8 条全过或全不过时 std = 0，所有 Advantage 为 0，这道题这一步不产生任何学习信号——这是对的：组内没有对比，模型不知道该往哪边改。

第 4 段是从 PPO 继承的后处理：PPO 的 Critic 给出的 Advantage 尺度会漂，归一化能稳定尺度；在 GRPO 里第 3 段已经归一化过，这一步不是必需的。

### 2.2 “GRPO 就是配置出来的 PPO”

PPO 用 Critic 估计 V(s)，再用 GAE 算 Advantage：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t),\qquad
A_t = \sum_{k\ge 0} (\gamma\lambda)^k\,\delta_{t+k}
$$

令 **V ≡ 0（没有 Critic）、γ = λ = 1、Reward 只放在最后一个 Token**，就有 `δ_t = r_t`，`A_t = Σ_{k≥t} r_k = 最终 Reward`：每个 Token 的 Advantage 都等于整条轨迹的 Reward。再在 Reward 上做组内归一化，就得到 GRPO 的公式。

所以同一套代码既能跑 PPO 也能跑 GRPO，差别在配置。若还把 KL 惩罚加进逐 Token Reward，Advantage 就变成“组内归一化 Reward + 后续 Token 的 KL 惩罚之和”（[10 月 9 日 §3.3](AgentRL的Reward崩溃与归因实验_20261009.md#33-可疑诱因kl-进-reward--γλ1-的隐式长度惩罚假设)），本质仍是 GRPO，只是多了 KL 一项。

PPO 与 GRPO 的角色、Baseline 与成本对比已在 [On-policy 训推 §4](../08/OnPolicy训推与MTP性能分析_20260806.md#4-ppo-与-grpo-的最小完整骨架) 讲过，这里不重复。

### 2.3 同属 GRPO 的实现选择

| 选择 | 选项 A | 选项 B | 影响 |
|---|---|---|---|
| KL 放哪 | 进逐 Token Reward | 作为 Loss 项或不加 | 前者经 Return-to-go 累加，有长度效应 |
| 批级归一化 | 做 | 不做 | 见 §4～§5 |
| Loss 加权 | 每个 Token 等权 | 每条轨迹等权 | Token 等权时，长轨迹（常是空转到轮数上限的失败轨迹）主导梯度 |
| 零方差组 | 保留（Advantage = 0） | 整组丢弃 | 保留时若再做批级归一化，会被改成非 0 |
| Advantage 粒度 | 在训练侧按 Token 走 GAE | 在 Rollout 侧按轨迹算好直接传入 | 后者通常绕开训练侧的归一化逻辑 |

这些都是 GRPO 内部的选择，跟“用 PPO 还是 GRPO”无关。

## 3. Advantage 在梯度里到底做什么

只看某一个位置的 logits z，`loss_t = −A_t · log π(y_t)` 的梯度下降方向是：

$$
\Delta z \propto A_t\,(e_{y_t} - \pi)
$$

- `e_y`：被采到的 Token 处为 1，其余为 0；`π`：当前完整分布；
- A > 0：被采到的 Token 的 logit 上升，其余按各自概率等比例下降；A < 0 反过来；
- **A = 0：这个位置完全不动**。

所以 Advantage 的**符号决定方向，大小决定步长**；0 是有特殊意义的值，表示“这里没有信息，别动”。

## 4. 批级归一化第一件事：减均值 = 给所有 Token 加同一个常数

### 4.1 Token 加权均值为什么不是 0

组内归一化保证每组 Advantage **按条数**平均为 0；批级归一化却**按 Token** 平均（用 `loss_mask` 求和再除以有效 Token 数，并跨所有 Rank 汇总）。一条 10k Token 的轨迹对均值的影响是 1k Token 轨迹的 10 倍。

小例子：一组 2 条成功（A = +1，每条 3k Token）、2 条失败（A = −1，每条 9k Token）：

```text
m = (2×3k×1 − 2×9k×1) / 24k = −0.5
减 m 后：成功 +1.5，失败 −0.5，零方差组 0 → +0.5
```

批里零方差组占三四成时，相当于三分之一的样本被统一推高或压低。

### 4.2 m 的符号会随训练动态变化

假设一组 4 成 4 败、A ≈ ±1，零方差组约占 35% 的 Token：

| 场景 | 成功轨迹 | 失败轨迹 | 组内 Token 均值 | 稀释后的 m | 平移 c = −m/s |
|---|---|---|---|---|---|
| 早期：失败多是空转到轮数上限 | 8k | 12k | −0.2 | ≈ −0.13 | 正 |
| 开始塌缩：失败多是每轮只写几十 Token | 8k | ≈ 1k | +0.78 | ≈ +0.5 | 负且大 |

失败的形态从“长篇空转”变成“一开口就结束”时，m 会从负翻正。

### 4.3 On-policy 下常数平移无害

多出来的项是 `c·(e_y − π)`。若 y 真从 π 采：

$$
\mathbb{E}_{y\sim\pi}[\,e_y - \pi\,] = \pi - \pi = 0
$$

期望为 0，只增加方差、不产生系统偏移——这正是策略梯度里 Baseline 的原理。只有这一个因素时，批级归一化不应让训练崩。

### 4.4 截断采样让它不再无害（假说）

Top-k/Top-p 采样实际是从截断后重新归一化的分布 q 里采：头部 Token 的 q > π，长尾 q = 0。代入：

$$
\mathbb{E}_{y\sim q}[\,c\,(e_y - \pi)\,] = c\,(q - \pi) \neq 0
$$

- c > 0：头部 logit 上升、长尾下降，分布变尖，熵下降；
- **c < 0：头部被压低、长尾整体上升，熵上升**。

这个偏移在每一步、每个位置都累积。一条轨迹有几千个位置，每个位置都给长尾加一点点。

### 4.5 为什么可能塌缩成 EOS（假说）

回复中间位置，EOS 的概率通常很低，正好落在截断之外的长尾里。c < 0 时它在每个中间位置被系统性抬高，直到某一步挤进采样头部，回复就提前结束。于是形成正反馈：

```text
失败回复变短 → m 变正 → c 变负
→ 截断采样下长尾（含 EOS）被抬高 → 熵上升、回复更早结束
→ 失败更多、更短 → m 更正 → …
```

这与已有观察方向一致：熵先于 Reward 上升；回复以正常 stop 结束、塌到十几个 Token；没做批级归一化（c = 0）的配置稳定。**但它是从公式推出来的，还没有数据验证。**

### 4.6 截断采样单独会怎样

即使没有批级归一化，截断也让 [Sampling 分布与 Logprob 契约](../08/OnPolicy训推与MTP性能分析_20260806.md#26-sampling-分布与-logprob-契约) 不成立：

- **长尾永远采不到，也就永远不会被直接惩罚**：A < 0 时被采到的头部 Token 被压低，挪走的概率流向长尾，而长尾下一轮依然采不到、没机会被压回去；训练端按完整分布算的熵会上升；
- **重要性比率可能有系统偏差**：引擎若返回截断后的 Logprob，被采到的 Token 有 q ≥ π，训练端 `π_prox / π_behave` 系统性小于 1；若返回原始 Logprob，比率无偏，但采样分布本身仍有偏。

另一套同样截断采样、但没做批级归一化的配置跑得很稳，说明截断单独不足以导致崩溃，更像放大因素——这也是 §4.4 “两者同时存在才会崩”推测的一个旁证。

## 5. 批级归一化第二件事：除标准差 = 按信号稀缺程度放大步长

设有信号（来自有成有败的组）的 Token 占比为 p，它们的 A ≈ ±1，其余为 0，则 Token 级标准差 s ≈ √p，有信号的 Token 被放大 1/√p 倍：

| p | 放大倍数 1/√p |
|---|---|
| 0.65（零方差组约占 35%） | 1.2× |
| 0.3 | 1.8× |
| 0.1 | 3.2× |
| → 0 | 只剩 KL 一项，被放大到 O(1) |

不做批级归一化时，有信号的组越少梯度越小，训练会自然“减速”；做了以后反而**信号越少步长越大**，更新被越来越少、越来越嘈杂的样本主导。

极端情况 Reward 全 0：γ = λ = 1 时 Token t 的 Advantage 只剩 `−β × 后续所有模型 Token 的 KL 之和`，除以同样很小的 s 后变成单位方差，等于用噪声全速更新（[10 月 9 日 §3.2](AgentRL的Reward崩溃与归因实验_20261009.md#32-为什么归零后回不来批归一化放大残余信号)）。

## 8. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| GRPO 和 PPO 是两套不同的损失函数 | 二者共用 Clip surrogate loss，只在 Advantage 来源上不同 |
| 配置里写的是 GAE，所以跑的是 PPO | V ≡ 0、γ = λ = 1、Reward 在末 Token 时，GAE 退化成 GRPO |
| 组内归一化后，批级再归一化一次只是改尺度 | 均值按 Token 加权，不为 0；它同时平移了所有 Token，零方差组也被改成非 0 |
| 零方差组一定被“压低” | 方向取决于 m 的符号，而 m 的符号随成功/失败轨迹的长短变化（此处先前讲解被修正过） |
| 给所有 Token 加一个常数一定有害 | On-policy 下它就是 Baseline，期望梯度为 0；有害的是它与截断采样的组合 |
| 全零时 KL 项只有 1e-3 量级 | 1e-3 是每 Token 的值；进入 Advantage 后沿后续 Token 累加，越早的 Token 越大（此处先前讲解被修正过） |
| 截断采样单独就会导致崩溃 | 同样截断、但没做批级归一化的配置稳定；它更像放大因素 |

## 9. 一分钟复习

1. GRPO 一步：采样 → 打分 → 组内归一化 → （批级归一化）→ Clip Loss → 更新；唯一信号来自组内差别。
2. GRPO = V ≡ 0、γ = λ = 1、Reward 在末 Token 的 GAE + 组内归一化；Loss 与 PPO 共用。
3. `Δz ∝ A(e_y − π)`：符号定方向，大小定步长，0 表示别动。
4. 批级归一化 = 减 Token 加权均值（零方差组变非 0）+ 除 s（信号越少放得越大）。
5. 常数平移：On-policy 下期望为 0；截断采样下变成 `c(q − π)`，c < 0 抬高长尾含 EOS（假说）。

## 10. 自测问题

### 问题 1

为什么说“这次跑的是 GRPO”和“两边 PPO 损失函数一样”并不矛盾？

期望回答：GRPO 与 PPO 只在 Advantage 来源上不同；拿到 Advantage 后都用同一个 Clip surrogate loss。没有 Critic、γ = λ = 1、Reward 在末 Token 时，GAE 算出来的就是 GRPO 的 Advantage。

### 问题 2

组内归一化后每组 Advantage 平均为 0，为什么批级归一化的均值不为 0？

期望回答：组内是按条数平均为 0；批级归一化按 Token 加权。成功和失败轨迹长度不同时，Token 加权均值偏向更长的一方。

### 问题 3

给所有 Token 的 Advantage 加同一个常数，什么时候无害、什么时候有害？

期望回答：样本真从 π 采时，`E[e_y − π] = 0`，常数只是 Baseline、只加噪声；Top-p/Top-k 截断采样时期望变成 `c(q − π)`，系统性地挪动头部与长尾的概率，c < 0 时抬高长尾、熵上升。

### 问题 4

为什么批级归一化会让“信号越少、步长越大”？

期望回答：有信号的 Token 占比为 p 时，Token 级标准差约为 √p，除以它把有信号 Token 放大 1/√p 倍；p → 0 时连极小的 KL 残余都被放大成单位方差。

## 11. 尚未解决与后续路线

- §4.4～4.5 的因果链需要数据：m 的符号与熵、EOS 概率的时间关系；
- 只保留减均值、只保留除标准差的两组拆分实验，能区分“平移”与“放大”哪一个起作用；
- 推理引擎返回的 Logprob 是截断前还是截断后，要按所用版本核实；
- GAE 在 γ、λ < 1 时的偏差/方差权衡、Critic Loss 仍待系统学习。
