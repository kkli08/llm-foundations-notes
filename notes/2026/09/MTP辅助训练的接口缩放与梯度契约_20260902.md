# MTP 辅助训练的接口、缩放与梯度契约

> 日期：2026-09-02
>
> 来源：近期 AReaL / Megatron-Core MTP 辅助训练实现与审计复盘
>
> 状态：已整理

## 0. 这篇笔记解决什么问题

把 MTP 接进 SFT、PPO 或 GRPO 训练，不只是“多算一个 Cross-Entropy”。它同时改变：

```text
Forward 接口
+ Label / Mask 语义
+ Microbatch 与分布式 Loss 缩放
+ 梯度流向
+ Packed / CP Layout
+ Activation Recompute ABI
+ Eval 路径和 Metrics
```

其中任何一项错了，都可能出现“Loss 有数值、训练不报错，但监督或梯度已经错位”的 Silent Corruption。

## 1. 先看完整接口链

```text
Trajectory / SFT Batch
→ input_ids + actor_loss_mask + packed metadata
→ Actor Forward
   ├── 主路径：Logits → Logprob / Main Loss
   └── MTP 路径：Future Label / Mask
                 → MTP Core
                 → Per-depth MTP Loss
→ 按全局权重合并 Total Loss
→ Backward
→ Optimizer Step
→ Per-depth Metrics
```

第一条原则是：

> MTP 是 Actor Forward 的辅助训练目标，不应破坏训练框架原有的 Logits 返回契约。

PPO/GRPO 仍可能需要 Logits 或 Logprob。一个安全实现通常是：

- 主 Forward 继续返回框架原本期望的 Logits；
- 只在 Train Forward 内把 Label/Mask 注入 MTP Helper；
- MTP Loss 通过明确的附加 Loss/回调接口合入；
- Logits-only、Evaluation 或 Inference Forward 明确跳过 MTP 辅助计算。

## 2. Label 与 Mask：最危险的是多 Shift 一次

### 2.1 先固定每个位置的语义

给定 Token：

```text
位置：       t        t+1       t+2       t+3
Token：      A         B         C         D
```

普通 Next-token Label：

```text
位置 t 的主 Label = B = x(t+1)
```

若第一层 MTP 预测再远一个 Token：

```text
位置 t 的 MTP Depth-1 Label = C = x(t+2)
```

第二层则是：

```text
位置 t 的 MTP Depth-2 Label = D = x(t+3)
```

### 2.2 Actor Loss Mask 通常已经和主 Label 对齐

`actor_loss_mask[t]` 通常表达：

> 位置 `t` 所预测的主 Label `x(t+1)` 是否属于可监督区域。

如果 Megatron-Core 的 MTP Helper 本身会为每个 Depth 继续 Shift Label 与 Mask，Adapter 就应传入 Helper 期望的基础语义，而不是看到“Depth-1 预测 t+2”后再提前 Shift 一遍。

典型错误：

```text
上游 Adapter 提前 Shift
→ 下游 MTP Helper 再 Shift
→ Label 与 Mask 的有效位置不再一致
```

最隐蔽的结果可能是：

```text
Label 在监督 x(t+2)
Mask 却按 x(t+3) 的合法性开关
```

这样会错误屏蔽最后一个合法 Response Token，或把 Prompt/Tool/下一条 Packed Sample 的 Token 纳入辅助 Loss。

### 2.3 正确门禁

在每个 Adapter 边界写清：

```text
当前 labels[t] 指向哪个全局 Token？
当前 mask[t] 保护哪个 Label？
下游 Helper 还会 Shift 几次？
Packed End / Padding End 在哪一步清零？
```

不要从 Tensor Shape 猜语义。

### 2.4 Packed 与 Padded 边界要先处理

```text
[Prompt A | Response A | Prompt B | Response B | Padding]
```

在进入逐 Depth Shift 前，至少要屏蔽：

- 每条 Packed Trajectory 的结束位置；
- Padded Row 的最后有效位置；
- Prompt、Tool 或其他不参与 Actor Loss 的区间；
- 向未来 Shift 后越界的位置。

Label、Mask、Future Token Input 必须共享同一边界语义。

## 3. 辅助 Loss 有四类正交缩放

### 3.1 算法权重

```text
λ_mtp
```

它回答“MTP 辅助目标在总优化目标里占多大比重”。这是算法超参数。

### 3.2 有效 Token / Microbatch 全局权重

动态长度下，各 Microbatch 有效 Token 数不同。正确目标通常是：

\[
L=\frac{\sum_m\sum_{i\in V_m}\ell_i}{\sum_m|V_m|}
\]

不能简单平均每个 Microbatch 的 Local Mean：

\[
\frac{1}{M}\sum_m\operatorname{mean}(L_m)
\]

否则短 Microbatch 和长 Microbatch 权重相同。

训练框架若已经为主 Loss 计算 `local_weight / total_weight`，MTP Side Loss 也必须进入同一口径。

### 3.3 DP / CP 框架补偿

分布式框架可能在不同位置重复或平均某些量：

- DP/CP 范围的 Total Weight 可能在多个 Rank 上重复；
- Backward 后 CP Gradient 可能再次平均；
- 某个 Rank 的本地有效 Token 数可能为零，但仍必须参与 Collective。

因此 CP 中常见两种不同补偿：

```text
补偿一：抵消 DP×CP Total Weight 的重复
补偿二：抵消后续 CP Gradient Average
```

它们不是同一个 Scale，不能因为数值上碰巧相等就合并为一条模糊规则。

### 3.4 Mixed-precision Optimizer Loss Scale

FP16/BF16 训练可能把 Loss 乘上数值稳定用的 Optimizer Scale，Backward 后再 Unscale。

若主 Loss 进入了该路径、MTP Loss 却绕过它，最终 MTP Gradient 的有效比例就会错误。

所以：

```text
λ_mtp
≠ Token/Microbatch Weight
≠ DP/CP Compensation
≠ Optimizer Loss Scale
```

不支持的组合应 Fail Fast。例如框架同时存在 Per-token Loss 模式和 CP 特殊归约，但语义尚未对齐时，明确拒绝比静默 Double-normalize 更安全。

## 4. 梯度隔离要按“边”定义

一句 `detach_encoder=true` 太粗。真正要问的是：MTP Loss 能否沿每条计算图边传播？

### 4.1 一个重复物理层的多 Depth 图

```text
Backbone Hidden h0 --detach--> MTP Depth 1 --> h1 --> MTP Depth 2 --> h2
Token Embedding e1 --detach-------^       e2 --detach-------^

h1 / h2
→ Shared LM Head Weight --detach
→ MTP Loss 1 / 2
```

若目标是“MTP Auxiliary Loss 只更新 MTP-owned 参数”：

- Backbone Hidden：只在进入第一个 MTP Depth 时 Detach；
- Shared Token Embedding：每个 Depth 的输入都 Detach；
- Shared LM Head Weight：Detach，避免 Side Loss 更新主 Head；
- Trainable LM-head Bias：也必须显式隔离或拒绝；
- Depth 1 → Depth 2 的 MTP Hidden Chain：不能 Detach。

### 4.2 为什么不能每个 Depth 都 Detach Hidden State

若同一物理 MTP Layer 被递归调用：

```text
W_mtp 调用 1 → h1
W_mtp 调用 2 → h2
```

Depth-2 Loss 理应能沿 `h2 → h1 → 第一次 W_mtp 调用` 回传。若每个 Depth 都 Detach，虽然 Backbone 被隔离了，但多 Depth 之间的学习链也被切断。

正确语义是：

```text
隔离 Backbone
≠ 隔离 MTP Depth 之间的递归梯度
```

## 5. CP 正确性同时包含 Layout 与 Scale

CP 不是只把 `input_ids` 切开。以下对象必须使用同一全局到局部映射：

```text
input_ids
position_ids
labels
loss_mask
packed segment metadata
```

若采用 Zigzag 或 THD Layout，Label/Mask 必须和输入一起切分。Loss Count 则需要 CP-global Denominator。

一个 Rank 本地有效 Token 为零是合法边界：

```text
local numerator = 0
local count = 0
仍参加相同 Collective
→ 使用 global numerator / global count
```

## 6. 通用 CP 能力不等于模型特定 CP 能力

运行时可能同时满足：

```text
Packed THD 的 CP-aware Roll API 可用
```

但不满足：

```text
某个具体 Backbone（例如 GDN）的 CP Kernel / State Split 可用
```

因此支持矩阵应按路径写：

| 路径 | 需要的能力 |
|---|---|
| Wrapper-owned Packed THD MTP | CP-aware Roll、CP Group、Packed Metadata、Loss Scale |
| Padded Transformer MTP | Padded Layout 的 CP Split/Gather 与 Attention 支持 |
| Padded GDN/Qwen3.5 MTP | 额外需要 GDN State 的 CP 实现 |

不能只写“版本 X 支持 CP”。应在启动时 Probe 实际 API 和调用签名，并保留模型特定 Guard。

## 7. Activation Recompute 还有 ABI 问题

某些 Checkpoint Wrapper 只允许 Tensor 参数：

```text
checkpoint(function, tensor_1, tensor_2, ...)
```

Packed Sequence Metadata 往往是 Python 对象。把它当作 checkpoint 输入可能出现：

```text
Forward 正常
→ Backward 触发 Recompute
→ 非 Tensor 参数不被支持
→ 只在 Backward 阶段失败
```

安全做法之一是把非 Tensor Metadata Close Over：

```text
def recompute_fn(tensor_inputs):
    return mtp_layer(tensor_inputs, packed_seq_params=captured_metadata)
```

所以 Recompute 能力必须验证到：

```text
Forward → Backward Recompute → Gradient → Optimizer Step
```

Forward-only 单测不够。

## 8. 按真实 Batch 判断 Text / Multimodal

有些 Qwen3.5 模型在 Registry 中使用 VLM Architecture 名称，但实际 Microbatch 可能完全没有视觉 Tensor。

若第一版只支持 Text-only MTP，更准确的 Guard 是：

```text
Microbatch 是否真的包含 vision tensors？
```

而不是：

```text
Model Class 名称里是否包含 VLM？
```

Architecture Label 表示模型能力上限，不等于当前 Batch 的实际 Modalities。

## 9. Metrics 的正确粒度

至少记录：

- 每个 Depth 的 Raw MTP Loss；
- 实际进入 Total Loss 的 Weighted Contribution；
- 有效 Token Count；
- Train Batch / Policy Version；
- 是否为 Train Forward，而不是 Eval/Logits-only Forward。

若一个 Train Batch 被拆成多个 Microbatch，Metrics 应在明确归约后发布一次，避免把 Microbatch 数误认为训练 Step 数。

## 10. 最小验证阶梯

### 10.1 Tensor 语义单测

- 手写短 Token 与 Prompt/Response/Packed Boundary；
- 检查每个 Depth 的 Label、Mask 和 Future Input；
- 覆盖 Padded Row End。

### 10.2 Loss Scaling 单测

- 构造不同有效 Token 数的 Microbatch；
- 比较拆分前后的全局 Token Mean；
- 覆盖 DP/CP 和本地零有效 Token；
- 覆盖 Mixed-precision Scale。

### 10.3 Gradient Isolation 单测

- Backbone/Embedding/Shared Head 无 Side-loss Gradient；
- MTP-owned 参数有有限非零 Gradient；
- Depth-2 Loss 能回传到第一次重复 MTP 调用；
- Optimizer Step 后 MTP 参数真的变化。

### 10.4 Runtime Smoke

- 真实依赖版本；
- Forward/Backward/Optimizer；
- Train/Eval Bypass；
- Packed/Recompute；
- 再扩展 TP/PP/CP。

## 11. 实现证据不能跨代码版本借用

两个实现即使都叫“MTP Auxiliary Training”，也可能在以下方面不同：

- Label/Mask 边界；
- Detach 契约；
- Loss Weight；
- Runtime 版本；
- Packed/CP 支持；
- Rollout 与 Weight Sync。

因此旧实现的真实 GPU PASS 不能直接当作新 Rewrite 的运行证据。新实现最多可以复用：

```text
问题拆解方法
+ 测试设计
+ 风险清单
```

必须重新验证 Exact Diff。

公开协作时还要区分：

- 独立依据公开 API 实现；
- 复制雇主拥有的内部代码；
- DCO / License / 作者身份；
- “Unit Test 通过”与“真实 GPU Runtime 已验证”。

## 12. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| MTP 训练只是加一个 CE | 还涉及接口、Mask、Scale、Gradient、Layout、Recompute 和 Eval |
| Loss 有限就说明监督正确 | Label/Mask 可错位且仍产生有限 Loss |
| 所有 Depth 都 Detach 更安全 | 会截断 MTP Depth 间的递归梯度 |
| `λ_mtp` 能处理所有缩放 | 它不替代 Token、DP/CP 和 Optimizer Scale |
| CP 只切 input_ids | Position、Label、Mask、Metadata 与 Count 都要一致 |
| 普通 Packed CP 可用就支持 GDN CP | 模型特定 State/Kernel 仍可能缺失 |
| Forward 能跑就证明 Recompute 正确 | 非 Tensor Metadata 可能只在 Backward 重算时失败 |
| VLM Registry 一律不能做 Text MTP | 应检查当前 Batch 是否真的含视觉 Tensor |
| 旧实现跑通过就能证明新 Rewrite | Exact Diff、Runtime 和梯度契约不同，证据不能借用 |

## 13. 一分钟复习

```text
MTP Auxiliary Training：
保留主 Logits 契约
→ 在 Train Forward 注入 Future Label/Mask
→ 下游只 Shift 一次且边界一致
→ λ_mtp × Token Weight × DP/CP Compensation × Optimizer Scale
→ 首 Depth 隔离 Backbone，但保留 MTP Depth 链
→ Packed/CP/Recompute 验证到 Backward + Optimizer
```

## 14. 自测问题

1. 为什么 Actor Loss Mask 很容易在 MTP Adapter 中被多 Shift 一次？
2. `λ_mtp`、Token Weight、CP Compensation 和 Optimizer Loss Scale 分别解决什么？
3. 为什么只在第一个 MTP Depth Detach Backbone Hidden，而不是每层都 Detach？
4. Packed THD CP 可用，为什么仍不能声称 Qwen3.5/GDN CP 可用？
5. 非 Tensor Packed Metadata 为什么可能只在 Backward Recompute 时报错？
6. 为什么真实 GPU 通过的旧实现不能直接验证一个新的公开 Rewrite？
