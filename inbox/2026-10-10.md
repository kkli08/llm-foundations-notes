>
> 来源：Claude Code 会话 `4dfc7f28`

### 今天的问题

- 路由回放的驻留优化，和不开回放的基线比，实际影响怎么样？

### 对话或资料摘录

- 先选对照：同模型、同序列长度、同卡数和布局，只差是否开回放；
- 回放数据放在 CPU 侧时，各阶段结束时的显存读数和基线持平，代价转移到训练侧的耗时，主要是每次从对象存储整批取回路由；拷到 GPU 本身可忽略；
- 比步时前先确认两边每步有效 Token 与 Microbatch 数相近，再按“每百万有效 Token 耗时”归一化；
- Rollout 时间差不能算到回放头上：两次运行隔了一周，环境负载不同；
- 训推一致性的汇总指标（重要性权重均值、KL 均值）看不出改善，可能是差异集中在少量 Token 的长尾，均值反映不出来；
- 要证明算法收益：固定同一批 Rollout，在训练侧分别开、关回放，比较逐 Token Logprob 差异的分布，重点看长尾。

### 我的当前理解

- 两次独立运行的对比不是严格 A/B；阶段结束时的显存读数也不是阶段内峰值。

>
> 来源：Claude Code 会话 `60e4e2ab`

### 今天的问题

- 两组归因实验哪个更正常？判断实验健不健康，第一反应应该按什么顺序看哪些指标？
- 这么看主要就是 KL 系数的区别？

### 对话或资料摘录

- 顺序：是否还在正常训练（步时、更新是否成功）→ 熵 → 梯度范数 → 生成行为（每轮输出长度、轮数）→ 学习信号（全零组占比、组内同分非零占比、整组接收率）→ 最后才看 Reward；
- Reward 是滞后指标，掉了通常已经晚了；熵和梯度范数比 Reward 早约 10 步抬头；
- 熵有两个失败方向：往上冲（不稳定 → 输出塌缩）和持续往下掉到接近 0（多样性丧失，组内同分越来越多，学习信号变弱）；降低采样温度会让熵的绝对值偏低，要看趋势而不是绝对值；
- 两组共同的改动是 KL 系数为 0，所以两组都不崩时它最可疑；但还没过危险区间、每组只跑一次，暂不能下结论；
- 待验证猜想：组内任务 Reward 完全相同时，组内样本唯一的差别可能只剩 KL 惩罚，它把模型往“少说话”推。

>
> 来源：Claude Code 会话 `db15d43c`

### 今天的问题

- Prefix Cache 开关的兼容代码是同事有意加的，改动会不会破坏原意？开关太多，人和 Agent 都不知道该用哪个。
- 整理的是 MTP 相关问题，为什么会扫到 Prefix Cache 的内容？
- 关闭 MTP 训练时导出的 HF 索引里留着没有对应权重的 MTP 条目，这算 bug 吗？
- 关闭 MTP 训练时，导出的 Checkpoint 还要不要带上 MTP 头？训后的 Backbone 推理时可能想试试开 MTP 能不能加速。

### 对话或资料摘录

- 反向开关的来历：命令行序列化会丢掉值为 False 的参数，所以另加一个“禁用”开关显式传出关闭参数；后来正向字段改成三态并显式翻译，从根上解决了问题，之后再加的“强制显式开启”改写就成了重复，还顺带把 False/None 覆盖成开启；
- 删兼容代码前先追溯历史意图，并确认所有启动路径都经过正确的翻译层；测试直接断言两种意图；
- 配置开关失效本身是通用配置 bug，与 MTP 无关；真正和 MTP 相关的是“混合结构 + MTP + Prefix Cache”的组合正确性风险；
- 分片 Checkpoint 的索引把每个 key 映射到分片文件；导出时直接复制源索引、又跳过了部分模块，就会出现“索引说有、文件里没有”；dtype 降精度还会让 `total_size` 对不上；
- 一开始倾向“去掉旧 MTP 头更诚实”，被用户的场景纠正：推测解码由 Target 验证，旧头只影响接受率和加速，不影响输出正确性，所以应带上并标明来源。

### 我的当前理解

- 之前测过 Frozen 情况下，一些场景命中率不会低太多，所以带上旧头有实际价值。
