## 1. 先给结论

- **GSPO = GRPO 只改一件事**：重要性比率与 clip 的单位从“每个 token”改成“整条序列”。Advantage 照搬 GRPO（组内比较、没有 Critic）。
- **动机是一条原则**：off-policy 修正的单位应与 Reward 的单位一致。Reward 给整条回答，ratio 也应在序列级算。
- **序列 ratio 取几何平均**：`s_i = exp(平均 log ratio)`。单个 token 的噪声被整条序列摊薄，所以 clip 范围要小几个数量级（论文约 3e-4 / 4e-4，GRPO 约 0.2）。
- **和 MoE 路由回放是同一个问题的两种解法**：路由回放在 infra 层把路由对齐；GSPO 在算法层让 Loss 对单 token 的路由抖动不敏感，论文称因此不再需要 Routing Replay。
- **PPO 与 GRPO 差在 Advantage 从哪来；GRPO 与 GSPO 差在 ratio/clip 按什么单位算**。三者共用“Advantage × 概率比 + clip 限速”的框架。
- **“online”是 rollout 接入方式，不是 RL 理论的 online**：外部环境平台驱动会话，训练框架只提供推理接口并收集数据。算法框架早就支持 PPO/GSPO，只是这条链路围绕 GRPO 搭建。
- **实现与论文三处不同**：异步框架把 π_old 拆成 π_behave 与 π_prox；代码按 token 数聚合而非每条序列等权；只改粒度不改 ε 等于没有 clip。
- **先只读审查、分类，再分开修**：归因实验在跑时不改训练行为。

## 2. 前置概念

### 2.1 ratio 在 PPO 里的两个作用

`ratio = π_新(token) / π_旧(token)`：

- **修正**：数据来自旧策略，用 ratio 加权近似“新策略自己采样”（重要性采样）；
- **限速**：超出 `[1−ε, 1+ε]` 就 clip，不让单步改太多。

PPO 与 GRPO 都是**每个 token 一个 ratio、各自判断要不要 clip**。

### 2.2 异步框架里的三个策略

| 策略 | 是什么 | 在哪个比值里 |
|---|---|---|
| π_behave | 推理引擎采样时的策略 | π_prox / π_behave：陈旧度 + 训推不一致，单独加权或过滤 |
| π_prox | 训练侧本步更新前重算的策略 | π_θ / π_prox：本步改动，clip 作用在这里 |
| π_θ | 正在更新的策略 | — |

论文里的 π_old 在异步框架里被拆成两个（见 [重算 Logprob 的两个比值](PPO的Critic与Clip在单次更新下的退化_20261013.md#34-为什么要重算-logprob)）。

## 3. 完整原理

### 3.1 PPO 论文（2017）怎么读

**§1–2 要解决的问题**：朴素策略梯度 `L = E[log π_θ(a|s) · Â]` 一批数据只能用一次；同一批上多更新几步，策略常会毁灭性地大幅变化。TRPO 改优化 surrogate `E[r_t(θ)·Â_t]` 并加约束 `KL(π_old, π_θ) ≤ δ`，但需要二阶优化（共轭梯度），实现复杂，也不兼容 dropout、参数共享。PPO 想要：只用一阶 SGD、同一批数据跑多个 epoch、同时保留“不一步走太远”的稳定性。

**§3 Clipped surrogate（全文核心）**：

```text
L^CLIP(θ) = E_t[ min( r_t·Â_t , clip(r_t, 1−ε, 1+ε)·Â_t ) ]
```

两点要抓住：

1. **min 取悲观下界，clip 只在“让目标更好看”的方向生效**：Â > 0 时 r 超过 1+ε 后目标变平；Â < 0 时 r 低于 1−ε 后变平；**反方向不 clip**——比如 Â < 0 而 r 已经很大，说明之前改错了，梯度照常存在，可以纠正回来。
2. **clip 不是硬约束**：它只是把 clip 区域里的梯度置 0、去掉继续往外走的激励。参数被所有 token 共享，r 仍可能被其他样本的更新带出区间。这一点和 GSPO 的论证直接相关。

**§4 Adaptive KL penalty（对照方案）**：`E[r·Â − β·KL]`，KL 偏大就把 β 翻倍、偏小就减半。实验里不如 clip。

**§5 算法**：完整 Loss = `L^CLIP − c1·L^VF + c2·S`（policy、value、entropy bonus）；Advantage 用截断 GAE；N 个 actor 各采 T 步，再在这批数据上做 K 个 epoch 的 minibatch SGD。

**§6 实验**：MuJoCo 上不加 clip 也不加 penalty 的版本归一化得分为负（训崩）；clip ε = 0.2 最好，adaptive KL 次之——clip 是让“多 epoch 复用数据”成立的关键。

**放到 LLM 上**：action = 一个 token；state = prompt + 已生成前缀；reward 通常只在末尾。RLHF-PPO 需要 Critic；GRPO 去掉 Critic、用组内标准化 reward 作为 Advantage 并广播到每个 token，但**保留了 PPO 的 token 级 ratio 与 clip**——GSPO 针对的正是这一点。

### 3.2 GSPO 论文（2025，Qwen 团队）怎么读

**§1 现象**：训练大模型时 GRPO 会出现不可逆崩溃，MoE 尤其明显；作者认为原因不在超参，而在重要性权重的用法原理上有问题。

**§2 GRPO 的写法**：

```text
J_GRPO = E[ 1/G Σ_i 1/|y_i| Σ_t min( w_{i,t}·Â_i , clip(w_{i,t})·Â_i ) ]
w_{i,t} = π_θ(y_{i,t} | x, y_{i,<t}) / π_old(y_{i,t} | x, y_{i,<t})
Â_i = (r_i − mean(r)) / std(r)
```

**§3 Motivation（最值得精读）**：重要性采样 `E_{z~π_tar}[f(z)] = E_{z~π_beh}[(π_tar/π_beh)·f(z)]` 要靠**对大量样本取平均**才能起修正作用。GRPO 的 `w_{i,t}` 在每个位置的 next-token 分布里**只采了一个 token**，起不到分布修正作用，只给梯度引入高方差噪声；噪声沿长序列累积，再被 clip 的不对称性放大，最终崩溃。原则：**off-policy 修正的单位应与 reward 的单位一致**。

**§4.1 目标函数**：

```text
s_i(θ) = ( π_θ(y_i|x) / π_old(y_i|x) )^{1/|y_i|} = exp( 1/|y_i| Σ_t log w_{i,t} )
J_GSPO = E[ 1/G Σ_i min( s_i·Â_i , clip(s_i, 1−ε, 1+ε)·Â_i ) ]
```

开 `1/|y_i|` 次方（几何平均）是关键：不做长度归一化时序列 ratio 是 token ratio 的连乘，长序列上几个 token 的变化就让它剧烈波动；归一化后不同长度的序列落在同一数值范围。所以 ε 的量级与 GRPO 完全不同。

**§4.3 梯度对比**：

```text
∇J_GSPO = E[ 1/G Σ_i  s_i·Â_i · 1/|y_i| Σ_t ∇log π_θ(y_{i,t}) ]
∇J_GRPO = E[ 1/G Σ_i  Â_i · 1/|y_i| Σ_t w_{i,t}·∇log π_θ(y_{i,t}) ]
```

GSPO 同一条序列里每个 token 权重相同、整条乘一个系数；GRPO 每个 token 带着各自不等的 `w_{i,t}`——这就是噪声来源。

**§4.4 GSPO-token 变体**：`s_{i,t} = sg[s_i] · π_θ(y_{i,t}) / sg[π_θ(y_{i,t})]`，数值等于 `s_i`；每个 token Advantage 相同时梯度与 GSPO 一致；用处是允许 token 级 Advantage（如多轮对话）。

**§5 实验重点三处**：

1. MoE 模型上 GSPO 训练更稳定，评测曲线持续上升；
2. **反直觉**：GSPO 被 clip 掉的 token 比例比 GRPO 高约两个数量级，样本效率却更好——GRPO 的 token 级梯度本身就嘈杂，“用到的 token 多”不代表有效；
3. **MoE 与 Routing Replay**：一次梯度更新前后，同一条 rollout 约 10% 的激活 Expert 会变化，token 级 `w_{i,t}` 基本失去意义，GRPO 只能靠 Routing Replay（缓存 π_old 的路由，算 π_θ 时重放）维持稳定；GSPO 看整条序列似然，对单 token 波动不敏感，不需要 Routing Replay。

§5.4 还提到一个 infra 好处：序列级似然对训推精度差异更宽容，**有可能直接用推理引擎给出的 Logprob、省掉一次重算**。

### 3.3 用一个例子看 token 级 ratio 的不稳定

一条回答里有一个 token 因路由变化 ratio 跳到 1.35，其他都在 1 附近（ε = 0.2）：

| | Â > 0（想推高） | Â < 0（想压低） |
|---|---|---|
| 那个 1.35 的 token | 超过 1.2，被 clip，梯度为 0，学不到 | 不 clip，按 1.35 倍力度被压低 |
| 其他 token | 正常更新 | 正常更新 |

同一条回答里各 token 被推的力度不同，而差异完全由路由噪声决定。放到 GSPO：该 token 的 log ratio ≈ 0.3，摊到 2000 个 token 上只有 0.00015，`s_i ≈ 1.00015`，几乎感觉不到。

### 3.4 三者异同

| | PPO | GRPO | GSPO |
|---|---|---|---|
| Critic | 有 | 无 | 无 |
| Advantage 来源 | Critic + GAE | 组内比较 | 组内比较 |
| Advantage 粒度 | 每 token 不同 | 整条一个值 | 整条一个值 |
| ratio 粒度 | 每 token | 每 token | **整条序列（几何平均）** |
| clip 单位 | 单 token | 单 token | **整条序列** |
| clip 范围 | ±0.2 左右 | ±0.2 左右 | 约 1e-4 量级 |
| 适合 | 需要轨迹内精细分配功劳 | 通用、省 Critic | MoE、长回答、token 级噪声大 |

### 3.5 “online”到底指什么

用户问：这个 online 是指所有 online 任务吗？——**不是 RL 理论里 online/offline 的含义**，而是 rollout 的一种接入方式。按“谁驱动 Agent 与环境的循环”分三种：

| 模式 | 循环跑在哪 | 含义 |
|---|---|---|
| 进程内 | 训练框架进程内部 | 框架自己调用 workflow：发 prompt、调工具、算 reward |
| 子进程 | 框架拉起的子进程 | 同上，只是隔离 |
| online | 外部评测/环境平台 | 框架只提供 OpenAI 兼容的推理接口（Gateway）；外部平台自己开会话、调模型、跑环境、打分，框架收集跑完的数据去训练 |

online 下 Gateway 负责：把同一道题的 n 条会话凑成一个 cohort（GRPO 的一组）；控制何时允许新请求进入（权重更新时暂停）；同一会话的请求固定路由到同一后端。用 infra 的话说，训练框架退化成“推理服务 + 训练器”，任务逻辑全部在外部（参见 [Online RL 的 Cohort 并发](../08/OnlineRL的Cohort并发与会话容量_20260818.md)、[Online EVO 不等于 On-policy RL](../08/OnlineEVO_Rollout架构与任务边界_20260828.md#3-online-在这里是什么意思)）。

online 内部还分两种训练粒度：**按轮**（外部给哪些交互打分，哪些就成为样本，Advantage 走框架自己的 GAE 路径）和**按整条轨迹**（整个会话作为一个 GRPO 单位，Advantage 由 rollout 侧算好传入）。

助手先说“PPO 在 online 下被配置校验拒绝”，随后**自我更正**：只在“按轨迹”粒度成立（传入的组归一化 Advantage 不能当 Value 的训练目标，所以禁止 Critic）；按轮粒度不拦截，但没人端到端跑过 Critic。

### 3.6 PPO/GSPO“之前不支持吗”

**算法框架本身早就支持**（进程内链路有现成的 PPO、GSPO 示例，GSPO 相对 GRPO 只多一行开关）。不支持的是 online 链路——它围绕 GRPO 搭建（按组路由 → cohort 管理 → 轨迹级 GRPO），PPO/GSPO 不是设计目标：

- **PPO** 需要 Critic 前向、GAE（多轮时要跳过环境输出的 observation token）、Critic 更新；
- **GSPO** 开关已有，但“一条序列”的边界取决于链路怎么组织数据：
  1. 几何平均按**打包后的每一行**算；按轮模式下一行是一轮，算出的是“每轮”而非“整条轨迹”的几何平均，与按轨迹给的 Advantage 单位又对不上；
  2. Context Parallel 把一条长序列切到多张卡，几何平均需要跨 CP rank 汇总，否则每张卡只是一部分 token 的平均；
  3. 序列级处理应作用在哪个比值上（见 §3.7）。

### 3.7 实现与论文的三处差别

1. **三个策略不是两个**：GSPO 的 `s_i` 在实现里算的是 `π_θ / π_prox`；陈旧度修正 `π_prox / π_behave` 走另一条路径（拒绝采样/加权），两者互相独立。而在“整批只做一次 optimizer step、prox 用同一份权重刚算出”时，`π_θ / π_prox ≡ 1`（[单次更新下 Clip 退化](PPO的Critic与Clip在单次更新下的退化_20261013.md#33-关键推论单次更新时-clip-退化)），光打开序列级开关 GSPO 与 GRPO 没有区别。GSPO 真正要对付的“采样与训练之间的差异”（含 MoE 路由不一致）在异步框架里对应 `π_prox / π_behave` 一侧——把这一侧也设为序列级，才最接近论文原意。
2. **聚合方式不同**：代码把 `s_i·Â_i` 广播到 `|y_i|` 个 token，再除以全 batch token 总数，第 i 条序列的梯度是 `s_i·Â_i·Σ_t ∇log π / N_tokens`；论文是 `1/G · s_i·Â_i · 1/|y_i| Σ_t ∇log π`。代码**按 token 数加权**（长序列权重大，接近 DAPO 的 token 级聚合），论文**每条序列等权**。不一定是 bug，但复现论文时要知道（与 [Loss 的 Token 等权是另一个“按 Token”](GRPO变体与两层归一化的拆解_20261013.md) 是同一件事）。
3. **ε 不会自动跟着改**：只把粒度改成序列、ε 仍是 0.2，`s_i` 几乎不可能越界，clip 等于没生效；按论文需调到 1e-4 量级。

### 3.8 推理端返回的 Logprob 是哪个分布

审查中核实的一个事实：所用版本的 vLLM 默认返回 **raw logprobs**——在温度、logits processor、top-p/top-k 之前的原始分布。含义：

- 样本是从截断后的分布采出来的，记录的 behavior Logprob 却是原始分布的；
- 训练侧算 Logprob 时是否除以温度、是否同样不截断，决定两边口径是否一致；
- 口径不一致时，`π_prox / π_behave` 会带系统偏差，而不只是数值噪声。

同时发现：在外部平台驱动的模式下，**训练配置里写的 top-p/top-k 不一定传到推理端**，实际采样参数由外部平台的请求决定，某些字段还可能被网关静默丢弃。所以“只改训练配置里的采样参数”的对照实验，可能和基线采样完全一样——这是 [请求配置 ≠ 运行事实](../08/推理性能的配置执行证据链_20260812.md#2-四层证据链) 在算法实验上的又一例。

### 3.9 要不要趁机修 GRPO：先审查，后修补

用户问要不要一起把 GRPO 的问题修了。建议：**要做，但先只读审查，范围限定在 PPO/GSPO 会复用的那段链路**（Advantage、归一化、Loss、cohort 到训练 batch 的组装）。现在不改的理由：

1. 归因实验还在跑，改训练行为会让新一轮与基线不可比，归因被污染；
2. 改默认值等于同时改所有任务的训练动态，需要实验证明，不是代码审查能决定的；
3. 把“审查 + 修复 GRPO”混进“支持 PPO/GSPO”同一个 PR，难 review、难回滚；
4. 同一块代码上还有别人未提交的大改动，各改各的容易冲突。

审查产出按三类处理：

| 分类 | 处理 |
|---|---|
| 确认的 bug | 单独 PR + 测试，尽快修 |
| 设计问题 | 加开关、默认行为不变，用实验决定是否改默认 |
| 配置有误导性 | 加校验或 warning（如单次更新时设置 clip-higher 提示不生效），成本低，可随 bug 修复一起提 |

结论必须附证据（代码位置 + commit，或可复现的最小例子）；只靠推理的标“可能（待验证）”。审查中逐条核实了先前的疑点：例如“组内归一化依赖连续 G 条为一组、cohort 拼 batch 可能打乱顺序”这一条，追完所查配置的链路后**被排除**；而 §3.8 的采样参数问题是新发现、最急。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 打开序列级 ratio 后指标与 GRPO 无差别 | 单次更新时 π_θ/π_prox ≡ 1；或 ε 仍是 0.2 | 看 clip 比例是否恒为 0；检查 ε |
| GSPO 的 clip 比例远高于 GRPO | 预期内：整条序列一起被截 | 对照论文的数量级 |
| 长序列在梯度里权重更大 | 实现按 token 数聚合 | 推导聚合公式；与每序列等权对比 |
| CP 下序列 ratio 异常 | 几何平均未跨 CP rank 汇总 | 构造跨 rank 切分的小例子 |
| 改了训练配置的 top-p，采样没变 | 采样参数由外部平台请求决定 | 抓推理端实际收到的请求参数 |
| behave/prox 比值有系统偏移 | 推理端返回原始分布 logprob，与截断采样口径不同 | 核对 logprob 模式与训练侧温度处理 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| GSPO 是一种新的 Advantage 算法 | Advantage 照搬 GRPO，只改 ratio/clip 的单位 |
| token 级 ratio 在做重要性修正 | 每个位置只有一个样本，起不到修正作用，只加噪声 |
| clip 是硬约束，ratio 不会出区间 | 只是把梯度置 0，参数共享仍可能把 ratio 带出去 |
| GSPO 用 0.2 的 clip 范围就行 | 几何平均让 s_i 极接近 1，ε 要到 1e-4 量级 |
| 打开序列级开关就等于用了 GSPO | 单次更新时 ratio 恒为 1；还要看 behave 一侧与 ε |
| 这里的 online 是 RL 的 online learning | 是外部平台驱动会话的 rollout 接入方式 |
| online 不支持 PPO/GSPO = 框架没实现 | 框架支持；是这条链路围绕 GRPO 搭建 |
| 趁支持新算法顺手修 GRPO 最省事 | 先只读审查；bug、设计问题、误导配置分开处理 |
| 推理端返回的 logprob 就是采样分布的 | 可能是温度与截断之前的原始分布 |

## 7. 一分钟复习

1. PPO：min 取悲观下界；clip 只挡“更好看”的方向，反方向照常纠错；clip 不是硬约束。
2. GSPO 原则：修正单位 = Reward 单位；序列 ratio = 几何平均；ε ≈ 1e-4。
3. 梯度：GSPO 整条一个系数，GRPO 每 token 一个不等的 w。
4. MoE：约 10% Expert 会变；Routing Replay（infra）与 GSPO（算法）是两种解法。
5. PPO vs GRPO 差 Advantage 来源；GRPO vs GSPO 差 ratio/clip 单位。
6. 实现三差：π_old 拆成 behave/prox；按 token 数聚合；ε 不自动变。
7. online = 外部平台驱动的接入方式；序列边界要看按轮/按轨迹与 CP 汇总。
8. 推理端 logprob 可能是原始分布；训练配置的采样参数不一定生效。
9. 先审查再修：bug 单独修，设计问题加开关，误导配置加 warning。

## 8. 自测问题

### 问题 1

为什么 GSPO 说 GRPO 的 token 级 ratio“起不到重要性采样的作用”？

期望回答：重要性采样要靠对目标分布的多个样本取平均才能修正分布；GRPO 在每个位置的 next-token 分布里只有一个采样 token，单个 ratio 只是高方差噪声，沿长序列累积并被 clip 的不对称性放大。

### 问题 2

一条 2000 token 的回答里有一个 token 的 ratio 是 1.35，A > 0。GRPO 和 GSPO 分别怎样处理？

期望回答：GRPO 下该 token 超过 1.2 被 clip、梯度为 0，其他 token 正常更新；GSPO 下 log ratio 0.3 摊到 2000 个 token，s_i ≈ 1.00015，整条序列正常更新、所有 token 等权。

### 问题 3

在“整批只做一次 optimizer step”的异步训练里，只打开序列级 ratio 开关，GSPO 会生效吗？要想接近论文，还应该改什么？

期望回答：不会，π_θ/π_prox ≡ 1。应把 π_prox/π_behave 一侧的修正也改为序列级，并把 ε 调到 1e-4 量级；同时注意聚合方式与论文不同。

### 问题 4

为什么不建议在支持 PPO/GSPO 的同时顺手修 GRPO 的问题？

期望回答：归因实验在跑，改训练行为会污染对照；改默认值影响所有任务，需要实验证明；混在一个 PR 里难 review、难回滚；同一块代码有并行改动。应先只读审查、分类，再分别处理。

## 9. 尚未解决与后续路线

- 手推 GSPO 梯度，看清 `1/|y_i|` 的来源；
- 用小数值例子比较 GRPO 与 GSPO 在 MoE 路由抖动下的梯度；
- online 链路上“序列”应按轮还是按整条轨迹，序列级处理作用在哪个比值上，待与负责人对齐；
- Routing Replay 与 GSPO 二选一还是叠加；
- 原始分布 logprob 与截断采样的口径差对 behave 一侧比值的实际影响，待用数据验证；
- 推训精度偏差的重要性采样修正（TIS/MIS 一类）待系统学习。
