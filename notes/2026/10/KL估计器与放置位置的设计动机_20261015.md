## 1. 先给结论

- **k1/k2/k3 都是“只用一个被采样 token”估计 KL 的公式**。k1 无偏但单样本可为负、方差大；k3 靠加一个期望为 0 的 `(r − 1)` 做到无偏且非负、方差小；k2 非负但有偏。
- **“reward 用 k1、loss 用 k3”不能反过来**：k1 直接进 loss 求导，期望梯度为 0，等于没约束；k1 当 reward 走策略梯度，期望梯度正好是序列 KL 的梯度。k3 进 loss 的期望梯度是**反向** KL(π_ref‖π_θ) 的梯度，两分布接近时与正向几乎相同。
- **两种放法目的相同、约束对象不同**：进 reward 约束整条序列的 KL 总量，偏离由之前所有 token 分担，设计前提是有 critic；进 loss 只拉回偏离发生的位置，GRPO 这样做是为了让 Â 保持“每条回答一个数”。
- **KL 放置与异步无关**：它是同步 PPO-RLHF 时代的算法选择；两种放法的计算代价都是同一次 ref 前向，不影响训推重叠。异步下 k1 进 reward 恰好更自洽，这是巧合的好处。
- **KL 和批级归一化是两个独立开关**（被纠正的误解）。关掉批级归一化，KL 照样在 advantage 里；开着时等效 β 变成 β/s，每步都在变。
- **批级归一化“本身没问题”只对一半**（被纠正的误解）：按 token 加权减均值，对“每条一个数再广播”的序列级 advantage 是实现缺陷；除以 s 是设计取舍。用户据此把问题拆成两项：GRPO 配方叠加批级归一化是配置问题；归一化组件本身的正确性要为后续 PPO 单独保证。

## 2. 前置概念

### 2.1 为什么要“估计” KL

```text
KL(π ‖ π_ref) = E_{x~π}[ log π(x) − log π_ref(x) ]
```

严格计算要对整个词表求和，而且每个位置都要算一次，代价太大。实际只看这个位置**真正被采到的那个 token x**，用它的两个概率构造一个估计量，再在大量 token 上平均。

### 2.2 三个估计器

记 `r = π_ref(x) / π(x)`（ref 与当前策略在被采样 token 上的概率比）：

| 名字 | 公式 | 期望等于真实 KL？ | 单样本可为负？ | 方差 |
|---|---|---|---|---|
| k1 | `−log r = log π(x) − log π_ref(x)` | 是（无偏） | 会 | 大 |
| k2 | `½ (log r)²` | 否（有偏） | 不会 | 小 |
| k3 | `(r − 1) − log r` | 是（无偏） | 不会 | 小 |

k3 的技巧：在 π 下 `E[r] = Σ π · π_ref/π = 1`，所以多加的 `(r − 1)` 期望为 0，不改变期望，却抵消了 k1 的大部分波动。又因为 `log r ≤ r − 1`，k3 每个样本都 ≥ 0。

手算两个 token：

| π | π_ref | r | k1 | k3 |
|---|---|---|---|---|
| 0.5 | 0.4 | 0.8 | +0.223 | +0.023 |
| 0.1 | 0.2 | 2 | **−0.693** | +0.307 |

KL 本身不可能为负，但 k1 在单个 token 上经常为负，要靠大量样本才能正负抵消到正确值。

## 3. 完整原理

### 3.1 用 4 个 token 看两种放法的差别

一条 4 token 的回答，组内归一化后得分 R̂ = +1；为看清楚取 β = 1，每个 token 的 KL 为 `[0.1, 0, 0.3, 0]`：

| token | 自己的 KL | KL 进 reward：A_t（从 t 往后累加） | KL 进 loss：A_t | KL 进 loss：额外惩罚 |
|---|---|---|---|---|
| 1 | 0.1 | 1 − 0.1 − 0.3 = **0.6** | 1 | 拉回 0.1 |
| 2 | 0 | 1 − 0.3 = **0.7** | 1 | 无 |
| 3 | 0.3 | 1 − 0.3 = **0.7** | 1 | 拉回 0.3 |
| 4 | 0 | **1.0** | 1 | 无 |

token 2 自己完全没偏离，但在 KL 进 reward 时因为后面的 token 3 偏离也被扣了 0.3：“是你把轨迹带偏的”。KL 进 loss 时 advantage 保持干净，只有真正偏离的位置被拉回。

| | KL 进 reward（PPO-RLHF） | KL 进 loss（GRPO 论文） |
|---|---|---|
| 谁为偏离负责 | 偏离发生之前的所有 token 一起分担 | 只有偏离发生的那个位置 |
| 约束的量 | 整条序列 KL 之和，越长罚得越多 | 每个 token 的平均 KL，与长度无关 |
| 怎样产生梯度 | 作为 advantage 的一部分，借策略梯度起作用；KL 本身 detach（k1） | 自己就是可求导的 loss 项（k3） |
| 和 advantage 处理的关系 | 经过 reward-to-go、批级归一化和 clip | 完全独立 |

表的后两行在 [当天 §3.9](温度偏差实测与KL放置位置_20261015.md#39-kl-的两种放法完整对比) 已有，这里补的是“谁负责”的直观例子。

### 3.2 两种设计各自的出发点

- **KL 进 reward**：出发点是带 KL 约束的 RL 目标 `max E[R] − β·KL(π‖π_ref)`。整条序列的 KL 正好等于逐 token KL 之和，所以自然把它当作每一步的小 reward，交给 return 和 critic 做信用分配：critic 学着预测“未来还会付出多少 KL 代价”，降低方差。**整套设计的前提是有 critic。**
- **KL 进 loss**：GRPO 没有 critic，它的 advantage 只有一个含义——“这条回答比同组兄弟好多少”，每条一个数、广播到所有 token。把逐 token KL 混进 reward，Â 就不再是每条一个数；零方差组会凭空冒出信号；长回答累积的 KL 还会和组间比较搅在一起。单独拿出来按 token 平均，Â 的语义干净，正则也与长度无关。

### 3.3 为什么 reward 用 k1、loss 用 k3

**k1 当 reward**：序列 KL 目标的梯度（x 按 π_θ 采样）是

```text
∇ E_π[ Σ_t k1_t ] = E_π[ (Σ_t k1_t) · ∇log π_θ(y) ] + E_π[ Σ_t ∇log π_θ(y_t) ]
                                                        └── 期望为 0
```

第一项就是“把 k1 当 reward、detach 后走策略梯度”。所以 k1 无偏 + 策略梯度 = 序列 KL 目标的无偏梯度。

**k1 直接进 loss**：`∇k1 = ∇log π_θ(x)`，而 `E_{x~π_θ}[∇log π_θ(x)] = Σ ∇π_θ = ∇1 = 0`。期望梯度为 0，等于没加约束。

**k3 进 loss**（整理时补全的推导）：

```text
k3 = π_ref/π_θ − 1 − log π_ref + log π_θ
∇k3 = (1 − r) · ∇log π_θ
E_{π_θ}[∇k3] = Σ (π_θ − π_ref) ∇log π_θ = −Σ π_ref ∇log π_θ = ∇ KL(π_ref ‖ π_θ)
```

严格说它优化的是**反方向**的 KL。π_θ 与 π_ref 很接近时两个方向几乎相同，这是 k3 在实践中好用的原因。

### 3.4 和异步训练有没有关系

用户猜测这种写法是为异步流式训练设计的。**不是**：

- **来历**：KL 进 reward 是从同步 PPO-RLHF 继承来的写法（常配自适应 KL 控制器，自动调 β 让 KL 停在目标值附近），早于异步特性；论文式 KL loss 是后来为兼容其他框架才加的开关。
- **资源**：无论放在哪，代价都是同一次 ref 前向，发生在训练步里、不在 rollout 侧。异步下 rollout 本来就和训练并行，KL 放哪不影响能重叠多少计算。

但异步之后有一个性质“恰好”成立（讲解者的分析，非框架官方说法）：

| | 估计用的样本 | 是否无偏 | off-policy 修正 |
|---|---|---|---|
| k1 进 reward | k1(π_behave, π_ref)，样本正好来自 π_behave | 是 | 在 advantage 里，和任务 reward 一起经过行为侧权重与拒绝采样 |
| k3 进 loss | k3(π_θ, π_ref)，无偏要求样本来自 π_θ | 数据其实来自旧策略 | 若实现没给这一项乘重要性权重，就没有修正 |

所以异步下 KL 进 reward 反而更自洽。陈旧度只有一两个版本、训推差很小时，这个差别可以忽略。**是巧合的好处，不是设计动机。**

### 3.5 KL 与批级归一化是两个独立开关（被纠正的误解）

用户问：“不开 adv norm，是不是就没法放 KL？”不是。KL 有三种状态，和批级归一化各自独立：

| 设置 | KL 去哪了 | 和批级归一化的关系 |
|---|---|---|
| KL 进 reward 的系数 > 0 | 并入 reward，经 reward-to-go 进入 advantage | 开不开都在；开了只是之后再把整个 advantage（含 KL）平移、缩放一次 |
| 开 KL loss | 独立的 loss 项 | 完全无关 |
| 系数为 0 且不开 KL loss | 没有 KL，也不必创建 ref 模型 | 无关 |

某个配置“没有 KL”，原因是它把 KL 系数设为 0 且不建 ref，与它关掉批级归一化无关。

反过来，**不开批级归一化时 KL 进 reward 更干净**：β 就是字面值。开了以后 KL 也被除以 s，等效 β 每步都在变，信号消失时被放大（[1/s 像自动增益](温度偏差实测与KL放置位置_20261015.md#35-批级归一化影响的不只是零方差组被纠正的误解)）。

这张表顺带说明了归因实验怎样把两个因素拆开：一组同时关 KL 和批级归一化，一组只关 KL，一组只关批级归一化。只看第一组无法区分是哪个因素起作用（与 [只用配置拆开平移与缩放](GRPO变体与两层归一化的拆解_20261013.md#39-怎样只用配置把平移和缩放拆开) 同一思路）。

### 3.6 批级归一化：哪部分是缺陷、哪部分是取舍（被纠正的误解）

用户的判断：“GRPO 不该开 adv norm，是配置问题，adv norm 本身没问题。”前半句对，后半句要拆开：

- **减均值（m 平移）是实现缺陷**：批级统计只能按 token 加权，没有“每条回答算一票”的选项。带 critic 的 PPO 每个 token 的 advantage 本来就不同，按 token 统计是对的；但 GRPO 的 advantage 是每条一个数再广播，组内已经减过均值，这一步本应约等于 0。按 token 加权让它变成非 0，进而平移零方差组（手算见 [当天 §3.6](温度偏差实测与KL放置位置_20261015.md#36-归一化的到底是什么不是-token-的-reward)）。实现成按条统计，这一步就无害。
- **除以 s（1/s 放大）是设计取舍**：本意是让每步梯度尺度稳定，代价是信号少时放大；group mean + batch std 的配方同样有这个性质。有没有害要靠实验判断。

还有一点：**“GRPO 不该开”会偏离很多框架的默认配方**——批级 std 常被当作标准做法写进各 GRPO 类示例里。改默认值前要有对照实验支撑。

用户最后的拆分是：**配置问题**（GRPO 配方在组内归一化后又叠一层批级归一化）与**组件正确性**（归一化组件本身，后续支持 PPO 时一定会用到）分成两项分别处理。按“修法能否只靠配置”来分类，见 §3.8。

### 3.7 为 PPO 审一遍归一化组件：四条通用检查

按带 critic 的 PPO 用法重新审查时，值得检查的点：

1. **核心数学**：按 token 加权对逐 token 不同的 advantage 是标准做法。**return 要在归一化之前算**（`return = advantage + value`），critic 拟合的才是未归一化的回报。
2. **缺少按条统计的选项**：只影响序列级 advantage（GRPO、GSPO 一类），做序列级算法时直接相关。
3. **归一化范围**：对整个训练 batch 归一化一次，与常见 PPO 实现按 minibatch 归一化不同。minibatch 数 > 1 时两者语义不同。
4. **分布式边界**：如果某个 rank 的有效 token mask 全为 0，在集合通信（all-reduce）之前提前返回，其他 rank 会一直等它 → 卡死。**原则：所有 rank 必须走过相同的集合通信序列，空数据也要参与（贡献 0）**，不能用提前返回处理边界。

另一个支持 PPO 前必须先修的通用问题：**“回答是否被截断”必须逐条判断**。如果用“整个 batch 里最长的那一行”来判断有没有 EOS，引入 critic 后会出错：被截断的序列需要用 V(s_T) bootstrap 后续价值，正常结束的不需要，两者混在一起 GAE 就算错了。GRPO 没有 critic，这个错误不显形。

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 逐 token 的 KL 读数经常为负 | 用的是 k1，单样本可为负 | 换 k3 看是否全部 ≥ 0、均值接近 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| k1 为负说明算错了 | k1 单样本本来就可为负，只有平均才等于 KL |
| k1、k3 都无偏，放哪都一样 | k1 进 loss 期望梯度为 0；k1 适合当 reward，k3 适合进 loss |
| k3 进 loss 优化的就是 KL(π_θ‖π_ref) | 期望梯度是反向 KL(π_ref‖π_θ) 的梯度，两者接近时才近似相同 |
| KL 进 reward 是为异步流式训练设计的 | 继承自同步 PPO-RLHF；两种放法计算代价相同，异步下的自洽是巧合 |
| 不开批级归一化就没法放 KL | 两个开关独立；不开时 β 反而是字面值 |
| 批级归一化本身没问题，只是 GRPO 不该开 | 按 token 加权减均值对序列级 advantage 是实现缺陷；除以 s 是取舍 |
| 空数据的 rank 直接返回最省事 | 会跳过集合通信，让其他 rank 卡死 |

## 7. 一分钟复习

1. r = π_ref/π：k1 = −log r（无偏、可负、方差大），k3 = (r−1) − log r（无偏、非负、方差小），k2 有偏。
2. k1 进 loss 期望梯度 0；k1 当 reward + 策略梯度 = 序列 KL 梯度；k3 进 loss 梯度 (1−r)∇log π，期望是反向 KL 的梯度。
3. KL 进 reward：前面的 token 替后面的偏离买单，约束序列总量，前提是有 critic；KL 进 loss：只拉回偏离位置，保持 Â 每条一个数。
4. KL 放置不是为异步设计的；异步下 k1 进 reward 恰好自洽，k3 进 loss 缺重要性权重。
5. KL 与批级归一化独立；开批级归一化时等效 β = β/s。
6. 批级归一化：减均值按 token 加权 = 序列级 advantage 的实现缺陷；除以 s = 设计取舍。
7. 集合通信前不能提前返回；截断必须逐条判断，否则 critic 的 bootstrap 出错。

## 8. 自测问题

### 问题 1

π = 0.1、π_ref = 0.2，分别算 k1 和 k3。为什么 k3 能无偏又非负？

期望回答：r = 2，k1 = −log 2 ≈ −0.693，k3 = (2 − 1) − 0.693 ≈ 0.307。在 π 下 E[r] = 1，加 (r − 1) 不改变期望；又因 log r ≤ r − 1，每个样本 ≥ 0。

### 问题 2

为什么不能把 k1 直接放进 loss 求导？

期望回答：∇k1 = ∇log π_θ(x)，在 x ~ π_θ 下期望为 Σ∇π_θ = 0，期望梯度为 0，约束无效。k1 要当 reward、detach 后经策略梯度起作用。

### 问题 3

一条回答 4 个 token 的 KL 为 [0.1, 0, 0.3, 0]、R̂ = 1、β = 1。KL 进 reward 时 token 2 的 advantage 是多少？为什么它会被扣分？

期望回答：0.7。reward-to-go 把 token 2 之后的 KL（0.3）累加进来；KL 进 reward 的语义是“偏离由之前所有 token 分担”。

### 问题 4

有人说“不开批级 advantage 归一化，训练里就没有 KL 了”。怎么纠正？

期望回答：KL 有三种状态（进 reward、进 loss、关闭），与批级归一化独立。关掉批级归一化后 KL 照样经 reward-to-go 进入 advantage，而且 β 是字面值；开着时等效 β = β/s。

### 问题 5

分布式训练中，某 rank 的有效 token 全为 0，归一化函数提前返回。会发生什么？怎么改？

期望回答：其他 rank 在 all-reduce 处等它，训练卡死。空数据也要参与集合通信，贡献 0 的分子和分母。
