## 1. 先给结论

- **PP 按层竖着切**，切口处只点对点传一次激活，所以能跨机器；代价是流水线空泡，靠拆 Microbatch（1F1B）摊薄，空泡占比约 `(p−1)/(m+p−1)`。
- **MTP 天然属于最后一个 PP Stage**：它要的主干末层 Hidden、LM Head、Labels 都在那里。唯一缺的是 Token Embedding，于是最后一个 Stage 需要一份 **Embedding 副本**，这带来了“两份参数是否一致”的新风险。
- **CP 切的是 Token（序列维度），是数据而不是参数**。只有“混合不同 Token”的算子需要通信：Full Attention 用 Ring 交换 K/V（可与计算重叠），线性注意力/GDN 常用两次 All-to-All（阻塞）。
- **Zigzag 切分**把序列分成 `2×cp` 块、首尾配对，是为了在 Causal Attention 下均衡负载、消除 CP 版的“空泡”。
- **SP 是挂在 TP 上的省显存技巧**：把 TP 区域外（Norm、Dropout、残差）的激活沿序列切成 `1/tp`，用 Reduce-Scatter + All-Gather 替换原 All-Reduce，**不增加通信量**。
- SP 的份数被绑死在 TP 上，Attention 仍看完整序列；长上下文要独立放大序列切分时选 CP。
- **SP 卡间传的是激活值，不是参数**：参数永久按 TP 切分；反向时只保存本卡分片、再 All-Gather 一次拼回完整输入；复制在每卡上的 Norm 等参数，在 SP 下梯度要在 TP 组内求和。
- **激活值是前向的中间结果**，为反向算梯度而保存，规模 ∝ Token 数 × hidden × 层数；长序列下它而非参数是显存主瓶颈。

## 2. 前置概念

### 2.1 为什么一张卡装不下

训练时每个参数大致需要：

| 内容 | 每参数开销 |
|---|---|
| BF16 参数 | 2 Byte |
| 梯度 | 2～4 Byte |
| Adam 状态（FP32 主权重 + 两个动量） | 12 Byte |
| 激活 | 随序列长度、层数增长 |

数十 B 参数的模型仅参数、梯度和优化器状态就达数百 GB，必须拆到多卡。

### 2.2 五种切法总表

把 Transformer 想成二维表：竖向是层，横向是层内矩阵。

| 并行 | 切什么 | 通信什么 | 通信特点 |
|---|---|---|---|
| TP | 每层内部矩阵（横切） | 每层 All-Reduce 中间结果 | 大且频繁，通常限于机内高速互联 |
| PP | 按层竖切 | 切口处 P2P 传激活 | 小且少，可跨机 |
| EP | MoE 不同专家放不同卡 | Token 分发给专家（All-to-All） | 中等 |
| CP | 一条长序列切成多段 | Attention 时交换 K/V 等 | 随序列长度增长 |
| DP | 不切模型，切数据 | 每步梯度 All-Reduce | 每步一次 |

PP 存在的理由就在表里：TP 能切参数但通信太频繁，跨机会很慢；PP 只在切口传一份激活。

## 3. 完整原理

### 3.1 PP 的空泡与 1F1B

Stage 1 要等 Stage 0 前向完，Stage 0 又要等 Stage 1 把反向传回。一次只喂一批数据时总有卡空等。把 Batch 拆成 `m` 个 Microbatch，交替执行前向/反向：

```text
时间 →
stage 0:  F1 F2 F3 F4 B1 F5 B2 ...
stage 1:     F1 F2 B1 F3 B2 F4 ...
```

空等只发生在开头和结尾，占比约 `(p−1)/(m+p−1)`（`p` 为 Stage 数）。长上下文 RL 中每个 DP 组每步常有数十个 Microbatch，PP=2 时空泡只有百分之几。

长上下文的一种常见组合：用较大 CP 切序列；为避免 CP 与 TP 叠加造成层内通信过重，令 TP=1，改用 PP 竖切分摊参数与优化器状态，MoE 专家再用 EP 分散。

### 3.2 MTP 在 PP 下怎样工作

MTP 每层输入三样：主干末层 Hidden、错位一格 Token 的 Embedding、计算 Loss 的 LM Head 与 Labels。前一和后一天然在最后一个 Stage，所以 MTP 放在最后 Stage 无需额外跨 Stage 激活传输（Owner 契约见 [MTP 与 PP 阶段所有权](../08/MTP与PipelineParallel阶段所有权_20260818.md#3-为什么-mtp-通常属于最后一个-pp-stage)）。

```text
Stage 0：Embedding（主副本）→ Decoder 前半
                    │ P2P 激活
Stage 1：Decoder 后半 → Output Layer + 主 Loss
         ├─ Hidden（detach）────────┐
         ├─ Embedding 副本 → 错位 Token Embed（detach）→ MTP 层 → MTP Loss（LM Head detach）
Embedding 主副本 ⇄ 副本：Embedding Group 梯度 All-Reduce 保持同步
```

新增的理解点：

- **Embedding 副本**：主 Embedding 在 Stage 0，最后 Stage 需要再建一份，并与主副本放进同一个 Embedding Group，每步对梯度做 All-Reduce 保持一致（这是 Megatron-Core 的设计，本地未读源码，属推断）。
- **detach 与 PP 配合得好**：三样输入都 detach 时，MTP Loss 的梯度只流到 MTP 参数，反向在最后 Stage 本地闭环，不增加 PP 通信。
- **一份参数、两处来源**：在线权重同步时，两个 Stage 都会以同一个名字发送 Embedding，后发的覆盖先发的。若两份不一致，**不只 Drafter，推理端主模型（Target）的 Embedding 也会被副本覆盖**——MTP 的问题被放大成主 Policy 的问题。可选对策：同步时只发 Stage 0 的那份，或实测两份始终相等。
- **最后 Stage 偏重**：它已有 Output Layer 与 Loss，又加 MTP 层、额外的词表投影与 CE、一份 Embedding 及其优化器状态；均匀切层会放大空泡，Layout 可给最后 Stage 少分几层。

### 3.3 CP 怎么切：Zigzag

CP 组内每卡持有完整的（TP/PP 下分到的）层权重，只处理一条序列 `1/cp` 的 Token。激活与序列长度成正比，长上下文下激活才是显存大头。

Causal Attention 中越靠后的 Token 要看的前文越多。若顺序切分，拿到末段的卡最累、其他卡等它。Zigzag 把序列切成 `2×cp` 块，第 `r` 张卡拿第 `r` 块与第 `2cp−1−r` 块：

```text
cp=2，序列: [块0][块1][块2][块3]
rank0: 块0 + 块3
rank1: 块1 + 块2
```

一前一后配对使各卡计算量接近。因此 Padding 常需对齐到 `tp × cp × 2` 的倍数；Packed 序列应逐条做 Zigzag 以保持均衡。

### 3.4 CP 下哪些算子要通信

| 算子 | 是否跨 Token | CP 通信 |
|---|---|---|
| MLP、MoE、Norm、QKV/输出投影 | 否 | 不需要 |
| Full Attention | 是，Q 要看全部 K/V | Ring：各卡保留 Q，K/V 块沿环传 `cp−1` 轮，边算边传 |
| 线性注意力 / GDN | 是，且沿序列有递推状态 | 两次 All-to-All：从“每卡一段序列、全部 Head”转成“每卡完整序列、`1/cp` Head”，算完再转回 |
| MTP Token 错位 | 只涉及块边界 | 只交换边界处少量 Token |

混合架构里多数层是线性注意力时，CP 通信的大头其实是 All-to-All 而不是 Ring。

### 3.5 CP 的“空泡”要分三类看

- **Ring Attention 基本无空泡**：每轮所有卡同时计算，只要算一块的时间不短于传一块，通信就被掩盖；长上下文下每块计算量大，通常能盖住。
- **All-to-All 是实打实的通信时间**：阻塞、不与计算重叠，每个线性注意力层付两次。这不叫空泡，但直接加到步时。
- **同步等待才是真正的空泡来源**：每层 Attention/GDN 处 CP 组都要互等；序列长度不一、Padding 不均都会让快卡等慢卡。CP 组跨机时还要走网卡，比机内互联慢（推断）。

### 3.6 SP：TP 留下的重复激活

TP 中 Attention 按 Head 切、MLP 先列切后行切，矩阵乘区域的激活已是 `1/tp`。但 Norm、Dropout、残差等非矩阵乘算子处，每张卡都持有**完整的 `[seq, hidden]`**——`tp` 份一模一样的数据。

这些算子都是逐 Token 的，SP 让它们沿序列切开：

```text
[S/tp, h]  SP 区域：Norm、残差
   │ All-Gather
[S, h]     TP 区域：列切 QKV → 按 Head 做 Attention → 行切输出投影
   │ Reduce-Scatter（求和 + 按序列切）
[S/tp, h]  回到 SP 区域
```

因为 All-Reduce = Reduce-Scatter + All-Gather，SP 只是把原来的一次 All-Reduce 拆成两半放到区域出口和下一入口，**带宽不变**，却把这部分激活显存降到 `1/tp`。模块边界若处在 SP 区域（如某个附加 Head 的输入），需要先 Gather 回完整序列再计算。

### 3.7 SP 与 CP 的区别

| | TP 的 SP | CP |
|---|---|---|
| 用哪组卡 | 就是 TP 组，没有独立维度 | 独立的一组卡 |
| 切的范围 | 只切逐 Token 区域，进入 Attention/MLP 前拼回 | 整层都切，Attention 也只有部分序列 |
| Attention | 看完整序列，按 Head 切 | 靠 Ring 或 All-to-All 看到其他卡的 Token |
| 通信 | 复用 TP 原有通信 | Ring K/V、All-to-All 为额外通信 |
| 份数 | 等于 tp | 等于 cp，可独立放大 |

所以“长序列为什么不靠 SP 切”：想切 16 份就得 TP=16，每层都要在跨机的 16 卡间 All-Gather/Reduce-Scatter，难以掩盖，且 Attention 输入仍是完整序列。

### 3.8 SP 补充：传的是激活值，不是参数

追问时的理解是：“SP 让每卡只存自己需要的张量；逐 Token 的地方只用这一部分；到了 Attention 这类要看完整序列的地方，复用 TP 原有通信把**别的卡上的参数**传过来，算完把收到的东西扔掉——所以省显存。”

大方向对（目的就是省显存、复用 TP 通信、完整序列不常驻），但要纠正一处、补充两处。

**纠正：参数从不在卡间传输。** 以 tp=8、序列长 S 为例：

- 参数：TP 一开始就把 QKV、输出投影、MLP 的权重切成 8 份，每卡**永久**只持有自己那 1/8（例如自己负责的那几个 Head），前向时不传参数；
- 激活：逐 Token 区域每卡只存 `S/8` 个 Token 的 Hidden；进入 Attention 前 All-Gather，收到**其他卡那部分 Token 的 Hidden**，拼成完整 `[S, h]`，再用本卡那份 Head 权重算 QKV 与 Attention。

更准确的说法：“需要完整序列时，把其他卡上那部分 Token 的激活值收过来，用本卡的那份参数算完。”

**补充一：反向时完整序列从哪来。** 列切线性层计算权重梯度需要它的输入，也就是完整的 `[S, h]`。如果为反向一直保存完整序列，SP 就白省了。Megatron 的做法是**只保存本卡 `[S/tp, h]` 分片，反向时再 All-Gather 一次**，临时拼出完整输入，算完梯度即丢——用一次额外通信换显存，这是 SP 真正省下显存的关键。

**补充二：复制参数的梯度要在 TP 组内求和。** Norm 权重这类小参数不被 TP 切分，每卡都有完整一份。没有 SP 时每卡处理完整序列，各卡梯度本来相同；开了 SP，每卡只处理 `S/tp` 个 Token，梯度只反映自己那部分，必须在 TP 组内 All-Reduce 求和才是完整梯度。Megatron 给这类参数打 `sequence_parallel` 标记，在优化器更新前统一做这次求和。输入落在 SP 区域的附加小 Head（例如价值头）同理。

一句话：**SP 只改变激活值怎么存**——逐 Token 区域只存 `1/tp`，需要完整序列时临时 All-Gather、反向再拼一次；参数仍按 TP 方式切，只有复制在每卡上的小参数需要额外做一次梯度求和。

### 3.9 激活值复习：为什么训练要存、为什么随序列变长

最小例子 `y = W·x`：`W` 是**参数**，训练要学、一直存在、与输入无关；`x`、`y` 是**激活值**，由这一次输入算出，换一批数据就不同。Transformer 每层的 Norm → QKV 投影 → Attention → 输出投影 → 残差 → Norm → MLP，每一步输出都是形如 `[Token 数, hidden]` 的激活张量。基础定义见 [训练与 RL 后训练基础 §2.3](../07/训练与RL后训练基础_20260724.md)。

**为什么训练必须保存。** 推理算完一层就能丢掉上一层的结果，训练不行：

$$
\frac{\partial L}{\partial W} = \frac{\partial L}{\partial y}\, x^\top
$$

算 `W` 的梯度要用前向时这一层的输入 `x`，所以前向过程中各层输入与中间结果都要留到反向传到这里。这些“为反向而保存的激活”是训练显存的大头之一。

**它有多大。** 以 hidden=4096、32 层的模型处理 32K Token 为例：一个 BF16 的 `[32768, 4096]` 张量 = 32768 × 4096 × 2 Byte = 256 MiB；一层要保存好几个这种量级的张量，MLP 中间层还要宽几倍；再乘 32 层，不做任何处理很容易超过 100 GB（粗估，取决于实现与是否重算）。

| | 参数 | 激活值 |
|---|---|---|
| 是什么 | 模型要学的权重 | 前向算出的中间结果 |
| 大小取决于 | 模型规模 | Token 数 × hidden × 层数 |
| 序列长度变成 3 倍 | 不变 | 变成 3 倍 |
| 存多久 | 一直存在 | 前向产生，反向用完释放 |

所以序列一长，激活就会超过参数，成为显存的主要瓶颈。

**省激活显存的四种办法：**

- 重算（Activation Checkpointing）：前向只保存少数检查点，反向时重算中间结果，用计算换显存（见 [MTP 重计算与显存测量](../09/MTP重计算布局与显存测量_20260909.md)）；
- TP + SP：逐 Token 区域的激活沿 Token 维切成 `1/tp`；
- CP：整层激活沿 Token 维切成 `1/cp`；
- PP：每个 Stage 只存自己那些层的激活（1F1B 下要同时保存若干在途 Microbatch 的激活）。

回到 §3.7：**SP 与 CP 切的都是激活的 Token 维**，差别在于 SP 只切逐 Token 区域，CP 连 Attention 一起切。

| 现象 | 原因 | 如何验证 |
|---|---|---|
| PP 下最后 Stage 步时明显更长 | Output Layer、Loss、MTP 都在最后 Stage | 分 Stage profile；调整 Layout 让最后 Stage 少分层 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 训练慢在 PP 空泡 | Microbatch 数多时 PP=2 空泡只有百分之几 |
| CP 切的是模型参数 | CP 切 Token；每卡持有同样的层权重 |
| 切上下文必然带来大量空泡 | Ring 可与计算重叠；真正的空泡来自负载不均的互等 |
| SP 是另一种独立并行维度 | SP 复用 TP 那组卡与通信，份数等于 tp |
| SP 会增加通信量 | All-Reduce 被拆成 Reduce-Scatter + All-Gather，总量不变 |
| MTP 只影响 Drafter | PP 下 Embedding 副本覆盖会影响主模型 |
| SP 在 Attention 处把其他卡的参数传过来 | 传的是其他卡那部分 Token 的激活值；参数永久按 TP 切分、从不传输 |
| SP 前向用完就扔，反向没有额外代价 | 反向要再 All-Gather 一次拼回完整输入，用通信换显存 |
| SP 不影响参数梯度 | 复制在每卡上的 Norm 等参数只看到部分 Token，梯度要在 TP 组内求和 |
| 显存大头永远是参数和优化器状态 | 长序列下为反向保存的激活随 Token 数线性增长，会成为主瓶颈 |

## 7. 一分钟复习

1. TP 横切层内，PP 竖切层，CP 切 Token，SP 在 TP 内切逐 Token 区域。
2. PP 空泡 ≈ `(p−1)/(m+p−1)`，靠多 Microbatch 摊薄。
3. MTP 在最后 Stage 本地闭环，但需要一份 Embedding 副本。
4. Zigzag：`2×cp` 块首尾配对，均衡 Causal 负载。
5. Ring 可重叠，All-to-All 阻塞；互等才是真空泡。
6. SP 传激活不传参数；反向再 All-Gather；复制参数的梯度在 TP 组内求和。
7. 激活为反向而存，∝ Token × hidden × 层数；SP、CP 都切激活的 Token 维。

## 8. 自测问题

### 问题 1

为什么 PP 可以跨机，TP 通常不行？

期望回答：PP 只在切口处每个 Microbatch 传一次激活；TP 每层都要 All-Reduce，频繁且量大，跨机带宽撑不住。

### 问题 2

cp=4 时 Zigzag 怎么分块？为什么这样分？

期望回答：切 8 块，rank r 拿块 r 与块 7−r；Causal 下靠后的块计算更重，首尾配对使各卡计算量接近。

### 问题 3

SP 为什么不增加通信？

期望回答：普通 TP 在区域出口做 All-Reduce；SP 改为出口 Reduce-Scatter、下一入口 All-Gather，两者之和等于一次 All-Reduce。

### 问题 4（对话中留下的思考题，尚未核对）

若把 `detach_encoder` 改成 false，PP=2 下会多出哪条跨 Stage 通信？Embedding 副本不一致的风险变大还是变小？

初步思路（待与代码核对）：MTP 梯度会进入最后 Stage 的主干 Hidden，再沿已有的反向 P2P 传回 Stage 0，通信链路不变但携带的梯度变了；Embedding 副本也将获得 MTP 梯度，并经 Embedding Group All-Reduce 汇入主副本。

### 问题 5

开了 SP 后，RMSNorm 权重的梯度为什么需要额外一次 TP 组内 All-Reduce？不开 SP 时为什么不需要？

期望回答：开 SP 后每卡只处理 `S/tp` 个 Token，复制在每卡上的 Norm 权重算出的梯度只反映部分 Token，要求和才完整；不开 SP 时每卡都处理完整序列，各卡梯度本来就一致。

### 问题 6

为什么推理时不需要保存激活，训练时却要？序列从 32K 变成 96K，参数显存和激活显存各怎么变？

期望回答：权重梯度 `∂L/∂W = ∂L/∂y · xᵀ` 需要前向输入 `x`，所以训练要把各层输入留到反向；推理没有反向。序列变 3 倍时参数不变，激活约变 3 倍。
