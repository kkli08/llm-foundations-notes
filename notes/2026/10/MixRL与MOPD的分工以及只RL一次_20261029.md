## 0. 今天最终要解决的问题

按提问顺序：

1. 最近比较火的这个 Mix RL，和 MOPD 有什么区别？
2. 你是说小米的这个 Mix RL 和 MOPD 不太一样吗？（**第一轮回答把 Mix RL 当成"只是一个范式名"，漏掉了最近那次"只 RL 一次"的发布**）

## 1. 先给结论

- **一句话区分**：Mix RL 是把所有领域的数据混在一起、直接对一个模型做 RL，学习信号是整条回答的**结果奖励**；MOPD（Multi-Teacher On-Policy Distillation）分两步——先在每个领域单独用 RL 训一个专家教师，再让学生自己采样、由对应领域的教师**逐 token** 打分，把几个教师蒸馏进一个模型。
- **最关键的区别不是"混不混"，是信号粒度和能力上限**：Mix RL 是序列级信号、理论上可以超过单领域训练；MOPD 是 token 级密集信号、收敛快，但**被教师封顶**。
- **生产版 MOPD 并不是纯蒸馏**：优势是 `A = sg[log(π_教师/π_θ)] + α·A_结果奖励`。**α = 0 就是纯蒸馏，α 很大时退化回 Mix RL** —— 两者不是互斥的二选一，而是**一个连续谱**上的两端。
- **四篇公开工作的结论互相不一致**，所以不能只记一个数：原论文给出 MOPD 明显领先但**没有算力对齐**；一篇综述发现三类方法平均差距很小而单 benchmark 差距很大，且**三者都只提升单次采样准确率、没有扩大解题覆盖面**；另一篇发现跨领域干扰其实很少、推理密集领域还互相促进，**削弱了"Mix RL 一定被干扰拖累"**；一篇复现工作把 MOPD 的短板归到 **token 级预算分配失衡**而不是梯度冲突。
- **最新一代流程把"合并多能力"的位置从蒸馏阶段挪到了 RL 阶段**（"只 RL 一次"）：一次混合 RL 同时训多领域多 harness，MOPD 降为之后的补充阶段（MOPD2），主要补自动打分难的任务。
- **MOPD2 最值得学的工程点是三路数据里的两路前缀**：接着更强教师的轨迹前缀、或 SFT 示范的前缀往下生成 —— **复用已有上下文、只在关键决策点上训练**，避免把很长的 agent 轨迹从头重跑。
- **选择依据**：没有现成专家 + 领域相近 → Mix RL（重点调配比）；多团队并行 + 领域差异大 + 要保住各自已有提升 → MOPD；想超过教师 → MOPD 加结果奖励，或蒸馏完再接一轮 RL。

## 2. 前置概念

### 2.1 两者各是什么

```text
Mix RL：  混合所有领域的数据 ──→ 一次 RL ──→ 一个模型
                               信号 = 整条回答的结果奖励

MOPD：    领域 1 数据 → RL → 教师 1 ┐
          领域 2 数据 → RL → 教师 2 ├─→ 学生自己采样，按领域路由到对应教师
          领域 3 数据 → RL → 教师 3 ┘    教师逐 token 给 log 比值 ──→ 一个模型
```

MOPD 的"on-policy"指的是**学生自己采样**（不是用教师的文本），所以没有 SFT 蒸馏那种 exposure bias；"multi-teacher"指的是**按领域路由**到不同教师。机制细节见 [10 月 26 日 §2.2](在线蒸馏OPD与多教师MOPD_20261026.md)。

### 2.2 信号粒度与能力上限

| | Mix RL | MOPD |
|---|---|---|
| 优势形式 | `Â = (r − mean)/std`，**一条回答里每个 token 拿同一个优势** | `Â_t = sg[log π_教师,d(y_t) − log π_θ(y_t)]`，**每个 token 一个** |
| 等价于在优化什么 | 期望结果奖励 | 在学生自己的采样上最小化**反向 KL**(π_θ‖π_教师) |
| 本质问的问题 | **结果对不对** | **对应领域的教师在这个位置会不会这么写** |
| 需要 verifier 吗 | 需要（每个领域各自的 reward） | 不需要（教师前向即可） |
| 样本效率 | 低 | 高（信号密集） |
| 能力上限 | 能在线探索，理论上可超过单领域训练 | **被教师封顶** |

"被教师封顶"这件事是 MOPD 的结构性限制，不是实现问题：优势为 0 的点就是"学生和教师在这个位置同样分布"，学生没有理由再往前走。

## 3. 完整原理

### 3.1 核心区别表

| | Mix RL | MOPD |
|---|---|---|
| 流程 | 一个阶段：混合数据 + 每个领域各自的 reward | 两个阶段：先分领域 RL 训教师，再多教师 on-policy 蒸馏 |
| 学习信号 | 序列级 | token 级，信号密集 |
| 本质 | 结果对不对 | 教师在这个位置会不会这么写 |
| 能力上限 | 可在线探索、理论上可超越 | 被教师封顶 |
| 主要难点 | **领域配比敏感，容易此消彼长（see-saw）** | **教师推理开销；不同领域的 token 预算分配不均** |
| 组织层面 | 各领域耦合，必须一起调 | 解耦，各团队可以并行训自己的教师 |

最后一行常被低估：**"各团队能不能并行"往往是真实的选型理由**，而不是指标差多少。Mix RL 要求所有领域的数据、reward、配比在同一次 run 里同时就绪。

### 3.2 生产版 MOPD 不是纯蒸馏（最容易忽略的一点）

公开技术报告里的生产配置是：

```text
A = sg[ log(π_教师 / π_θ) ] + α · A_结果奖励
    └── 逐 token 的教师密集信号 ──┘   └ 序列级结果奖励 ┘
```

于是：

| α | 等价于 |
|---|---|
| 0 | 纯 MOPD（纯蒸馏） |
| 适中 | 蒸馏 + 结果奖励联合 |
| 很大 | 退化回 Mix RL |

**所以"Mix RL 还是 MOPD"不是二选一，而是在一个连续谱上选 α。** 从实现上看，生产版 MOPD 可以理解成"Mix RL 再加一项教师逐 token 给的密集奖励"。

这也直接回答了"被教师封顶怎么破"：**加上结果奖励这一项，上限就不再只由教师决定**。与 [10 月 28 日 β 是两项梯度的相对比例](蒸馏项接入已有RL配方的正确写法与权重定法_20261028.md#37-蒸馏权重-β-怎么定) 是同一个结构 —— 只是那里是"蒸馏项加进 RL loss"，这里是"结果奖励加进蒸馏优势"，方向相反、数学形状一样。

### 3.3 四篇公开工作的结论互相不一致

这是本节最该记住的东西：**不要只记一个数**。

| 工作 | 结论 | 边界 |
|---|---|---|
| MOPD 原论文（30B-A3B 规模） | 归一化分数 MOPD **0.937** vs Mix RL **0.882**；差距归因于跨领域互相干扰。MOPD 每领域约 25–30K 样本就到教师水平，Mix RL 要 150–180K | **没有做算力对齐的比较** —— MOPD 的两阶段总算力含训教师的部分 |
| 融合范式综述 | 参数合并 / Mix RL / MOPD 三者**平均差距不超过 1.4 分**，但单个 benchmark 上**最多差 8.6 分**；三者都只提升单次采样准确率、**没有扩大解题覆盖面**。结论：Mix RL 依赖配比、MOPD 被教师封顶 | 平均值掩盖了单项的大差异 |
| "混合还是合并" | 跨领域 RLVR 的**互相干扰其实很少**，推理密集的领域之间还会**互相促进** | **削弱了"Mix RL 一定被干扰拖累"这个前提** |
| 开源复现工作 | 标准 MOPD 只拿回了 **35.6%** 的提升空间；原因**不是梯度冲突，而是 token 级优化预算分配失衡**；做了 token 占比平衡等修正后提升到 **83.4%** | 诊断本身是重要结论，见 §3.4 |

**读法**：第一篇的差距（0.937 vs 0.882）在第二篇里缩成 1.4 分，第三篇还推翻了第一篇对差距来源的解释。所以当前能说的只有"两类方法各有适用场景"，**不能说哪个更好**。

另外第二篇那句"三者都只提升单次采样准确率、没有扩大解题覆盖面"值得单独记：**这意味着三类融合方法都在把已有能力调得更稳定，而不是让模型会做原来不会做的题。** 想扩覆盖面得靠别的东西。

### 3.4 Open 复现工作的诊断：失衡不是冲突

这条诊断比那个百分比更有价值：

- **直觉的解释**：多教师蒸馏效果不好是因为**梯度冲突**（不同教师把学生往不同方向拉）；
- **实测的解释**：不是冲突，而是 **token 级优化预算分配失衡** —— 不同领域的回答长度差异很大，而优化预算是按 token 分的，于是**像指令遵循这种短回答的任务会被饿死**；
- 修正方式是平衡各领域的 token 占比，35.6% → 83.4%。

**通用规律**：**按 token 计数的 loss 归一化，会隐式地按"回答长度"给各类数据分配权重。** 任何"多种数据混在一起、按 token 平均"的训练都有这个问题 —— 长回答的领域自动拿到更多权重，不是因为它更重要，而是因为它更长。

这与已有的两条笔记同源：[loss 的 token 等权 vs 轨迹等权（9%/91% vs 50/50）](多轮轨迹拆行对GRPO与GSPO的影响_20261019.md)、[按有效 token 归一化](路由回放的代价转移与效果验证_20261010.md)。**本篇把它从"单任务内的长度偏置"推广到"多领域之间的预算分配"。**

### 3.5 当天被纠正的地方

第一轮回答说"Mix RL 不是某一个具体的新算法，它是最近这批讨论里的一种范式名，MOPD 论文和几篇对比论文都拿它当基线"。这个说法本身不错，但**漏掉了最近那次真正让它变火的发布** —— 用户追问"你是说小米的这个 Mix RL 和 MOPD 不太一样吗"才补上。

**教训**：被问"最近火的 X 和 Y 有什么区别"时，"X 是一个范式名"这种回答有可能回答错了问题 —— 对方问的往往是**某一次具体发布**。先确认指的是哪一次发布，再讲范式对比。

### 3.6 "只 RL 一次"：一次混合 RL 的具体做法

最新一代的做法（官方称 "You Only RL Once"）：

- **只跑一次 RL**，代码、通用 agent、视觉、网络安全几类任务，**加上多种 agent 框架（harness）**，全部混在同一个 batch 里一起训；
- 算法是**完全异步的 GRPO**，每步约 1568 个 prompt × 16 条 rollout；
- 奖励用两种机制叠加：
  - 一种**离线从对比的 rollout 里生成评分规则**（rubric）；
  - 另一种在**已经通过测试的轨迹之间**再按质量重新分配优势；
- 信号是整条轨迹的结果奖励加 rubric 打分。

第二种机制值得记：**通过测试的轨迹之间也要分出高低**。二元 reward 下这些轨迹全是 1、组内优势为 0、不贡献梯度（同 [零方差组](训练Reward不升的读法_20261028.md)）；在它们之间按质量重分配优势，等于**把原本浪费掉的全对组重新变成有信号的样本**。这是对"全对组无梯度"这个老问题的一个正面解法。

"把多种 harness 混在一个 batch 里"也是一个独立的设计选择：它让 reward 不再绑定某一个 agent 框架，官方声称能迁移到训练时没见过的 harness。

### 3.7 MOPD2 的三路数据与两路前缀

MOPD2 用三路数据：

| 路 | 怎么来 | 作用 |
|---|---|---|
| 1 | 学生自己完整跑的 rollout | 标准 on-policy 蒸馏 |
| 2 | **接着更强教师的轨迹前缀**往下生成 | 把学生放到"教师已经走对了一段"的状态上训练 |
| 3 | **接着 SFT 示范的前缀**往下生成 | 同上，前缀来自人工 / 示范数据 |

后两路的工程价值：**复用已有的上下文，只在关键决策点上训练，不用把很长的 agent 轨迹从头重跑。**

这解决的是 agent RL 的一个真实成本结构：一条长轨迹里真正需要学的可能只是中间某几个决策，但要到达那个状态必须把前面几十轮全跑一遍。用教师 / SFT 的前缀直接"摆"到那个状态，省掉的是生成成本（而生成在 agent RL 里占步时的绝大部分，见 [步时由环境执行主导](蒸馏项接入已有RL配方的正确写法与权重定法_20261028.md#312-长跑成本的结构步时由环境执行主导)）。

**代价（本篇推断，公开材料未展开）**：前缀来自别的分布，所以这两路严格说不是 on-policy 的，需要重要性修正或接受偏差；与 [写答案的 ≠ 被更新的 → 要比值](蒸馏项接入已有RL配方的正确写法与权重定法_20261028.md#32-为什么纯蒸馏也需要-off-policy-的刹车当天两次没看懂的点) 是同一个问题。

### 3.8 流程的变化：合并能力的位置挪了

| | 上一代 | 最新一代 |
|---|---|---|
| RL 阶段 | 分领域各训一个 RL 教师 | **一次混合 RL，所有领域一起训** |
| 多能力在哪合并 | 在 MOPD 蒸馏阶段 | **在 RL 阶段直接合并** |
| MOPD 的角色 | 主要的合并手段 | RL 之后的补充阶段（MOPD2），主要补**自动打分难**的任务 |

最后一格是 MOPD 剩下的不可替代用途：**自动打分难的任务没法做 RL（没有 reward），但可以蒸馏**（教师前向就是信号，不需要 verifier）。这与 [OPD 的无需 verifier 特性](在线蒸馏OPD与多教师MOPD_20261026.md) 对上了 —— 它的优势正好落在 RLVR 覆盖不到的地方。

### 3.9 为什么从"分领域 RL + MOPD"换成"一次混合 RL"

**官方给的两条理由：**

1. 不同领域的能力在 RL 里会**互相促进**，还能迁移到训练时没见过的 harness；
2. 目标是把 **RL 算力、环境多样性和打分算力一起放大**，走向自我提升。

**以下是推断，官方没有明说：**

- MOPD 最多只能学到教师的水平，想持续往上涨还得靠 RL 本身（§2.2 的封顶）；
- 现在的 agent 任务（SWE、终端、网安）之间**领域界限本来就模糊**，分领域训教师的意义变小；
- 用**超大 batch** 再**冻结 MoE router**，可能缓解了之前 Mix RL 的此消彼长问题。

第三条如果成立，意义是：**"Mix RL 配比敏感"可能不是方法的固有缺陷，而是 batch 不够大、以及 MoE 路由被不同领域互相拉扯造成的。** 这与 §3.3 第三篇"干扰其实很少"的发现方向一致。但这是推断，没有对照证据。

另有一条**未证实**的信息：搜索摘要里提到"只 RL 的那个权重在 agent 任务里可能反复调用同一个工具，建议优先用 MOPD 版本"，官方页面上没找到这句话。

### 3.10 怎么选

| 场景 | 选 | 重点 |
|---|---|---|
| 手上没有现成专家，领域比较相近（数学 / 代码 / 科学推理），想一次训完 | **Mix RL** | 调领域配比；batch 尽量大 |
| 多个团队并行开发，领域差异大（SWE agent / 指令遵循 / 数学），首要目标是保住每个专家已有的提升 | **MOPD** | 教师推理成本；**各领域 token 占比要平衡**（§3.4） |
| 有自动打分难的任务 | **MOPD** | 它不需要 verifier，这是 RLVR 覆盖不到的地方 |
| 还想超过教师 | MOPD **加结果奖励**（§3.2），或蒸馏完再接一轮 RL | α 的取值 = 两项的相对比例 |

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 多领域混合 RL 时某个领域掉点 | 配比敏感、此消彼长 | 按领域分别看通过率曲线；调配比做单变量 |
| 多教师蒸馏后短回答任务几乎没提升 | **token 级预算被长回答领域占掉**，不是梯度冲突 | 统计各领域贡献的 token 占比；平衡后重跑 |
| 蒸馏到教师水平就不涨了 | α = 0 时被教师封顶 | 加结果奖励项，看上限是否打开 |
| 蒸馏收敛很快但天花板低 | token 级信号密集 + 被封顶 | 比样本效率与最终分数两条曲线 |
| 融合后单次准确率涨、但原来不会的题还是不会 | 三类融合方法都不扩大覆盖面 | 比 pass@1 与 pass@k 两条 |
| 全对组不贡献梯度、样本浪费 | 二元 reward 下组内优势为 0 | 在通过测试的轨迹间按质量重分配优势 |
| 长 agent 轨迹重跑成本压过训练成本 | 要到达关键决策点必须重跑前面几十轮 | 用教师 / SFT 前缀直接摆到该状态 |
| 换了 agent 框架后效果掉很多 | reward 绑定了单一 harness | 训练时混入多种 harness |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| Mix RL 和 MOPD 是互斥的两条路线 | 生产版 MOPD 的优势里带 α × 结果奖励；α = 0 是纯蒸馏、α 很大退化回 Mix RL，是一个连续谱 |
| MOPD 被教师封顶是方法的固有上限 | 那是 α = 0 时的性质；加上结果奖励这一项上限就不再只由教师决定 |
| 原论文 0.937 vs 0.882 说明 MOPD 明显更好 | 该比较没有算力对齐（两阶段含训教师的算力）；另一篇综述里三者平均只差 1.4 分 |
| 多教师蒸馏的瓶颈是梯度冲突 | 复现工作的诊断是 **token 级优化预算分配失衡**，短回答任务被饿死；平衡后 35.6% → 83.4% |
| "Mix RL 一定被跨领域干扰拖累" | 有工作发现干扰其实很少，推理密集领域之间还互相促进 |
| 融合多领域能力能让模型会做原来不会的题 | 三类方法都只提升单次采样准确率，没有扩大解题覆盖面 |
| MOPD 在新一代流程里被淘汰了 | 它降为 RL 之后的补充阶段，但保留了不可替代的用途：**自动打分难的任务没法做 RL，却可以蒸馏** |
| 按 token 平均的 loss 对各类数据是公平的 | 它隐式按回答长度分配权重，长回答的领域自动拿到更多 |
| 问"最近火的 X 和 Y 有什么区别"，答"X 是个范式名"就够了 | 对方问的往往是某一次具体发布，先确认是哪一次（当天被追问纠正） |

## 7. 一分钟复习

1. **Mix RL** = 混合数据一次 RL，信号是整条回答的结果奖励；**MOPD** = 先分领域 RL 训教师，再学生自采样、教师逐 token 打分。
2. 粒度：Mix RL 一条回答一个优势；MOPD `Â_t = sg[log π_教师 − log π_θ]` 每 token 一个 = 学生采样上最小化反向 KL。
3. 上限：Mix RL 可在线探索、理论上可超越；MOPD **被教师封顶**（优势为 0 处就是追平教师）。
4. 难点：Mix RL **配比敏感、此消彼长**；MOPD **教师开销 + 领域间 token 预算失衡**。组织层面：耦合 vs 解耦（常是真实选型理由）。
5. **生产版 MOPD 不是纯蒸馏**：`A = sg[log(π_T/π_θ)] + α·A_结果`；α=0 纯蒸馏、α 大 → Mix RL → **连续谱，不是二选一**。
6. 四篇结论不一致：原论文 0.937 vs 0.882（**无算力对齐**）；综述平均差 ≤1.4 分但单项差 8.6 分、**三者都不扩覆盖面**；"干扰其实很少"推翻差距解释；复现工作 35.6% → 83.4%。
7. MOPD 短板的真因是 **token 预算失衡不是梯度冲突**；推广：**按 token 归一化 = 隐式按回答长度分权重**。
8. "只 RL 一次"：完全异步 GRPO、约 1568 prompt × 16、多领域 + **多 harness 同 batch**、rubric 离线生成、**通过测试的轨迹间按质量重分配优势**（= 把全对组变回有信号）。
9. **MOPD2 三路**：学生完整 rollout + **教师前缀**续写 + **SFT 前缀**续写 → 复用上下文、只训关键决策点，省掉长轨迹重跑。
10. 流程变化：合并能力从**蒸馏阶段**挪到 **RL 阶段**；MOPD 剩下的不可替代用途 = **自动打分难的任务**（不需要 verifier）。
11. 选：没专家 + 领域相近 → Mix RL（调配比、大 batch）；多团队 + 差异大 + 保已有提升 → MOPD（**平衡 token 占比**）；想超教师 → 加结果奖励或蒸馏后再 RL。

## 8. 自测问题

### 问题 1

用两句话说清 Mix RL 和 MOPD 的区别，并指出"最关键的区别"不是"混不混"而是什么。

期望回答：Mix RL 是把所有领域的数据混在一起直接对一个模型做 RL，学习信号是整条回答的结果奖励；MOPD 分两步——先在每个领域单独用 RL 训一个专家教师，再让学生自己采样、由对应领域的教师逐 token 打分蒸馏进一个模型。最关键的区别是信号粒度和能力上限：Mix RL 是序列级信号、能在线探索、理论上可以超过单领域训练；MOPD 是 token 级密集信号、样本效率高得多（每领域 25–30K vs 150–180K 量级），但被教师封顶——优势为 0 的点就是追平教师，学生没有理由再往前。

### 问题 2

"MOPD 被教师封顶，所以想继续涨只能换方法"——这句话错在哪？

期望回答：封顶是 α = 0（纯蒸馏）时的性质，不是 MOPD 的固有上限。生产版 MOPD 的优势是 `A = sg[log(π_教师/π_θ)] + α·A_结果奖励`，默认带结果奖励项。α = 0 是纯蒸馏，α 很大时退化回 Mix RL，所以两者是一个连续谱上的两端而不是互斥选择；加上结果奖励这一项，上限就不再只由教师决定。另一条路是蒸馏完再接一轮 RL。

### 问题 3

公开工作对"MOPD 和 Mix RL 谁更好"的结论为什么不能只记一个数？分别说出四篇的结论和边界。

期望回答：① 原论文给 MOPD 0.937 vs Mix RL 0.882，把差距归因于跨领域干扰，但没有做算力对齐的比较（MOPD 两阶段的总算力包含训教师）；② 一篇融合范式综述发现参数合并 / Mix RL / MOPD 三者平均差距不超过 1.4 分，但单个 benchmark 最多差 8.6 分，而且三者都只提升单次采样准确率、没有扩大解题覆盖面；③ 另一篇发现跨领域 RLVR 的干扰其实很少、推理密集领域还互相促进，直接削弱了第一篇对差距来源的解释；④ 一篇开源复现工作指出标准 MOPD 只拿回 35.6% 的提升空间，原因不是梯度冲突而是 token 级预算失衡，平衡后到 83.4%。综合起来只能说两类方法各有适用场景，不能说哪个更好。

### 问题 4

多教师蒸馏里"短回答任务被饿死"的机制是什么？把它推广成一条通用规律。

期望回答：优化预算是按 token 分配的，而不同领域的回答长度差异很大，于是长回答的领域自动占掉大部分 token、短回答的任务（如指令遵循）拿到的有效预算很少。这不是梯度冲突，而是预算失衡；平衡各领域 token 占比后效果从 35.6% 提到 83.4%。通用规律：按 token 计数的 loss 归一化会隐式地按"回答长度"给各类数据分配权重——长回答的领域拿到更多权重，不是因为它更重要，而是因为它更长。任何"多种数据混在一起、按 token 平均"的训练都有这个问题。

### 问题 5

"在已经通过测试的轨迹之间再按质量重新分配优势"解决的是什么老问题？

期望回答：解决"全对组不贡献梯度"的问题。二元 reward 下，同一题全部通过的那一组回答 reward 都是 1，组内归一化后优势恒为 0，完全不贡献梯度，样本白生成。在这些已通过的轨迹之间按质量（更简洁、更少冗余步骤等）重新分出高低，就把原本浪费掉的全对组重新变成有信号的样本。

### 问题 6

MOPD2 的三路数据分别是什么？后两路的工程价值是什么，代价是什么？

期望回答：① 学生自己完整跑的 rollout；② 接着更强教师的轨迹前缀往下生成；③ 接着 SFT 示范的前缀往下生成。后两路的价值是复用已有上下文、只在关键决策点上训练，不用把很长的 agent 轨迹从头重跑——agent RL 里真正要学的往往只是中间某几个决策，但到达那个状态要重跑几十轮，而生成占步时的绝大部分。代价（推断，公开材料未展开）是前缀来自别的分布，这两路严格说不是 on-policy 的，需要重要性修正或接受偏差，和"写答案的模型 ≠ 被更新的模型就要比值"是同一个问题。

## 9. 尚未解决与后续路线

- 算力对齐的 Mix RL vs MOPD 比较还没有公开工作做过，现有分数差距都不可直接比；
- "超大 batch + 冻结 MoE router 缓解了配比敏感"是本篇推断，没有对照证据；
- MOPD2 两路前缀的分布偏差怎么修（是否带重要性权重、怎么界定关键决策点）公开材料未展开；
- 三类融合方法"都不扩大解题覆盖面"这个结论的适用范围（是否只在那批 benchmark 上成立）未知；
- 本地要落地 MOPD 时，α（结果奖励权重）与蒸馏权重是两个独立旋钮，两者的定法还没有方法，只能沿用[β = 两项梯度相对比例](蒸馏项接入已有RL配方的正确写法与权重定法_20261028.md#37-蒸馏权重-β-怎么定) 的思路先量级再定；
- 领域路由的粒度（按数据集标签还是按内容分类）与路由错误的后果没有材料。
