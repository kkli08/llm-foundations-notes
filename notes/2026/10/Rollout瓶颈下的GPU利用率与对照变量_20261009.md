## 0. 今天最终要解决的问题

训推分离的 Agentic RL 任务里，训练节点一直报 “low usage”。是不是 Router Replay 让训练变慢、推理卡在等？还是推理时保存 Expert ID 更耗时？

## 1. 先给结论

- **两个猜测的方向都需要修正**：训练只占每步一小部分，是**训练卡在等 Rollout**，不是推理卡在等训练；Expert ID 返回是否拖慢推理，在现有数据里分不出来。
- 训推分离时，每步时间 ≈ 等 Rollout 收齐一批 + 训练；训练节点利用率 ≈ 训练时间 / 步时间。Rollout 占大头时训练节点天然低利用率。
- Agentic 多轮任务的 Rollout 常受**会话并发低 + 长尾**限制：同时在跑的会话远少于上限，推理每轮 Decode 批很小，GPU 主要在等显存读写。
- 两次运行若除目标开关外还改了 Padding、Sandbox 集群、源码版本、运行时间段，就**不是单变量对照**，单请求耗时差异不能归因到目标开关。
- 提高并发：推理端通常不会直接 OOM（KV 预分配，不足时抢占重算，结果是变慢）；训练端每步数据量固定，不受影响；真正的风险在 Sandbox 侧失败率与配额。

## 2. 前置概念

### 2.1 训推分离的步时分解

```text
step time ≈ wait_rollout（收齐一批）+ train（重算 logp + 前反向 + 权重同步）− overlap
```

“low usage” 告警看的是 GPU 利用率；训练节点每步只忙几分钟、其余时间等数据时，利用率自然只有一成左右。这本身不影响正确性。

### 2.2 单请求耗时与批大小

Decode 批越大，单请求每步越慢、总吞吐越高。所以“单请求平均耗时变长”可能只是因为同时在跑的会话更多，而非某个额外开销。

## 3. 完整原理

### 3.1 先看瓶颈在哪一侧

判断顺序：

1. 拆步时：等 Rollout 占比 vs 训练占比；
2. 分节点角色看利用率：推理节点与训练节点分开；
3. 再看 Rollout 内部：在跑会话数、Decode 平均批大小、会话耗时分布（均值与最慢者）。

若训练占比很小，即使目标功能让训练慢了一些（例如重算 logp、反向各多几十秒），对端到端也几乎无影响；优化对象应是 Rollout。

### 3.2 并发上限不是唯一瓶颈

一批开始时能打满并发上限；后半段只剩长尾慢会话在跑，并发自然掉下来。提高上限只加快前半段，**长尾不会变短**，而一批要等最慢会话结束才能进训练。因此优化顺序通常是：

1. 先处理长尾：单会话超时或轮数上限；
2. 再把并发与 Sandbox 池一起小幅提高，短 smoke 观察推理抢占次数与 Sandbox 失败率。

### 3.3 提高并发的三处风险

| 位置 | 会不会出问题 | 原因 |
|---|---|---|
| 推理引擎 | 一般不直接 OOM，但可能变慢 | 显存按比例预分配给 KV；KV 不足时暂停部分请求、之后重算。长上下文 + 高并发下抢占频繁 |
| 训练 | 不受影响 | 每步训练样本数固定，与 Rollout 并发无关 |
| Sandbox / 环境 | 风险最实际 | 池要跟着加大；配额、创建失败、网络错误增多，失败会话被丢弃或重试反而浪费时间 |

附加的路由缓存若按 KV 物理块数分配，也随 KV 容量有上限，不会随并发无限增长。

### 3.4 单变量对照的要求

把“开 R3 前后”的长跑当对照前，逐个比对配置差异：

| 差异类型 | 是否影响结论 |
|---|---|
| 目标开关本身（Replay 模式、返回 Route） | 预期内 |
| Padding 策略 | 影响训练显存与耗时 |
| Sandbox 所在集群 | 影响会话延迟与可并发数 |
| 源码版本 | 未逐文件核对就不能排除 |
| 运行时间段 | 集群负载与服务状态不同 |
| 保存间隔 | 不影响单步速度 |

只要存在非目标差异，单步更快/更慢都只能说“相关”，不能说“由目标开关导致”。要单独量出某项开销，需要同源码、同环境、只切换该开关的短 A/B。

## 5. 工程中的具体表现

| 现象 | 原因 | 如何验证 |
|---|---|---|
| 训练节点持续 low usage | 训练只占步时一小部分，在等 Rollout | 步时分解 + 分角色利用率 |
| 推理节点也跑不满 | 会话并发低、Decode 批小、等 Sandbox | 在跑会话数与 Decode 平均批大小 |
| 开某功能后单请求变慢 | 可能是并发更高、批更大 | 同时比较并发与批大小；做单变量 A/B |
| 提高并发后反而不快 | 长尾不变、KV 抢占或 Sandbox 失败增多 | 抢占次数、失败率、会话耗时分布 |

## 6. 常见误解

| 容易误解为 | 更准确的理解 |
|---|---|
| 训练变慢导致推理等待 | 训推分离下通常是训练等推理；先拆步时再判断 |
| 单请求变慢就是新功能开销 | 批变大也会让单请求变慢，需控制并发 |
| 并发调高就能线性提速 | 长尾不变；后半段并发自然下降 |
| 推理高并发会 OOM | 预分配 KV 下多表现为抢占重算、变慢 |
| 两次长跑只差一个开关 | 必须逐项比对配置、源码、环境与时段 |

## 7. 一分钟复习

1. 训推分离：训练利用率 ≈ 训练时间 / 步时。
2. 先定位瓶颈侧，再谈优化；Rollout 侧先治长尾再提并发。
3. 推理高并发多是抢占变慢，风险在 Sandbox。
4. 单变量对照前先 diff 全部配置与环境。
